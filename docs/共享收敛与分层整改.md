## 1. 模块依赖方向：合规，无需动

- `common` 对上层零 `import` 回跳（仅 KDoc 提及 `engine.skia`，在 `ParagraphBreaker.kt` / `ParagraphShapeRef.kt`）。
- `engine-skia` 对壳层/`shared-ui` 零实现依赖（仅注释提及）。
- `shared-ui` 对 `common`/`engine-skia` 均为上调下；两壳经 `ReaderScreen` + `ReaderHost` 装配，无自建阅读面。
- 结论：分层问题不在模块 DAG，在**同义代码各写一份**与**内核逻辑上浮**。

## 3. Q2：分层违规（内核上浮 / 分页底层缺位）

### 3.1 内核级逻辑写在上层

- `ReaderActivity.kt:715 fontPool()`：Activity 内拼 Android `Typeface` 投影，主文本已走 skia 窗口，此桥只剩表格 fallback，不应再参与主流程。
- `ReaderActivity.kt:756 withBookStyle()`：壳内跑 `LightCssParser+StyleComputer+BookStyleProbe` 级联快照，引擎层职责。
- `ReaderActivity.kt:485 scheduleRelayout` / `:342` 重排事务 / `:511 applyReflowResult`：分页 epoch、整书扫描、版式绑定在 Activity，`BookDocumentController` 只被当调用库。
- `app/.../engine/text/SystemCjkSerif.kt`：Android 缺族补丁是真边界（桌面靠 CoreText 回退），但放错模块，应迁 `engine-skia/androidMain` actual。
- `desktopApp/.../ReaderView.kt:63`：字体枚举+中文名双链写在视图层；`ReaderModels.kt:142 fontSlotFor`：UI 层做字体槽位路由（与 Q1-3 同源）。
- `engine-skia/.../BoxChapterLayouter.kt:73 Executors.newFixedThreadPool`：JVM 并发原语在 `commonMain`，今能编过只因目标全 JVM 系，iOS 一加即炸，应换协程分发或 expect/actual。
- 以下经复核**不判违规**：`ReaderScreen.kt:98 TypographicProfile.build`（density 是 UI 关切，计算体在 common，纯调用）；`ReaderPageCanvas.kt:61 anchorY/shift`（绝对坐标进绘制必须对齐，与 `alignPageTop` 同口径，收益小不动）。

### 3.2 分页底层缺位（根因）

- 增量分页/磁盘缓存/并发优先级（F>A>B1>B2>P、`canonicalJobs`、`TEMP_WINDOW`）全在 `BookDocumentController`（engine-skia facade），`common` 的 `BidirectionalPaginator` 生产零调用（仅测试在调）——**common paging 层是空的**。
- `DesktopReaderHost.kt:210 landAnchor` 切片查找、`onSaveProgress` 两壳复刻存档顺序，皆同根所生，随底层补齐自然消除。
