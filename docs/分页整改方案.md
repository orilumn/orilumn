# 分页整改方案

依据：`docs/分页预排原则.md`（S1–S7、队列 1–8、表维护口径）。本方案只列改动条目与验收，不重复原则。
层级声明（AGENTS.md）：条目主体属**排版层（上）**；R4/R5 跨用户层（理由见条目内）；渲染层不动；
KMP 共享模型：引擎改动全在 `engine-skia`/`common` 的 commonMain，平台壳只调既有接口（R4 节流位置、R5 尺寸监听除外）。

## R1 handoff 窗口记账（L6，最高优）

- 背景：全量绑定的地方窗口都没记，下一翻重塑并丢弃全章成果（日志实锤 `layoutLC 636→34`）。
  全量绑定点共 5 处：`finalizeTempOnLeave`（`BookDocumentController.kt:1248`）、
  `fullLayoutAndPersist`（`:1692`，B2 后台全量——面最广，每章首访即弃 B2 成果）、
  小章全排（`:614`）、`bindReflow`（`:1799`，小章 reflow 全量时）、legacy 全排（`:580`，非 Box 才可达，defensive）。
  部分绑定（已带窗口，正确，无需动）：`ensurePageRangeShaped:508`、DISK-HIT `:572`、`prewarmForOpen:1649`。
- 改动（排版层（上））：5 处全量绑定记窗口为全量范围（`shapedPageFrom=0, shapedPageTo=slices.size`），
  收敛为 `bindFull()` helper，防第六处再漏。
- 验收（平板落盘）：改参→到首页→章内连翻，全程无 `ensurePageRangeShaped` 日志（冷命中首窗除外）；
  `FLIP` 的 `layoutLC` 保持全章行数；B2 跑过的章首访也不重塑。命令：`run-as orilumn.reader cat files/logs/日志_YYYYMMDD.txt | grep -E "Orilumn.FLIP|ensurePageRangeShaped"`。

## R2 跨章诊断（L9，纯日志，先行）

- 背景：症状 3（翻一页变一章）定位靠猜；`tempNav→null` 有 6+ 分支（前向尾 `:1093`、后向塑形失败 `:1152`、
  Boundary `:1182`、RE-ROOT 等），现只有一句笼统日志。
- 改动（排版层（上））：跨章前记“哪个 null 分支 + 指针（`curIsForward/curIndex/headLanded`）+ 窗（`forwardPages/backwardPages` 首尾 slice）+
  当前 slice”，打到 `Orilumn.FLIP` 同行或紧随行。零行为变更。
- 验收：复现跳章时，一眼定位分支。后续 R11/症状 1 排查复用。

## R3 磁盘窗邻页预塑（L1，体感主体）

- 背景：S7 要求章内命中后重做第 2/3 步；磁盘窗通道现在一步都没有，连翻每页现塑 350ms+。
- 改动（排版层（上））：落页后（`ensurePageRangeShaped` 窗内命中、跨章落位、`prewarmForOpen` 窗）后台塑邻页：
  方向优先（按下页/上页 order，同 `stepTempPrefill:885` 口径），上页跨章跳过，复用 `unitShapeCache`，
  与翻页线程串行（`layoutMutex`），参数代际过期自弃。temp 路径不动（prefill 已覆盖）。
- 验收：连翻时第二页起命中预塑窗，`ensurePageRangeShaped` t= 显著下降。平板实测（2026-09-25 ch6）：
  L2 命中≈100% 时 t= 从 ~1100–1700ms 降到 ~550–680ms（块塑形占约 2/3）；剩余约 550ms 为窗口组装
  （prepareLight + 行流重建 + skia 窗 + 分页），不在本步范围内，未命中页（如预塑未发布）仍全量塑形。
  `win-l2` 计数与 `win-prefill t=` 常驻日志供持续对账。

## R4 S1 瘦身（V-a，跨层）

- 背景：S1 定死“只刷当前页、不跑队列”；现状平板 preview 每 16ms 全量 `prepareRelayout`（废他章+bump+voidPreflight）。
- 改动：用户层（宿主节流循环 `ReaderActivity.kt:587-604`、桌面 `ReaderView.kt:162-180`）只做本章轻刷新；
  排版层（上）收敛作用域（`prepareRelayout` 拆轻/重，或加 scope 参数；轻量不碰他章/epoch/preflight）。
  跨层理由：触发频率与副作用范围分属两层——节流与“是否全套”判定在用户层，作用域收敛只能在排版层，接口须跨层传参。
- 验收：拖滑块期间，他章无 relayout/layout 落盘动作（落盘无他章 `layout|DISK-WRITE|anchorBlock` 行，`FLIP` 他章不受扰）；松手/退出后 B2 一次跑完。

## R5 平板 resize（V-b，S6，跨层）

- 背景：平板旋转/分屏零处理（旧尺寸旧表继续画，实锤 bug）；桌面靠重建隔离。
- 改动：用户层监听尺寸（`ReaderActivity.kt:276-285` 处补分支）→ 排版层（上）走 S1/S2 同链（`contentW/H` 已在键内）。
  跨层理由同 R4（事件在用户层，失效与重排在排版层）。
- 验收：旋转后即时重排，日志出现对应 relayout + 新 `contentW/H` 的 hash；无旧表复用（R6 守卫兜底）。

## R6 旧表复用 hash 守卫（V-c，安全网）

- 背景：三处用表不验 hash（`ensureChapterLayout:455`、`ensurePageRangeShaped:471`、`backwardEntryAnchorChar:48` 且先读后 ensure）；
  `invalidateForParam` 零调用。
- 改动（排版层（上））：复用前比对 `unit.paramHash` 与现算 hash，不等即废（复用 `invalidateForParam`，或删掉该死 API二选一）。
- 验收：改参/resize 后无旧表复用；R4/R5 落地的前置安全网，优先于它俩合并。

## R7 B2 距离序与覆盖（L2）

- 背景：B2 现状是方向分组、组内最近优先（`orderRemainingChapters:2306-2310`：前向组 `6,7,8…` + 后向组 `4,3,2…`），
  不是严格章号偏离绝对值交错（应为 `6,4,7,3,8,2…`）；只在改参后跑（开书/跨章不跑）；磁盘 LRU32；无全书状态登记。
- 改动（排版层（上））：`orderRemainingChapters` 改绝对值交错（同距离按阅读方向破平）；dispatch 点加开书
  （`prewarmForOpen` 尾）与跨章（`findAdjacentPage` 成功后，均 epoch 去重，均不取消在途，S7 相容）；
  上限 32→256（`PaginationCacheCodec.kt:39`，≤8MB 最坏）；内存状态登记以 **skip-fresh** 代之（磁盘表即 done 登记，
  B2 跳过表已新鲜的章，断点续跑天然便宜，`skippedFresh=` 计数）；新章 B1 提权默认开（B1 派发时取消在途 B2
  并在其后 `force` 重排，`force` 只 bypass epoch 去重）。
- 落地时追加（实现中发现）：小章重排（轻/重两处）清 `blockShapeCache`——heavy 从不进共享缓存，否则 R5 重绑新表后
  翻页复用旧字形（R6 守卫会放行，错得安静）。
- 验收：B2 日志顺序为 |距离|交错（含 `skippedFresh=`）；开书后远章逐步落盘（`DISK-WRITE` 按序出现）；重进大书不再反复 misses。

## R8 跳转命中分支与路径标记（L5）

- 背景：跳转无命中分支、无路径标记（`PATH_TEMP/FULL/WIN`）。
- 改动（排版层（上）为主）：`ensureChapterLayout` 类入口显式化命中分支并写标记；`bind`/finalize/ensure 只写标记不猜；
  用户层跳转入口行为不变（已调 `finalizeOnLeave` + ensure）。
- 验收：跳转日志打出 `PATH=` 与命中情况；R3/R7 的验证依赖此标记对账。

## R9 窗口诚实值（L8，顺手）

- 改动（排版层（上））：DISK-HIT 塑 1 页记 1 页窗（`:568` vs `:574` 对齐），seam canary 的 `oldTo` 对账同步。
- 验收：`DISK-HIT shape shapedPages=1` 与窗口一致；无行为变化。

## R10 前置决策门（已清空）

- D1、D3 已决（见原则文档 §2 S1/D1、S5/D3 注记），对应验收放行：S1 验收按 D1 四规则（含回翻倒推、上页排满即显示、
  未满按 S5）；跨章语义按 D3（连跳 + R2 跳过日志；阈值已核实，审计关闭）。
- D4 已决：修改 = 增量切全量时的标记变更（`PATH_TEMP`→`PATH_FULL` + 废增量），设置 = 开书初设 `PATH_FULL`；
  表内容永不可变。R8 gate 打开。

## R11 avoid 统一（已暂缓，有重开条件）

- 背景：`break-inside:avoid` 只在 `Paginator` 路径生效，temp 装配不消费 → 两套分页在 avoid 块处分叉，
  handoff 后错位 + 页底空白口径不一。
- 定案（2026-09-25 平板实测）：R1 落地后约 30 翻（temp/全量/磁盘窗三态）逐页核对，接缝全部连续，
  无缺行、无跳页、无页底异常——avoid 分叉无活体症状。R11 暂缓，不动手。
- 重开条件：落盘出现 `SEAM-*` canary、或 `FLIP` 接缝核对发现缺口（核对法见 docs 调试文档 §6）。
  动手内容不变：temp 装配消费 avoid（或证明等价并立单测）。

## R12 同章 mid-jump 搬指针（V-f，优化项，排版层（上））

- 目标落在已塑窗口则只搬指针，不走 `relayoutTo` 全 nuke。效率项，不影响正确性，排后。

## R13 实例与书 1:1 不变式（V-e，健壮性，用户层 + 排版层设施）

- `open()` 零清理靠构造隔离。记不变式 + `close()` 二选一，排后。`close()` 若加，加在 controller（引擎设施），
  由宿主（用户层）调，跨层点仅此一调用。

## R14 进度条空章双向（小项，排版层（上））

- 背景：`pageAtFraction`（`BookDocumentController.kt:1898-1910`）目标章无内容时只单向扫有内容章，
  进度精确拖放可能落错章。
- 改动（排版层（上））：双向就近找有内容章（距离优先，同队列 |距离| 口径）。
- 验收：进度条拖到空章区间落到就近有内容章，不跳远。

## R15 双端 S1 节流收敛（小项）

- 背景：桌面 150ms 防抖单发 vs 平板 16ms 循环（R4 瘦身后仍是两种触发节奏），行为应收敛到“稳定后单发”。
- 改动（用户层，两端宿主）：统一节流语义；排版层接口不变。
- 验收：双端拖滑块期间引擎侧调用序列一致（本章轻刷新 N 次 → 退出全套一次）。

## 实施顺序与依赖

R1 → R2 → R6 → R4 → R5 → R3 → R8 → R7 → R9 → R11 → R12 → R13 → R14 → R15。
R6 是 R4/R5 的前置安全网；R8 的标记是 R3/R7 对账依据（可先行简版标记，不 block R3）；
R11 已暂缓（残留检查通过，无活体症状，重开条件见条目）；R10 已清空（D1–D4 全决），各 gate 打开。
验证总则：每条合并前平板实测，落盘 `grep -E "Orilumn.FLIP|ensurePageRangeShaped|SEAM|DISK-HIT|DISK-WRITE|temp 作废"` 对账；
症状映射：卡顿归 R1/R3，跳章归 R2(+R11)，缺行/空白归 R1/R11。
