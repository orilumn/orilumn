# 分页计算集中化方案

层级声明（AGENTS.md）：本文主体属**排版层（上）**（分页算法与调度）+ **排版层（下）**（Store/编解码基础设施）；
§6 字形度量共享涉及**渲染层**（字体渲染、几何测量），跨层理由见该节。KMP：集中化逻辑全在
`common`/`engine-skia/commonMain`，双端壳只调既有函数（导入钩子/open 接线）。

目标：分页慢的根因是同一份计算在错误的时间、错误的地点反复跑。本方案把分页全链路按
“**随什么变**”切开——不变的导入时算一次持久化，半变的打开时算一次，真正随参数变的才
留给阅读/排版时；其中可共享的一次算完多处复用。

## 0. 基线：冷 prepare 各阶段耗时（真书 558 章，JVM 实测；平板按比例放大）

| 阶段 | 全书 | 占比 | 备注 |
|---|---|---|---|
| zip 读章节+CSS 文本 | 190ms | 6% | `readText`，懒加载分摊到各章首次触达 |
| XML→DOM（`convertWithStyles`） | 512ms | 15% | 同上，在翻页线程上付 |
| CSS 收集+tokenize | 114ms | 3% | 1115 份文本只有 **3 种不同**，2MB 被重复 tokenize 558 次 |
| `preprocess` | 36ms | 1% | 产物是新树 |
| **结构级联**（`computeStructure`） | **2671ms** | **78%** | 大户；单章最慢 76ms |
| 块塑形（skia break，首遍全书） | 章均 20–180ms（设备落盘） | — | 随字号/字库变，不可集中 |
| 窗口组装 | ~550ms/页（R17 实测） | — | 成品页缓存命中则 0ms |

结论：结构级联是唯一值得跨时间持久化的 CPU 大户；DOM/CSS 是 IO 型小户但**在翻页线程上付**，
体感上同样要搬走。

## 2. 落位总表

### 导入时（`addBook` 后台 fire-and-forget，双端共用 `ImportStructures`）

- 全章：1.2 DOM → 1.3 CSS（去重）→ 1.6 preprocess → 1.7 结构（media-free 章），写
  `structure/book_<id>/`：`_sheets.bin`（hash→文本，全书一份）+ `<ch>.bin`
  （sheet hash 表 + 后处理树 + 结构 + cssHash）。
- 含 `@media`/条件 `@import` 的章节只记 flag，不写结构文件（也不写树：preprocess 可能随视口变）。
- 1.9 字体需求、1.14 章节标题表：文本量极小，随包持久化（每章几十字节，开屏追装/目录零解析）——格式与树文件同批落，未实现先记待办。

### 打开时（已有包：缺啥补啥，不阻塞首屏）

- 结构文件齐：读一章文件即得树+结构+CSS（**不再碰 epub 文本**）→ relink（路径逐条校验，失败即现算覆盖）。
- 缺文件（老书/media 章）：走老路（1.1–1.7 现算）+ 顺手写盘（`prepareLight` 回调 + `ensureMarkup` relink 位）。
- 只做一次的：1.8 unique sheet 解析（✅ 已落：`BoxChapterLayouter.sheetCache`，同文本同视口全书一份，轻重同吃，并发门 `sheetLock`）、1.10 池预热、1.15 spine map memo、B2 整书扫描（注意：B2 走重路径 `prepare`，自带级联，不吃轻结构缓存——`styleMap` 统一后才省，见 §2）。
- 升级：构建号（`diskCacheVersion`）对不上即分页表整体失效（已落地）；结构文件另有
  `STRUCTURE_VERSION`（级联语义）+ `cssHash`（作者 CSS）双保险。

### 阅读/排版时（只剩真变量）

- 1.11 块塑形（字号/字库/版心宽任一变即重算；同周期 `blockShapeCache` 去重）。
- 1.12 几何+分页（磁盘表命中则只组装窗口；`pageCache` 命中则 0ms）。
- 1.5/1.8 只有含 media 章或旋转/改参才跑；media-free 章旋转不再重算结构（`loadedMediaFree`）。
- 绘制：行/图/背景缓存随 `layoutRevision` 失效（现状，不动）。

### 一次算完多处共享（同进程）

- `parsedAuthorSheets`：已按章缓存；**待办**：跨章 unique 共享（同一文本全书只解一次）。
- `prepareResult`（重路径）：已按 `paramHash` 缓存；轻重双级联同周期各算一遍是已知浪费
  （小章）， sheets 去重先做，`styleMap` 统一单列大项。
- 1.15 spine map、1.9 demand：book 级 memo（小项）。
- 1.11 塑形：同周期跨章同文本同样式可共享行对象（§6 铺垫，当前仅 `blockShapeCache` 章内有效）。

## 4. 附：为什么重路径 `prepare()` 不进导入

它的产出（全量 `styleMap` + 盒几何） staple 在 profile（字号/行距/边距/字体）和视口上，
import 时 profile 未知，**无法**预建——不是优先级取舍，是不可行。它的浪费是同周期重复
（小章 light+heavy 双级联），归 §2“一次算完多处共享”，不归跨时间持久化。

## 5. 版本纪律（与 `LAYOUT_VERSION` 同级）

- `ChapterStructureCodec.STRUCTURE_VERSION`：converter/preprocess/级联谓词/char 归一/
  属主规则/UA-主题-UI 任一触及结构消费属性（display/white-space/background/break-inside/
  visibility）的改动即 bump。
- 树格式 `VERSION`：节点字段变化即 bump。
- 漏 bump 的后果是静默错位（不是崩溃），故单测加“双 profile 字节一致 + 篡改拒绝”双锁
  （已落：`PersistedStructureRelinkTest`）。

## 6. 更深入：字形度量共享（立项分析，不在本期实现）

用户直觉是对的：**汉字在同一字体/字号/字重下 advance 恒定**（方块字 em 等宽），逐章逐段
重复调 skia 量同一批字是纯浪费。但“度量”要拆三层，共享粒度各不同：

1. **单字 advance**（`paint.measureText` 级）：决定元 =（字体文件字节/版本、字号 px、字重/伪粗斜、
   letter-spacing、script/fallback 解析结果）。CJK 统一码块在同一面内 advance 与上下文无关，
   可跨章、跨书共享；键必须含**字体文件版本**（池签名里已有驻留族，缺文件版本——补上才敢共享），
   且 latin/数字/全角标点按比例宽度走（同键仍可共享，天然 covered）。
   反例：fallback 逐字不同（同一 run 里中日文混排回退到不同面）、`font-feature` 上下文替代
   （连字/条件字形）、合成表情（多码点一字形）。所以共享单位是**同 fallback 解析的 run**，
   不是裸字符。
2. **断行**：用共享 advance 跑断行算法（`SkiaParagraphBreaker` 上游），断行本身是纯函数，
   可复用；但两端对齐/标点挤压（CJK kinsoku）的行内调整是行级上下文，调整量可缓存、决策不可跨行共享。
3. **整段塑形**（`ParagraphShape`）：文本+样式+版心宽全同才可共享（标题/重复段落天然命中）；
   内容寻址（文本 hash + style hash + 宽）做全书/跨书 LRU，命中即零 skia 调用。

层级注记：度量缓存在**渲染层**（`engine-skia/.../skia/`，`SkiaParagraphBreaker` 下）或紧贴其上的
塑形缓存（`blockShapeCache` 跨章化）二选一；键里的字体文件版本由用户层池同步提供（跨层只传
版本号，不碰池）。先做第 1 层（advance LRU，风险最小、覆盖汉字主体），第 2/3 层按实测命中率再定。

实施顺序建议：树+sheets 持久化 → unique 解析/memo 小项 → 度量第 1 层立项。
