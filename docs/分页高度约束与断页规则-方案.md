# 分页高度约束与断页规则接线 — 方案

> 分支：`fix/platform-consistency` ｜ 状态：设计定案，分阶段执行
> 关联：`docs/image-fullwidth-preprocessing-plan.md`、`docs/分页预排原则.md`、
> `docs/分页计算集中化方案.md`、`docs/TODO-未尽事宜.md`（Q30）

## 0. 一句话

分页模式下，块级插图的高度必须受「**它所属的不可断簇要装进一页**」这一预算约束（口径乙）；
而「簇」由相邻块的 `break-before`/`break-after`（含 legacy `page-break-*`）与强制分页决定
—— 因此必须先把这两个**今天只是死字段**的属性接线。

## 1. 问题与口径

### 1.1 现象

全屏（版心 4920×2560）读《Kotlin in Action, 2nd Edition》：整宽插图被主题
`.orilumn-fullwidth-image { width: 100% }`（tier 42）拉到 4920 宽，内在 1122×735
⇒ 盒高 3223 > 版心高 2560 ⇒ **图装不进一页**，被裁。

> ⚠ **本条触发路径已于 P3a 从用户层退役（§4.5）**：产品决策删掉主题那条拉伸规则后，
> 本样本回到 intrinsic 1122×735，**不再溢出**。以下保留现场记录，同时作为 P3「安全网」
> 的动机说明（仍要覆盖原书自定宽高 / 原图本身就超高 / 显式 min-height 三类）。

### 1.2 为什么必须缩，不能折页

已核实：

- `Paginator.fillWholeLines` 只收**整行**；「装得进整页但装不进剩余空间」的图本就会顺延到下一页
  （这不是 bug）；只有**单行本身高过整页**时才强收一行（`Paginator.kt:38`）。
- `applyBreakInsideAvoid` 对 oversized 块明确「allowed to tear」（`Paginator.kt:98`）。
- 引擎无 `vh`/`vw`，无 monolithic 概念（`StyleComputer.parseBoxSize` 对不认识单位返 null ⇒ 静默
  当 auto）。

⇒ 对「单行高过整页」的整宽图，折页物理上无解，**唯一出路是按比例缩小**（浏览器不缩，是靠阅读系统
注入 CSS 决策；本仓落成布局约束，见 §3）。

### 1.3 口径乙（已拍板）

- img 与**其所在不可断簇**（图注，以及由 `break-*: avoid` 串联起来的相邻块）必须装在**同一页**；
- img 预算 = `contentH − 簇内非图内容实测高`；
- 簇被**强制分页**（`break-before/after: always | page | left | right`）截断 —— 不给强制断页另一侧
  的内容让位；
- 簇内非图内容**自己就 ≥ contentH** ⇒ 缩图也无济于事 ⇒ **不缩**（保持现状，允许撕裂）；
- 切图有**下限 FLOOR**，避免缩成不可见（见 §9）。

### 1.4 真实触发例（已核实，作为验收样本）

`~/.orilumn/books/book_1791219085400.epub` → `OEBPS/Text/Ch01.htm:706`：

```html
<p class="fm-figure"><img class="calibre3" src="../Images/CH01_F02_Isakova.png"/><br/></p>
<p class="fm-figure-caption"></p>
```

书内 `stylesheet.css:402`：

```css
.fm-figure { display: block; page-break-after: avoid; ... }
```

⇒ 图片块 `breakAfter = AVOID`（**已解析、从未被消费**）⇒ 图注必须与图同页。今天因不消费，
图被单独撕裂裁切。**簇 = {图块, 图注块}**，正是「乙 + 邻居 break」要处理的对象。

> 注：P3a 退役主题拉伸后，本样本的图不再超页（§1.1 注），因此它**不再是 P3 的验收输入**，
> 而转为「P4 forced/avoid 接线」的样本（图注与图仍应同页）。P3 的验收输入改用：
> 竖长原图 / 原书自定 `width` 的图 / 显式 `min-height` 的图（§5-B5、§8）。

## 2. 现状事实（已核实）

### 2.1 `break-before` / `break-after` 是死字段

- `ComputedStyle.breakBefore/breakAfter` 全仓**零读点**（生产代码只赋值，从不读）。
- `BreakRule` 只有 `{ AUTO, AVOID }`（`css/ComputedStyle.kt:28`）；`parseBreakRule`
  （`css/StyleComputer.kt:563-564`）= 「含 `avoid` → AVOID，否则 AUTO」
  ⇒ **`always`/`page`/`left`/`right` 静默降级为 AUTO**，引擎里根本没有「强制分页」概念，
  `Paginator` 也不含强制分页。
- legacy 别名**已接**（`parseBreakAny`，`StyleComputer.kt:403-405`）：`page-break-after` → `breakAfter`，
  `page-break-inside` → `breakInside`。⇒ 真实书里的声明**确实落进了字段**，只是没人读。
- 唯一被消费的是 `break-inside`：`LayoutBox.breakInsideAvoid` → `breakInsideAvoidRanges`
  → `Paginator.applyBreakInsideAvoid`。

### 2.2 图片 used size 是「多点重复计算」（量画失配风险）

单源数学：`ComputedStyle.usedReplacedSize(iw, ih, containingW)`（`css/ReplacedSizing.kt:37`，§10.4
约束表）。封装：`NormalFlowLayout.replacedUsedSize` / `replaceableHeightOf`。调用点：

### 2.3 几何与断页有 N 条实现（本仓经典「双路漂移」坑）

- **几何**：重路径 `NormalFlowLayout.buildBoxTree` + `flowBoxes`；轻路径 `LightPrepare.block(i)` +
  `rebuildLocalLines`；临时页 `assembleTempPage` 的 trim 循环 + `shapeTempPageForward/Backward`
  （内里有**第二份**页面填充实现）。
- **avoid ranges 三份**：`BoxBookLayout.breakInsideAvoidRanges`（重）、
  `text/BoxDrawableLayout.breakInsideAvoidRanges`（绘制）、`LightPrepare/PartialDrawableLayout`
  的（轻，靠结构缓存 `leafToBreakInsideAvoidOwner`）。
- **填充规则两份**：`Paginator.fillWholeLines`（唯一共享），以及临时页
  `while (lines[lastLine-1].yBottom - pageTop > contentH) lastLine--`。

### 2.4 结构缓存是「视口/排版无关」的

`ChapterStructureCodec`：media-free 章的结构在导入期建库、开书期按 child-index relink；它消费的
级联属性（display / white-space / background / break-inside / visibility）**只来自 author/UA 表**，
所以不随排版参数失效。⇒ **预算（依赖 contentH/contentW）绝不能进结构缓存**；簇的 `break-*` 属性
可以现算（不必持久化）。

## 3. 分层归属（AGENTS.md）

- **渲染层**：`usedReplacedSize` 只多收一个「高度上限」参数 —— 纯几何、无策略。**不碰** ua.css /
  主题表 / 级联，**不加** `vh` 与 `%` 高度解析。
- **排版层（下）**：`BoxLayouter.layoutBoxes` / `NormalFlowLayout.layout` 薄转发 `contentH`。
- **排版层（上）**：簇计算 + 预算 + `Paginator` 的强制/避免断页 —— 这是**分页约束**，只在分页层
  成立（滚动模式不该缩图；浏览器也只在阅读系统注入 CSS 时才有等价行为）。

**样式层叠优先级三问**：

1. **进哪层哪 tier？** —— **零声明**。本方案不新增/不修改任何 CSS 声明，不动 tier，不动
   ua.css / 主题表 / `ReaderSettings`。
2. **会盖掉书在同名元素上的什么声明？** —— **不盖**。图宽高的最终值仍按既有级联计算；本方案只在
   **分页层**给 used size 追加一个高度上限（语义上等价于浏览器阅读模式注入 `max-height`，但落成
   **布局约束**而非级联声明，避免污染级联、避免「量规则条数」式的误判）。
3. **读者没配这个值时，是不是干脆不发声明？** —— 是（本方案压根不发声明）。

⇒ 不违「样式层叠优先级」，不违层级架构，无需 bump 主题 `schemaVersion`。

> 本节（设计 B / P3）**零声明**。**另**有 P3a（§4.5）确实要动用户层主题表 —— 但那是**删一条**声明，
> 不是新增可调字段，同样不涉及 `ReaderSettings` / `schemaVersion`。两件事互不依赖，但都属用户层决策。

## 4. 设计 A：断页规则接线

### A1 `BreakRule` 扩档

```kotlin
enum class BreakRule { AUTO, AVOID, ALWAYS }   // ALWAYS = forced；单栏下 page/always/left/right/recto/verso 等价
```

`parseBreakRule`：`avoid*` → `AVOID`；`always|page|left|right|recto|verso` → `ALWAYS`；其余 `AUTO`。
本阶段**不接消费者** ⇒ 生产输出不变（只多新测试）。

### A2 不可断簇（单源纯函数）

新增 `common/.../laying/BreakClusters.kt`，在**同一父容器**的块级子序列上处理相邻 A(上)/B(下)：

- 边被强制（`A.breakAfter == ALWAYS || B.breakBefore == ALWAYS`）⇒ 断开；
- 否则 `A.breakAfter == AVOID || B.breakBefore == AVOID` ⇒ 同簇；
- 否则断开。
- 容器自身 `break-inside: avoid` ⇒ 整棵子树成**原子簇**，再与其相邻容器按同规则串。

产物 `clusters: List<IntRange>`（全局行区间，**页面无关量**）。与既有 `break-inside` ranges **合并**
为 `avoidSplitRanges` 交给 Paginator（重叠由既有算法天然取最早，见 `Paginator.kt:90-105` 注释）。

> 簇计算属**分页语义**，但输入是盒树（渲染层）⇒ 放在 `laying/` 的纯函数里，由分页侧消费。

### A3 `Paginator` 消费

`BreakAwareBookLayout` 后向兼容扩展：

```kotlin
val breakInsideAvoidRanges: List<IntRange>                          // 保留
val avoidSplitRanges: List<IntRange> get() = breakInsideAvoidRanges // 新：A2 簇 ∪ break-inside
val forcedBreakBeforeLines: Set<Int> get() = emptySet()             // 新：该行之前必须断页
```

`paginateFrom`：先按 `forcedBreakBeforeLines` **切段**（段首即页首），段内沿用
`fillWholeLines` + `avoidSplitRanges`（`applyBreakInsideAvoid` 原样复用，仅输入集合更换）。

**临时路径必须同改**：`assembleTempPage` 的 trim 循环 + `shapeTempPageForward/Backward` 要在同一
forced/avoid 口径下；上面**三份** ranges 实现（`BoxBookLayout` / `BoxDrawableLayout` / `LightPrepare`）
中若消费 `break-before/after`，必须**同源**，否则重轻漂移。

### A4 forced 的全局影响（风险）

接线后**所有书**的分页都会变（本样本一册就有 11 处 `page-break-after: avoid` 与若干
`break-inside`）。⇒ bump `LAYOUT_VERSION`、全书重排一次。验收：语料 A/B，确认新断页符合书意
（小节/章节起头另起一页）。

## 5. 设计 B：插图装页预算

### B1 `usedReplacedSize` 收一个「高度上限」

```kotlin
fun ComputedStyle.usedReplacedSize(
    intrinsicW: Int?, intrinsicH: Int?, containingW: Int,
    fitMaxH: Int? = null,          // 新；null = 现状（默认形参 ⇒ 老调用点像素零变化）
): Pair<Int, Int>
```

`fitMaxH` 折进 §10.4：`effMaxH = min(自身 max-height 有效值, fitMaxH)`，比例保持（既有
`violMaxH` 分支 `w = h*w0/h0` 天然等比缩宽）。

### B2 预算计算（单源）

新增 `common/.../laying/ReplacedFitBudget.kt`：

```
对每个块级替换叶 el：
  cluster = A2 中包含 el 的簇
  othersH = 簇内非图内容的实测高（图按 0 高计）
  if othersH >= contentH      -> null   // 簇自己就装不下 ⇒ 不缩（允许撕裂）
  budget = contentH - othersH
  if budget >= 图自然高       -> null   // 无需约束
  if budget < FLOOR           -> null   // 缩到不可见不如不缩（FLOOR 见 §9）
  else                        -> budget // fitMaxH
```

- **关键前提**：图高只影响它自己那一行，**不影响簇内其它块的高** ⇒ 可「先按自然尺寸流一遍量
  `othersH` → 再改图高重流一遍」。此性质**仅对块级替换（独占行）成立**；行内图不成立（故行内
  figure 划到 out of scope）。
- 两路落地（**决策逻辑单源，测量回调分路**）：
  - 契约（**已落地**，`caf3133` 之后）：`ReplacedFitBudget.budget(naturalH, othersH, contentH) -> Int?`
    —— **纯决策**（自然高 + 簇内其它高 + 一页高 → 预算），单源、易测、无依赖。
    `FLOOR_DIVISOR = 6`（可调）。
  - 契约（**待落地**）：`ReplacedFitBudget.plan(roots, contentH, measureBlock) -> Map<MarkupElement, Int>`
    —— 簇走查（消费 `BreakClusters` 的兄弟分组）+ `othersH` 汇总 + 逐图调 `budget`；
    `measureBlock(box) -> Int`（某成员的垂直占位）由各路注入。
    两路必须量出同一个 `othersH`（量画/重轻一致性测试守）。
  - **重路径**（`fullLayout`）：shape → `rebuildLinesFromShapes`（自然流，得盒 extent）→
    算预算（`measureBlock` 读盒 extent）→ patch 替换叶 `replaceableHeight` 与对应
    `shape.replaceableBottom` → 再 `rebuildLinesFromShapes`（线性一遍，不重塑形）→ 分页。
    **一次额外流**。需把 `LayoutBox.replaceableHeight` 由 `val` 改 `var`，并新增
    `var replaceableFitH: Int?`（见 B3）。
  - **轻/临时路径**：`measureBlock` 走 `tempShape`（有缓存）+ 与 `shapeTempPageForward` 同一份
    「块间 advance（margin 折叠）」，在 `LightPrepare.block(i)` 物化时就算出预算。
    - ⚠ **不能用「组页后再按本页行 extent 校正」的简化**（原打算）：当簇跨页时（图在页底、
      图注落下一页 —— 正是本 bug 的形态），本页 extent 里**没有**图注 ⇒ `othersH` 被低估 ⇒
      budget 偏大 ⇒ 图仍裁切。必须按**DOM 簇**去量（成员可能不在本页）。
    - 代价：轻路径要能「按元素找块序 + 塑形取高」。`LightPrepare` 已有 `markupLeaves` 与 `tempShape`
      缓存，需补一个 `el -> blockIndex` 的映射（或按 DOM 邻接推成员后线性查找）。
- 预算由**排版层上**给出；`usedReplacedSize` 只收数（渲染层无策略）。

### B5 新不变式（会被既有回归测试感知）

预算生效后得到一条强不变式：**任何块级替换叶的 used 高 ≤ contentH**（无簇时预算 = 整页高）。

- ⇒ 既有 `engine-skia/.../OversizedReplacedPageProgressTest`（`44b54cf` 加）的**前提消失**：它断言
  `replaceableHeight == 3223 > contentH`。P3 必须**改基**该测试：
  1. 「触发条件」断言改为「整宽图被缩到 ≤ contentH，且等比保持宽高比」；
  2. 「游标永不停滞」的守卫（`placedLines`）仍然是真修复，不能删 —— 改用**仍会超页**的输入保住它
     （如显式 `min-height` 的 img：§10.4 `violMinH` 优先于预算，仍可超高 ⇒ 仍会撕裂）；
     ✅ **该改基已在 P3a 顺带完成**（`caf3133`：输入改为 `img{…min-height:3000px}`，
     `oversizedBoxH = 3000`）；P3 接线后再加一条「缩到 ≤ contentH 且保比」的断言即可。
  3. 新增「图 + 图注同页」断言（正是 §1.4 的用户可见结果）。
- 影响面：**所有**插图超过一页的书，图都会等比缩小到装进一页（这是口径乙的本意，但会改全书面貌）
  ⇒ 与 P4 一起进 `LAYOUT_VERSION` bump。

### B3 线程化（量画同值）

- `LayoutBox` 增 `replaceableFitH: Int?`（盒携带预算，与 `replaceableHeight` 同源写入）。
- §2.2 表中 ★ 全部改为「从**唯一预算源**取 `fitMaxH`」；绘制侧直接读 `leaf.replaceableFitH`
  ⇒ 与测量恒同值。
- 新增「量 = 画」一致性回归（同图在重 / 轻 / 临时 / 绘制四处 used size 恒等）。

### B4 居中口径

`WindowedBookLayout.pageImages:127-135` 已有「`margin-left/right: auto` 居中」。缩宽后若书/主题未声明
auto，图会**左对齐**。**内核不额外居中**（AGENTS.md「内核不多做事」）——要居中就让**主题**要求
（另立一条，不进本方案）。

> 注：P3a（§4.5）退役主题拉伸后，`.orilumn-fullwidth-image` 这个名字已名不副实；若选 β，它作为
> 居中挂钩也不再存在。届时主题要居中应直接对 `img`（或另立一个语义正确的图注/图版类）声明，
> 不要再复活 `fullwidth` 这个名字。

## 9. 决策点

**已定：**

- ✅ **A（新不变式）**：接受「块级替换叶高过一页就等比缩到一页，哪怕没有图注」（§5-B5）。
- ✅ **B（`OversizedReplacedPageProgressTest` 改基）**：把「超高」输入改成显式 `min-height` 的图，
  保住「游标永不停滞」守卫；并新增「图 + 图注同页」断言。（表述曾过绕，已澄清：这只是内部改基。）
  已落地（§4.5.5 实测）。
- ✅ **居中**：**内核不居中**。要居中由**主题**要求（另立，不进本方案）。
- ✅ **P3a（主题拉伸规则退役）**：已删，且取 **β**（连打类一起退役，§4.5.5）。

**待拍板：**

1. **FLOOR**：建议 `FLOOR = contentH / 6`（低于此不缩、保持现状）。一个常量，易调。
   已落地为 `ReplacedFitBudget.FLOOR_DIVISOR = 6`（`contentH / FLOOR_DIVISOR`）；接线前仍可改。
2. **`<figure><img/><figcaption>`**：`image-fullwidth-preprocessing-plan.md` §3.3A 现判「2 element
   children → rejected」。真实书不走这条（走 `<p class="fm-figure">`）⇒ 建议本轮不动。
3. **float 图 / 行内图 / 表格格内图**：本轮 out of scope（§2.2 ○）。

## 10. 风险

- **R1 多点重复计算**：used size 有 10 个调用点，漏传一处即量画失配（本仓经典坑）⇒ 靠「盒携带
  `replaceableFitH` + 一致性测试」兜。
- **R2 N 路漂移**：几何 3 路、avoid ranges 3 份、填充规则 2 份 ⇒ 必须同源。
- **R3 forced 全局改版**：P4 改所有书分页，需语料验证后再放行（`LAYOUT_VERSION` bump 会不可逆地
  作废旧表）。
- **R4 循环依赖**：`othersH` 必须在图高确定前测得 —— 依赖「图高不影响他块高」（块级替换独占行，
  成立；行内不成立，已划 out）。
- **R5 结构缓存边界**：预算视口相关，误入结构缓存会导致换视口读到旧预算。
