# 分页高度约束与断页规则接线 — 方案

> 分支：`fix/platform-consistency` ｜ 状态：设计定案，分阶段执行
> 关联：`docs/image-fullwidth-preprocessing-plan.md`、`docs/分页预排原则.md`、
> `docs/分页计算集中化方案.md`、`docs/TODO-未尽事宜.md`（Q30）

## 0. 一句话

分页模式下，块级插图的高度必须受「**它所属的不可断簇要装进一页**」这一预算约束（口径乙）；
而「簇」由相邻块的 `break-before`/`break-after`（含 legacy `page-break-*`）与强制分页决定
—— 因此必须先把这两个**今天只是死字段**的属性接线。

## 1. 问题与口径

### 1.1 现象

全屏（版心 4920×2560）读《Kotlin in Action, 2nd Edition》：整宽插图被主题
`.orilumn-fullwidth-image { width: 100% }`（tier 42）拉到 4920 宽，内在 1122×735
⇒ 盒高 3223 > 版心高 2560 ⇒ **图装不进一页**，被裁。

> ⚠ **本条触发路径已于 P3a 从用户层退役（§4.5）**：产品决策删掉主题那条拉伸规则后，
> 本样本回到 intrinsic 1122×735，**不再溢出**。以下保留现场记录，同时作为 P3「安全网」
> 的动机说明（仍要覆盖原书自定宽高 / 原图本身就超高 / 显式 min-height 三类）。

### 1.2 为什么必须缩，不能折页

已核实：

- `Paginator.fillWholeLines` 只收**整行**；「装得进整页但装不进剩余空间」的图本就会顺延到下一页
  （这不是 bug）；只有**单行本身高过整页**时才强收一行（`Paginator.kt:38`）。
- oversized `break-inside: avoid` 块明确「allowed to tear」（P4 前的 `applyBreakInsideAvoid`，
  现行单源为 `resolveAvoidCut` / `tornByAtomic`）。
- 引擎无 `vh`/`vw`，无 monolithic 概念（`StyleComputer.parseBoxSize` 对不认识单位返 null ⇒ 静默
  当 auto）。

⇒ 对「单行高过整页」的整宽图，折页物理上无解，**唯一出路是按比例缩小**（浏览器不缩，是靠阅读系统
注入 CSS 决策；本仓落成布局约束，见 §3）。

### 1.3 口径乙（已拍板）

- img 与**其所在不可断簇**（图注，以及由 `break-*: avoid` 串联起来的相邻块）必须装在**同一页**；
- img 预算 = `contentH − 簇内非图内容实测高`；
- 簇被**强制分页**（`break-before/after: always | page | left | right`）截断 —— 不给强制断页另一侧
  的内容让位；
- 簇内非图内容**自己就 ≥ contentH** ⇒ 缩图也无济于事 ⇒ **不缩**（保持现状，允许撕裂）；
- 切图有**下限 FLOOR**，避免缩成不可见（见 §9）。

### 1.4 真实触发例（已核实，作为验收样本）

`~/.orilumn/books/book_1791219085400.epub` → `OEBPS/Text/Ch01.htm:706`：

```html
<p class="fm-figure"><img class="calibre3" src="../Images/CH01_F02_Isakova.png"/><br/></p>
<p class="fm-figure-caption"></p>
```

书内 `stylesheet.css:402`：

```css
.fm-figure { display: block; page-break-after: avoid; ... }
```

⇒ 图片块 `breakAfter = AVOID`（**已解析、从未被消费**）⇒ 图注必须与图同页。今天因不消费，
图被单独撕裂裁切。**簇 = {图块, 图注块}**，正是「乙 + 邻居 break」要处理的对象。

> 注：P3a 退役主题拉伸后，本样本的图不再超页（§1.1 注），因此它**不再是 P3 的验收输入**，
> 而转为「P4 forced/avoid 接线」的样本（图注与图仍应同页）。P3 的验收输入改用：
> 竖长原图 / 原书自定 `width` 的图 / 显式 `min-height` 的图（§5-B5、§8）。

## 2. 现状事实（已核实）

> **本节的「现状」是 P0 设计时的基线快照**（这正是「死字段 / 零读点 / 无人消费」的立项理由）。
> forced / avoid 的接线已在 **P4** 落地（见 §11、§7 进度），文中引用的旧实现名
> （如 `Paginator.applyBreakInsideAvoid`）以当时为准，现行实现是单源分页核
> `Paginator.resolveAvoidCut` / `tornByAtomic`。

### 2.1 `break-before` / `break-after` 是死字段

- `ComputedStyle.breakBefore/breakAfter` 全仓**零读点**（生产代码只赋值，从不读）。
- `BreakRule` 只有 `{ AUTO, AVOID }`（`css/ComputedStyle.kt:28`）；`parseBreakRule`
  （`css/StyleComputer.kt:563-564`）= 「含 `avoid` → AVOID，否则 AUTO」
  ⇒ **`always`/`page`/`left`/`right` 静默降级为 AUTO**，引擎里根本没有「强制分页」概念，
  `Paginator` 也不含强制分页。
- legacy 别名**已接**（`parseBreakAny`，`StyleComputer.kt:403-405`）：`page-break-after` → `breakAfter`，
  `page-break-inside` → `breakInside`。⇒ 真实书里的声明**确实落进了字段**，只是没人读。
- 唯一被消费的是 `break-inside`：`LayoutBox.breakInsideAvoid` → `breakInsideAvoidRanges`
  → `Paginator.applyBreakInsideAvoid`。

### 2.2 图片 used size 是「多点重复计算」（量画失配风险）

单源数学：`ComputedStyle.usedReplacedSize(iw, ih, containingW)`（`css/ReplacedSizing.kt:37`，§10.4
约束表）。封装：`NormalFlowLayout.replacedUsedSize` / `replaceableHeightOf`。调用点：

| 1 | `NormalFlowLayout.kt:499` | 重路径·块级 img 叶 | ★改 |

### 2.3 几何与断页有 N 条实现（本仓经典「双路漂移」坑）

- **几何**：重路径 `NormalFlowLayout.buildBoxTree` + `flowBoxes`；轻路径 `LightPrepare.block(i)` +
  `rebuildLocalLines`；临时页 `assembleTempPage`（窗口布局 `PartialDrawableLayout` + 钉尾 trim）。
- **avoid ranges**：`BoxBookLayout.breakInsideAvoidRanges`（重）、
  `text/BoxDrawableLayout.breakInsideAvoidRanges`（绘制）、`LightPrepare/PartialDrawableLayout`
  的（轻，靠结构缓存 `leafToBreakInsideAvoidOwner`）。
- **填充规则一份**：`Paginator.fillWholeLines`。临时页也建出窗口布局（`PartialDrawableLayout`
  本身实现 `BreakAwareBookLayout`，原子区间/禁止切点/强制行来自 `BreakClusters.plan`）后调
  `Paginator.paginateFrom` 定页尾；`shapeTempPageForward/Backward` **只圈窗口**（按行高累加 +
  `BreakClusters.chainRange` 取整到 avoid 边链闭合），不自算任何判据。
  （仅「锚页/锚前页的钉尾」——切点由读者锚点决定——仍走 `assembleTempPage` 的字符钉尾 trim。）

### 2.4 结构缓存是「视口/排版无关」的

`ChapterStructureCodec`：media-free 章的结构在导入期建库、开书期按 child-index relink；它消费的
级联属性（display / white-space / background / break-inside / visibility）**只来自 author/UA 表**，
所以不随排版参数失效。⇒ **预算（依赖 contentH/contentW）绝不能进结构缓存**；断页属性
（`break-before/after/inside`）可以现算（不必持久化）。

## 3. 分层归属（AGENTS.md）

- **渲染层**：`usedReplacedSize` 只多收一个「高度上限」参数 —— 纯几何、无策略。**不碰** ua.css /
  主题表 / 级联，**不加** `vh` 与 `%` 高度解析。
- **排版层（下）**：`BoxLayouter.layoutBoxes` / `NormalFlowLayout.layout` 薄转发 `contentH`。
- **排版层（上）**：断页判据（`BreakClusters`）+ 预算 + `Paginator` 的强制/避免断页 —— 这是**分页约束**，只在分页层
  成立（滚动模式不该缩图；浏览器也只在阅读系统注入 CSS 时才有等价行为）。

**样式层叠优先级三问**：

1. **进哪层哪 tier？** —— **零声明**。本方案不新增/不修改任何 CSS 声明，不动 tier，不动
   ua.css / 主题表 / `ReaderSettings`。
2. **会盖掉书在同名元素上的什么声明？** —— **不盖**。图宽高的最终值仍按既有级联计算；本方案只在
   **分页层**给 used size 追加一个高度上限（语义上等价于浏览器阅读模式注入 `max-height`，但落成
   **布局约束**而非级联声明，避免污染级联、避免「量规则条数」式的误判）。
3. **读者没配这个值时，是不是干脆不发声明？** —— 是（本方案压根不发声明）。

⇒ 不违「样式层叠优先级」，不违层级架构，无需 bump 主题 `schemaVersion`。

> 本节（设计 B / P3）**零声明**。**另**有 P3a（§4.5）确实要动用户层主题表 —— 但那是**删一条**声明，
> 不是新增可调字段，同样不涉及 `ReaderSettings` / `schemaVersion`。两件事互不依赖，但都属用户层决策。

## 4. 设计 A：断页规则接线

### A1 `BreakRule` 扩档

```kotlin
enum class BreakRule { AUTO, AVOID, ALWAYS }   // ALWAYS = forced；单栏下 page/always/left/right/recto/verso 等价
```

`parseBreakRule`：`avoid*` → `AVOID`；`always|page|left|right|recto|verso` → `ALWAYS`；其余 `AUTO`。
本阶段**不接消费者** ⇒ 生产输出不变（只多新测试）。

### A2 断页判据（单源纯函数）

新增 `common/.../laying/BreakClusters.kt`，判据是**扁平块叶序列**（不是「同父容器兄弟」，差异见下）
上的相邻 A(上)/B(下)。**两种 avoid 的语义严格区分**（CSS Fragmentation §4.4）：

- **`break-before/after: avoid`（边）**：只禁止**这一条 class A 断点**（A、B 之间那个行缝）。
  A、B **各自内部仍可断**（class B 断点照常可用）。这正是规范 Rule 1 的措辞：
  *"may break at a class A break point only if all the break-after and break-before values
  applicable to this break point allow it"* —— avoid 只否掉这一个点，**不**把 A、B 并成原子块。
  产物是**禁止切点集合** `forbiddenCutLines`（每条 avoid 边右侧叶的首行）。
- **`break-inside: avoid`（块）**：整个属主盒内**没有** class B/C 断点（Rule 4）⇒ 该属主的全部
  叶行成**原子区间** `atomicRanges`，装得下一页才整体顺延，装不下允许撕裂。
- 强制边（`A.after == ALWAYS || B.before == ALWAYS`）⇒ 断开并记 `forcedBeforeLines`
  （强制边在 `joins` 里返回 false，两种 avoid 都不跨过它）。

产物 `Plan(atomicRanges, forbiddenCutLines, forcedBeforeLines)`（**页面无关量**）：
`breakInsideAvoidRanges`/`avoidSplitRanges = atomicRanges`，`forbiddenCutLines` 交给 Paginator。

> **为什么边簇不再是「整段不许切」**（本次口径修正）：旧口径把一条 avoid 边膨胀成
> `[A首行, B末行)` 的原子簇，于是「书只说标题别和第一段分开」被实现成「标题 + **整段**第一段
> 一起搬走」，页面底部平白空出一大截（目录那种 1.1/1.2 连着 avoid 的条目串更被整串顶走）。
> 规范只否掉那一条边：A 内部、B 内部都能断 —— 图 + 图注照样同页（`.fm-figure{page-break-after:avoid}`
> 只否掉图与图注之间那一条），但标题后面的大段正文可以照常跨页。
> （浏览器「做法 2」——顺带按 `orphans`/`widows` 把右侧 ≤2 行的小块整块绑住——属**主题**该管的
>  事，原书模式不引入，见 §9。）

> **判据为什么是「扁平块叶序列」而不是「盒树兄弟」**（与 CSS 的**有意**差异，已被测试钉住）：
> 唯一必须遵守的一致性，是**预算**（`ReplacedFitBudget`，P3）与**分页**（Paginator）用**同一条**
> 边判据 —— 否则 P3 把图缩到「图+图注装得下」，分页器却跨过图与图注之间的 avoid 边，缩图白做。
> 预算侧为兼顾重/轻两路用的是扁平块叶序列（`NormalFlowLayout.enumerateBlockLeaves` ↔
> `LightPrepare.markupLeaves`），**不做父容器边界检查**，本类因此采用同一份序列、同一判据
> （`joins`/`isForced` 就是它的边判据）。差异：`<div><p>a</p></div><p break-before:avoid>b</p>`
> 这类跨容器边界的 avoid 边，本判据也会否掉这条切点（CSS 只在同一父容器内判定）。真实语料不受影响
> （块级 avoid 边都在同一父容器下，见 §1.4），差异由 `BreakClustersTest` 的
> 「跨容器边界的 avoid 边在扁平叶序上给出禁止切点」钉住。
> 提升叶（独图提升）的断页边取**宿主块**（`LayoutBox.breakCarrierStyle`）——真书
> `.fm-figure { page-break-after: avoid }` 正是如此，否则「图 + 图注」的 avoid 边丢失。

> 断页判据计算属**分页语义**，但输入是盒树（渲染层）⇒ 放在 `laying/` 的纯函数里，由分页侧消费。

### A3 `Paginator` 消费（P4 已接线，现状）

`BreakAwareBookLayout` 后向兼容扩展（默认值保证旧实现零改动）：

```kotlin
val breakInsideAvoidRanges: List<IntRange>                          // 保留（独立属性，旧语义不变）
val avoidSplitRanges: List<IntRange> get() = breakInsideAvoidRanges // 原子区间：break-inside: avoid（装得下才整体顺延）
val forbiddenCutLines: Set<Int> get() = emptySet()                  // 新：禁止切点（break-*: avoid 边右侧叶首行）
val forcedBreakBeforeLines: Set<Int> get() = emptySet()             // 新：该行之前必须断页
```

`paginateFrom`：先按 `forcedBreakBeforeLines` **切段**（段首即页首，段尾是硬边界：强制断页压过 avoid），
段内先用 `fillWholeLines` 求自然填充点 `baseCut`，再由 `resolveAvoidCut` **逐行下扫**：

- 切点命中 `forbiddenCutLines` ⇒ 退到**前一个合法断点**（左块内部的行缝仍合法，不锁整块，见 §A2）；
- 切点落在 **装得下** 的 `avoidSplitRanges` 内部 ⇒ 退到该区间首行；
- **退无可退**（页内 `(pageStartLine, baseCut]` 全非法）⇒ 按规范 §4.4 兜底：弃掉 discouragement
  （rule 1/2/4），仍切在自然填充点 `baseCut` —— 不丢内容、不死循环；
- 单行就高过整页时强收一行，保证游标永不滞停在零前进页。

**ranges 实现全部同源**（都走 `BreakClusters.plan(...)`）：

| 实现 | 用途 | 状态 |
|---|---|---|
| `BoxBookLayout`（`common/laying`） | 纯 JVM `BoxLayouter`（`BoxPathConsistencyTest` 路径） | ✅ |
| `BoxDrawableLayout`（`engine-skia/text`） | canonical 全章分页（`fullLayout` → 磁盘表） | ✅ |
| `BoxChapterLayouter.PartialDrawableLayout`（`engine-skia`） | 增量窗口分页（`incrementalLayoutForPage`）+ 临时页窗口 | ✅ |

> ⚠ 坑（P4 真踩过）：`PartialDrawableLayout` 的 `localLast` 默认值是 `localFirst`，**必须显式传**。
> 漏传时每个叶的行区间都是空的（`localLast[i] == localFirst[i]`），`BreakClusters.plan` 恒返
> 「无原子区间、无禁止切点、无强制行」——临时页与增量窗口的 forced/avoid 会**静默失效**（还看不出来，因为旧临时填充
> 自带一份判据兜着）。

**临时路径不再另写一份**（`shapeTempPageForward` / `shapeTempPageBackward` / `assembleTempPage`）：
临时页也建立自己的窗口布局（`PartialDrawableLayout`，本身实现 `BreakAwareBookLayout`，原子区间/禁止切点/
强制行来自单源 `BreakClusters.plan`）后，把页尾交给 `Paginator` —— 与 canonical 调的是**同一段代码**：

- 非钉尾页：`assembleTempPage` 直接 `Paginator.paginateFrom(窗口布局, pageFirstLine, contentH).first()`
  定页尾（切点再反推 `blockEndExclusive`）；
- `shapeTempPageForward` **只圈窗口**：按行高累加装到 `contentH`，再沿单源
  `BreakClusters.chainRange` 把窗口补到 avoid **边链**闭合（窗口截断边链会让 `plan` 漏掉链上后续接口的
  **禁止切点** → 切点漂移、半页空白），最后用返回页的 `lastLineExclusive` 反推 `(nextBlock, nextLine)` 游标；
- `shapeTempPageBackward` 也**不自算判据**：窗口补到链首 → 建 probe 窗口布局 →
  `Paginator.resolveAvoidCut` 求合法断点 + `Paginator.paginateFrom(...).first().lastLineExclusive` 校验
  （既不溢出也不早停）；
- 钉尾页（锚页 / 锚前页：切点由**读者锚点**决定，不是填充判据）保留 `assembleTempPage` 的字符钉尾
  只在超页高时回退（`lastLine` 只会变小）。

> `Paginator` 是**几何无关**的（`topAt`/`bottomAt` 注入行顶/行底），canonical 传
> `layout::getLineTop/Bottom`，临时路径传自己窗口布局的同名实现 —— 判据（`BreakClusters`）与填充
> （`Paginator`）都只有一份实现。
> 等价性由 `engine-skia/.../TempBreakRulesEquivalenceTest` 钉住：对一串 `contentH`（切点覆盖边链内/
> 强制行/普通块内），**临时前向页序列与 canonical `slices` 逐页 `charStart/charEnd` 全等**；
> 后向是独立的倒包岛（页界与正包本就不保证重合），只锁**自身合规**（禁止切点不当页首、强制行必为页首、无缝覆盖全章）。


### A4 forced 的全局影响（风险）

接线后**所有书**的分页都会变（本样本一册就有 11 处 `page-break-after: avoid` 与若干
`break-inside`）。⇒ bump `LAYOUT_VERSION`、全书重排一次。验收：语料 A/B，确认新断页符合书意
（小节/章节起头另起一页）。

## 4.5 用户层：主题拉伸规则退役（P3a）

## 5. 设计 B：插图装页预算

### B1 `usedReplacedSize` 收一个「高度上限」

```kotlin
fun ComputedStyle.usedReplacedSize(
    intrinsicW: Int?, intrinsicH: Int?, containingW: Int,
    fitMaxH: Int? = null,          // 新；null = 现状（默认形参 ⇒ 老调用点像素零变化）
): Pair<Int, Int>
```

`fitMaxH` 折进 §10.4：`effMaxH = min(自身 max-height 有效值, fitMaxH)`，比例保持（既有
`violMaxH` 分支 `w = h*w0/h0` 天然等比缩宽）。

### B2 预算计算（单源）

新增 `common/.../laying/ReplacedFitBudget.kt`：

```
对每个块级替换叶 el：
  cluster = A2 中包含 el 的簇
  othersH = 簇内非图内容的实测高（图按 0 高计）
  if othersH >= contentH      -> null   // 簇自己就装不下 ⇒ 不缩（允许撕裂）
  budget = contentH - othersH
  if budget >= 图自然高       -> null   // 无需约束
  if budget < FLOOR           -> null   // 缩到不可见不如不缩（FLOOR 见 §9）
  else                        -> budget // fitMaxH
```

- **关键前提**：图高只影响它自己那一行，**不影响簇内其它块的高** ⇒ 可「先按自然尺寸流一遍量
  `othersH` → 再改图高重流一遍」。此性质**仅对块级替换（独占行）成立**；行内图不成立（故行内
  figure 划到 out of scope）。
- 两路落地（**决策逻辑单源，测量回调分路**）：
  - 契约（**已落地**，`caf3133` 之后）：`ReplacedFitBudget.budget(naturalH, othersH, contentH) -> Int?`
    —— **纯决策**（自然高 + 簇内其它高 + 一页高 → 预算），单源、易测、无依赖。
    `FLOOR_DIVISOR = 6`（可调）。
  - 契约（**待落地**）：`ReplacedFitBudget.plan(roots, contentH, measureBlock) -> Map<MarkupElement, Int>`
    —— 簇走查（消费 `BreakClusters` 的兄弟分组）+ `othersH` 汇总 + 逐图调 `budget`；
    `measureBlock(box) -> Int`（某成员的垂直占位）由各路注入。
    两路必须量出同一个 `othersH`（量画/重轻一致性测试守）。
  - **重路径**（`fullLayout`）：shape → `rebuildLinesFromShapes`（自然流，得盒 extent）→
    算预算（`measureBlock` 读盒 extent）→ patch 替换叶 `replaceableHeight` 与对应
    `shape.replaceableBottom` → 再 `rebuildLinesFromShapes`（线性一遍，不重塑形）→ 分页。
    **一次额外流**。需把 `LayoutBox.replaceableHeight` 由 `val` 改 `var`，并新增
    `var replaceableFitH: Int?`（见 B3）。
  - **轻/临时路径**：`measureBlock` 走 `tempShape`（有缓存）+ 与 `shapeTempPageForward` 同一份
    「块间 advance（margin 折叠）」，在 `LightPrepare.block(i)` 物化时就算出预算。
    - ⚠ **不能用「组页后再按本页行 extent 校正」的简化**（原打算）：当簇跨页时（图在页底、
      图注落下一页 —— 正是本 bug 的形态），本页 extent 里**没有**图注 ⇒ `othersH` 被低估 ⇒
      budget 偏大 ⇒ 图仍裁切。必须按**DOM 簇**去量（成员可能不在本页）。
    - 代价：轻路径要能「按元素找块序 + 塑形取高」。`LightPrepare` 已有 `markupLeaves` 与 `tempShape`
      缓存，需补一个 `el -> blockIndex` 的映射（或按 DOM 邻接推成员后线性查找）。
- 预算由**排版层上**给出；`usedReplacedSize` 只收数（渲染层无策略）。

**接线现状（P3 接线已落地）**：

- **簇判据**：`ReplacedFitBudget.clusterRange` / `plan` 复刻 `BreakClusters` 的 avoid/forced 边规则，
  但**有意不展开 `break-inside: avoid` 祖先原子簇** —— 该情形下 `othersH` 通常已 ≥ `contentH`
  （预算自然失效），语义交给既有 `breakInsideAvoidRanges`。于是三路只需要同一份**扁平块叶序列**
  （重路径 `enumerateBlockLeaves` ↔ 轻路径 `LightPrepare.markupLeaves`），不需要盒树。
- **断页边取宿主块**：独图提升（`<p class="fm-figure"><img/></p>` 被枚举成 img 叶）会把宿主块的
  `break-*` 丢掉 —— 真书 `.fm-figure{page-break-after:avoid}` 挂在**块**上，于是「图 + 图注」
  永不簇合（口径乙在这本书上直接失效）。修法是 `LayoutBox.breakCarrierStyle`：提升叶带上宿主块
  样式，`breakBefore` / `breakAfter` / `breakInsideAvoid` 一律经它读取（非提升叶恒 `null`
  ⇒ 旧行为逐字节一致）。
- **重路径**：`NormalFlowLayout.layout(contentH)` 先流出**自然**几何 → `applyReplacedFit` 算预算 →
  改写 `replaceableHeight` + `replaceableFitH` → 再 `flowBoxes` 一趟（缩高不改水平几何 ⇒ 精确，
  且 `flowBoxes` 不塑形，成本线性）。
- **轻路径排期**：预算是**按块懒算**的 —— `BoxChapterLayouter.tempShape` 在塑形**之前**调
  `LightPrepare.applyReplacedFits(i, i+1)`。`othersH` 用注入的 `clusterBlockOwnHeight` 测量
  （同一份塑形器量块自身 border-box 高），且**不进共享塑形缓存**（否则会在预算定好之前把自然尺寸
  的 shape 写进缓存，之后按预算塑形就命中旧值 ⇒ 量画漂移）；替换叶的 used 高走
  `replaceableHeightOf(..., fitMaxH)`（幂等重算，不看已写入的预算）。
- **量画同值**：四处读同一个 `LayoutBox.replaceableFitH` —— 重路径盒 → 轻路径盒 → `ShapeGeometry`
  塑形 → `DrawLineBuilder` / `WindowedBookLayout` 绘制。绘制侧**不得**自行重算预算（CSS 拿不到
  `contentH`，重算必漂移）。
- **out of scope**：悬浮替换叶（`float != none`）本轮不参与预算（浮动几何是另一套，见 §9-3）；
  行内 `<img>` 与表格格内图仍按自然尺寸（§2.2 ○，由既有例外口径承担）。

  3. 新增「图 + 图注同页」断言（正是 §1.4 的用户可见结果）。
- 影响面：**所有**插图超过一页的书，图都会等比缩小到装进一页（这是口径乙的本意，但会改全书面貌）

另一路症状：「明明还有空间，最后一行却被推到下一页」。

### 12.2 根因：分页预算与绘制锚点不同源

- **页栅格**尺寸恰为 `contentW × contentH`（`PageRasterSpec.widthPx/heightPx`）：帧就是页。
- **旧分页帧只量行**：`Paginator.fillWholeLines` 用 `getLineBottom(末行) − getLineTop(首行) ≤ contentH`；
  同时 `BoxDrawer.emit` 对「本页内起始/结束的箱子」**有意**放宽到 border-box
  （`top = minOf(bandTop, box.contentTop)`，见 `BoxDrawerPageBandTest`）——页首块的
  `margin-top` 与容器的 `padding/border` 可以画在首行**之上**。
- **旧绘制锚点**取 `min(行, 图, 盒背景)`，于是**装饰**把锚点拉低：本页首个箱子是
  `div.fm-sidebar-block`（`padding:10px 20px`），其 border-box 顶 = 首行顶 − (10 + 首子块
  `.fm-sidebar-title` 的 `margin-top` 65.5 + `padding-top` 15) ≈ **−91px** ⇒ anchor=−91
  ⇒ 整页下推 91px ⇒ 末行落到栅格外被裁（`extent=2475 > 2400`，`OVER=75`）。
- **两个方向不对称**：页**底**方向的装饰只被裁、不移动锚点；页**顶**方向却移动了锚点。
  根因是**锚点纳入了装饰**，且**预算根本没给页首那段留位置**——预算量到首行就开始装内容，
  页首装饰只能是「多出来的」，不是被裁就是被推走。

### 12.3 口径 v2（已被 §12.8 取代，保留为历史记录）：完整帧口径 + 锚点抬到帧顶

> **本节公式已被 §12.8 的 v3 口径取代**（页首块的折叠 `margin-top` 不再画在本页）。下面这段
> 保留为「v2 当时怎么定的」的现场记录，实施/排障一律以 §12.8 为准。

**甲、预算按「绘制帧」量**（`common/.../paging/BookLayout.kt` 两个默认实现，全仓唯一来源）：

```
frameTop(i)    = if (i <= 0) lineTop(i) else minOf(lineTop(i), frameBottom(i-1))
frameBottom(i) = lineBottom(i) + 页尾叶自身 padding-bottom/border-bottom      （默认实现无盒信息 ⇒ 退化为 lineBottom(i)）
```

- 页首元素的 `margin-top`、页首块的 `border/padding` **画在本页** ⇒ 记在**本页帧顶**：
  `frameTop(首行) = frameBottom(上一行)`，中段开页（同一叶内换页）行盒紧贴、额外开销为 0。
- 页尾叶自身的 `padding-bottom/border-bottom` 记在**本页帧底**；`margin-bottom` 属**块边界缺口**，
  归**下一页**页首缺口。
- **拼合不变式** `frameBottom(i) == frameTop(i+1)`（v3 起放宽为 `frameTop(i+1) >= frameBottom(i)`，
  见 §12.8）：一条块边界缺口**只归一页**。
  这是本次必须守住的收敛条件——预算与绘制同源时，缺口被收两次会让每页白丢一行。
- `Paginator` 的两处消费（`fillWholeLines` 与 `resolveAvoidCut` 的 `topAt/bottomAt`）都换成这对
  帧函数：带装饰的整块若按行高判「装得下」，放上去仍会溢出被裁。

**乙、绘制锚点抬到帧顶**（`shared-ui` `ReaderMath.pageAnchorY`，全仓唯一来源，三处共用）：

```
anchor = min(行顶, 图顶) − 页首缺口(px ≥ 0)        // 行、图都缺时才回落到盒背景（缺口不参与）
```

- 页首缺口 = `ReaderHost.pageFrameLead(pos)`，引擎侧
  `BookDocumentController.pageFrameLead = getLineTop(首行) − getPageFrameTop(首行)`。
  **坐标无关**（是相对首行行顶的差值）：重路径（章节绝对 Y）与临时页（页内归一化 Y）同值。
- 调用点：`ReaderPageCanvas`（画布 shift）、`Preraster`（预栅格）、`ReaderScreen.tryOpenLinkAt`
  （点按命中，坐标必须同式）。三处都走 `ReaderMath.pageAnchorY`，**禁止任一路自算**。
- 默认值 0 = 旧行为：宿主未实现时像素与修前逐字节相同（`PageAnchorTest` 锁着）。
- 盒背景/边框**仍不进锚点**（虽然现在预算给了页首位置）：`BoxDrawer` 对页内起止的箱子按 border-box
  画，盒 yTop 可比首行更靠上；那段已由 `frameLead` 承担，再让盒 yTop 参与取最小就**重复下推**、
  末行越栅格被裁。

**为什么必须同时改两边**：只抬锚点不改预算 ⇒ 预算量到首行，实际要画到帧顶，页底越栅格被裁；
只改预算不抬锚点 ⇒ 页首那段记在预算里却被画在页底（虚假空白），页首装饰在上沿被裁。

### 12.5 残留（已知、可接受）

1. **容器链（祖先容器）的底边不计入帧底**：轻路径（临时页/增量窗）只有窗口内的扁平叶、看不见容器链，
   任何依赖容器链的口径都会让两路算出不同帧（症状：调参后的临时页与磁盘表页数对不上）。容器底边
   恰好落在页尾的少数情形，绘制侧仍按 border-box 画出，**由栅格裁掉**——是装饰少画几 px，不是内容丢失。
2. **章首容器链的额外 margin/padding 不上抬**（v3 收窄后）：v3（§12.8）已让**章首第一个块自身**的
   `margin-top` 与 `padding-top` 照画在章首页页首（`getPageTopLead(0) = 自身 top 边 + 自身 margin-top`）。
   仍不上抬的是**叶口径之外**的那部分——首子链折叠出的额外 margin（`emit(first=true)` 消费整条祖先链，
   与叶自身 `margin-top` 之差）与祖先容器的 `padding-top/border-top`；文本叶/匿名块宿主（`#text` 的盒
   属性按约定清零）的 top 边同样为 0。理由是**重/轻两路径必须同值**（§12.5 残留 1 同理）：轻路径窗口里
   只有扁平叶、看不见容器链，任何依赖容器链的口径都会让两路算出不同帧。绘制侧仍按 border-box 画出，
   **由栅格裁掉**——是装饰少画几 px，不是内容丢失。
3. **页首行墨迹可高于 `yTop`**：大字号 CJK 行的墨迹可高出 `yTop` 几 px（真机侧栏标题约 4px），
   该页首行顶端会裁掉那几 px。这是引擎行顶口径的既有性质（任何页首行的墨迹高于 `yTop` 都会被栅格裁），
   不是本次修复引入。要根治得让分页预算也计入**墨迹**范围（会 bump `LAYOUT_VERSION`、全书页码变化），
   另立项。
4. **页底余量不再有虚假空白**：现在的页底余量 = 本页真正没装下的量（不足「下一行 + 其段前距」），
   页首段前距画在**下一页页顶**。若读者觉得「还有空间」，那空间不足一行加其段前距，属正常；
   要把它也吃掉只能让段前距与页边距合并（违反 §12.3 口径）。

### 12.6 临时锚页手工累加：每处块边界**只记一次**（2026-10-15 真机回归，已修）

**症状**（调参关面板后，临时表路径）：真书 ch8 锚页 `PG [anchor] lines=[0,20) chars=0..542
extent=1868 contentH=2400 UNDER-532` —— 页尾空 **532px**（约五行），而磁盘表同页是
`lines=[0,26) chars=0..798`。前向页（`Paginator` 出的）只有正常的 `UNDER-116`。

**根因**：`BoxChapterLayouter.shapeAnchorPageForward` 的手工累加把**同一段边界缺口记了两次**。
该函数不走 `Paginator`（大章锚页要**同步**出页），自己累加行高 + 块间缺口。口径 v2 落地时给它加
「页首缺口只归本页」这一条，写成了无条件：

```kotlin
if (b > anchorBlock) acc += blockBoundaryGap(prepare, b - 1, b)   // 已含前块自身下边 + 折叠边距 + 本块 top 边
if (k0 == 0)          acc += leadAbove(prepare, b)                // = 同一段 **减** 前块自身下边 ⇒ 白丢一截
```

`b > anchorBlock` 的页内相邻块已按完整落差记过，`leadAbove` 又记一遍 ⇒ 每个块边界白丢
「折叠边距 + 本块自身 top 边」。真书 46~122px × 十余处 ≈ 一个 532px 的页尾空洞。

**修法**（两种口径分管不同段的边界，互斥）：

```kotlin
if (b > anchorBlock) acc += blockBoundaryGap(prepare, b - 1, b)   // 页内相邻块：缺口两端都在本页
else if (k0 == 0)    acc += leadAbove(prepare, b)                // 本页首块首行：只记**页首**那段
```

> **v3（§12.8）下同一结构成立，只是 `leadAbove` 的含义改了**：v2 的 `leadAbove` = 整段落差 − 前块自身
> 下边（折扣掉归前一页页尾的部分）；v3 的 `leadAbove` = 本块**自身 top 边**（`b == 0` 章首再加自身
> `margin-top`）——段前折叠 margin 并入页边距，两页都不收。上述「双记」缺陷与修法结构不变，
> 倒包累加器只额外分出 `interiorGapAbove`（= 旧 `leadAbove`）供 `acc` 用（§12.8）。

**A/B（真机同几何 `contentW=1590 contentH=2400`，JVM 复算同一章）**：

| 锚点页 | 双记（缺陷） | 只记一次（修后） | 磁盘表（canonical） |
|---|---|---|---|
| 切片 | `chars=[0,542)` 20 行 | `chars=[0,798)` **26 行** | `chars=[0,798)` 26 行 |
| 页尾余量 | `UNDER-532` | `UNDER-168` | `UNDER-168` |

修后锚页与磁盘表**逐字节同切**（`charStart/charEnd` 及行数全等）。

**回归锁**：`engine-skia/.../AnchorPageFillEquivalenceTest.kt`——合成章（40 段、
`p{margin:40px 0}` 保证折叠边距非零）逐页取页首字符作锚点，断言锚页与磁盘表**同页同切**。
反向验证：把 `else if` 改回无条件 `if`，立刻红在 `p0 line count expected:<10> but was:<6>`。
（`RealBookTitleGapEquivalenceTest`/`TempVsFullTitlePageEquivalenceTest` 只覆盖**前向首屏**，
锚页手工累加的页尾空洞不在其视野内——这是本节锁补的缺口。）

### 12.7 来回翻页内容变化：倒包页没有恰好收在 pin（2026-10-15 真机，已修）

**症状**（真机 vivo PA2353，ch8 `2.2 封装行为和数据：类和属性` 段来回翻）：同一段字符在不同时刻
落在不同页上；`FLIP` 日志里同一次翻页的 `slice` 与上一次的相邻页**接不上**，越翻越偏。

**先排除掉的那个假设**：这**不是**临时表 ↔ 磁盘表的交接切换（`diskTable=true` 全程成立、`path=TEMP`
恒定，会话只在章首/离开本章时交接）。病灶在**临时会话内部**：**倒包页没有恰好收在 pin**（要么丢字、
要么重叠），随后前向重建从错位原点起塑，整条链跟着漂。

**为什么倒包页首绝不能去抄磁盘表**（本轮重审的核心结论）：

- 前向页的切点由 `Paginator.paginateFrom` 决定（整行填充 + 断页规则），是**精确**的；从块 0 起锚的
  前向链就是 canonical（§12.4 已测：临时表 vs 磁盘表逐页 `diffs=0`）——这也是**章首那一页**两条路径
  逐字相同的原因（交接点保无缝）。
- 倒包页（`shapeTempPageBackward`）旧实现**自己累加**确定「从哪一行起页」，累加式与 `Paginator` 的
  帧口径不完全同式 ⇒ 起页行与 pin 对不上。

**决定性实测**（真书 ch2，45 个正典页界，按「`pin` 的回原像」分类）：

| 回原像形态 | 界数 |
|---|---|
| 唯一解 | 30 |
| 最大解（最满） | 8 |
| 最小解（最稀） | 7 |
| 内部解 | 3 |
| 无解 | 0 |

⇒ 回原像多解，**任何**局部规则都不保证等于 canonical。但这张表真正说明的**不是**「倒包要去抄正典」，
而是**两份分页本章内本来就会不同**——这正是总则 1 要求「章内始终用临时表、只在回章首/离开本章才切换」
的机制原因。于是倒包页首的权威**只能来自临时表自己**：①本会话前向链登记过的边（读者**实际见过**的
那一页）②临时表自己的几何规则。**一旦去读 `ip.canonicalSlices`/磁盘表**，同一翻页手势的结果就由
「后台 B1 何时算完」决定（时序相关、不可复现），并且等于在章内悄悄掺进另一份分页的页界——正是总则
禁止的章内切换的微缩版。

**真病灶（临时表内部不自洽）：**

- 倒包累加器**漏记页内块的自身下边**（`pre{padding-bottom}` 等非文本块）⇒ `acc` 偏小 ⇒ 估计的起页行
  过早 ⇒ 组装后页尾**收不到 pin**（真机实测 `bwd=[b100[7314,8189)]` vs 前向页首 `8199`：少 10 字）
  ⇒ 两页之间那段字符无人显示 ⇒ 随后前向重建从错位原点起塑，页界整条链跟着漂 ⇒ 来回翻页内容就变。
- 几何估计只按帧高估起页行、不经 `paginateFrom` 复核 ⇒ 上述偏差不会被发现（旧版没有 pin 自校验）。

**三条修法**：

**甲、倒包页首只取自临时表自己**（`BookDocumentController.resolveBackwardStartCursor`，两级优先）：

1. **前向链边缓存** `InProgressPagination.prevStart`：`页尾字符 → 页首游标 (块, 行)`，在本会话**每一次
   前向塑形**（锚页、`stepTempPrefill.fillForward`、`tempNav fwd-repair`、`shapeAndAppendForward`）时登记。
   那是读者**实际见过**的那一页，回翻必须逐字回到它。**倒包页的页首不回写**（不许把几何估计当边记忆，
   覆盖真正见过的前向链边）。随会话对象同生命周期，不跨会话串味。
2. **几何倒包**（乙/丙）：中章起锚（TOC/搜索跳转）且前向链没有该边时用。页界仍严格 tiling；
   **不保证**等于磁盘表——章内本就允许不同（见上）。
   （原「甲-1 正典表切点」一级及其折算工具 `lineCursorForChar` 已**删除**：章内读磁盘表 = 时序相关的隐式章内切换。）

**乙、倒包累加器补齐页内块自身下边**。帧高单源推导（v3 版，§12.8）：

```
span(S, L) = frameBottom(L) − frameTop(S)
           = leadAbove(页首块)（仅当页首落在某块首行）
           + Σ_{页内块 b} ownBottomEdges(b)
           + Σ_{页内块 b > 页首块} interiorGapAbove(b)      // v3：页内边界记满
           + Σ行高
```

（用 `blockBoundaryGap = ownBottomEdges(prev) + 折叠边距 + 本块自身 top 边`；
`interiorGapAbove(b) = blockBoundaryGap(b-1,b) − ownBottomEdges(b-1)` 是**页内**边界段；
`leadAbove(b)` 是它的**页首**版本（段前折叠 margin 并入页边距，故少一段）。
v2 时 `leadAbove` 就是 `interiorGapAbove`，两者同式；v3 拆开，页首少收折叠 margin。
`shapeAnchorPageForward` 的累加式是同一恒等式的另一种写法。）
旧式只记**页尾那一次**自身边 ⇒ `acc` 偏小 ⇒ 倒包起点过早 ⇒ `Paginator` 从该起点整行填充收不到页尾
（帧高先超）⇒ 正是上面的「页缝丢字」。修法：页尾块按 `maxLine` 判（钉在锚点行时该边不在页内），
**其余每块都要记一次**。

**丙、页尾 pin 自校验**（`shapeTempPageBackward` 内的**最后防线**，与甲/乙是否精确无关）：组装后若
`slice.charEnd != pinChar`，就在探针布局上用帧几何反查「自哪一行起页，整行填充恰好收到 pin」——
判据就是 `Paginator.paginateFrom`（与 `assembleTempPage` 逐字同式），自 `pageStartLine+1` 起**只向下**
（页变短）取首个可行行 = 最大填充；再按 `localLineRanges(shapes)` 折回 `(块, 行)` 重组。
恒等式：页在 `pin` 处 tiling ⟺ `span(S, END) ≤ contentH` ⟺ `paginateFrom(S).first().lastLineExclusive ≥ pinLine`。
修正出声（`Orilumn.TEMP` 常开信道）：`BWD-FIX`（已修，带 `lost=N`）、`BWD-UNFIXED`（反查无解，error 级）、
`BWD-PIN-DRIFT`（链边游标与几何不一致，回退倒包）、`BWD-PIN-STALE`（游标块/行越界）。
**全部为 0** 即无页缝丢字。

**A/B（真书 ch2，45 个页界，JVM 同几何复算）**：

| 项 | 修前 | 修后 |
|---|---|---|
| 倒包页 `charEnd == pin`（tiling） | 有失配（真机 -10 字） | **45/45 命中** |
| 链边缓存游标倒包页 vs 前一页逐字（`charStart/charEnd`） | — | **45/45 相同** |
| 几何倒包起点 vs 正典 | 不保证 | 45 个界里 11 个起点不同（回原像多解，见上表），**但页尾仍恒等 pin** |
| 前向链 vs 磁盘表 | 0 diffs | 0 diffs（章首同源的根据） |

**回归锁**：`engine-skia/.../BackwardPageTilingTest.kt`——合成章混入 `pre{padding-bottom:40px}`
（`ownBottomEdges > 0` 的非文本块）与小页高（每页数块、块内切页多），扫**每一个**页界断两条：
① 几何倒包页 `slice.charEnd == pin` 且帧高 ≤ `contentH`；② 链边缓存游标（`prevStart`）倒包页与前一页
`charStart/charEnd` 全等（回翻必须逐字回到读者刚看过的页）。反空跑：必须真的出现块内切页与链边命中。
另有一条独立的锁（`mid-chapter backward chain tiles and is stable without any canonical input`）：
中章起锚、**全程不给任何权威**（`pinnedStart = null`）倒包整条链，断言页页 tiling、链内首尾相接
（`back[j].charEnd == back[j-1].charStart`，既不留空洞也不重叠）、页高不溢出、且**重复倒包逐字同页**
（稳定：同一手势不因后台正典何时算完而变）。
反向验证：把乙（`acc += ownBottomEdges(leaf)`）改成 `acc += 0` **且**把丙强制走快路，立刻红在
`bwd[2] 页尾必须恰好收到 pin expected:<352> but was:<320>`——整整一行（32 字）的页缝丢字，
正是真机症状。甲/乙/丙各自都能单独守住 tiling（乙=精度、丙=兜底）。

**同轮重审的其余结论（交接点/可观测性）：**

1. **章内两份分页可以不同**（设计，不是缺陷）：中章起锚（TOC/搜索）的会话走几何倒包，页界严格 tiling
   但不保证等于磁盘表的首选切点（回原像多解，见上表）。**不再当「待修残留」**：一旦去读磁盘表就是章内
   切换。离开本章时按**字符**重新解析落点（磁盘命中则 `pageIndexForChar` 吸附到**包含**该字符的正典页），
   回章首时按总则 1 切换到磁盘表。
2. **回章首时「本章磁盘表已就绪、但本会话没拿到正典副本」仍走重根临时表**（`resolveHeadArrival` 的未就绪
   分支），**没有**立刻切到磁盘表——字面偏离总则 1(d)。触发条件：本会话的 B1 被 skip-fresh（表由另一路
   落盘），或上一代会话的 B1 在读者离开后才落盘（`ip` 已换代，晚到的 B1 按 3 不再写副本）。**可见内容不受
   影响**：重根后章首那一页两条路径逐字同源（见上表「前向链 vs 磁盘表」行 / 回归锁的章首同源断言），读者看到的页与
   磁盘表那一页相同。要真切换得在翻页线程/`tempStateLock` 外先按表塑出章首窗口（`ensurePageRangeShaped`
   是 suspend 且空 `pageSlices` 会早退，需改造调用路径），风险大于收益，**未做**。
3. **交接点副本的跨线程发布没有同步**（已修）：`InProgressPagination.canonicalLayout/Slices` 由后台正典
   线程写、由前台在 `tempStateLock` 内读，写侧不在锁内 ⇒ 无 happens-before：轻则交接点永远看不到产物，
   重则读到「layout 非空 + slices 空」的半个副本（`bindFull(layout, emptyList())` = 零页单元）。修法：
   两字段 `@Volatile` + 固定发布序（**先 slices 后 layout**，`layout` 非空即「已完整发布」）+ 会话换代时
   不写副本（B1 晚到）。
4. **`finalizeTempOnLeave` 在离开本章时可能丢掉一张已就绪的磁盘表**（已修）：未就绪分支原来无条件
   `invalidateLayout()`；若本章表其实已就绪（同 2 的两种触发），这就等于「磁盘表已就绪却作废重排」，下次
   进入白重算。修法：`paramHash` 匹配的 `unit.paginationTable` **保留**下来（清临时会话与旧版式后重新
   `bindPaginationTable`），下次进入即磁盘命中。
5. **`buildLayout` 的命中判据只看缓存文件**（已修）：内存里已绑定的同参数表被忽略 ⇒ 写盘失败或
   `bookId<0`（无 store）时会误判未命中而退回临时表。修法：文件读不到时退回**内存里已绑定的同参数表**——
   有它就等于命中（prewarm/B2 的「直接晋级整表」也正靠它）。诊断：`FLIP` 行补印 `tableParam=`，让落盘
   日志能判「这张表是不是本参数的」（原来只有 `diskTable=true`，分不出新旧）。
6. **`prewarmChapterBody` 可能往活着的临时会话里绑磁盘版式**（已修）：派发时判了 `index ==
   activeChapter`，但任务真正执行时读者可能已经跳进本章 ⇒ `unit.bind(layout, slices)` 在章内换了另一份
   分页的页切（显示不变——渲染走临时版式——但 `pageSlices`/`laidOut` 变成错位的那份，随后读表路径会读到
   它）。修法：表照绑（它是交接点的权威），**窗口预塑跳过**（`unit.inProgress != null` 时只 `bind
   PaginationTable` 就返回）。同族的 `b2ChapterTask` 本来就 skip 当前章（`skipCh=`）、`finishCanonical
   Background` 只绑表不绑版式，均无此问题。

### 12.8 口径 v3（2026-10-15 拍板，已落地）：页首块段前距并入页边距

**需求原话**：「页面顶部块的 **margin-top** 与上边距合并，但不合并 **padding-top**。章开头的第一个块的
`margin-top` 不能与上边距合并。」

**与 v2 的差别**（只动**页顶**这一段，页内块边界与页尾口径不变）：

| | v2 | v3 |
|---|---|---|
| 块边界开页（页首行 = 某叶首行） | 整段落差画在本页（折叠 `margin-top` + 本叶自身 `padding/border-top`） | **只画本叶自身 `padding/border-top`**；折叠 `margin-top` **并入页边距**（两页都不收） |
| 段中开页（页首行非叶首行） | 0 | 0（不变） |
| 章首（`i == 0`） | `frameTop(0) = lineTop(0)`（页顶整段被裁） | `frameTop(0) = 首叶 margin-box 顶` ⇒ **首叶 `margin-top` 照画**（章题留白不被吞） |

**接口（`common/.../paging/BookLayout.kt`，仍是全仓唯一来源）**：

```kotlin
frameTop(i)    = if (i <= 0) lineTop(0) - pageTopLead(0)
                 else maxOf(frameBottom(i-1), lineTop(i) - pageTopLead(i))
frameBottom(i) = lineBottom(i) + 页尾叶自身 padding-bottom/border-bottom
pageTopLead(i) = 行 i 行顶之上**仍画在本页**的那段页首缺口（新增，默认实现见下）
```

- **默认 `pageTopLead`**（无盒树，只有行几何）保守退化为**整段缺口** `lineTop(i) - frameBottom(i-1)`
  ⇒ 与 v2 **逐字节相同**：只有行几何的测试替身（`FakeBookLayout`，行盒紧贴 ⇒ 恒 0）零变化。
- **有盒树的实现覆盖**（判据同源，重/轻必须同值）：重路径 `BoxBookLayout`、绘制侧
  `WindowedBookLayout`（覆盖整章 `BoxDrawableLayout` 与窗口 `PartialDrawableLayout` 的 `i > 0` 分支；
  窗口 `i <= 0` 仍走调用方传入的窗外缺口 `frameLeadTop`）：
  - 段中行、**文本叶**（`#text` 盒属性按约定清零）⇒ 0；
  - **叶首行** ⇒ 该叶自身 `border-top + padding-top`；
  - **`i == 0`（章首首行）** ⇒ 再加该叶自身 `margin-top`。
  - 轻路径对应量：`BoxChapterLayouter.ownTopEdges/ownMarginTop`、`leadAbove`
    （页首 = 自身 top 边，`b == 0` 加自身 margin）、`windowLeadTop`（窗口上边界；
    `blockLo == 0` 加章首 margin）。**文本叶判据必须照搬**：轻路径 `LightPrepare.blockStyleFor` 给文本叶
    继承宿主样式（真书 `#text` 叶 `margin-top` 非 0，实测 29.6），不按 `el.isText` 清零就与重路径分叉。

**拼合不变式（放宽）**：`frameTop(i+1) >= frameBottom(i)`，差值恰为被并入页边距吞掉的那段折叠
`margin-top`（0 = 段中开页/无段前距，正 = 块边界开页且该块有段前距）。**一条缺口仍不许两页各收一次**
（这是 §12.3 的核心收敛条件，v3 不解禁）：页缝里消失的是**折叠 margin**，不是内容。

**倒包累加器（`shapeTempPageBackward`）**：`acc` 一律按**页内**口径累加
（`interiorGapAbove(prepare,b) = blockBoundaryGap(b-1,b) - ownBottomEdges(b-1)`，即旧 `leadAbove`），
只有「本行**当选页首行**」的判据改用 `leadAbove`（页首版，少一段折叠 margin）。这样继续向上找页首时，
下面已收的各段仍是完整页内落差；若把页首口径也累进 `acc`，每个块边界都会少收一段折叠边距 ⇒ 倒包页多装行。

```
candidateHeight = acc(页内口径，下面各行) + leadAbove(本行所属块) + 行高      // 仅当本行是块首行
```

**验证（JVM 实测，真书 ch8 `Ch02.htm` 同几何）**：重/轻两路逐页 `charStart/charEnd` 仍 `diffs=0`；
`PageFrameTilingTest` 主锁改判「不许重复收」+ 差值单源式一致；新增直测
`page top block merges margin but keeps padding, chapter head keeps margin`（fixture
`p { margin: 100px 0; padding: 40px 0 }` ⇒ 段首开页缺口 **40**、章首 **140**、段中 **0**，重/轻同值）。
真书 CSS 形态的章首 JVM 实测：首叶 = `span.sec_num`（`display:block` 包裹章题 ⇒ **元素叶**，`mt=200`）
⇒ 章首缺口 **200**（重/轻相同），即「章题留白不被吞」对真实电子书成立（`display:block` 的标题包裹元素
是元素叶，不是 `#text`；`#text` 只出现在块内被拆出的裸文本，其宿主 top 边见下残留）。

**残留**（并入 §12.5）：叶口径之外的部分仍不上抬 —— 首子链折叠出的**额外** margin（`emit(first=true)`
消费整条祖先链，与首叶自身 `margin-top` 之差）与祖先容器的 `padding-top/border-top`；文本叶/匿名块的
宿主 top 边同样为 0。理由仍是重/轻同值（§12.5 残留 1）。
