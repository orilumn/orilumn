# 卷曲 3D 实施计划（分支 `feat/curl3d`，2026-11-15）

> 目标：把卷曲从「正交投影下的横向压缩」做成**看得出纸是立起来的 3D 卷页**，
> 且全程 GPU 光栅（`drawVertices` + 逐像素着色器），CPU 只算顶点。
>
> 现状（P0 已完成）：`curl/CurlMesh.kt` 生成扫描线 × 2 的三角形网格（正面 / 卷背 / 平铺三段），
> 桌面用 skiko `drawVertices` + `RuntimeEffect` 出图；形状正确，但**没有透视**，
> 卷起来那一段只表现为压缩，读不出立体感。

## 原则（不再重复讨论的几条）

1. **纹理供给不动**：页栅格 + 覆盖层两张图，由页槽 `onImages` 发布，`CurlPageImages` 收。
   不合成、不建第二个池、不加预算。
2. **不用整页快照**：`GraphicsLayer` 快照路线真机三十帧全空，已废。
3. **纸背不例外**：纸背 = 同一张纸的背面，读者写的字透过来（压到 0.39），页码也一样。
4. **GPU 优先**：几何在 CPU（必须有人铺三角形），光栅、纹理采样、明暗、软阴影全在 GPU。

## 步骤

### P1 透视（已完成）

- 顶点出网格前过一遍透视除法：观察者高度 `D`，屏幕上 `scale = D / (D − z)`，
  以页面中心为投影中心。
- 纸背/正面/平铺三段的 z 单调，画序仍按 z 从小到大。
- 落地取值：`D = 2.2 × 页高`（moon+ 用 fov 45°、相机在 `1/tan(fov/2)` 处，
  换算过来是 1.2 页高；那个量在平板近处会把人眼压出鱼眼，页边会被顶出画面，
  所以收到 2.2）。**半径 `R = 0.085 × 页宽`**：R 越大，纸卷吞掉的露出区越多
  （露出区边界 = 折痕 + R），moon+ 的 0.5 页宽是「整页弓起来」那一档，不适合我们的折痕扫过手感。
- 验收：同一半径下，卷起来的那一段**近处宽、远处窄**，轮廓不再是直边；
  出 `shared-ui/build/curlm-*.png` 目视。

### P2 明暗与影（已完成）

- 逐像素法线（`θ = s/R`，透视后仍按材料弧长算；法线不受透视影响）。
- 明暗：圆柱法线 `N = (sinθ, 0, cosθ)`，背面法线反号；光从观察者左上前方来
  （`diff = max(−0.35·sinθ + 0.90·cosθ, 0)`），卷顶压出一道暗带，再叠一道窄高光。
  照抄 moon+ 的 `sqrt(sinθ+1.5)·0.9+0.1` 不行——那个式子恒 >1，是「把纸提亮」，
  白纸会整段吹成纯白，反而读不出圆。
- 三道影：卷面自阴影（靠折痕那一侧暗）、纸卷投在露出页上的落影
  （长度 = 卷起来的高度 `R(1−cosθmax)`，影与纸同源）、纸背自由边压在正面页上的那道影，
  外加折痕接触处的暗角。

### P3 两端落点（已完成）

- `commonMain` 只留 `expect fun drawCurlMeshBand(...)` 与 `expect fun curlMeshSupported()`。
- 桌面 actual：`org.jetbrains.skia.Canvas.drawVertices` + `RuntimeEffect`。
- 安卓 actual：`android.graphics.Canvas.drawVertices` + `BitmapShader` + `RuntimeShader`（API 33+）；
  低于 33 → `curlMeshSupported()` 为 false，直接走折页，不出现「有动画但很假」。
- 着色器源码只有一份（`CurlMeshShader.kt`），SkSL 与 AGSL 在这几个特性上语法一致。
- 验收：两端同一份几何/着色器源码，只有最后一跳不同。

### P4 接线（已完成）

- `FlipCurlLayer`：3D 优先，`drawCurl3DFrame` 返回 false 才退回折页；
  进度、方向、倾斜、结算全部沿用现有闭包，不新建状态机。
- 折痕比读者手指位置**回收一个半径**：手指拖的是纸的自由边（屏幕上那条轮廓），
  折痕在它后面一个半径处。不回收的话露出区会被纸卷吃掉整整 R（低进度时几乎看不到新页）。
- 等图规则不变：两张页图缺一张就保持不动。
- 验收：真机拖两个方向、松手收尾，末帧逐像素等于目标页。

### P0 修订（几何）

- 纸卷必须落在**掀起那一侧**、纸背落回**另一侧**（moon+ `NewCurl3D.java` 与
  duokan `CurlMesh.java` 都是这么分的）。两侧同侧时，平铺段（z = 2R）正好盖住纸卷（z ≤ 2R），
  屏幕上永远只剩一条平铺的纸背 —— 这就是「看起来是 2D」的根因。

### P5 测试与验收（进行中）

- 几何单测：弧长单调、网格无缝、`s > πR` 分段正确、退化输入返回空网格。
- 出图单测：断言「卷起来那一段的竖向边界不是一条直线」（透视生效的机器判据）。
- 目视：`CurlMeshPreviewTest` 多姿态出图；真机拖一次录帧时间。
- 帧预算：网格生成 < 0.5ms，整帧与折页持平。
