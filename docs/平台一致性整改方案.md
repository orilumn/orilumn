# 平台一致性整改方案（:app = :desktopApp = （未来）iOS）

> **母文档**：`docs/架构分层与共享边界.md`（分层总览、共享矩阵、平台真边界表、整改面 A–G）。
> 本方案是该母文档 §4「整改面 A–G」的**执行清单**：不再只谈排版一致性，而是把两端一切
> 「该共享却分裂」的面全部单源化，最终**所有平台共享同一引擎 + 同一阅读 UI + 同一编排宿主**，
> 平台壳只剩进程入口 + expect/actual 接缝 + 打包。
>
> 原则（用户拍板）：**所有能被多平台共享的部分必须共享；消除双份副本后再做对齐。**
>
> 相对 Sxx 迁移主线的关系：A/B（样式、绘制语义）可**立即并行**（不依赖迁移主线）；D/E/C 需在
> Q1（平板绘制侧切 Skia）前按序插入；Q1 是总闸，完成后 F/G 随 StaticLayout 一并退役。
> 步骤编号用 **Z / P / D / E / C / Q** 系列，每步原子、一步一 commit、可中断续接。

## 已共享（不动的部分）

**common 单份：** CSS 层叠/样式 `StyleComputer`/`Cascade`/`ComputedStyle`/`LightCssParser`、
盒式流布局 `BoxLayouter`/`NormalFlowLayout`、分页 `Paginator`+`BreakAwareBookLayout`、
排版映射 `TypographicProfile`、列表标记 `ListMarkers`、HTML/EPUB 解析、设置/存储、
SQLDelight schema、字体二进制 `FontParser`、WiFi 上传 `FontUploadServer`。

**engine-skia（android+jvm 同源码）：** `SkiaParagraphBreaker`（断行）、`LineWindowDrawer`（按行绘制）、
`SkParagraphFactory`（字体/样式）。

**shared-ui（CMP）：** 书架/阅读面/设置/目录/Snackbar/亮度遮罩 `ReaderLight`。

## 1. Z 系列：样式层单源化（所有平台共同读取）—— 母文档 A 行

### Z1 — common 建 CSS 单源（资源文件 + 加载器）

- 新增 `common/src/commonMain/resources/css/{ua.css,traditional.css,modern.css}`，内容 = 现
  `app/src/main/assets/css/` 同名文件**逐字节一致**（含文件头注释与 `.orilumn-fullwidth-image{width:100%}`）。
- 新增 `common/src/commonMain/kotlin/com/orilumn/engine/css/ReaderStylesheets.kt`：
  - `expect fun readReaderCss(name: String): String?`（`contrib/key` 由文件名给出）
  - `object ReaderStylesheets { fun ua(): String; fun theme(layoutTheme: String): String? /* original→null */ }`
  - 缺失时**抛异常**（不做内联兜底，防止再造第二份正文）。
- actual：`jvmMain` 与 `androidMain` 均走 `classLoader.getResourceAsStream("css/<name>")`；
  iOS 未来补 `actual`（框架 Bundle 读取），不阻塞本轮（common 目前仅 android+jvm 目标）。
- 新增 jvmTest：断言读到的 `ua` 含 `ul,ol{padding-left:2em}`、`strong,b{font-weight:bold}`、
  `em,i{font-style:italic}`、`code,kbd,samp,tt{font-family:monospace}`、`blockquote{margin:1em 2.5em}`。

完成标志：`./gradlew :common:jvmTest` 绿。

- **删除 `app/src/main/assets/css/{ua,traditional,modern}.css`**（防双副本继续漂移）。

完成标志：`./gradlew :app:assembleDebug :app:testDebugUnitTest :common:jvmTest` 绿。

### Z3 — 桌面改走同一单源（删内联 UA/theme）

## 2. P 系列：渲染对齐（绘制语义收进共享引擎）—— 母文档 B 行

### P1 — engine-skia `DrawLine` 收 `xLeft` + `listMarker`

- `DrawLine` 增 `xLeft: Int = 0`（文本相对内容区的水平起点；表叶 `contentLeft` + 自身
  `border.left + padding.left`）与 `listMarker: ListMarkers.ListMarker?`（common 类型，`= null`）。
- `LineWindowDrawer.drawLines`：
  - 文本画在 `contentLeft + line.xLeft`；
  - 有 marker 时：OUTSIDE 在沟槽悬挂——`lineStartX - markerW - gap`（`markerW` 用同
    `paragraphStyle` 的 SkParagraph 实测，`gap = ListMarkers.markerGapPx(fontSizePx)`，语义对齐
    `ParagraphShape.drawListMarker` 的 `-markerW-gap`）；INSIDE 行首内嵌（文本向右让
    `markerW + gap`，近似平板 LeadingMarginSpan 语义，标注为已知近似）；
  - marker 字形用 `ListMarkers.markerText(kind, order)`，与平板"格子/编号"同一标的。
- `ReaderPageCanvas` / `ReaderPageRenderer` 无需改（x 已进行）。Android 侧 shared-ui 复用同一
  `LineWindowDrawer`（Q1 平板绘制切换后自动受益）。
- 新增 engine-skia jvmTest：xLeft>0 的行落在 x 偏移处；marker 行在其沟槽绘制（离屏 Canvas 校验）。

完成标志：`./gradlew :engine-skia:jvmTest :shared-ui:jvmTest :desktopApp:test` 绿。

### P2 — common `ListMarkers.markerForLeaf` 助手（共用依附逻辑）

- `ListMarkers.markerForLeaf(leafEl, carriers, styleOf)` =
  `if (leafEl in carriers) specOf(leafEl, styleOf) else null`。
- 平板 `BoxChapterLayouter.listMarkerFor`（`BoxChapterLayouter.kt:1046-1051`）→ 委托；
  桌面 `buildDrawLines` 用同一助手（B 行第 5 项差异关闭）。

完成标志：`./gradlew :common:jvmTest :app:assembleDebug :desktopApp:test` 绿。

### P3 — 桌面 `buildDrawLines` 输出 `xLeft` + marker

- 每叶 `xLeft = leaf.contentLeft + (leaf.style.border.left + leaf.style.padding.left).roundToInt()`
  （对齐 `BoxPageRenderer` `xOff`，B 行第 6 项差异关闭）。
- `carriers = ListMarkers.firstCarrierSet(盒叶序 el 列表)`；marker 只挂**首个载体叶的首行**
  `DrawLine`（`leaf.firstLineIndex`），与平板"每个 `<li>` 只画一个 bullet"一致。
- 桌面真书 jvmTest：含 `<ul><li><code>` 的章，断言存在 `xLeft > 0` 的行（≈2em）、该列表首行携带
  marker、code 行为等宽栈（`families` 命中 mono）。

完成标志：`./gradlew :desktopApp:test` 绿。

> **P 系列完成即**：列表缩进/悬挂 bullet/编号、每叶水平偏移在两端共用同一几何与绘制语义；
> B 行关闭。

## 3. D 系列：字体匹配/池收敛到 engine-skia —— 母文档 D 行

### D1 — SkFontCollection 成为唯一字体池入口

- 平板删 `FontPairing` + `WeightedFontResolver` 的类型链（Android Typeface 参与匹配的路径）；
  字体二进制（SQLDelight + `FontParser`）交给 engine-skia `SkParagraphFactory` 加载进
  `FontCollection`，resolve/fallback 全走 `SkParagraphFactory.resolveFamilies`。
- 行为对账 jvmTest：同一 `TypographicProfile`/`font-spec`，engine-skia 与平板旧解析器给出的
  字体族命中一致（作为过渡断言，退役后删除）。

### D2 — 系统字体集合显式化

- `FontCollection` 各平台实例的构造收敛到 `expect fun systemFonts(): ...`（Android 系统字体 /
  macOS CoreText），即母文档 §3「系统字体集合」边界的第一处显式接缝（不再散落引擎内部）。
- 记录：平台字体度量差异是能力边界（见母文档 §3），不在共享范围内强制像素级。

完成标志：`./gradlew :engine-skia:jvmTest :app:assembleDebug :desktopApp:test` 绿。

## 5. C 系列：编排层共享评估 —— 母文档 C 行（面最大，需单独论证）

### C1 — 阅读宿主纯逻辑策略收进 common/engine-skia

- 现状：平板 `BookDocumentController`(～1900 行)/`BoxChapterLayouter` 持有全部编排策略
  （增量分页、磁盘分页缓存 `PaginationCacheStore`、并发优先级 P1–P14、preflight/chunked）；
  桌面 `DesktopReaderHost` 是简化宿主（无增量/无缓存）。
- 目标形态：编排纯逻辑（窗口/优先级/缓存/invalidate）进 common 或 engine-skia，两端共用同一宿主
  能力；桌面不再保留简化宿主。
- **前置**：本步必须先落 Q1（平板绘制宿主切 shared-ui 后，`BookDocumentController` 的渲染依赖
  消失，只剩纯逻辑），否则会带着 StaticLayout 依赖一起平移，白做。
- 论证项：
  - `PaginationCacheStore` 磁盘布局是否也做跨平台（写 common 的缓存格式），或仅进 engine-skia
    由两端各自落盘；
  - 增量 path（`incrementalLayoutForPage`/`ensurePageRangeShaped`）与共享 `Paginator` 的边界。

完成标志：两端真书走同一编排宿主（同一增量/缓存/优先级行为）后闭合。

## 8. 风险与边界

- **Android 读库资源**：common 的 `resources/` 在 androidTarget 应经 classloader 取到
  （AGP 打包库 java resources）。Z1 必须先以 jvmTest + app 断言验证；若实测取不到，兜底：
  `app` `android.sourceSets["main"].resources.srcDir("../common/src/commonMain/resources")`
  并保留 Z2 的删除动作（仍单源）。
- **INSIDE list-style**：桌面以"行首内嵌 + 首行让位"近似平板 LeadingMarginSpan，已知近似，
  断行宽度未同步让位（书排几乎不用 INSIDE，标注不追平）。
- **字体平台差异**：系统字体集合是能力边界（母文档 §3），不强制像素级一致，文档记录。
- **C 系列范围大**：磁盘分页缓存是否跨平台落盘需单独论证后再动工；本方案将其排在 Q1 之后，
  避免把 StaticLayout 依赖带进共享层。
