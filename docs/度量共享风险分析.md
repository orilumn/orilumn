# P5 度量共享：风险分析（GIMP 3.0 手册实证）

层级声明（AGENTS.md）：本节属**渲染层**（字体渲染、几何测量）+ 排版层（上）调用点；
字库池签名补文件版本属用户层池同步。KMP：全在 `engine-skia/commonMain` + `common`。

## 0. “测量”到底是什么（已核实代码，非猜测）

每叶一次 `SkParagraph build + layout(widthPx)`（`SkiaParagraphBreaker.breakLines`），输出只取
**行区间**（行高走 `lineHeightPx()` 公式，与 skia 无关）。没有逐 run `measureText`——引擎从不
单字度量。另有 `preferredWidth`（表格 min/max content，每格两次整形）。

调用链：`shapeLeaf → shapeGeometry`（每叶 6 遍子树遍历：文本抽取 + 着色/字体/基线/注音/
下划线 runs）`+ breakWrappedLines → breaker.breakLines`（native）。

## 1. GIMP 书实证（51MB，29 大章，中英混排技术手册）

- 字符：latin 173 万 / CJK 40 万 / ASCII 标点 76 万 / 数字 8 万——**latin 主导**，与小说书相反。
- 结构：547 表格 / 64 pre / 332 code / 16589 span / 10234 链接 / 1800+ 图；无内嵌字体
  （系统栈：SF Mono/Menlo/Open Sans/sans-serif/monospace）。
- CSS：单文件 21KB，含 **1 处 `@media`**——按现行规则整书结构持久化直接跳过（`hasMediaRules`
  按章判，共享单 CSS 即全跳；`@media` 章豁免机制见 §4）。
- 段落重复率（同文本）：≥20 字段 6.9%，5–19 字短句 7.7%（“单击工具箱中的工具图标”等手册套话）。
  **整段 memo 天花板约 7% 的 break 调用**，不含表格 `preferredWidth`（cell 文本重复另计，未量）。

## 2. 可共享项与键（完备输入捕获，缺一不可）

`breakLines` memo（L1）：键 = 文本串 + `widthPx` + `fontSizePx` + `lineHeightRatio` +
`alignment` + 整条 families 栈 + weight + italic + monospace + `letterSpacingEm` +
`firstLineIndentPx` + `fontRuns` 全表 + `baselineShifts` 全表 + `floatLead`（环绕改行宽）+
**池内容版本**（回退解析随池变，见 R1）。值 = 行区间表（`BrokenLine` range，不含高度——
高度公式化，调用方自算）。

`preferredWidth` memo（L1 附带）：同上减宽/对齐/缩进；表格自动列宽每格省两次整形。

单字 advance 缓存（不做）：引擎无逐字度量 API，为它改断行器架构是以小博大；“汉字一样大”
的直觉由整段 memo 覆盖（同 run 同文本即同结果，无需拆字）。

6 遍子树遍历合一（L2，另计）：与 memo 正交的常数项优化（span 大书受益），单列。

## 3. 风险清单与处置

- **R1 池内容漂移**：回退逐字解析依赖驻池面。处置：`FontPoolSync` 签名先补**文件版本**
  （face 路径+字节数/mtime），memo 键含该签名；池一换即整体失效（内存 memo 随小版本走，
  不做细粒度驱逐）。
- **R2 Skia/字体版本漂移**：内存 memo 随进程死，天然免疫；磁盘不存 memo（只存区间？不——
  连区间也不落盘，内存 LRU 即够，首触成本仍在）。
- **R3 键遗漏**：`floatLead`、缩进、`letterSpacingEm`（breaker 实例级）、`baselineShifts`
  （`forceStrut` 改行盒）、双向文本（文本串本身在键内，同串同果）——逐项审计，单测锁
  “缺任一键维度即 perder 命中”（变异：改任一输入必须 miss）。
- **R4 内存上界**：只存区间（数十 int/条），LRU cap（如 4096 条，~1MB 级）；文本串存引用
  还是拷贝视 GC 定——拷贝（跨章共享要求值语义）。
- **R5 并发**：塑形线程（B2 池/翻页线程）并发进出，`SyncLock` 短临界（hash 查表级）。
- **R6 对齐**：kJustify 是否影响断点存疑——键含 alignment（便宜求全）。
- **R7 CJK 标点/连字**：全角标点同面内多为等宽，latin 连字/字距是 run 内上下文——memo 以
  run（含 `fontRuns` 边界）为单位，键含 runs 全表即 sound；跨 run 不共享。
- **R8 monospace 代码块**：等宽 advance 与文本无关，同键命中更高，是主要受益者之一
  （GIMP 64 pre + 332 code）。

## 4. `@media` 章豁免的连带影响

GIMP 因共享 CSS 含 1 处 `@media`，全章 `hasMediaRules=true`——结构/树持久化整书跳过
（P1 收益在这本书上为零！）。P5 memo 不受影响（键是塑形输入，与 media 无关）。
后续可做 media 粒度细化（只含无关 media 查询的章仍持久化），单列，不进 P5。

## 5. 实施形状（立项即定）

`MemoizingParagraphBreaker(ParagraphBreaker)` 装饰器（渲染层归位）：命中返区间，
miss 委托。单测用假 `ParagraphBreaker` 计数 native 调用（纯 JVM，不碰 skia）：
同输入 1 次调用、任一维度变化即 miss、LRU 淘汰、池签名变化即全失效。
设备验收：GIMP 开书 B2 阶段 `breakLines` 调用计数对比（落盘计数器，默认关）。

顺序：R1 池签名补文件版本 → 装饰器 + 单测 → 设备计数对比 → 遍历合一。
（2026-09-29 更新：整段 memo 经论证降级——命中靠文本巧合（GIMP ~7%），结构性重复早被
`blockShapeCache`/`pageCache` 覆盖；`preferredWidth` memo 已砍（同参复现≈零）；遍历合一已先行
落地——`shapeGeometry` 内 5 家收集器共享一次 `styledSegments`（`precomputed` 透传，外部调用零变化）；
R1 未立项。）
