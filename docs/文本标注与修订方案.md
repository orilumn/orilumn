## 2. 决策记录（逐条追加）

### D-1 锚点 = 章号 + 章内字符区间（与 `ReadingLocator`/`PageSlice` 同源）

- 表达为 `[charStart, charEnd)`，即用户所说的「原 CFI」；**不新造坐标**。
  （`ReadingLocatorCodec` 存 `chapter:char`；`PageSlice.charStart/charEnd`；页表 `PageRecord` 同源。）
- **所有标注都相对「原书」解算**：书不动，偏移就不动；标注之间**永不互相漂移**；
  排版参数改变（字号 / 边距 / 主题 / 旋转）不影响锚点。
- **装饰类不触发重排**；将来**内容修改**改变文字 ⇒ 该章必须重排一次 —— 这是唯一代价，接受。
- 引擎升级导致归一化口径变化的风险：**暂不处理**（还没有用户），与书签/阅读进度同一风险等级。

### D-2 渲染 = 专用「区间装饰通道」，不注入 CSS 标记，也不用 `border`

- 依据：`text-decoration` 在 CSS 里是「每元素一套、绘制时重合」，**无法与书内已有的下划线共存**
  （只能有一条线，且当前连颜色都改不了）；`border` 是「不得已」手段，**不采用**。
- 规范对应物：**CSS Custom Highlight API（`::highlight()`）** —— 样式挂在**区间**上而不是节点上，
  因此不去抢书作者元素那个「每元素一套」的槽位，可带自己的颜色 / 粗细 / 位置叠加在文字装饰之上。
- 本引擎里对应 **run（区间 + 样式）** 机制。
- 这条通道**同一个东西**同时服务：**临时选区**、**持久标注**、将来**审阅视图的标记**。
- 颜色随记录直达绘制，**不进 CSS 级联** —— 它是「用户侧叠加标记」，不是覆盖书样式的声明
  （故不涉及《样式层叠优先级》的 tier 之争）。

### D-3 标注层 = 两种应用模式，共用锚点与存储

| 模式 | 载体 | 用途 | 动树 / 重排 |
|---|---|---|---|
| **装饰模式（区间）** | 区间装饰通道（D-2） | 高亮、划线、选区、审阅视图标记 | 否，零重排 |
| **内容模式（节点）** | 注入 / 改写 `MarkupElement` | 将来删 / 改 / 加文字（v3） | 是，该章重排 |

- v1 只跑**装饰模式**；**内容模式的位置预留好** —— 这就是用户要的「框架基础」。
- 内容模式下注入会碰「import 时算结构 / open 时 relink」的持久化快路径
  （`PersistedChapterFile`；`MarkupElement.children` 是 `val`，注入 = 重建节点）。
  两条路待 v3 时定：**(a)** relink 之后受控就地插入（保叶身份与字符偏移，快路径不退化）；
  **(b)** 该章 open 时重算结构（丢持久化收益）。

### D-4 绘制归属与缓存

- **「字符区间 → 纸面矩形」只能在 `engine-skia` 做**（`LineAligner` 是 `internal`，只在渲染层可见）。
  用户层（`shared-ui`）只提供「章号 + 字符区间 + 样式」，消费结果。
- **持久标注烘焙进页面位图**：机制是「行数据变 ⇒ 指纹变 ⇒ 自动重烤」——
  `PageRasterSpec.fingerprint()` 按**值**比较 `lines`（`DrawLine` 与 `PageRasterFingerprint` 都是
  `data class`），行里的装饰 run 一变即未命中重画。位图池是**内存**的（`PageRasterStore`，非落盘）
  ⇒ 无旧像素残留。翻页动画 / 预栅格 / 两级分辨率天然一致。
- **不要复用 `contentRevision`**：它是**版式**修订号，由平台壳在**重排之后**推入
  （`ReaderActivity.applyReflowResult` / 桌面 `ReaderView` 的推送），`shared-ui` 无权 bump，
  语义也是「版式变了」而非「标注变了」。
- 正确做法：`host.pageLines(pos)` 的记忆**保持不变**，在其后**另加一步投影**
  `remember(rawLines, 装饰修订号)`；该修订号由 `shared-ui` 自己持有
  ⇒ 标注增删改**既不触发重排，也不必惊动平台壳**。
- **拖拽中的选区**不能每帧重烤（一页栅格 ~0.2s）⇒ 走**轻量覆盖层**路径，几何与烘焙同源，
  只是「即时画」而非「烘焙」。

### D-5 通道契约草案（渲染层定义，用户层消费）

```kotlin
// engine-skia（渲染层）：输入是章内字符区间 + 样式；输出是 DrawLine 上的行内 run
enum class DecorKind { BACKGROUND, UNDERLINE }   // 将来 OVERLINE / LINE_THROUGH

data class DecorRange(
    val start: Int,            // 章内字符偏移（与 ReadingLocator / PageSlice 同源）
    val endExclusive: Int,
    val kind: DecorKind,
    val argb: Int,
    val thicknessPx: Float? = null,
    val offsetPx: Float? = null,
    val priority: Int = 0,     // 叠加次序（例如选区压过标注）
)
```

- 归集的现成 seam：`styledSegments` 的每个 `StyledSegment` 都带 `node`（`StyledText.kt:55-60`），
  照 `collectUnderlineRuns` 的写法扩展即可。
- 绘制次序按规范：块背景 → 行内装饰背景 → 文字 → 下划线 / 着重号。

### D-6 存储 = SQLDelight 表（数据库），不用每书一个附件文件

- 新增一张标注表（终态表 + 一条迁移），与 `reading_states` 同源、同库、同事务。
- 形态（草案）：

  ```sql
  CREATE TABLE annotations(
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    bookId INTEGER NOT NULL,
    chapter INTEGER NOT NULL,
    charStart INTEGER NOT NULL,      -- 含
    charEnd INTEGER NOT NULL,        -- 不含（与 PageSlice 同口径）
    kind TEXT NOT NULL,              -- highlight / underline / note / ...
    color INTEGER,                   -- ARGB
    note TEXT,                       -- 批注文本（v2）
    createdAt INTEGER NOT NULL,
    updatedAt INTEGER NOT NULL
  );
  CREATE INDEX annotations_by_book_chapter ON annotations(bookId, chapter);
  ```

- 删书时与 `books` 同事务一并删除（不留孤儿）。
- **代价（已接受）**：标注不再是一个「用户可见、可随手拷走」的附件文件；
  将来导出「改过的 EPUB」要**另写一个导出器**（从库里取记录 → 生成补丁/新书），
  而不是像附件文件那样「天然就是补丁」。这是选 A 换取事务安全与查询便利的明账。
- **加一层接口**：读写走一个共享层的存储接口，DB 只是它的一个实现；
  将来若要做「可导出的附件」，在接口下再加一个实现，不必动上层。

### D-7 选区单位 = 英文按词、中文按句

- 英文「词」：文档空白 + 常规标点，撇号 / 连字符连缀。
- 中文「句」：以全角句末标点（`。！？…；` 等）断句，闭引号 / 闭括号归前句。
- **关键收益**：两者都**不需要分词器**，**不开平台 `BreakIterator` 缝**，纯共享层可做。
- 待细化：句末标点集合、换行是否算句边界。

### D-8 跨页 v1 必做；不跨章

- 交互模型：**拖手柄到页边缘 → 自动翻页并继续扩选**（移动端标准做法）。
- **触发带按正文缘算**（越出正文 8dp；边距窄到放不下时退回屏幕最外 12dp），
  并且**一次进入只翻一页**——翻完要退回正文区再进带才翻下一页，
  避免读者停在页边等选区时被连翻两三页（详见 §3.3）。
- **手柄接力规则**：手指位置不动，翻页后手柄跳到**新页最靠近手指那一侧的行**，继续跟随手指。
- **不跨章**：拖到章末页边缘即停住（选区封顶到章末），保持「一条标注 = 一个章内区间」的模型。
- 存储不受影响：跨页只是**同一章内的区间变长**。
- 渲染：选区跨页时，每页只画该页与选区的**交集**；翻页动画期间选区覆盖层如何呈现，待细化。
- **架构约束**：自动翻页**不能**复用滑动翻页的手势会话（同一根手指正在拖手柄），
  需由选区逻辑驱动一条**独立的翻页路径**。

### D-9 桌面鼠标：拖拽拖选，单击左右 1/3 翻页（2026-11-20 恢复）

- 需要按**指针类型**分流（触摸 / 鼠标），而不是两套 `pointerInput` 硬抢。
- 鼠标**拖拽 = 文本拖选**（桌面最自然）；**不允许拖动翻页**（跟手滑动动画随之取消）。
- **翻页走横向滚动通道 + 鼠标滚轮**（2026-11-04 用户定口）：
  触控板双指向左滑 = 下一页，反之为上一页；鼠标滚轮拨一格 = 翻一页。
  **触控板的双指上下滑不翻页**（想滚这一页、或只是手指在触控板上挪了一下，翻页是误触）。
  两者在事件里长得像，按**形状**分：滚轮是整数格（±1..±3）、一格一格拨、间隔 ≥25ms；
  但 macOS 会把一格平滑成一串小数事件（真机：从 0.1 平滑涨到 7.7，整串 100–250ms，
  随后断流 200ms 以上），这一串按「只有竖向、起手极小、涨到峰值就断流」认，且要等它
  断流才结算（迟到的那几条不能当场翻，否则触控板惯性正好落在整数上会翻两次）；
  触控板是小数、8–17ms 一条的连续流，抬手后还拖着衰减到零点几的惯性尾巴。
  拿不准就按触控板处理（不翻）。
  横滑判据用**净横向位移**：横向累计要压过纵向噪声够一格才翻，略微斜着滑照样翻，
  竖滑不会被误判。一次连续横滑最多翻一页（抬手后的惯性算在同一次里，不会顺着惯性连翻）；
  **再滑一把**也算新的一次：断流超过 60ms，或者这一把的速度连续两条掉到峰值的四分之一
  以下、又从谷底涨回两倍以上（惯性是平滑衰减的，两把之间则是断层式掉下来再涨回去）；
  掉头往回滑也立刻算新的一次，不用先把上一把的惯性抵消掉。翻页动画还没落地就赶上的
  那一下，会等落地后补翻一次。标注卡片开着时滚动改为在视口里上下滚页（见 D-28 §2），
  不翻页。
- 鼠标**单击恢复翻页**（2026-11-20 用户定口）：左 / 中 / 右三区**三等分**，与触摸端
  完全同一套（左 1/3 上一页、右 1/3 下一页、中间 1/3 切上下栏）；点中已有标注 / 链接
  仍按平板同一优先级先吃掉这次点按（有选区时单击先清选区；封面页前进区回正文、
  其余切栏）。滚轮 / 触控板双指翻页照旧可用，两套并存。
  （2026-11-04 曾收口为「单击不翻页」，本次恢复。）
- 桌面翻页仍可只用键盘（左右箭头；拦着方向键时照旧冒泡）。
- 触摸端的滑动翻页与三区点按**保持不变**；分流按**指针类型**，不按平台
  （Android 平板接鼠标同样走鼠标语义）。
- 落地：鼠标按下后**移动超过点按阈值**才起选区（单击不起选区）；单击落点直接进平板的
  点按入口，不再按版心几何另判「点正文无操作、只认左右页边距」。
- 拖选的**锚点 = 鼠标按下那个字**，不扩成整词 / 整句（桌面没有长按语义；扩成整句时
  从行中往右拖会变成「行首 → 手指」，看起来就是选区从行首开始）。
  拖到页边自动翻页是**选区接力**，不属于翻页手势，照旧保留。
- 触控板**边缘手势归系统**（右侧边缘两指横滑 = 通知中心），那几条事件根本到不了 APP，
  表现为「滑了没反应、通知栏滑出来了」——不是判据的问题，APP 侧无法接管；
  从触控板中部起滑即不受影响。

> 历史口径（2026-10-17 定稿、2026-11-03 作废）：鼠标只能拖选，点左右页边距翻页，
> 点正文无操作。2026-11-03 改成「单击与平板同一三区点按」；2026-11-04 再改为
> 「单击不翻页，翻页走滚轮 / 触控板双指」；同日收口为「单击不翻页，翻页走触控板横滑
> 与鼠标滚轮（拨一格一页），触控板双指上下滑不翻」。

### D-10 放大镜：移动端要，桌面不要

- 纯**用户层**（shared-ui）实现：复用页栅格位图放大绘制，不涉及排版层与渲染核心。
- **当前落地**：直径 96dp、1.5 倍、圆心优先在手指上方 56dp，贴顶翻到下方、贴边内移；
  长按起手和拖手柄时出现，松手即消失；桌面鼠标不出现（按指针类型判定）。
  实现上不另取位图，而是把同一个 `PageContent` + `ReaderPageRenderer` 再画进圆形裁剪层，
  由渲染器现有的页位图缓存直接命中，所以与静止页像素同源。

### D-11 移动端：三区点按保留，长按进入选区

- 点按三区（左 1/3 后退 / 右 1/3 前进 / 中间切栏）**必须保留**——这是移动端的主要翻页方式。
- **长按**是进入选区的唯一入口；进入选区后，点按改为「清除选区」（不翻页）。
- 桌面无「长按」语义，改由鼠标拖选进入（见 D-9）。

### D-12 动画与选区互斥（时间维）

- 翻页动画 / 滑动会话进行中 → **不响应**长按与选区手势（现有 `ctl.isBusy()` 守卫扩用）。
- 选区手势进行中（长按起手 → 抬手，或按住手柄拖动）→ **不播任何翻页动画**；
  跨页翻页一律**直接跳（瞬切）**，不做淡入。
- 选区**已存在但未在操作** → 翻页不受限（点按 / 滑动 / 键盘），翻页后选区保留，各页只画交集。
  - 触摸端例外（D-11）：有选区时**点按 = 清除选区**、不翻页 ⇒ 此时翻页走滑动或键盘。

### D-13 颜色体系：用户可自定义调色板

- 高亮与划线**各自一组色槽**（4–5 个）；每个槽的**颜色与透明度**（ARGB）由用户自定义。
- 两类各有一个**默认色槽**（新建标注时用它）；浮动菜单里点哪一格，哪一格就**成为默认**
  （即「记住上次用的颜色」，下次打开双圈就在那一格）。
- 浮动菜单还记住**上次用的类别**（高亮 / 划线），下次打开直接摊开该类别的色槽行，
  不必先点一次类别按钮。
- 归属：**全局**（`ReaderSettings`），跨书统一——与字体 / 主题同类。
- 记录里存的是**创建当时的颜色**（解析后的 ARGB 快照）⇒ 改调色板**不影响已有标注**（墨迹已干）。
- 颜色仍**不进 CSS 级联**（延续 D-2）：它是标注自身颜色，不是覆盖书样式的声明。
- **当前落地**：高亮 / 划线各 5 格，存 `ReaderSettings` 的 `highlightColorSlots` /
  `underlineColorSlots`（ARGB `Int`），另存 `highlightDefaultSlot` / `underlineDefaultSlot`。
  设置面板「笔记」页两行标签各带五格色槽，点格后在下方调 RGB 与不透明度（100% = 完全盖住文字），
  拖动中即时生效、松手落盘；最下方的「恢复默认颜色池」把两类十格一起恢复出厂值
  （**只恢复色槽**，不动下面的批注字体 / 字号 / 画法），按完按钮短暂变成「已恢复」并金色高亮
  ——色槽本来就是出厂值时色块不会变，没有这一步反馈读者分不清「按到了」和「没按到」；
  默认色槽不在这页体现（新建标注用哪一格由浮动菜单决定）。
  浮动菜单点高亮/划线后展开五格，点哪格就用哪格颜色创建标注。老存档缺键自动取默认，
  无需 bump 结构版本。
- **两个类别完全独立**：菜单里「高亮」「划线」的样张、色槽行、线型行各取**本类别**的色槽与默认槽；
  编辑另一类别的记录不会让本类别串色。从高亮转成划线（点线型）时颜色改用**划线的默认色槽**，
  不把高亮那半透明的底色带进墨线。
- **划线的线型**：实线 / 波浪 / 虚线（高亮没有线型，该行不出现）。线型行只画线、
  不写字，线色 = 当前划线色；选中那条垫一层与类别按钮同款的高亮底。
  选区场景**点线型即落笔**（用当前划线色，不必再点颜色）；编辑已有标注时点线型即改这一条
  （高亮顺手转成划线）。线型存 `Annotation.lineStyle`，浮动菜单另记「上次线型」
  `annotationLastLineStyle`（纯全局，同标注一族）。
  > **2026-11-09 用户定口：删除线这一档整体移除**（实线 / 波浪 / 虚线保留），免得和审阅视图里
  > 表示删字的红色删除线混淆。老记录里存过的删除线按实线下划线显示，不另做迁移。

### D-14 已有标注可编辑 / 删除（v1 必做）

- 入口：**长按已有标注 → 同一个标注浮动菜单**（改色 / 删除）；长按空白 → 新建选区。
  语义统一为「长按 = 针对此处」。
- 跨页标注是一条记录，菜单作用于整条。
- **当前落地**：长按只在当前章内存列表里按字符区间命中（不查库、不反查几何），页边距不参与；
  命中后**把选区恢复成这条标注原来的字符范围**（两端手柄照常显示，可以直接拖），弹出与选区
  共用的那张卡（见 3.2）：该标注所属类别的五格色槽预展开（当前色描强调边，点哪格即改色、
  并同步换成该类别），删除一步直删（无二次确认），复制复制这条标注覆盖的原文。改色与删除先改
  内存立即出图，再异步落库，失败回滚并提示。长按空白仍进入选区；菜单外点按只关菜单。
  **编辑时拖手柄改范围，按 `确定` 把新范围连同样式 / 批注一起写回**（2026-11-03 用户定口）。
  桌面鼠标按住正文等价于长按（拖过阈值仍是拖选）；翻页、换章、旋转/改排版都会收起菜单。

### D-15 视图模式按书持久化

- `CLEAN` / `REVIEW` 的状态**按书**存（每本书各自记），因为它描述的是「这本书的展示方式」。
- v1 恒为 `CLEAN` 且**不暴露界面**，只为 v3 的内容修改预置位置。

### D-16 颜色设置界面 = 共享 Compose，不开平台分支

- **不做**安卓 / 桌面 / iOS 各自的平台对话框；做**一套共享 Compose 界面**，挂在现有面板体系里
  （`ReaderSettingsPanel` / `FontLibraryPanel` / `ReaderTocPanel` 同制，复用 `paletteFor(scheme)`）。
- 理由：① `AGENTS.md` 的 KMP + CMP 约束要求基本组件跨平台共享；
  ② **Android 没有系统颜色选择器**，本来就得自绘；③ 透明度支持三端系统选择器参差不齐，自绘最省事。
- 形态建议：**色槽网格 + 透明度滑条**（必要时补 HEX 输入）。细节见待决。
- **当前落地**：设置面板内新增「笔记」页（与现有设置页同制，复用 `paletteFor(scheme)`）：
  高亮 / 划线两行标签各带五格色槽、红/绿/蓝/不透明度四条滑条、恢复默认颜色池按钮，
  最后是旁注自己的两项样式——**批注字体**（复用正文那套字体下钻页，系统 / 导入字体都能选，
  多字重的族同样进字重页，选完族与字重一起生效）与**批注字号**（滑条编辑倍率，右侧显示换算后的实际字号，滑条右端最多到 25）；
  最上面是**折叠所有批注**总闸（打开后旁注只留贴着划线的小图标，下面这组批注控件一并置灰）；
  四条颜色滑条与字号滑条拖动中即时生效（只应用不落盘，松手才写设置）。
  不新增第三方依赖，也不开平台颜色对话框；未做 HEX 输入，也不再有快捷色。

### D-17 删书清理走共享的「一次删三张表」（事务）

- 现状**没有外键级联**，且两个平台各自删、**非事务**：
  - Android `BookRepository.removeBook` = `db.removeBook(id)` + `db.clearReadingState(id)`；
  - 桌面 `ShelfStore.delete` = `requireDb().removeBook(id)` + 删文件（**不碰** `reading_states`）。
- 定案：在 `LibraryDb` 加**一个共享方法**（`removeBookAndData(id)`），用 `db.transaction { … }`
  一次删 `books` + `reading_states` + `annotations`；两个平台都改调它。
- 顺带收益：修掉现状「删书与清进度分两步、非原子」的问题（中断即留孤儿）。
- 注意：改了桌面既有行为 ⇒ 实现后必须实测「删书 → 三张表都干净」。

### D-18 章节文本 = 引擎投影，同步、与排版同源

- **问题**：全仓没有「取整章原文」的现成入口。`DrawLine.text` 只是**行片段**
  （按页窗口切开、带断行与行尾连字符），直接拼会漏字 / 重字，复制出来与原文对不上，
  选词与断句也会跟着错。宿主侧同样没有章节文本查询。
- **定案**：在**排版层（下）**新增章节文本投影，复用
  `NormalFlowLayout.leafText`（与塑形同一份归一化字符串）+
  `ChapterPrepareResult.globalCharStarts`（与 `DrawLine.charBase` 同一套章内偏移），
  按叶序拼出整章文本。这样「排版用的字」「标注锚点」「复制/选词用的字」是**同一份**。
- 另给「按区间取原文」：块与块之间在**复制结果**里补换行，但**换行不计入偏移**
  （偏移只认排版字符流）。
- **必须同步**：长按是手指按下即要出结果的手势，不能走异步往返。宿主在开章排版时
  顺手缓存，`textOf(chapter, start, end)` 与 `pageLines` 同级（廉价、立即返回）。
- 归属：投影与切片都在共享层（排版层（下）），平台宿主只是转发；**不允许**两个平台各拼一遍。

### D-19 标注列表由 shared-ui 自持，数据库只在开章与保存时参与

- 阅读页要同时做三件事：画当前章的标注、长按命中已有标注、增删改后立刻可见。
  每帧查库会卡，异步往返又会让长按有延迟。
- 定案：shared-ui 进章时读一次，**持有当前章的标注列表（Compose 状态）**；
  新增 / 改色 / 删除先改内存并递增「装饰修订号」（界面立刻更新），再异步落库；
  落库失败回滚并提示。
- `ReaderHost` 只加四个后台口：读本章、增、改、删（平台实现转发给共享的 `LibraryDb`）。
- **相邻章预读**（2026-11-01 补）：进章时顺手把前后两章的标注各读一次，放进一份只读的
  小缓存（最近几章，按章淘汰）；进预读过的章时直接摆上去，不再等一次库往返，跨章翻页的
  目标页也能首帧带上自己的装饰与旁注。预读**不参与增删改**（改的永远是当前章那一份），
  外部改动（笔记清单里删标注）走既有的整章重读，并把预读缓存整批作废。
- **不做**「监听数据库变化」的通用流：v1 只有这一个写入口；等 v2/v3 出现第二个写入口再补。

### D-20 视图模式延后到 v3：开关在阅读页底部工具栏，与书架无关

- 用户 2026-10-20 明确：审阅视图属于后面「内容修改」阶段的功能，
  开关预计放在**阅读页底部工具栏**，不是书架 / 书目属性。
- 因此 **v1 不建视图模式列、不建表、不存任何状态**；原 §5.10 的
  「`books` 加一列」建议**作废**（且与现有整行覆盖写入冲突，见 §5.10）。
- D-15 的「按书持久化」保留为 **v3 待定**：真做到内容修改时再定落点与默认值。

### D-21 颜色面板 = 共享自绘，不调平台颜色对话框

- 核实（Compose Multiplatform 1.11）：**没有官方颜色选择器组件**；通用 `Dialog` / `Popup`
  只是容器，取色控件仍要自己写。
- 平台系统对话框不可行：Android 本身没有系统取色器；桌面只有旧式 Swing 组件，
  风格与阅读器面板不一致，两端行为也不齐。
- 定案：沿用 D-16，**自绘共享 Compose 面板**（色槽网格 + 透明度滑条 + 可选十六进制输入），
  不新增第三方依赖，不开平台分支。色槽值存 `ReaderSettings`（§5.9）。

### D-22 自定义样式 = 读者规则层，压在 UI 之上

- 用户 2026-10-20 明确：选中一段内容后，应用反查候选选择器
  （元素本身、父元素 > 子元素、类名、ID、父类名 > 子元素等），**按具体程度从高到低**列出；
  读者挑一条选择器，再挑样式、填属性值，最后生成一条规则。
- 这不是「给一个元素塞内联样式」，而是**读者自己写的 CSS 规则**（选择器 + 声明）。
  因此它属于读者侧，整体压过书本；读者内部，它高于 UI 的全局偏好。
- 层叠顺序：`自定义样式（45/49） > UI（44/48） > 主题（42/46） > 书本 > UA`。
  层内仍按选择器特异度与源码序决胜；候选排序只帮读者选作用范围。
- **规则必须以样式表注入**，不能写成元素上的内联 `style`：内联样式在引擎里属于书本侧
  （tier 30），会被任何读者层压掉。
- 宽选择器（如 `p`）也会压过 UI 的全局设置，界面需显示命中范围 / 预览并提示。
- v1 不做（高亮 / 划线走装饰通道，不经过样式层叠）；v3 内容修改如需样式，走这一层。

### D-23 标注 / 批注清单 = 目录抽屉的第二个 tab（标题「笔记」）

- 用户 2026-10-22 提出：*这些高亮、画线、批注笔记需要在笔记面板中实现清单（跳转+删除），
  面板的入口早就有了，可以考虑把它和目录使用同一个面板的不同 tab。*
- 现状核实：底部工具栏**入口已有**（`✎ 笔记`，与 `☰ 目录` 并列），但 `onNote` 为 null，
  点按只弹一句「笔记（规划中）」；本方案原 §1 只在 v2 写了一行「标注列表面板」，没有设计。
- 定案：
  1. **同一个左停靠抽屉，两页**（目录 / 笔记）。抽屉壳（遮罩 + 滑入动画 + 顶部条 + ✕）
     抽成共享壳，标题文字位置换成「目录 | 笔记」分段控件，✕ 原位不动。
     `☰` 打开落在目录页、`✎` 落在笔记页；页内切换**不关面板**；当前页在会话内记忆。
  2. **设置面板不并入**：设置是分区滚动 + 滑块的另一种形态，并进 tab 只会让两边都变差，
     保持独立抽屉（现状）。
  3. **行内容**：原文摘录（最多两行，超出省略）**按该条标注本来的颜色与线型直接画在摘录文字上**
     —— 高亮垫同色底，划线画同色实线 / 虚线 / 波浪线，与正文那一处完全同一套口径；
     不在左侧另立类别图标（颜色和线型本身就是类别）。另有批注行下一行显示批注正文；
     删除不再占用行尾：整行左滑露出红色「删除」，用的是字体管理面板那件左滑通用组件
     （同一套橡皮筋、吸附与「同时只展开一行」的手感）。所在章的标题仍作为分组头算出来，
     但**不画在清单里**（2026-11-04 用户定口：笔记内容中不夹章标题），
     留在分组数据里给将来导出笔记当标题用。
  4. **分组与排序**：按书内章序分组，章标题取目录项标题、缺项回退「第 N 章」；
     章内按区间起点升序（与 `annotationsForChapter` 同序）。分组头不显示，清单是平铺的
     一条接一条；打开时滚到当前阅读章的**第一条笔记**。
  5. **跳转**：点行落到**包含该区间起点的页**（不是章首），走壳里既有的锚页漏斗，
     与目录跳转同口径：`finalizeOnLeave` → 落位 → 保存进度 → 关面板。不新增手势、不新增状态机。
  6. **删除**：行尾按钮**直接删**（与长按菜单的删除同口径，无二次确认），删完立刻从面板列表
     与当前章内存态移除；落库失败则恢复并提示。删当前章的标注后，屏幕上那条装饰必须同时消失。
  7. **空态**：一句「还没有高亮、划线或批注」。
  8. **不做**：搜索、按类型/颜色筛选（v2 批注落地时再加）、导出、跨书汇总、分页
     （`LazyColumn` 足够；超大书若真卡再考虑按章折叠）。
  9. **键盘（桌面）**：清单内沿用现有 `PanelNav`（上下键 + 回车）；tab 切换先只做点按，
     不进 `Tab` 焦点链——真有人要键盘切页再加。
  10. 抽壳时**不改外观常量**：顶条高度、抽屉宽度、滑入时长（`TocAnimMs`）、遮罩透明度一律照旧，
     只把标题文字换成两页控件；否则等于顺手改了一遍目录的手感。
- 归属：**v1.5**。它只依赖已有标注数据，先做清单；v2 批注落地时同一列表直接多显示批注正文，
  不换壳、不返工。

### D-24 清单要摘录原文 ⇒ 标注表存「创建时原文快照」

- 冲突点：清单每行要显示「这段标注划的是哪句话」，但章节文本（`textOf`）**只对已排版缓存过的章
  可用**（远章已驱逐，返回 null）。为了一个清单去把全书各章的版排出来，直接违背分页调度总则
  （用户一开面板就排全书）。
- 定案：标注表加 `quote TEXT`（原文摘录），**创建时**从 `textOf` 取并截断到约 200 字，
  迁移 8→9（`8.sqm`）。与颜色同理是**创建当时的快照**：改排版参数不回溯（文字本身不变，
  基本不会漂）；v3 内容修改后引用原文可能变化，届时按「以原书为准 / 刷新快照」重新定，
  不在 v1.5 预支。
- 老记录（v1 已有标注）`quote` 为空：开该章时顺手回填一次（章节文本已在缓存里，一条 UPDATE/条）；
  仍未回填的面板显示「（无摘录）」兜底，不阻塞跳转与删除。
- 不另建表、不存富文本：一列足够；批注正文继续用 `note` 列，v2 不需要新表。

### D-25 批注 = 独立类型 + 虚线标记（v2 初版，**已被 D-26 取代**）

> 2026-10-22 用户否决：「批注的样式不好定，干脆让它作为高亮和划线的附件」。
> 本节留作失败路径的记录，实现已按 D-26 改成附件模型；旧的 `kind = 'note'` 记录
> 由迁移 9→10 统一改写为高亮，文字与颜色原样保留。

- 原定案：`kind = note` + 正文固定虚线下划线 + 独立色系（`noteColorSlots`）+ 自绘居中输入框；
  Android 阅读页 `adjustNothing`（键盘弹出不许改窗口尺寸）——这一条被 D-26 继承。
- 否决理由（留给后来人）：
  1. **同一段文字只能有一种墨迹**：读者先高亮、隔天想补一句话，独立类型会逼他再叠一条记录；
     两条记录各画各的，删除 / 改色 / 跳转 / 清单都要额外处理「两条落在同一段」。
  2. **样式没有判断依据**：虚线与「划线 + 虚线线型」在正文里看不出区别，只能靠颜色体系区分；
     颜色一独立成组，设置页就要多一个类别、菜单就多一套规则（编辑批注时不许点高亮色槽）。
  3. **居中弹窗挡住了那条墨迹**：批注是「顺手补一句」，读者要一边看着高亮一边写。

### D-26 批注 = 高亮 / 划线记录上的附件 + 底部输入条 + 正文旁就近显示（v3，现行）

> **2026-10-22 再次定形（见 D-28）**：贴着选区浮动的那个菜单取消，操作项并入键盘上方的输入条
> 组成一整条「操作栏 + 输入行」；被遮住时整页上顶；旁注增加指向原文的箭头。
> 本节其余内容（附件模型、`note` 列、旁注布点、清单筛选）继续有效。

- 一句话：**批注不是第三种标注，而是高亮 / 划线记录上附带的一句话**（`note` 非空即「带批注的标注」）。
  没有输入就是普通标注，有输入就是「标注 + 一句话」——墨迹仍是那一条，不会多出第二条记录。
- 定案：
  1. **记录形态**：只有 `highlight` / `underline` 两类；`note` 是可选文字，`color` 仍是创建当时的快照。
     旧数据：v2 试验期的 `kind='note'` 由迁移 9→10（`9.sqm`）统一改写成 `highlight`（颜色与文字不动）；
     解析侧未知类型**回落高亮**，不再抛错（外部导入不该让书架打不开）。
  2. **删掉批注专用色系**：`noteColorSlots` / `noteDefaultSlot` / `DEFAULT_NOTE_COLOR_SLOTS` /
     `DEFAULT_NOTE_ARGB` 全部移除，设置页的标注颜色回到「高亮 / 划线」两类。
  3. **输入条**（`NoteComposeBar`）：贴着**键盘上沿**的一行输入框（桌面没有键盘，就贴窗口下边框），
     用 `imePadding()` 把整条抬到键盘之上；Android 壳保持 `adjustNothing`——键盘弹出**不改窗口尺寸**，
     否则视口一变就是一次整书重排（本功能最大的坑，见 D-25 第 5 条）。
     - **落笔即弹**：点色槽 / 线型落成一条标注后，输入条自动弹出并聚焦。
     - 长按已有记录 → 菜单「批注 / 改批注」重新打开**同一条**（带出已有文字）。
     - **退出即保存**（口径已被 D-28 取代）：当时是完成 / 返回键 / Esc / 点条外全走提交。
       现在落笔只在 `确定` 与点卡片外的正文，返回键 / Esc 是取消（见 D-28 第 1 部分）。
     - 透明遮罩只吞点按、不压暗：打字时正文与刚画上去的墨迹一直看得见。
  4. **正文旁显示**（`NoteBubbles`）：批注文字就近显示在那条墨迹旁边，**纯覆盖层**——
     只读行几何（`DrawLine.yTop/yBottom/xLeft/lineWidthPx` + 页面位移）找空白，
     **不进分页、不进栅格、不触发重排**。候选取用顺序（都不会压到正文行）：
     ① 锚点末行右侧（最像「旁批」）→ ② 锚点下方到下一行之间的空隙（多半是段间距）→
     ③ 页脚空白 → ④ 左右页边距兜底（窄到只能显示一个字加省略号也认）。
     （**此候选顺序与兜底口径已被 D-28 §3 取代**：2026-10-23 起按整页空白统一评分，
     页边距是一等候选，且绝不显示只有省略号的框。）
     压到正文行或已放好的旁注即作废，四个都不成立就**不显示**（宁可看不见，也不糊住正文）。
     点旁注文字块 = 打开该条的输入条。
  5. **清单**：类型筛选改为独立枚举 `AnnotationFilter`（全部 / 高亮 / 划线 / 批注），
     「批注」按**有无 `note`** 判定；带批注的高亮 / 划线也显示正文（最多三行）。
  6. **浮动菜单**：「批注 / 改批注」只在**长按已有记录**时出现；新建场景用不着，
     输入条落笔后自己会弹。
- 不做（v3）：批注富文本 / 导出 / 跨书汇总 / 清单内直接编辑正文。
  旁注的字体 / 字号 / 颜色**已排期**（用户 2026-10-22 点名），见 **D-29**：只动 `NoteBubbles`
  与箭头绘制，不碰排版。

### D-27 批注输入条细则（D-26 第 3 条的落地细化，2026-10-22）

> 代码注释里的「D-27」指的就是这一节。它没有推翻 D-26，只是把输入条的行为写实。

- 输入条 = 贴着**键盘上沿**的一行输入框（桌面/无键盘时贴窗口下边框），透明遮罩只吞点按、不压暗正文。
- 打开即聚焦（顺带把键盘顶起来）。（**退出语义已由 D-28 取代**：落笔 = `确定` / 点卡片外；
  返回键 / Esc = 取消。）
- 它与浮动菜单**同开同关**：选中文字就一起弹（新选区），长按已有记录也一起弹（带出原文字）。
- 空输入 = 不写批注：新选区提交后只剩墨迹（连墨迹都没有就什么都不留），已有记录提交后只清掉那句话。
- 状态：输入条本身**保留**；D-28 把操作菜单并进它上面，合成同一张卡片。

### D-28 选区操作栏 = 菜单 + 输入条，遮挡时整页上顶，旁注用箭头指向原文（v2.1，2026-10-22 用户定形）

> 用户原话（2026-10-22）：「现有的弹出菜单删掉，合并到键盘上方的批注输入框上方，整体为一行……
> 菜单区+下方输入区+下方键盘区作为一个整体，计算它的总高度 H……把页面整体向上顶出上边界……
> 批注文字按就近优先，其次完整显示优先的原则，布放在同一页空白区，通过箭头指向书中对应的原文。」
> 以及：「对原有笔记，单击直接弹出键盘+功能区；其余划屏、点击翻页操作，首次触屏点必须避开所有
> 笔记标注区和链接区，手指滑动过程中可以触及笔记区和链接区，这时不弹出键盘+功能区。」
>
> **布点口径已于 2026-10-29 再次修订（现行）**：先保整句（截断是最后手段），再比就近
> （额外引线长度，差一个行高以内算同档），同档挑最宽的那块空白（折行最少），
> 之后才比环数与方向（右上/右下 → 左上/左下 → 正右 → 正左 → 正上 → 正下）；
> 段界已删除，范围只由空白是否连成一片决定，满行左右页边距可用但排在四个角之后；
> 同一行多条先最右那条占正右、其余从左到右**各自独立取位**（不排成一列），整句放不下时才请挡路批注上下 / 左右
> 让位；**让位 / 自己滑开得到的位置不算定案**，挪出去以后还要继续沿候选链找更近的空白（2026-10-29 用户定口）；
> 全部落位后长外短内综合安排；所有环都不行才退成 0.5em 的小椭圆。
> 标注占空白；留白两档：空间够时正侧与正上 / 正下都留 1em，不够只收远离正文一侧到 0.1em；
> 近侧一律不压——正上 / 正下推不出 1em 就宁可不用这个方向，四个斜向近侧固定 2px，
> 靠横向错开的一个字画 L 形引线；
> 框宽按字体 / 字号 / 行距 / margin 综合计算；取位「贴住锚点行 / 角」；
> 引线只画横线、竖线与折线；指向**离框更近的那一头**（跨行选区比框到选区首尾，单行看框落在
> 这一行的左半还是右半）；四个斜向必须从框的侧边横着出去、再竖着接住文字，折成 L 形；两端必须接住。
> 完整方案见 `docs/旁注布点与引线-实施方案.md`，以下文现行规则为准。

#### 1. 一条操作栏取代浮动菜单

- **删掉**现在贴着选区/长按点浮动的那个 `AnnotationMenu`（锚点、上方/下方翻边、左右收边那套定位全部作废）。
  菜单项并入键盘上方的卡片，卡片自上而下两段：**操作栏**（可 1–2 行）+ **输入行**。
- **操作栏单行时的从左到右**：
  1. `高亮` `划线`（类别切换，按钮本身仍是样张）；
  2. `修订`（v3 起接正文修改：有选区即可点，进入正文修订卡，见 D-31 起）；
  3. 当前类别的一排 **5 个色槽**（点一格只选中，色槽仍记住上次的类别与格子）；
  4. **3 个线型开关**（实线 / 波浪 / 虚线，只在「划线」类别出现；高亮类别不占位）；
  5. 贴右侧的 **3 个按钮**：`复制` `删除` `确定`（落笔键用正文墨色加粗，不用金色）。
- **输入行**：只留输入框（占位提示「写点批注（可不填）」），**原来的「完成」按钮删掉**——
  落笔由操作栏最右的 `确定` 或点卡片外的正文承担；返回键 / Esc 是取消。
- **窄屏（手机、桌面小窗口）自动两行**：第一行 = `高亮` `划线` `修订` … `复制` `删除` `确定`；
  第二行 = 5 个色槽 + 3 个线型。判定用**实测单行宽度**（一次测量装不下就换两行），不用屏幕 dp 阈值。
- **色槽（2026-10-23 改口径）**：点色槽**只选中**、不落笔（点错还有机会改，卡片也不会忽然关掉）；
  落笔交给 `确定` 或**点卡片外的正文**。选中后卡片不关、当前格外面套互补色 + 灰半透明双圈，
  写下的字与颜色在落笔时一起写入。
  色槽仍记住上次的类别与格子（写盘、无重排提交）。
- 语义沿用已定案的部分：删除只在有可删记录时点亮
  （编辑时是这条记录，新建时是选区内相交的那一条）；成功不弹提示，失败才提示；点条外 = 提交并关闭。
- **点按已有标注 / 旁注 = 打开卡片（2026-10-23 落地）**：单击（不必长按）页上的高亮、划线或旁注框，
  直接弹出键盘与操作栏，带出这条的记录与批注；点按命中标注**不翻页**，长按与单击同一套字符区间命中。
- **线型（已确认）**：只**选中**、不落笔；落笔交给下面两个提交口，这样能先选线型再写字。
  新建时选中线型后落笔 → 按当前类别 + 当前线型 + 当前颜色（没选过就是该格默认色）落一条；
  编辑时选中线型 → 落笔后这条改成「划线」（高亮 → 划线）。
- **落笔只有 `确定` 一处（2026-10-23 定形）**：有批注文字就一起写入；新建选区即使没写字，
  也按当前类别 / 线型 / 颜色落一条（这是「先选样式再落笔」的落笔口）；编辑模式把选好的
  颜色 / 线型 / 文字一次性写回（清空文字即去掉批注）。**编辑时打开卡片就把选区恢复成
  这条标注原来的范围，读者拖过两端手柄就以当前选区为准，`确定` 时范围与摘录一起写回**
  （2026-11-03 用户定口）。
- **其余一切退出都是取消（2026-10-23 定形）**：点卡片外的屏幕、返回键、Esc —— **什么都不改**——
  写了一半的批注、刚选的颜色与线型全部丢掉；编辑态原记录保持原样；新选区连同选区一起清掉。
  它们都**不是**「保存后退出」。（复制只进剪贴板：不动记录，也不关卡片。）
- 菜单不再依赖选区锚点 ⇒ 选区在页面任何位置（含贴底、贴边、跨页）都不存在「菜单跑出屏幕」，
  也不需要 `noteBarHeightPx` 这类估算——卡片自己贴键盘上沿，量到多高就是多高。

#### 2. 被遮住时整页上顶（不是重排版）

- 操作栏 + 输入行 + 键盘（桌面为 0）合成一个整体，占有屏幕底部的高度 H；卡片上沿即「被占用区」的边界。
- **不遮选区就不动**：选区的墨迹（新建 = 选区矩形；编辑 = 打开时恢复成该条标注范围、拖手柄后
  跟着当前选区变）整块都在卡片上沿之上时，卡片直接覆盖在页面上，页面一动不动。
- **会遮就整页上顶，且一次推满 H（2026-10-23 定形）**：只要卡片会压住选区，就把页面**上推 H**
  （H = 操作栏 + 输入行 + 键盘的总高度），推到「页面底边正好与卡片上沿相接」为止；
  顶部超出的部分直接截断。不再是「刚好让选区露出来」的少量推法——推满之后整页都在视口里，
  读者还能继续往下看刚才被盖住的部分。
- **只改绘制与命中，不改版式**：平移量是一个数（单一来源），
  - 页面画布（含翻页滑动层里的静止页）、选区覆盖层、手柄、放大镜、旁注覆盖层都按它平移；
  - 点按/长按/手柄命中在**屏幕坐标 → 页坐标**换算时加回同一个数；
  - **不分页、不重排、不重建栅格**（页位图只是整体位移，缓存照旧命中），也不动 `contentRevision`。
- 键盘收起 / 卡片关闭 ⇒ `shiftY` 归零（是否加一小段动画只是观感参数）。
- **视口内可上下滑（2026-10-23 新增）**：卡片开着时，视口 = 卡片上沿之上那一条（高 `屏幕高 − H`）。
  整页可以在这个视口里上下滑动：
  - 在页面区（卡片外）上下滑手指 → 页面跟着手指走，范围 `0 … H`（`0` = 页顶贴屏幕顶，`H` = 页底贴卡片上沿）；
    抬手后按当时的速度**继续滑**，再按指数摩擦逐步减速，撞到视口两端就停（2026-11-04 用户定口：
    「甩一把」应当自己滑到底，而不是抬手指就钉住）；新手势按下即打断这段惯性；
  - **桌面（鼠标 / 触控板）不拖拽，改用滚轮或双指上下滚**（2026-11-04 用户定口）：
    在页面区滚多少走多少（鼠标滚轮一格约 40dp，触控板每次只报零点几个单位、系统自带惯性），
    滚到视口两端即停，滚动接管时先停掉还没滑完的惯性；鼠标按下只认「点按 = 取消」，拖动不滚页。
    指针压在卡片或工具栏上时不滚页，交给那一层自己处理；
  - 上下拖动手柄到视口边界 → 页面按帧连续自动滚（起手 0.2s 内从 0 加速到 600dp/s，
    不再是每 40ms 挪 12dp 的定步长——那样两步之间看得见一顿一顿），
    边滚边按手指位置延伸选区（能一路选到被盖住的部分）；
  - 读者自己滑过之后以他滑的位置为准；卡片关闭 / 换一条记录时复位，再按「遮不遮住」重新决定推不推。
- 卡片自身不参与平移：它永远贴键盘上沿；键盘动画过程中 `sheetTop` 逐帧变，页面跟着上顶，
  看起来是「页面给键盘让位」，而不是「页面被键盘盖住」。

#### 3. 退出输入后：旁注布点 + 箭头指向原文

**「空白」只排除四类东西（用户定形）**：判断能不能放旁注/箭头时，非空白**只认**——

1. **文字**：逐字墨迹矩形（不是「行的盒子」）；
2. **图形**：插图、图版等图形对象；
3. **表格**：表格整体（框线与全部单元格范围）算障碍，不在表格内部找空白；
4. **线条**：分隔线、框线、装饰线等画出来的线。

**其余全部算空白、可以压**：`blockquote` / `div` / `pre` 这类块的**非文字区**（底色、内边距）、
元素的 `margin` / `padding`、版心四周的四个页边距、行与行之间的空隙、行右侧没排满的地方、
首行缩进的留白。已经放好的旁注框本身当然要互相避开。

- 判据是**字的墨迹**而不是行的盒子：旧实现把整行当障碍，于是「行右侧还剩半截」也被判成压字，
  旁注索性不显示（缺陷 3 的一半原因）。
- **布点排序**（2026-10-23 四稿**定稿**，见 `docs/旁注布点与引线-实施方案.md` §0.1 / §1）：
  1. **整句 → 环 → 折行 → 就近 → 方向**（2026-10-31 用户定口，取代 2026-10-29「就近第一、宽度第二」）：
     先保整句（截断是最后手段）；本行（上一行 / 下一行的左右也算 0 环）那一圈先于隔行的，
     同一环里一行放得下的空位先于要折两行的，折行相同才比额外引线长度（差一个行高以内算同样近）；
     之后才比方向
     （右上/右下 → 左上/左下 → 正右 → 正左 → 正上 → 正下）；本行最右那条先占正右
     （正右会把它挤成比同档最宽位置更多行时不先占）；右上/右下
     完整挡住右侧批注的上下出线时先走左上/左下；缩进行只让最左那条优先走左侧；
     满行左右页边距可用但排在四个角之后；
  2. **截断档内部同一套顺序**：整句全都放不下时才开截断档（至少 4 字），
     截断候选同样先比环、再比折行、再比就近与方向；所有候选都不行才退成小椭圆；
  3. **同一行多条**：先给最右那条占正右，再从左到右依次计算，但各自独立取位
     （不排成一列、不对齐）；
     占不到的走自己的下一格；别的空位都放不下、挡路的又占着同一块空白时，才请它上下让一让；
     落到这一行上方 / 下方的框（右下 / 右上 / 正下 / 正上）左缘不得越过**左侧那条批注第二个字的
     左缘**，也就是左侧那条第一个字的下方（或上方）始终空着，它的引线才接得进去；
  4. **标注本身占空白**：已放好的旁注框进障碍表，后面的标注不重叠、不紧贴；
  5. **标注不能紧贴文字**：留白只剩两档——空间够时正侧与正上 / 正下都留 **1em**，不够只收
     远离正文一侧到 **0.1em**，再不够就换位置；近侧一律不压：正右 / 正左 / 正上 / 正下守住 1em
     （引线从这里出去），**正上 / 正下推不出这 1em 就宁可不用这个方向**；四个斜向反过来，
     近侧固定 2px、横向特意错开一个字——那一个字是 L 形引线的走廊，不是摆放留白；
  6. **空白里怎么取位**：贴住锚点行 / 角——正右垂直居中于该行、右下 / 右上以末行第一个字
     右移一个汉字为基准、左下 / 左上以末行末字符左移一个汉字为基准，四个角上下贴该行行盒边
     留 2px；正上 / 正下横向与锚点对齐、离字墨迹 1em；贴不下才在空白内挪；
  7. **最少可读量 4 个字**：截断档也至少 4 字；不到 4 字或整页确实没空白时，退成原文右下角的
     0.5em 小椭圆（不画箭头，不参与其他标注的避让）；
  8. **框宽按字体 / 字号 / 行距 / margin 综合计算**：先算整句所需宽度，再看空白扣掉 margin
     后够不够；够就单行、按文字宽收窄，不够才按可用宽折行并得到行数与高度。
- **每条旁注配一条箭头**指向它的原文（§6）：
  - **只画横线、竖线与折线**（不画斜线、不画弧线），两端严格垂直于框边：
    - 先定终点：指向**离框更近的那一头**——比一比框到选区开头（首字左上角）与选区末尾
      （末字右下角）的距离，近开头就指首行起点、近末尾就指末行终点；单行选区看框中心落在
      这一行的左半还是右半，左半指行首、右半指行尾；正下 / 正上指向最近的字的对应边；
    - 再沿框边找能对齐的出口：上下左右摆法能画直线就画直线，不通才一折 → 两折 → 三折 → 四折绕开；
      **四个斜向必须画成 L 形两段折线**——从框的侧边横着出去，沿横向错开的那一个字走到选区角
      外侧，再竖着进字下 / 字上；不许变成贴着框的一条单线，也不许为了凑空档把批注推远；
  - **两端必须接触**：起点落在标注框边界上、终点落在锚点字墨迹边界上，**中间不许留缝**；
  - **起笔端朝正文那一头**：标注在右侧时从左侧（头部）起笔，在左侧时才用右缘；
  - 避让用的是**逐字墨迹**，不是整行行盒：线段不得进入字的墨迹，但**可以从两个字之间、
    标点前后的空白穿过**；图形、表格框线、线条、其他标注框同样要避；
  - **箭头必须画**：唯一例外是小图标形态。直线 / 一折 / 两折 / 三折 / 四折全撞时，
    取「穿得最少、最短」的一条照样画，**不返回空**；
  - **只避那四类障碍与标注框**：从块底色、`padding`、`margin`、页边距上穿过是允许的（那里本来就是空白）；
  - 箭头颜色 = 该条标注的墨色（将来可被「批注样式」覆盖，见 D-29），线细、箭头小；
    箭头画在旁注框之下（同一覆盖层里先画线后画框）。
- 旁注与箭头都是**纯覆盖层**：只读行几何、图版/表格/线条几何与页面位移，不进分页、不进栅格、
  不触发重排。**翻页动画期间跟着页走**（2026-11-01 用户定口）：当前页的旁注与页画布放进同一个
  滑动槽、共用同一平移量滑出去，目标页的旁注同理滑进来，落地那一刻不再「原地消失又出现」；
  早期实现是整层在动画期间让位、落地才冒出来，观感闪一下，已废。封面 / 卡片期间仍然让位
  （与选区覆盖层同口径）。
- 点旁注框或小省略号图标 = 打开这一条（键盘 + 操作栏，带出原文字）；点箭头不额外响应（箭头不可点）。

#### 4. 点按与滑动：点按避开标注/链接，滑动照常翻页

- **单击已有标注（高亮 / 划线墨迹）或旁注框 = 直接打开键盘 + 操作栏**（带出这条记录的颜色与批注），
  不再需要长按；长按同一条记录保留同等效果（不删）。**单击链接 = 跳转**。
- **点按要避开标注 / 链接区**：三区点按（左翻 / 中间切栏 / 右翻）只在按下点**不落在**标注墨迹、
  旁注框或链接上时才成立；落在它们上面的一记「点按」归它们（打开操作栏 / 跳链接），不翻页。
- **滑动不受此限**：点击与滑动本来就能分开（现有判据就够——越过 tap slop 即滑动，
  未越过且时长在阈值内才算点按）。所以**从标注 / 链接区起手也可以滑动翻页**：
  一旦判定成滑动，标注与链接一概不触发，照常翻页 / 切栏 / 调亮度。
- 判定口径：
  - 归属只在**按下点**判一次，抬手点与途经点都不参与；
  - 按下点在标注 / 链接上 ⇒ 先记成候选：抬手时**没动过**（点按）就打开 / 跳转；
    **动过**（滑动）就什么都不打开，按滑动处理；
  - 滑动途经标注或链接区 ⇒ 一律不触发（与按下点在哪无关）。
- 现有实现要改两处：链接命中从「抬手点」改成「按下点」；标注命中从「只有长按」扩到「点按 + 长按」。
- 有选区时点按正文 = 清选区（沿用 D-11）；点标注则先清选区再打开那一条。
- 这条规则也是「操作栏必须贴在键盘上方」的理由：打开操作栏的那一下点击就发生在标注本身，
  卡片不能反过来盖住它（第 2 部分的整页上顶来保证这一点）。

#### 5. 与既有决策的关系

- D-26 的附件模型、`note` 列、清单筛选**不变**；D-27 的输入条**保留**，只是挪到操作栏下面。
- 浮动菜单里「取消」早已去掉，这次连「弹窗」本身也去掉：操作栏是阅读页的一部分，不再有锚点。
- 仍然**不改排版**：整页上顶与旁注/箭头都是覆盖层与绘制位移，`Paginator` / 分页表 / 磁盘表一概不参与。

#### 6. 已确认（2026-10-22 全部定案，无待确认项）

1. **滑动从标注 / 链接区起手照样翻页**；只有「点按」必须避开标注 / 链接区（点按归标注 / 链接）。
2. **旁注行数不设死上限**：按当前空白区能放几行就放几行，空间足够就整句显示。
3. **「空白」只排除文字、图形、表格、线条**：块底色（`blockquote` / `div` / `pre` 的非文字区）、
   `margin` / `padding`、四个页边距一律算空白。
4. **批注样式设置**后续要在设置面板里加（字体 / 字号 / 颜色等），见 **D-29**。
5. **线型按钮**：先选中线型，点色槽或 `确定` 才落笔（不改线型就关卡片的老行为作废）。
6. **`修订`**：v3 起已接正文修改——有选区即可点、进入正文修订卡，不再是占位。
7. **批注样式（D-29）排在交互收口之后**：作为独立小步做，不阻塞本轮。


### D-29 批注样式设置（字体 / 字号 / 颜色等，用户点名要加，期数待定）

- 需求（2026-10-22）：「后面要在设置面板中添加批注样式设置界面，用来设置批注的字体、字号、颜色等内容。」
- 设置项（读者可调 ⇒ 存 `ReaderSettings`，不进主题、不进 CSS 级联）：
  - **字体**：旁注文字的字体族（默认沿用正文/系统默认，可另选已安装字体）；
  - **字号**：旁注字号（默认 = 正文主字号 × 0.72，可单独放大缩小）。滑条**按字号走 0.1 一档**
    （存盘仍是倍率，正文字号变了旁注等比变）；按倍率给 0.1 档时读者看到的数字一跳 1.3，等于没有细档；
  - **颜色**：旁注文字色（默认沿用正文墨色；也可选「跟随所属标注的墨色」）；
  - 顺带可放：底色浓度 / 边框显隐 / 是否显示箭头（默认全按现状）。
- 生效范围：只作用于**旁注覆盖层**（文字、底色、边框、箭头），**不碰排版**——旁注本来就不进分页、
  不进栅格；改了样式不重排、不重烤页位图。
- 存放：与「笔记」并列的读者设置；老存档缺键走默认值（= 今天的样子），不需要迁移；
  将来若要按书覆盖，再进 `PerBookSettings` 白名单（与标注偏好同口径）。
- 落地位置：设置面板新增一页「批注样式」，共享 Compose 自绘（CMP 没有现成取色器，沿用 D-21 的做法）；
  `NoteBubbles` / 箭头绘制从设置读样式，纯覆盖层。

### D-30 卡片与键盘当作一块整体进出（2026-11-03 用户点名）

- 需求：「键盘和笔记菜单弹出时分两段，先菜单、再键盘。能像顶端的系统状态栏 + 标题栏那样
  组合成一个整体，一次性滑入 / 滑出吗？」
- 病根（实测，不是猜）：阅读页是 `adjustNothing`，系统**不派发静态 IME insets**——
  `WindowInsets.ime` 恒为 0（`imePadding()` 等于没写），值只在键盘动画**结束**那一刻才跳一次。
  于是旧行为是：卡片先弹在屏幕底下 → 键盘升上来把卡片盖住 → 键盘升完、insets 跳到终值，卡片再跳上去。
- 定形（**第 2 版，2026-11-03 当天复盘后改**：第 1 版仍被读者判「还是两段」，见下）：
  1. **键盘高度只有一个来源**：宿主（Android 阅读页）`WindowInsetsAnimationCompat` 动画回调的逐帧值，
     经 `ReaderScreen(imeInset = …)` 进来；卡片位置 = 屏幕底 − 键盘高度，**不再吃 `imePadding`**。
  2. **卡片位置 = 屏幕底 − 键盘高度 + 卡片高 ×（1 − 升起度）**。升起度 0 = 整张卡片在屏幕下沿之外，
     1 = 卡片贴住键盘上沿。这样在升起途中，卡片的上沿永远在键盘上沿之上「卡片高 × 升起度」处，
     下半截一直压在键盘底下——看上去是从键盘后面长出来，键盘落回去时被它一口吞掉。
  3. **起步时刻绑定键盘**（第 1 版就是栽在这里）：光标落进输入框后宿主才叫键盘，键盘窗口要过几十毫秒
     才开始升。第 1 版让卡片自己先滑 200ms（`AnimatedVisibility`），读者看到的就是「先弹卡片、
     再顶键盘」。现在升起度**等键盘真的开始升（逐帧值离开 0）才起跑**；等不到（外接实体键盘、
     桌面、读不到逐帧值）最多等 200ms 就自己走，不会把卡片卡在屏幕外。
  4. **页面让位跟着升起度走**：卡片还在屏幕外时页面不动，卡片冒多少页面才让多少
     （否则先跳一下、再等卡片，又是一处两段）。
  5. **收起时先失焦**（`LocalFocusManager.clearFocus()`），键盘与卡片同一段时间里各自归位；
     不失焦的话键盘会等卡片卸载才开始降，又变回两段。收起时卡片同时淡出（卡面在那一刻已经清空）。
  6. 键盘被系统自己收起（键盘上的收起键、返回键先消键盘）时卡片**不跟着走**：落在屏幕底边继续可写。
     「一起进出」只约束卡片先退的那条路。
  7. 平台差异留在宿主：Android 11+ 逐帧给值；桌面没有软键盘、Android 10 及以下没有逐帧回调，
     传 null 退回系统 insets（= 旧行为）。

### D-31 正文修改 = 「原书坐标的修订表」，载入时套到章树副本上（2026-11-07）

- 一条修订 = 原书章内字符区间 `[charStart, charEnd)` + 替换文本；同章内**互不重叠、按起点排序**。
  它和标注（D-1）用同一个坐标空间：都相对原书解算，换字号/边距/主题/旋转不影响。
- 载入一章时，把该章的全部修订应用到**章树副本**上再排版；**原树和结构缓存不写回**
  （否则下次载入会在已经改过的树上再套一遍）。磁盘上仍然是导入时那一份原树，修订是独立的覆盖层。
- 为什么不用「按编辑先后串起来的脚本链」：链里每一步的偏移属于它之前那个空间，
  删掉或改动中间一条，后面全部失效；原书坐标的修订可以任意增删（撤销、审阅视图都要靠它），
  载入时一次扫描就能重放。代价是「改已经改过的文字」要做一次区间合并（见 D-33 末条）。
- 修订主要改文字；跨段时**可以合并 / 拆分段**（D-34），但表格行不拆。段数不变时排版叶集合与
  结构缓存里的叶路径仍然成立，只需按叶的文本长度增量修正字符起点；段数变了则由载入重放一次性
  重建受影响的那几个块，叶表与起点跟着增减。

### D-32 两个坐标空间：原书 / 渲染，落盘锚点一律存原书（2026-11-07）

- **原书空间** = 不含修订的章文本；**渲染空间** = 应用修订之后的章文本。
  排版、分页、`PageSlice`、选区、`textOf`、标注装饰、页内命中都在渲染空间。
- **落盘的用户锚点一律存原书空间**：标注区间、阅读进度 locator、修订本身。
  引擎在边界处换算（进章/跳转时原书→渲染，存档/建标注时渲染→原书）。
- 换算表由修订表**纯算术**得到（不依赖排版就绪）：`toRendered` / `toOriginal`；
  偏移落在某条修订的替换文本内部时，夹到该修订的区间边界（不会跑到区间外）。
- 标注被修订完全删掉时，映射出来是空区间：**不画装饰，但记录保留**（清单里仍能看到原文摘录）。
- 老数据（没有修订）两个空间完全相同，不需要迁移。

### D-33 修改只替换「真正改了的中段」；新文字按原元素逐段保留样式（2026-11-07 用户定口）

- 输入区是纯文本。提交时先求「旧选区文本」与「新文本」的公共前缀/后缀，**只把中段换成新文本**；
  没改到的前后文（以及它们所在的行内元素、类、样式）原样保留。
- 中段再与旧中段做**字符级对齐**（Myers diff）：没变的字留在原来的文本节点里，
  新插入的字挂到「它前面那个字」所在的文本节点（中段最前面则挂到第一个文本节点），
  删掉的字从原节点移除。于是 `<em>` 里的字改完仍在 `<em>` 里、`<strong>` 里的仍在 `<strong>` 里，
  每个元素的类与样式**逐段保住**；只有整段换新字（没有任何公共字）时才退化成
  「全部落在中段起点那个元素里」。
- 空掉的行内元素**整个走掉**，不留空壳（`code` 这类带内边距的元素留空会渲染成一小块）；
  书里本来就写成空的元素（没有子节点）不动。
- 中段覆盖 `<br>` 可以编辑（`\n` 与字符流 1:1，替换文本里的 `\n` 落成新的 `<br>`）。
  **行内图片**（`img` 在文字块内部，正文里是一个 `U+FFFC` 占位）跟着占位字走：占位还在就留图
  （图排在原处，前后被改动的字在它两侧），占位被删掉就是连图一起删——不能「字没了、图还在」。
  读者在卡片里看到的就是那一个占位字，删掉它即删掉这张图。
  **生成内容（`::before/::after`、`q` 引号）**被中段碰到时整次拒绝并提示。
  **表格行叶**只改格里的字：格数、表头、`rowspan` / `colspan` 不变就按格重建（提交时随修订
  落一份目标格结构，重放按它把新文字分回各格）；**整块图片叶**（`img` 单独成叶）只许整张删除
  （删掉 `U+FFFC`）或原样保留，换成文字拒绝并提示。
  **整表结构修改**（2026-11-12 补）：卡片触到任一表格行就把选区扩到整张表，读者可以删整行 /
  加整行、删整表 / 加整表、每行增删格、改 `rowspan` / `colspan`——判据只看整张表能否铺成一个
  矩形网格（`TableGrid`：不重叠、不空洞、`rowspan` 不越过末行；0 行 = 删表），文字长短不看。
  落一条修订：区间 = 整张表、`text` 为各行文字直接相接、`editedBlocks` 首行短码用大写 `T`
  （`T…`）标记，重放走整表重建通道（`ChapterRevisionReplay.TableEdit`），不按叶分段落字。
  半张表 / 表格前后还带着段落时不能改结构，只许逐行改字，提示「请只选中这张表」。
- 替换文本按边界空白预归一（叶的 `white-space` 模式 + 前后邻字符 + 节点边界再归一一次），
  保证「渲染文本 = 原文本按区间替换」严格成立，长度增量才算得准（坐标映射与分页都靠它）。
- 字符对齐只在**中段**上做，且带规模上限（中段长度 × 新文本长度超过阈值时退化为单节点插入），
  避免整段长文替换退化成平方复杂度。对齐算法与提交时**必须逐字一致**，所以算法版本号
  参与 `contentRev` 哈希（见 D-35）：算法一改，旧分页表与页数清单自动作废。
- 中段如果碰到已有的修订，把那条修订的区间一起**扩张进来**再整体替换（保留它两端没被选到的文字），
  被吸收的旧修订删除。这样「改自己刚改过的字」不会留下半截重叠。

### D-34 跨行与跨段（2026-11-07 定口跨段；2026-11-08 修订：段数由输入换行符决定；
审阅空间同日晚些改为「原文照排 + 改动就地插入」，见本节末尾补记）

- **折行**天然支持：偏移是字符级，与显示行无关。
- **叶内 `<br>`**：可编辑，`\n` 在输入区和字符流里都是 1 个字符；删 `\n` 即删 `<br>`。
  读者**新敲**的回车不是 `<br>`，而是段界 ⇒ 拆成真块（D-34 修订版）。
- **跨段（v3.0 就做）**：输入区用 `\n` 分隔各段，**结果段数 = 输入里的换行符数 + 1**，
  与选区跨了几个排版叶无关。删光中间的字（输入 0 个换行）就把几段并成一段；输入多行就拆成多段。
  - 例：`<p>正文保留1 正文修改或删除</p><p>正文修改或删除 正文保留2</p>`，选中第一段的后半 +
    第二段的前半（选区里有 0 个换行），输入区删空 → 两段并成 `<p>正文保留1 正文保留2</p>`。
  - 存储的修订文字里，**段界用私用区字符 `U+E000`**（`RevisionBlocks.SEPARATOR`）表示，
    不占字符；`\n` 仍然只表示叶内 `<br>`（算 1 个字）。这样「段界」与「换行」不再二义，
    跨段选区里含 `<br>` 也能一起改。
  - 前缀 / 后缀决定新旧文字的关系：首块 = 首叶前缀 + 第一行，末块 = 最后一行 + 末叶后缀，
    中间各行各占一块；没被用到的叶整块删掉。首块用首叶承载、末块用末叶承载，后缀的行内样式不动；
    拆分多出来的块新建同 tag / 同属性的块（去掉 `id`）。
  - 行数等于跨的叶数时仍走「每叶一条修订」的老路径（保留每叶的行内样式、做公共前后缀裁剪），
    结果与合并路径一致，只是粒度更细。
  - 跨段改段数时**不做公共前后缀裁剪**：裁掉边界上的字会把区间缩回叶内，合并 / 拆分的信息就丢了。
  - 表格行叶、图片叶、匿名文本叶不参与合并；选区碰到又**真要合并 / 拆段**时拒绝并提示。
    提示语按**实际挡路的那一叶**说（整块图片 / 表格行 / 段落之外的零散文字各说各的），
    不再一律推给「选区跨到整块图片或表格」——匿名 run 是最常碰到的那一种，读者看到
    「含图、块」只会以为自己选到了图片。
  - **匿名 run（段落之外的零散文字）没有块可拆**：读者在它中间敲换行，落成这段里的 `<br>`
    （叶内换行），不拆块、也不拒绝。它本来就只有一段，硬按「拆成两块」处理只会被合并规则挡掉。
- 单叶选区里**新敲**的换行是段界（拆成真块，`</p><p>` 或插入点所在的那个标签），不再落成段内
  `<br>`；原文里本来就有的 `\n`（`<br>`）保持原样。两者靠**字符级对齐**分开：能对上前一个
  原文字的 `\n` 是留下来的 `<br>`，对不上的就是读者新按的回车（见补记 2026-11-08）。
- 「添加文字」（没有选区、在某点插入）需要先有光标模式，排到 v3.1。

### D-35 修订让该章分页缓存作废（2026-11-07）

- 分页表头加 `contentRev`（该章修订哈希，0 = 无修订），页数清单每条也加 `contentRev`；
  格式版本升 4，旧表旧清单一次性作废。当前页快照同样加 `contentRev`（schema 升）。
- `contentRev` 的输入 = 该章修订表（按起点排序的区间与文本）+ **重放算法版本号**；
  重放算法一改，哈希自然变化，不会拿旧版式配新文字。
- 提交修改：清掉该章解析态（树/结构/版式/当前页快照）、删该章磁盘表（所有参数指纹）、
  把该章从页数清单里摘掉；重排完再把新的页数填回去。在途的后台任务用 `contentRev` 挡住旧结果落盘。
- 只影响被改的那一章：其他章的表、清单条目、页码都不动。
- 2026-11-08 补记实际口径（D-40 审阅视图的教训）：**页数清单文件**仍是「一本一份」、文件头只记
  整本版本，但内存里的每条页数结论按**章级版本**认领（[章号, 章内容版本]）。所以切审阅视图
  或改一章时，只有版本对不上的那几章算「未知」，由定点补排按章补上；不必整份作废重扫全书表头
  （那会让页脚在扫完前退回百分比）。分页表本身一直是章级 `contentRev`，两个视图互不覆盖。

### D-36 修改入口与输入控件（2026-11-07 用户定口）

- 选区菜单里的修订按钮**文案保留「修订」**（不改成「修改」），有选区才可点。
- 输入区**复用批注输入区同一个控件**：把 `AnnotationSheet` 的卡片外壳 + 输入字段 +
  键盘逐帧高度 / 升起度 / 返回键取消机制抽成共享的底部输入卡，批注与正文修订都用它。
- **正文修改与高亮、划线共用同一根操作栏**（不另起「修改正文 / 取消 / 确定」那套）：
  - 「修订」标为当前项（垫底、不再响应点按）；
  - 左边的「高亮 / 划线」留着可点——点它就**切回该类别的批注**（保留选区，只丢掉还没提交的输入）；
  - 色槽整排**不显示**，线型也不出现（修改模式下没有落笔颜色这回事）；
  - 「删除」与批注同义：删掉**覆盖这段字的修订**、把那段恢复成原文；这段没改过时它是虚的

    整张表 / 表里的一行）时，读者把选区挪到别处 ⇒ 卡片按新选区重开，「删除」随之回到虚态——
    它只对着手上选着的东西亮，不顺着先前的目标一直亮着；
  - 「复制」复制选区文字，「确定」提交修订；**取消仍是点卡片外 / 返回键 / Esc**（落笔只认确定）。

  贴近屏幕顶端，**上方留三行**给读者点卡外取消（这张卡没有「取消」按钮）；
  再多的内容在字段内部滚动，不再固定 8 行。

  照旧（越界的那头收进新文字里），读者接着打字还是替换原来选中的地方。
- 确定后：页界没变（各段行数不变）就不重排，读者停在原页；页界变了才重排，

- 失败（含换行的跨段、碰到整块图片/表格/生成内容、库写失败）就地提示，不改正文、不重排。
- **不做 undo / redo**（用户定口）。
- **补记（2026-11-08 用户定口）：点按改动痕迹 = 直接开卡改它。** 审阅视图里点按红字（删掉的原文）
  或绿字（新添的文字），与点按已有标注同义：直接弹出修改卡与键盘，选区恢复成这条修订的整段
  （审阅空间：原文 + 新文字），输入区带出改后的文字；点红字或点绿字落到的是同一条修订。

  点一下改过的字（命中口径同样是「落在某条修订的整段里」）就打开修改卡。
  判定按字符区间、只看本章内存修订表，不做几何反查；页边距上按不到行，不会误开。
  放在点按标注之后：同一段字上既有标注又有修订时，先按老规矩开标注卡。
  **例外（表格）**：表格上压着整表修订时，点按只看**真正改动过的字**（红字 / 绿字）——点它照常
  进修订状态、卡片带出改后的内容（审阅视图里按点到的行开行卡片，选区框住点的那一行、不框整张表；
  点的是被删掉的红字行时卡片空白，正文框住那一排红字）；点在表格其他区域（没改过的格、行间空白）

  而审阅空间里那块文字还排着被删的原文，扩块会把旧字写回去。落库口径不变：整段原样提交
  仍会裁回最小修订。

- **补记（2026-11-14 用户报「重选整个标题时输入区不显示匿名块内容」）：区间撑到整段时，
  替换文字也换成整段的当前结果。**
  读者在标题后面那段零散文字（`<h2><span class="sec_num">第十五章</span> 一个不愿意透露姓名的靓仔</h2>`
  里 `display:block` 的章节号之后那一截）里敲了一个 `<br>`，然后在审阅视图里把整个标题重新选一遍：
  输入区里那一段的字一个都不在，只剩「第十五章 / `<br>` / …」。根因是两条尺：落库的是**最小修订**
  （替换文字就是那个换行），而宿主为了「点哪儿都能开卡」把给阅读面的区间撑到**整段**（两端被裁掉
  的公共字也带上）。区间与文字一旦不同尺，凡是「拿这段区间配这串文字」的地方都会错——重选整段时
  卡片按最小文字填，整段没改的字就凭空少掉；直接确定还会把区间里那些没显示的字一起删掉。
  现在宿主发区间时同步发文字：撑段了就把替换文字换成整段的当前结果（`editedText`，即读者上一次
  卡片里那一段的字，由两端公共字与最小修订拼回），没撑段仍是 `text`。落库口径不变（仍是最小修订），
  撑段与否则仍由「反推得出两端公共字、且不碰别的修订」决定。

- **补记（2026-11-14 用户报「审阅模式下应该显示绿色换行符」）：段落之内新加的换行也画绿 ¶。**
  段界（段落之间的换行）本来就有 ¶ 可看，但**段落之内**的换行（`<br>`，以及代码块里的换行）
  是文字流里的一个真换行字符：它在版面里只表现为断行，本身没有字形，标成绿字也看不见——
  审阅视图里读者只知道「这里绿了」，却看不出换行加在哪儿。现在这种「新插进来的换行」在
  断行处上一行末尾补一个绿 ¶，与段界那套完全同口径（占一格、可点按、取文字时跳过），
  换行本身照旧断行。审阅空间的字数变了 ⇒ 重放算法版本升一级（`ALGORITHM_VERSION = 15`），
  有修改的章内容版本随之变化，旧分页表一次性作废。
  **被删掉的换行也补红 ¶**（2026-11-14 用户定口：「当然要补呀」）：断行本身没有字形，红字同样
  看不见，所以删除时也在断行处补一个红 ¶（与删段界同口径：红字 + 删除线、可点按、取文字跳过）。
  那个换行本身留在原处——审阅空间「原文一字不删」，删掉的字都原地留着标红，它一样；红 ¶ 就是
  「这里原来有一道换行、已经删掉了」的记号。正文、标题、引用、代码块一律如此（按字符走，
  不看块是哪种），不存在「只在段落里补、标题里不补」。

- **补记（2026-11-14 用户定口「用户拖到哪里，下次还是显示哪里」）：整段选区显式落库。**
  落库的仍是**最小修订**（两端没改的公共字照裁，改一个字只动一个字），但从这次起，提交时把
  读者拖出来的**整段区间**（原书空间）一并写进修订里（样式列的可选键，老版本忽略、老数据没有）。
  重开修改卡时正常视图按它换算渲染区间、审阅视图按它换算审阅区间，卡片带出整段的当前结果；
  不再靠「原文 / 新文字」两行去反推两端被裁掉的公共字——跨段（原文按段插 `\n`、修订文字用段界
  字符）、空白归一、带着旧修订提交时反推都会差一两个字，一退回最小修订，选区就缩小 / 偏位。
  没有这个键的老数据仍按反推兜底，行为与修复前一致；整段原样重新提交会裁回同一条。
  清单行摘要的两端公共字也优先用它，不再各自反推一遍。
  另外，**卡片开着时拖手柄只挪落笔范围**，不再把选区弹回修订整段（选区停在读者拖到的地方）。

### D-37 修订卡片的纠错候选词（2026-11-21 用户定口）

- 修订模式下色槽整排隐藏，`修订` 右边本来空着：这块空白用来列**当前选区**在纠错词典里的
  正确候选词，绿色文字（与审阅视图「新写进去的字」同一支绿）。
- 只认**整词精确命中**：选区正好等于词典里的词（如「的」）才出候选，多一个字、少一个字、
  带标点都不算。不做模糊匹配、不做上下文判断——猜错上下文会把对的字改坏。
- 候选词是**同音族里除它自己以外的词**（如「的」→「地」「得」），顺序按词典里写的顺序。
- **选区一变，候选跟着换**：拖手柄 / 重选后按新选区重算；选区不是整词时这一行不出现。
- **点一下就提交**：把选区那几个字换成该候选，直接落库、重排、收卡，不用再点 `确定`；
  只替换选区本身，不读输入区里读者还没提交的手工改写。
- 词典收的是拼音输入法最常见的同音 / 近音错词族，纯数据 + 纯函数，增删词只改一处表。


## 3. v1 交互规格（提案，实现前定稿）

> 下面这些是配套的量化细节，方向已认可，具体数值可在实现时微调。

### 3.1 长按与手柄

- 长按时长用系统的 `longPressTimeoutMillis`（Android ≈500ms），不自造。
- 长按后**手指不抬起、直接移动 = 扩选**；**抬手 → 出菜单 + 显示两端手柄**。
- 手柄：视觉圆点 ~12dp，**命中范围 ~44dp**；贴在选区首 / 末行下缘；贴屏幕边自动内移。
- 长按选中的单位按 D-7（英文词 / 中文句）。
- **拖动起点 = 长按那个字**：整词 / 整句只是「抬手不拖」时看到的样子；手指一动，锚点就挪到
  按下那个字，之后按字符跟手指走。否则从行中往右拖，选区会变成「句首（常是行首）→ 手指」。
- **跨页时手柄只画落在当前页的端点**：另一端在别的页就暂不显示（翻回去即出现），
  **不画贴边的假手柄**；正在拖动的那个手柄永远在手指所在页。
- 手柄拖动按**字符**微调（长按起手才按 D-7 的整词 / 整句）；跨页后仍按字符继续。
- **当前落地**：长按立即出选区与两端手柄；抬手后出浮动菜单；手柄拖到左右页边会自动翻页并接力，
  到章首/章末停住并提示；长按与拖手柄期间会显示移动端放大镜。

### 3.2 浮动菜单

- v1 项：**高亮 / 划线（切类别）/ 复制 / 删除**（批注 v2 再加）。
- **一步到位**：打开即摊开**上次用过的类别**的色槽行，点一格颜色就落笔；
  顶部的高亮 / 划线只用来换类别（不再是「先展开色槽」的第一步），因此按钮上不需要类别色小圆点。
- **只有一套菜单**：新建（选区抬手）与编辑（长按已有标注）共用同一个弹窗，
  差别只在初始类别（编辑时用该条自己的类别）与删除是否可用。
- **不设「取消」项**：点菜单外面即关（长按场景有透明遮罩，选区场景由正文点按清除选区）。
- 删除：有可删记录（长按命中的那条，或选区与之相交的第一条）时才亮，否则虚掉且点了没反应。
- 位置：选区上方；贴顶则放下方；跟随选区变化。
- 阅读层目前零 `Popup` 使用 ⇒ 需确定用 Compose `Popup` 还是自绘覆盖层（与栅格层同制）。
- **当前落地**：自绘覆盖层（不用 `Popup`）；色槽行常显（正在用的那一格外面套互补色 + 灰半透明双圈，
  编辑时是这条记录的颜色，否则是上次用的那格；全栏只有这一种选中画法，不再有金边），
  点一格就用该格当时的 ARGB 快照创建（编辑时则改该条）并立即落库，
  同时把「类别 + 该格」记进设置（下次打开停在这里）。
  复制走整章原文并在块边界补换行（编辑时复制该条覆盖的原文）。

### 3.3 跨页自动翻页

- 触发带按**正文缘**算：手指越过正文左 / 右缘再往外 8dp 才进带（不是距屏幕边 24dp）。
  边距小的书（滑块最小 0）因此不会「拖到行末就翻页」；页边距窄到放不下 8dp 时，
  退回屏幕最外 12dp 的保底带，零边距的书仍能跨页。
- 进带并**持续 ≥ 350ms** → 翻一页。**一次进入只翻一页**：翻完必须退回正文区（回差 6dp）
  再进带才会翻下一页。早先是「按住不放每 400ms 再翻」，读者停在页边等选区跟过来、
  或只是沿着页边往下拖，就会被连翻两三页。
- 翻页**瞬切**（D-12），且**等目标页就绪再继续**（栅格 ~0.2s，不等会白一帧）。
  翻页没成（邻页未就绪 / 导航被丢弃）时每 200ms 重试，成功即停。
- 翻页**必须走现有导航漏斗**（与链接跳转 / 目录跳转同一条提交路径）：
  位置提交后照常保存进度、按总则启用本章临时表 / 切换磁盘表。
  **不要**直接调宿主翻页查询口——那条口是只读的，推进指针会多翻一页（已有真机事故记录）。
- 到章末 → 停住（D-8 不跨章），并给提示（见 3.5）。
- 拖选手指落在正文左右边距里时，焦点先贴到该行靠边的字（右缘取行末、左缘取行首），
  再按触发带翻页；不再「选区冻住、翻页时一次性跳一整页」。
- **当前落地**：按正文缘 8dp 触发带 + 350ms 首次延迟、一次进入一页；
  翻页后手柄按手指 y 接到新页最近行的靠边字；到本章首/末页停住，选区封顶到边界并提示。
  真机已验证向前连翻两页、接力与章首停住；章末向前停住走同一套边界判定。

### 3.4 放大镜（移动端）

- 圆形，直径 ~96dp；倍数 ~1.5x；中心悬在手指**上方 ~56dp**；贴屏幕边自动内移。
- 内容复用页栅格位图放大绘制（`PageRasterStore.obtain`），**纯用户层**。
- 出现时机：长按开始 + 拖手柄时（跟随当前拖动的手柄）。
- 卡片让位（整层上推）时，指针给的仍是**屏幕坐标**：手指与可见区都换算进同一层再算圆心，
  镜面才跟得住手指（2026-11-01 真机：不换算的话，页面一让位镜面就离手指差一整段让位量）。
- **当前落地**：`SelectionMagnifier.kt` 把同一页内容再画进圆形裁剪层并做 1.5 倍图层缩放；
  渲染器实例与 `PageContent` 都和当前页共用，命中现有页位图缓存，不重烤、不重排版。
  位置由纯函数 `magnifierCenter` 计算，贴顶翻到下方、左右上下内移；桌面鼠标不显示。

### 3.5 其它

- 章末停住提示：移动端轻触感；桌面一句 snackbar。
- 复制：内容 = 选区章内区间的**原文**（跨样式不带格式）；走 **D-18 的章节文本**，
  **不要**拼 `DrawLine.text`（行片段会漏字 / 重字）。块与块之间在复制结果里补换行，
  但换行不参与标注偏移。另需**剪贴板 expect/actual**（全仓目前零剪贴板代码）。
  复制后保留选区并提示「已复制」。
- 桌面键盘扩选（Shift+箭头）v1 不做。
- 高亮默认以 **~45% 不透明度**铺背景（荧光笔感）；划线粗细 / 位置刻意与书内下划线错开
  （更粗 ≥0.08em、更靠下），避免与书自带的线糊在一起。

## 5. 落地接线要点（实现前先定）

> 前面写的是「做什么」，这一节是「接在哪」。这几条不定清楚，写下去必返工。

### 5.1 装饰 run 怎么进到页里（分层关键）

- 数据流：DB → 宿主 → `shared-ui`（共享）→ **引擎的纯投影函数** → `DrawLine` 上的装饰 run。
- **投影必须在 `engine-skia`**（`LineAligner` 是 internal，`visibleSpan` 是唯一「区间 → 几何」入口）；
  但**取数据与调用点必须在 `shared-ui`**（commonMain，三端共享）——
  **不能**让宿主（平台侧）去投影，否则 Android / 桌面各写一遍，违反 KMP 共享约束。
- 落点：`rememberPageContent`（`PageContent.kt:87`）里，`host.pageLines(pos)` **保持原样记忆**，
  在其后**另加一步投影** `remember(rawLines, 本章标注列表, 装饰修订号)`（标注列表与修订号由
  `shared-ui` 自己持有，见 D-19 / §5.4）；`rememberPageContent` 因此要新增这两个入参。
  后面所有消费 `lines` 的地方（栅格 spec、`pageFrameLead` 等）改用投影后的行。
- 栅格失效**自动**：`PageRasterSpec.fingerprint()` 按值比较 `lines`（`DrawLine` 是 `data class`），
  装饰 run 一变即未命中重烤 ⇒ **不需要动 `contentRevision`，也不需要平台壳配合**。
- 预栅格同章邻页也走同一投影；跨章目标页**同样投影**——相邻两章的标注已由阅读面在
  进章时预读（见 D-19），投影一律按「这一页属于哪一章」取那一章的列表，绝不拿当前章的
  区间去投别章的字（`宁缺勿串`仍成立：那一章还没读回来就先不投，读回来即补上）。
- `DrawLine` 要新增一个装饰 run 字段（默认空）——这会改变它的值相等，正好是上面重烤的判据；
  旧构造点不传即行为不变。

### 5.2 引擎需新开的公开 API（渲染层）

- `projectDecor(lines, chapter, ranges) -> lines'`：把章内区间合进每行的装饰 run（烘焙用）。
- `decorRects(lines, chapter, range) -> List<Rect>`：只算几何、不画（拖拽覆盖层与手柄定位用）。
- 已落地：`DecorProjection.kt` 定义 `DecorKind` / `DecorRange` 与 `projectDecor`；
  `LineWindowDrawer.decorRects` 是几何入口（`Rect.x` 相对内容区左缘，`y` 为章节绝对 Y）。
  `DrawLine.decorRuns` 存**章内全局区间**，绘制侧按 `charBase` 换回行文本坐标；高亮底色在
  文字之下、书内行内盒之上，划线在文字与书内装饰之后（默认 `0.08em` 粗、基线下 `0.20em`）。
- 两者都复用 `LineWindowDrawer` 既有的 `aligner.visibleSpan(placement, n, ps, pe)` 路径
  （`LineWindowDrawer.kt:427/513/654`），保证**命中 / 绘制 / 装饰三者同一份几何**。
- **「点 → 章内字符」不另开引擎口**：复用现成的三步
  `ReaderMath.tapLineAt`（屏坐标 → 行）→ `LineHitTest.hit`（行内字形）→ `DrawLine.charBase`（章内偏移），
  在 `shared-ui` 收成一个 `charOffsetAt(...)`。**不要**另写一套反查几何。
- **页坐标换算抽公共函数**：`shift = pageAnchorY(行/图/背景/页首缺口) - 内容顶`。
  画布、链接点按、选区覆盖层、手柄、放大镜共用同一个 `pageShift(...)`；
  现状画布与链接点按各算一遍，第三次再抄必然漂移（链接点按有过整页偏移的事故记录）。

### 5.3 放大镜要拿到当前页位图（需要提权）

- 页位图现在**私有在 `ReaderPageCanvas` 内的 `PageRasterStore`**（由 `rememberReaderPageRenderer()`
  持有），`ReaderScreen` 拿不到。
- 放大镜**必须复用当前页已烤好的位图**（每帧重烤一页 ~0.2s，不可行）。
- **最终实现（不改接口）**：`SelectionMagnifier` 把同一页的 `PageContent` 和**同一个**
  `ReaderPageRenderer` 交给一个全屏 `ReaderPageCanvas`，外层只做圆形裁剪 + 1.5 倍
  `graphicsLayer` 缩放。`ReaderPageCanvas` 的 `renderer.drawLines` 会命中渲染器现有的
  `PageRasterStore`，因此像素与静止页同源，也不需要在 Android 侧每帧把 skia 图转成
  `ImageBitmap`（那会多一次整页拷贝）。代价是放大镜组合里多一层全屏画布，但绘制仍是一张
  缓存位图，不是重烤。

### 5.4 标注数据怎么到 shared-ui（D-19 落点）

- `shared-ui` 是 commonMain，可以依赖 common 的 `LibraryDb`；但 db 实例在宿主手里。
- 沿用现有模式（如 `onSaveProgress`）：**扩展 `ReaderHost` 的四个后台口**——
  「读本章标注 / 增 / 改 / 删」，宿主转手给 `LibraryDb`（实现集中在 common，平台侧只是转发）。
- **当前章列表由 shared-ui 持有**（D-19）：进章时读一次，放进 Compose 状态；
  增删改先改这份内存列表并递增装饰修订号，再异步落库（失败回滚 + 提示）。
  投影、长按命中、画覆盖层都读这份列表，**不查库**。
- 新增**同步**章节文本口（D-18）：`textOf(chapter, start, end)`（复制 / 选词 / 断句共用），
  与 `pageLines` 同级、开章时已缓存；**不要**做成异步。
- 长按查已有标注：直接在这份内存列表里按「章号 + 字符区间」找
  （`charStart <= off && off < charEnd`），**无需几何反查、无需查库**。

### 5.5 剪贴板平台缝

- 实际落地：使用 Compose Multiplatform 的 `LocalClipboardManager`，共享层直接取用，
  Android / 桌面各自平台实现由 CMP 提供；**不需要**再新开一套 `expect`/`actual`。
- 复制内容仍走 D-18 的整章原文，块间补换行只进剪贴板，不参与标注偏移。

### 5.6 手势状态机的改造原则（风险最高）

- 现有手势块是**长期调优过的**（`ReaderScreen.kt:828` 起，注释里记着多起「点了没反应」
  「快速闪一下」的历史缺陷），且已有单测（`ReaderLogicTest`）。
- 原则：**新增分支，不重写**。长按只加一条「未移动 + 超时」的旁路；
  手柄做成**覆盖层独立手势区**，避免主状态机去懂多指。
- 互斥守卫（D-12）**复用**现有的会话繁忙判定（`ctl.isBusy()`），不另立状态。

### 5.9 颜色槽的存储（D-13 落点）

- 存 `ReaderSettings`（全局记忆，`settingsDir/reader.json`）；每本书另有一层私有快照
  （见下），与书无关的只是全局记忆本身。
- 读取是**手写 `opt*` + 默认值**（`ReaderSettings.fromJson`；`SettingsJson` 为
  `ignoreUnknownKeys` + `encodeDefaults`）⇒ **老存档缺键即取默认**，
  故新增色槽字段**不必强制 bump** `CURRENT_SCHEMA_VERSION`（现为 1）；
  只有当需要**改造旧值**时才 bump（先例：`migrateCjkLatinSpacing`）。
- 色槽形态建议：每类 4–5 槽，各存 ARGB `Int`（含 alpha）；另有「默认槽索引」。
- **当前字段**：`highlightColorSlots` / `underlineColorSlots`（各 5 个 ARGB `Int`）与
  `highlightDefaultSlot` / `underlineDefaultSlot`，另加浮动菜单的「上次类别」
  `annotationLastKind`（`highlight` / `underline`）与「上次线型」`annotationLastLineStyle`
  （`straight` / `wavy` / `dashed`；旧版的 `strike` 已移除，读到按实线）；六者都登记进 `withoutNonLayout`
  （只改像素、不触发重排），设置面板的改色行走无重排提交。
  读取用 `SettingsJson.optIntList`：缺键/非数组取默认，短列表补齐、长列表截断到 5 格；
  默认槽索引越界自动钳到 `0..4`；上次类别未知值一律按高亮。因此老存档不需要迁移。
- **全局项 + 每书稀疏覆盖（2026-10-29 定口，取代 2026-10-28 的「按书 + 全量快照」）**：
  笔记页的所有设置项——色槽四件、上次类别 / 线型、批注字体 / 字号——**都是全局项**，
  与某本书无关（读者印记），只存 `settingsDir/reader.json`，换书不复位；
  它们照旧登记进 `withoutNonLayout`（只改像素、不触发重排）。
  本书私有层（`settings/books/{bookId}.json`）只收**私有项**（排版/字体槽/开关族），
  且是**稀疏**的：只记「和本项目预设不同」的项，读者把某项改回预设，该键即消失。
  全局项**不再写进本书文件**，「改了传染全局、新书继承」这条通道已整条删除。
  完整口径与字段归属表见 `docs/设置模型整改计划.md` §1 / §3.2；
  新增字段先判归属（全局还是私有），归属由 `SettingsScope` 与 `SettingsPersistenceScopeTest` 锁住。
- **旁注样式（2026-10-28）**：`noteFont`（字族名，空串 = 采用正文字体：正文槽挑过的族，
  或排版主题给正文的通用族 / 读者的通用族替换；「原书设置」下正文听书，覆盖层退回系统默认）、
  `noteFontWeight`（100..900，0 = 跟随字族自身默认）与
  `noteFontScale`（相对正文旁注默认字号的倍率，1 = 默认，0.5–2.0）只作用于盖在页面上的
  旁注层，**不进分页**，因此登记进 `withoutNonLayout`；落盘口径同上一段（纯全局）。
  字重没有按族记账：换字族即清回「跟随字族默认」，免得新族套着上一个族的粗档。
  存倍率而非绝对像素，是为了正文字号一变旁注等比跟随（不会「正文调大了旁注没动」）。
  字族名由两端壳经 `shared-ui` 的 `noteFontFamilyOf` 解析成可绘制字体（导入字体按文件、
  系统族按族名，字重原样透传），解析不到就回界面默认——批注照样能读。

  竖线空档，推不出就宁可不用这个方向，名次排到四个角、正右、正左之后；四个斜向反过来——

- 2026-10-29 **让位以后可以另找更近的位置**：让位 / 自己滑开得到的那一格不再当场定案，

- 2026-10-29 **布点改为「整句 + 就近 + 宽度」，环数退到后面**（取代 2026-10-27 的「环数绝对第一」）：
  截断再也不能靠「环数近」抢在整句前面；整句之后先比就近（差一个行高以内算同档），

- 2026-11-03 **D-30 复盘改版（用户复报「还是分两段」）**：真机再看，第 1 版仍会先弹卡片——

### 8.2 数据模型

`text_revisions` 表（新增 `TextRevisions.sq` 与迁移 `10.sqm`；`11.sqm` / `12.sqm` 补清单两行，当前库版本 13）：

```sql
CREATE TABLE text_revisions(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  bookId INTEGER NOT NULL,
  chapter INTEGER NOT NULL,
  charStart INTEGER NOT NULL,      -- 原书空间，含
  charEnd INTEGER NOT NULL,        -- 原书空间，不含（= charStart 表示纯插入）
  text TEXT NOT NULL,              -- 替换文本（空串 = 删除）
  originalText TEXT NOT NULL DEFAULT '', -- 清单上行：改之前的整段选区
  editedText TEXT NOT NULL DEFAULT '',   -- 清单下行：改之后的整段文字
  delta INTEGER NOT NULL,          -- 渲染后长度 − (charEnd − charStart)
  groupId INTEGER NOT NULL,        -- 同一次提交的多条修订共用（跨段；审阅视图按组显示）
  createdAt INTEGER NOT NULL,
  updatedAt INTEGER NOT NULL,
  CHECK (charStart >= 0),
  CHECK (charEnd >= charStart)
);
CREATE INDEX text_revisions_by_book_chapter ON text_revisions(bookId, chapter, charStart);
```

- 同章内 `[charStart, charEnd)` **互不重叠**，按 `charStart` 排序；提交时由引擎保证。
- `originalText` / `editedText` 是**只给清单看的两个快照**：提交时这段选区的文字、读者输入的文字
  （都是渲染空间，按叶各存一份）。它们与 `charStart` / `charEnd` / `text` 那套「最小修订」
  互相独立：公共前后缀照裁不误（改一个字只动一个字），但清单两行仍显示**整段**，
  读者才看得出「改之前是什么、改之后是什么」。反复修改同一处时，两行就是这次提交前后
  读者眼前的字（不是书上最初的原文）。加这两列之前写的老修订没有快照，清单按回退规则显示。
- `delta` 是提交时实测的长度增量，用于**不载入章树**也能换算坐标（相邻章标注预取、开书定位）。
  载入重放时会再量一次；不一致以重放值为准并记日志（`Orilumn.REV`）。
- 删书时与 `books` / `annotations` 同事务清理（D-17），不留孤儿。
- 接口照标注那一套：`TextRevision`（模型）+ `TextRevisionStore`（common 数据层接口）+
  `LibraryDb` 实现 + `BookRepository` 转手 + 两端宿主接线。UI 不直接碰库。

### 8.3 坐标换算

两个空间只差在修订上，换算是**纯算术**，不需要排版就绪：

```
修订 r 的渲染区间 = [r.charStart + shiftBefore(r),
                     r.charStart + shiftBefore(r) + (r.charEnd - r.charStart) + r.delta)
其中 shiftBefore(r) = 排在 r 前面的所有修订的 delta 之和。
```

- `toRendered(p)`：找到 p 落在哪一段。
  - 在修订之前 → `p + shiftBefore`；
  - 落在修订内部 → 夹到该修订的渲染区间（`min(p - charStart, 渲染长度)`）；
  - 在修订之后 → `p + shiftBefore + delta`。
- `toOriginal(q)`：上式的逆；落在替换文本内部时夹回该修订的 `[charStart, charEnd]`。
- **纯插入（`charStart == charEnd`）的边界口径**：映射一个**区间** `[a, b)` 时，
  起点按「越过 a 处的插入」算，终点按「不越过 b 处的插入」算——
  于是「在标注末尾插入文字」不会把新字吞进旧标注，「在标注开头插入」则会包含进来。
  单点换算不区分，只按「越过」处理，并在调用处注明。
- 标注被修订完全删掉（替换文本为空且区间被覆盖）时，映射结果是空区间：
  **不画装饰，记录保留**；清单跳转落到该修订的起点。

### 8.4 提交一次修改的算法

输入：章号、渲染空间选区 `[s, e)`、输入区新文本 `N`。UI 打开输入区时已经用
「各叶选区文本 + `\n`」拼出预填文本 `P`（`textOf` 返回的是各叶文本的**裸拼接**，
叶与叶之间没有分隔符，所以段分隔符由 UI 补）。

**A. 选区落到排版叶**

1. 用 `chapterTextBlockEnds(chapter)`（块尾偏移数组）把 `[s, e)` 按叶切开，
   得到每叶的选区子串 `S0..Sk`，以及预填文本 `P = S0 + "\n" + ... + Sk`。
2. 校验：
   - 涉及的叶不得是表格行 / 整块图片叶 / 匿名文本叶（要合并时）；中段不得碰到生成内容；
   - `N` 的行数（`N.count('\n') + 1`）就是**结果段数**，不要求等于 `k + 1`（D-34 修订版）；
     等于时走每叶一条的老路径，不等时走跨叶单条（见 C2）。
   - **接缝空白**：选区两端若贴着「接缝上被吃成零宽的分隔空白」（`使用 <code>val</code> 的`
     里 `val` 与 `的` 之间那格空格），先把它并进替换区间 `[s, e)`。它本来就在原文里、读者从来
     看不见，但替换后新接缝可能不再吃它（夹在两个汉字之间），确认后就会凭空多出一个空格。
     判据与排版同源：把这次替换落成结果文字，问那格空白**在结果里**还会不会被吃掉；
     仍被吃掉（`val` → `values`）或原样确认时一个字节都不动。

**B. 先做整体 diff，再按叶拆**

3. 求 `P` 与 `N` 的公共前缀 `p`、公共后缀 `q`（两者不重叠）：
   `cp = p`、`cq = P.length - q`、`Nc = N[p .. N.len - q)`。
   `cp == cq` 也合法（纯插入）。`[cp, cq)` 是预填文本里的中段。
4. 把 `[cp, cq)` 映射回「叶 + 叶内局部区间」：
   - 预填文本里第 i 段（叶）占 `[start_i, end_i)`，段间各一个 `\n`；
   - 中段起点所在叶 = 含 `cp` 的那一段，终点所在叶 = 含 `cq` 的那一段（纯插入时取 `cp` 所在叶，
     正好落在段界上时归后一段，章末归最后一段）；
   - 每叶的叶内渲染区间：首叶 = `[selStart + (cp - start), 该叶选区末尾)`，
     末叶 = `[该叶选区起点, selStart + (cq - start))`，中间叶 = 该叶整个选区
     （`selStart` / `start` 是该叶选区在渲染空间 / 预填文本里的起点）；
   - 把 `Nc` 按 `\n` 拆开；**行数 = 中段跨的叶数**时一行对一叶（单叶时整段 `Nc` 归这一叶，不拆）；
     **行数不等**时改走 C2 的跨叶单条路径。

**C. 每叶各自生成一条修订（段数不变）**

5. 对中段跨到的每一叶（局部区间 `[ls, le)`、新文本 `Nc_i`）：
   a. 找与该区间相交的已有修订（用它们的渲染区间；纯插入只算严格落在替换内部的）。
   b. **没有相交**：`os = toOriginal(ls)`、`oe = toOriginal(le)`，
      新修订 = `[os, oe) → 预归一(Nc_i)`。
   c. **有相交**：把相交修订的渲染区间并进来得到 `[ls', le')`：
      - `旧展开文本 = 渲染文本[ls' .. le')`；
      - `新展开文本 = 旧展开文本[0 .. ls-ls') + Nc_i + 旧展开文本[le-ls' ..)`；
      - `os = toOriginal(ls')`、`oe = toOriginal(le')`（端点必在修订边界或普通文字上，换算精确）；
      - 删掉被 `[os, oe)` 完全覆盖的旧修订；新修订 = `[os, oe) → 预归一(新展开文本)`。
      这一步就是「改已经改过的文字」：整条旧修订连同它两端没被选到的文字一起重写，
      不会留下半截重叠，也不会出现两条修订抢同一段。
   d. **同点纯插入合并**：`os == oe` 且该点已有一条纯插入时，把 `Nc_i` 接在它后面，不新增一条
      （否则两条零长度修订的先后无法定义）。

**C2. 跨叶一条修订（段数变了，D-34 修订版）**

5'. 把中段跨到的叶合并成一段「虚拟叶」，选区在其中占 `[s, e)`（原书偏移，相对首叶起点）：
   a. 与 C 同样的规则吸收相交的旧修订（扩张到 `[ls', le')`，被吸收的删掉）；
      扩张后可能跨更多叶，首末叶按扩张后的区间重新定位。
   b. `新文字 = 旧展开文本[0 .. s-ls') + 各行用 U+E000 连接 + 旧展开文本[e-ls' ..)`；
      每行按叶的 `white-space` 预归一（首行看前缀末字、末行看后缀首字，中间行两侧按块边界丢空格）。
   c. `os = toOriginal(ls')`、`oe = toOriginal(le')`；新修订 = `[os, oe) → 新文字`，
      `delta = 新文字渲染长度（不含 U+E000） − (oe − os)`。
   d. **不裁公共前后缀**：裁掉边界字会让区间缩回叶内，合并 / 拆分的信息就丢了。
   e. 新旧文字完全相同时也不算 noop——段数变了本身就是改动，仍要落一条（`delta = 0`）。

6. **实测增量**：每条新修订的 `delta` 用「应用后的渲染长度 − 原区间长度」实测
   （走与载入重放同一条重建路径，不另写一套估算）；节点边界空白导致对不上时，
   以实测值为准并记日志。跨叶修订按修订 id 一对一修正，叶内修订仍按叶归并。
7. **落库**：删除被吸收的旧修订 + 插入全部新修订，同一事务；同一次提交共用一个 `groupId`
   （取当前时间的毫秒值）。成功后把该章的新修订表交给控制器，由控制器清缓存、重排。

`预归一` 的规则：按叶的 `white-space` 归一替换文本，再按前后邻字符 / `<br>` 去边界空格，
使「渲染文本 = 原文本按区间替换」严格成立。它不改用户可见的字（只合并会被浏览器合并掉的空白），
但让长度增量可算、坐标映射精确。`pre` / `pre-wrap` 只展开制表符，不合并。

### 8.5 载入时怎么把修订套到树上

```
1. 从磁盘读原树 + 结构（叶路径 + 每叶原书字符起点）；无修订 → 原样走旧路径。
2. 有修订：
   a. 先把结构重链到原树（旧路径已有的动作），拿到叶表与起点。
   b. 逐叶找落在它区间里的修订（按 charStart 二分 + 顺序扫）；只有被碰到的叶才解析样式
      （懒级联，与轻路径同入口），没碰到的叶一个样式都不算。
   c. 取该叶的 StyledSegments（与排版、字符投影同一个单源），把修订的原书局部区间
      映射到文本节点：文本段可编辑，`<br>` 可删可插，行内图片随它的 `U+FFFC` 占位一起
      留/删，生成内容不可碰。
   d. 一趟重建该叶：对每条修订，取它覆盖的原文本 `M` 与新文本 `Nc`，做**字符级对齐**
      （与提交时同一算法、同一版本）：
      - 没变的字留在原来的文本节点里；
      - 新插入的字挂到「它前面那个字」的节点（中段最前面挂到第一个节点）；
      - 删掉的字从原节点移除；`\n` 落成 `<br>`，被删的 `<br>` 一并移除。
      **没改到的节点保留原始文本**（不重写空白）。
   e. 从叶到根复制路径重建，其余叶对象不动；有跨叶修订时改为一次性重建受影响的那几块
      （没变的子树原样复用，身份不变）。
   f. 用同一个 StyledSegments 量新叶长度 → 该叶增量 → 修正后面所有叶的字符起点。
   g. **跨叶修订**（段数变了）：按修订文字里的 U+E000 切块 —— 首块 = 首叶前缀 + 第一行
      （只有一段时再接末叶后缀，由首叶承载）；中间各行各占一块（能对上叶的复用原叶，
      对不上就新建同 tag / 同属性的块）；末块 = 最后一行 + 末叶后缀（由末叶承载，后缀行内样式不动）；
      没用到的叶整块删掉。叶表与起点按结果重排，块数可以比原来多也可以少。
      实测增量按修订 id 直接修正（不是按叶归并）。
      **审阅视图**下只有「只挪段界、一个字没改」的跨叶修订走这一条（判定见 §8.7 补记）；
      其余跨叶修订仍按「原文照排 + 新文字接在选区末尾」处理，段落结构不动。
3. 被碰到的叶若是「匿名 run」（结构里 syntheticText 非空）：结构缓存里的合成文本已过期，
   放弃这份结构，按变换后的树重算（只这一章、只这一次）。
   **补记（2026-11-13）：匿名 run 里的 `<br>` 与源码换行必须分得开。** 合成原文是「源码文字 +
   各标签的替身」拼出来的，`<br>` 和源码换行原先都写成 `\n` ⇒ 整段归一把两者一起折成空格，
   版面不换行、敲换行也没反应，逐节点样式段与排版文本还对不上（重放只能放弃）。
   现在 `<br>` 走一个空白占位符（`ANON_RUN_BR`），归一化按它逐行处理：**源码空白照 `white-space`
   折掉，`<br>` 才是真换行**，`<br>` 两侧的空格与逐节点样式段同口径剥掉。因此匿名 run 的
   排版文本、字符投影、编辑重放三处仍是同一串文字；读者在它里面敲的换行也落在这里的 `<br>` 上。
4. 结构缓存重链到变换后的树（段数不变时叶路径不变、只换 charStarts；段数变了则叶表整体重排）。
5. **不把变换后的树写回磁盘**：saveUnitStructure 在「本章有修订」时直接跳过，
   磁盘上的原树与结构文件保持原样（否则下次开书会二次套用修订——这是最危险的一条）。
6. 标题、目录片段锚点都从变换后的树取，和渲染一致。
```

叶级重建的细节（对应 D-33）：

- 对齐在**中段**上做，逐字归属：`<em>` 里的字改完仍在 `<em>` 里、`<strong>` 里的仍在 `<strong>` 里；
  整段换新字（没有任何公共字）时才退化成「全部落在中段起点那个元素里」。
- 未改到的元素（含被截一半的）类、`style`、属性原封不动；字被删光的元素整个走掉，不留空壳。
- 纯插入（中段为空）落在边界上时，挂到**前一个字符**所在的文本节点（续写手感）；
  落在叶首则挂到第一个文本节点（或叶本身）。
- 对齐结果落树后**再取一次 StyledSegments** 校验新叶文本是否等于「原文本按区间替换」；
  不等（只可能是节点边界空白）就退化为「全部落在起点节点」并记日志——保证重放可复现。

### 8.6 三个必答问题

**（1）行内元素只被截取了前/后一部分。**
选区起点落在 `<em>` 的文本节点中间时，只拆这个文本节点：`<em>` 保留，前半段仍在 `<em>` 里，
替换文本也插在 `<em>` 里；后半段同理。元素的 `class` / `style` / 其他属性一个都不动。
只有「中段整个吞掉某个元素」时，那个元素的文字才会被删，但元素本身保留为空（伪元素、边框照旧）。

**（2）选区包含其他行内元素，类与样式怎么处理。**
输入区是纯文本，但写回时不是「整段套一个样式」：
- 没改到的元素（包括中段两端被截一半的）**原样保留**，类与样式完全不动；
- 中段与旧中段做**字符级对齐**：没变的字留在原元素里，新插入的字挂到前一个字的元素，
  删掉的字从原元素移除——**逐段保住每个元素的类与样式**；
- 整段换新字（没有任何公共字）时才退化成「全部落在中段起点那个元素里」；
- 中段覆盖到的元素文字被删、元素本身也一起走掉（不留空壳）。
例：`<p>他<em class="a">慢慢</em><strong class="b">地</strong>走</p>` 选中第二个「慢」加「地」、
改成「快快地」，公共字只有「地」：第二个「慢」被删，`<em class="a">` 得到「慢快快」、
`<strong class="b">` 保留「地」，`<p>` 两端的「他 / 走」不动，整句变成「他慢快快地走」。

**（3）跨行。**
- **折行**（一行排不下自动换行）天然支持：选区偏移是字符级的，与显示行无关。
- **叶内 `<br>`**：可以编辑，`\n` 在输入区和字符流里都是 1 个字符；删除 `\n` 就是删掉 `<br>`。
  读者**新添**的换行不是 `<br>` 而是段界：单叶选区里也能把一段拆成两段（D-34 修订版）。
- **跨段**（跨两个及以上排版叶）：v3.0 就支持。输入区用 `\n` 分隔各段，
  **结果段数 = 输入里的换行符数 + 1**（D-34 修订版）：删光中间的字就把几段并成一段，
  输入多行就拆成多段。行数恰好等于跨的叶数时每段一条修订，不等时落一条跨叶修订
  （段界用 U+E000 记）；同一次提交共用一个组号。

### 8.6.1 修订清单（全书修订列表）

- **平铺，不画章标题**：清单按书内章序、章内起点升序一行一条（与笔记清单同一套行形态）。
  按章分组**暂不做**（用户 2026-11-11 定口：还没想好按哪级章、要不要能折叠；真要做必须
  能按章折叠，且笔记清单同步做成完全一致）。
- **搜索暂不做**（同一天定口）：单独给修订做搜索会和笔记、全文搜索分家，等整套想清楚再说。
- **读取失败与「真没有修改」分开**：读取失败显示「读取失败 / 点这里重试」，不再显示
  「还没有修改过正文」（两者看起来一样，读者会以为记录丢了）。
- **一行画的就是审阅视图里那一段**（2026-11-13 用户定口：清单的显示模式与审阅视图**完全一致**，
  除非太长折叠）：行摘要不再拿「原文 / 改文」两行快照自己算字符差异，而是直接取这条修订在
  **审阅空间**里的那一段（`ChapterRevisionMap.reviewExcerpt`，与正文审阅视图同一份数据）：
  两端没改的公共字照排、删掉 / 换掉的红字带删除线、新写的绿字、被删 / 新写的标记痕迹（`**`、
  `## `）与 ¶ 全在里面。只改了标记的修订（字一个没改）在快照里两端一模一样，按差异一条颜色
  都出不来，清单会显示成普通文字，与审阅视图里的绿 `**` 对不上——这正是这一条的起因。
  取不到那份数据时（本章结构还没载入、老数据没有原文投影、快照与最小修订对不上）才退回快照
  差异，行为与以前一致；两行加省略号的上限不变（`ExcerptMaxChars`）。
- **全部恢复原文**：清单顶部一颗按钮，点了先展开确认条（「把 N 条修改全部恢复成原文？」），
  再点「恢复」才真删；宿主一次删光、作废所有有修订的章的版式，当前章按改前页首重新落位。

### 8.7 缓存失效与重排

修订改变的是正文文字，**必须让该章重排一次**（这是内容修改唯一的代价，D-3 已认）。

- **章内解析态**：清树 / 结构 / 版式 / 文本投影缓存 / 当前页快照；下一次 ensure 重新走载入路径
  （读原树 → 重放修订 → 重链结构）。
- **分页表**：表头加 `contentRev`（该章修订哈希，0 = 无修订），格式版本升 4。
  读表时 `contentRev` 不符即当未命中；提交时顺手删掉该章当前参数指纹的表文件，
  其他参数指纹的旧表由 `contentRev` 挡住（后台 sweep 会清）。
- **页数清单**：每条 `(chapter, pages)` 加 `contentRev`（格式版本同升 4）。
  提交时把该章条目摘掉；重排完回填。开书读清单时 `contentRev` 不符的条目当缺失。
- **当前页快照**：`matches` 加 `contentRev`（schema 升），否则会拿旧页的行文本画新页。
- **在途任务**：单章重排与全书 B2 的写盘都要带 `contentRev`；提交时把该章的 contentRev 换掉，
  旧任务的结果自然写不进去。
- **不重排快路径（2026-11-08 用户定口）**：改前改后**各段总行数完全相等**（页界没变）就不重排。
  实施上不去逐段数行，而是把改动后的内容**只重塑当前页那一窗**，拿「重塑出来的页界 ==
  平移后的分页表」当判据（等价且更稳）：成立就把表原样留用——页首不动、当前页页尾与之后每页的
  页首页尾一起平移字数差、内容版本换新、写回磁盘，读者停在原页原位。
  只改几个字、页界没动的常见情形全部走这条路，代价是一页的塑形，不是整章重排。
- **真要重排时的落位**：与开关审阅模式同口径——锚定**改动前的当前页页首**（先按旧的修订表
  换算成原书坐标，再在新空间换算回来）。长章照常起临时表（锚页首行即改前页首那一行），
  短章整章排完落在含页首的那一页。**禁止按「改动所在位置」落位**：那会把读者从当前页
  拽到改动所在的页，看着就是乱跳。
- **UI**：宿主 bump `contentRevision`（阅读页据此重取当前页），拿不到改前页首时才退回
  「落到改动起点」；页脚页码、目录页码按新的页数清单刷新。

### 8.8 界面与接口

**界面**

- 选区菜单里的修订按钮**文案保留「修订」**，有选区才可点。
- 输入区**复用批注输入区同一个控件**（`NoteComposeBar` / `AnnotationSheet` 那张底部卡片）：
  同一套键盘逐帧高度 / 升起度 / 返回键取消机制（D-30）。正文修订与高亮、划线**共用同一根操作栏**
  （D-36）：`修订` 标为当前项，色槽整排不显示，右侧 `复制` / `确定` 照旧；输入框多行、可滚动。
- 打开时把选区文字整体放进输入区并全选，直接打字即整段替换；跨段时用 `\n` 分隔各段。
- **退出语义与批注完全一致**：点卡片与键盘以外的正文、返回键、Esc 都是**取消**——
  写了一半的内容丢掉、正文不动、选区收掉；落笔只有卡片上的 `确定` 一个入口。
- 确定成功后：清选区、重取当前页，**不**把替换后的文字重新选起来（免得挡住刚改的正文）；
  失败就地提示，卡片不关、正文不动。
- **修订清单**（抽屉第三页，与审阅视图同一套对照形态）：左侧抽屉的第三页「修订」
  （目录 | 笔记 | 修订），按书内章序、章内起点升序平铺，**不画章标题、不写字数说明**。
  一条修订**一行**，就是它在正文审阅视图里长的那一段：原文照排，删掉的字红字 + 删除线，
  新写的字绿字，中间没动的字照常；最多折两行，再多用省略号收住。纯删除只有红字。
  比对的两端直接取提交时的整段原文 / 新文字快照，只把**真正变了**的字上色——
  只加几个字时，被选中的那段原文照样在行首照常排出来，不会整段画上删除线。
  加两列之前写下的老修订没有快照，但修订是**外挂**在章树副本上的，原书文本从未改动：
  打开清单时按持久化章树把 `[charStart, charEnd)` 的原文切出来补回库（只补快照，不动区间、
  替换文字与内容版本）；区间为空的老行（只加字，选区已被公共前后缀裁光）补不回选中范围，
  只显示当时改成的文字。点行跳到该修订的起点
  （原书坐标由宿主换算成渲染坐标，与标注清单同一跳转口径）。
  每行左滑露出「删除」按钮（与笔记清单共用同一套手势物理，同时只展开一行）：删的是**那一条修订
  本身**，落库后该区间立即恢复原书文字，并只作废该章缓存（页界没变就不重排；变了才重排该章，
  本章页数可能变化，页脚与目录页码随之刷新）。删的是当前阅读章时按**删除前的当前页首**重新落位，
  读者不会被拽到清单行处；
  别的章只作废缓存、当前页不动。跨段修改产生的同组多条修订按行各删各的，不连坐。
  清单显示只读库；补录只读
  持久化章树与结构文件，**不要求本章排过版**，与全文对照视图（整章原文 / 改文并排）是两件事，
  后者仍归 v3.2。

**宿主接口**（`ReaderHost`，两端实现）

```kotlin
/** 提交一次正文修改：引擎算修订 + 宿主落库 + 该章重排。返回新落位与替换后的选区。 */
suspend fun commitTextEdit(
    chapter: Int, start: Int, endExclusive: Int, text: String,
): TextEditOutcome

/** 渲染区间 → 原书区间（建标注 / 存进度用）。 */
fun originalRangeOf(chapter: Int, start: Int, endExclusive: Int): IntRange?

/** 原书区间 → 渲染区间（画标注 / 标注清单跳转用）。 */
fun renderedRangeOf(chapter: Int, start: Int, endExclusive: Int): IntRange?

/** 删除一条修订（修订清单行左滑）：落库 + 重读修订 + 只作废该章。 */
suspend fun deleteTextRevision(revision: TextRevision): TextRevisionDeleteOutcome
```

`TextEditOutcome`：`Success(pos, selStart, selEnd)` / `Rejected(reason)` / `Failed(message)`。
`TextRevisionDeleteOutcome`：`Success(pos)`（`pos` 非空 = 删的是当前阅读章，阅读面按这个新落位
重新取页；null = 别的章，当前页不动）/ `Failed`（宿主未支持或落库失败，行不消失、就地提示）。

**引擎接口**（`BookDocumentController`）

- `setTextRevisions(byChapter: Map<Int, List<TextRevision>>)`：开书时由宿主灌入全书修订。
- `planTextEdit(chapter, start, end, text): TextEditPlan`：纯计算（校验 + diff + 合并），不落库。
- `applyTextRevisions(chapter, list)`：更新内存表、清缓存、触发单章重排。
- `renderedOffset` / `originalOffset` / `renderedRange` / `originalRange`：坐标换算。
- `contentRevOf(chapter): Long`：修订哈希，供分页表 / 清单 / 快照校验。

**标注与进度**

- 标注仍存原书空间（D-1）；`annotationsForChapter` 由宿主把区间映射到渲染空间再交给 UI，
  `addAnnotation` / `updateAnnotation` 反向映射后落库。
- 阅读进度 locator 存档时渲染→原书，开书跳转时原书→渲染（在章载入后、定位页之前完成）。
- 标注被修订完全删除时映射为空区间：不画装饰，记录保留（清单仍可跳转）。

### 8.10 风险、分层与验收

**最大风险：空白归一 + 字符对齐的确定性。** 渲染文本必须严格等于「原文本按区间替换」，
否则坐标映射与分页全错；提交时与重放时的对齐结果必须逐字一致，否则同一份修订在两次开书后
会得到不同的行内样式（甚至不同分页）。单测必须覆盖：节点边界空格、叶首尾空格、`<br>` 相邻空格、
`pre` / `pre-wrap`、`::first-letter`、`small-caps`、跨节点删除、纯插入、同点连续插入、
改已改过的文字、重复字（对齐的并列解必须按固定规则取一个）。对齐算法版本号进 `contentRev`。

**运行时兜底：长度以实测为准。** 提交时的预归一只是尽量逼近「原文本按区间替换」，
节点边界（两个文本节点相接处、生成内容、`small-caps`）仍可能让重放实测长度与库里的 `delta`
差一两个字。载入重放按叶记录实测增量；与库里的合计不一致时：只记 `revision delta drift`
日志，**在内存里用实测增量修正换算**（同一叶多条修订时差额记到最后一条，保证叶尾之后严格对齐），
库里的修订不静默改写。`contentRev` 因此不含 `delta`——重放结果只由区间与替换文本决定，
否则「修正前 / 修正后」两个版本号会让刚写好的分页表在下次冷开书时立刻失效。

**第二风险：把变换后的树写回磁盘。** 一旦写回，下次开书会在已改的树上再套一遍修订（双重修改）。
`saveUnitStructure` 的守卫与单测必须显式覆盖。

**第三风险：匿名 run（syntheticText）**。结构缓存里的合成文本会过期，必须走「放弃结构、重算」的兜底；
兜底只发生在被改到的叶是匿名 run 时，频率低。

**第四风险：跨段换行二义。** 段界与叶内 `<br>` 必须分得开：修订文字里段界用私用区字符
`U+E000`，`\n` 只表示 `<br>`（D-34 修订版）。若两者共用 `\n`，跨段选区含 `<br>` 时就无法判定。

**分层归属**

| 层 | 内容 |
|---|---|
| 用户层 | 修订记录、标注、阅读进度（数据与存储接口） |
| 排版层（上） | 修订重放、叶级重建、坐标换算、单章重排与缓存失效 |
| 渲染层 | 不新增逻辑；替换文本是新的文本节点，走既有塑形 / 分行 / 绘制 |

**样式/级联三问（AGENTS.md 要求）**

1. 这条声明进的是哪一层、哪个 tier？——**没有新声明**。替换文本是挂在原有父元素下的新 `#text` 节点，
   样式完全由既有层叠（书本 / 主题 / UI / 自定义）决定，不新增、不改动任何 tier。
2. 会盖掉书在同名元素上的什么声明？——**不盖**。未改到的元素原样保留；改到的文本节点只改文字，
   不动 `class` / `style` / 属性；被中段吞掉文字的元素保留为空，仍按原 CSS 渲染。
3. 读者没配这个值时，是不是应该干脆不发声明？——**是**；本方案不发任何声明。

**v3.0 验收**

- 改一个字 / 一句话 / 删一段 / 加一个换行 / 改标题，写回后文字正确、样式不串、页码与目录随之更新。
- 行内元素（`<em>` / `<strong>` / 带 `class` 的 `span`）被截一半时，元素的类与样式不变。
- 选区夹着多个行内元素、改完仍有公共字时，**每个元素各自保留自己的类与样式**
  （`<em>` 的字仍在 `<em>` 里、`<strong>` 的字仍在 `<strong>` 里）。
- 改带标注的文字：标注仍在原书位置，装饰按映射落在改后的文字上；完全删掉时装饰消失、清单保留。
- 改已经改过的文字：不出现重叠修订，第二次修改后文字正确。
- 跨两段一起改：段数不变时每段一条修订；删光中间的字（输入 0 个换行）并成一段；
  输入多行拆成多段；跨段选区含 `<br>` 也能正常替换。
- 重启 App / 重开书：修改仍在，且**只应用一次**（不会变成「改了两遍」）。
- 旋转 / 改字号 / 改边距：修改跟着重排，坐标不漂。
