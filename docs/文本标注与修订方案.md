## 2. 决策记录（逐条追加）

### D-1 锚点 = 章号 + 章内字符区间（与 `ReadingLocator`/`PageSlice` 同源）

- 表达为 `[charStart, charEnd)`，即用户所说的「原 CFI」；**不新造坐标**。
  （`ReadingLocatorCodec` 存 `chapter:char`；`PageSlice.charStart/charEnd`；页表 `PageRecord` 同源。）
- **所有标注都相对「原书」解算**：书不动，偏移就不动；标注之间**永不互相漂移**；
  排版参数改变（字号 / 边距 / 主题 / 旋转）不影响锚点。
- **装饰类不触发重排**；将来**内容修改**改变文字 ⇒ 该章必须重排一次 —— 这是唯一代价，接受。
- 引擎升级导致归一化口径变化的风险：**暂不处理**（还没有用户），与书签/阅读进度同一风险等级。

### D-2 渲染 = 专用「区间装饰通道」，不注入 CSS 标记，也不用 `border`

- 依据：`text-decoration` 在 CSS 里是「每元素一套、绘制时重合」，**无法与书内已有的下划线共存**
  （只能有一条线，且当前连颜色都改不了）；`border` 是「不得已」手段，**不采用**。
- 规范对应物：**CSS Custom Highlight API（`::highlight()`）** —— 样式挂在**区间**上而不是节点上，
  因此不去抢书作者元素那个「每元素一套」的槽位，可带自己的颜色 / 粗细 / 位置叠加在文字装饰之上。
- 本引擎里对应 **run（区间 + 样式）** 机制。
- 这条通道**同一个东西**同时服务：**临时选区**、**持久标注**、将来**审阅视图的标记**。
- 颜色随记录直达绘制，**不进 CSS 级联** —— 它是「用户侧叠加标记」，不是覆盖书样式的声明
  （故不涉及《样式层叠优先级》的 tier 之争）。

### D-3 标注层 = 两种应用模式，共用锚点与存储

| 模式 | 载体 | 用途 | 动树 / 重排 |
|---|---|---|---|
| **装饰模式（区间）** | 区间装饰通道（D-2） | 高亮、划线、选区、审阅视图标记 | 否，零重排 |
| **内容模式（节点）** | 注入 / 改写 `MarkupElement` | 将来删 / 改 / 加文字（v3） | 是，该章重排 |

- v1 只跑**装饰模式**；**内容模式的位置预留好** —— 这就是用户要的「框架基础」。
- 内容模式下注入会碰「import 时算结构 / open 时 relink」的持久化快路径
  （`PersistedChapterFile`；`MarkupElement.children` 是 `val`，注入 = 重建节点）。
  两条路待 v3 时定：**(a)** relink 之后受控就地插入（保叶身份与字符偏移，快路径不退化）；
  **(b)** 该章 open 时重算结构（丢持久化收益）。

### D-4 绘制归属与缓存

- **「字符区间 → 纸面矩形」只能在 `engine-skia` 做**（`LineAligner` 是 `internal`，只在渲染层可见）。
  用户层（`shared-ui`）只提供「章号 + 字符区间 + 样式」，消费结果。
- **持久标注烘焙进页面位图**：机制是「行数据变 ⇒ 指纹变 ⇒ 自动重烤」——
  `PageRasterSpec.fingerprint()` 按**值**比较 `lines`（`DrawLine` 与 `PageRasterFingerprint` 都是
  `data class`），行里的装饰 run 一变即未命中重画。位图池是**内存**的（`PageRasterStore`，非落盘）
  ⇒ 无旧像素残留。翻页动画 / 预栅格 / 两级分辨率天然一致。
- **不要复用 `contentRevision`**：它是**版式**修订号，由平台壳在**重排之后**推入
  （`ReaderActivity.applyReflowResult` / 桌面 `ReaderView` 的推送），`shared-ui` 无权 bump，
  语义也是「版式变了」而非「标注变了」。
- 正确做法：`host.pageLines(pos)` 的记忆**保持不变**，在其后**另加一步投影**
  `remember(rawLines, 装饰修订号)`；该修订号由 `shared-ui` 自己持有
  ⇒ 标注增删改**既不触发重排，也不必惊动平台壳**。
- **拖拽中的选区**不能每帧重烤（一页栅格 ~0.2s）⇒ 走**轻量覆盖层**路径，几何与烘焙同源，
  只是「即时画」而非「烘焙」。

### D-5 通道契约草案（渲染层定义，用户层消费）

```kotlin
// engine-skia（渲染层）：输入是章内字符区间 + 样式；输出是 DrawLine 上的行内 run
enum class DecorKind { BACKGROUND, UNDERLINE }   // 将来 OVERLINE / LINE_THROUGH

data class DecorRange(
    val start: Int,            // 章内字符偏移（与 ReadingLocator / PageSlice 同源）
    val endExclusive: Int,
    val kind: DecorKind,
    val argb: Int,
    val thicknessPx: Float? = null,
    val offsetPx: Float? = null,
    val priority: Int = 0,     // 叠加次序（例如选区压过标注）
)
```

- 归集的现成 seam：`styledSegments` 的每个 `StyledSegment` 都带 `node`（`StyledText.kt:55-60`），
  照 `collectUnderlineRuns` 的写法扩展即可。
- 绘制次序按规范：块背景 → 行内装饰背景 → 文字 → 下划线 / 着重号。

### D-6 存储 = SQLDelight 表（数据库），不用每书一个附件文件

- 新增一张标注表（终态表 + 一条迁移），与 `reading_states` 同源、同库、同事务。
- 形态（草案）：

  ```sql
  CREATE TABLE annotations(
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    bookId INTEGER NOT NULL,
    chapter INTEGER NOT NULL,
    charStart INTEGER NOT NULL,      -- 含
    charEnd INTEGER NOT NULL,        -- 不含（与 PageSlice 同口径）
    kind TEXT NOT NULL,              -- highlight / underline / note / ...
    color INTEGER,                   -- ARGB
    note TEXT,                       -- 批注文本（v2）
    createdAt INTEGER NOT NULL,
    updatedAt INTEGER NOT NULL
  );
  CREATE INDEX annotations_by_book_chapter ON annotations(bookId, chapter);
  ```

- 删书时与 `books` 同事务一并删除（不留孤儿）。
- **代价（已接受）**：标注不再是一个「用户可见、可随手拷走」的附件文件；
  将来导出「改过的 EPUB」要**另写一个导出器**（从库里取记录 → 生成补丁/新书），
  而不是像附件文件那样「天然就是补丁」。这是选 A 换取事务安全与查询便利的明账。
- **加一层接口**：读写走一个共享层的存储接口，DB 只是它的一个实现；
  将来若要做「可导出的附件」，在接口下再加一个实现，不必动上层。

### D-7 选区单位 = 英文按词、中文按句

- 英文「词」：文档空白 + 常规标点，撇号 / 连字符连缀。
- 中文「句」：以全角句末标点（`。！？…；` 等）断句，闭引号 / 闭括号归前句。
- **关键收益**：两者都**不需要分词器**，**不开平台 `BreakIterator` 缝**，纯共享层可做。
- 待细化：句末标点集合、换行是否算句边界。

### D-8 跨页 v1 必做；不跨章

- 交互模型：**拖手柄到页边缘 → 自动翻页并继续扩选**（移动端标准做法）。
- **手柄接力规则**：手指位置不动，翻页后手柄跳到**新页最靠近手指那一侧的行**，继续跟随手指。
- **不跨章**：拖到章末页边缘即停住（选区封顶到章末），保持「一条标注 = 一个章内区间」的模型。
- 存储不受影响：跨页只是**同一章内的区间变长**。
- 渲染：选区跨页时，每页只画该页与选区的**交集**；翻页动画期间选区覆盖层如何呈现，待细化。
- **架构约束**：自动翻页**不能**复用滑动翻页的手势会话（同一根手指正在拖手柄），
  需由选区逻辑驱动一条**独立的翻页路径**。

### D-9 桌面鼠标：只能拖选，不能拖动翻页

- 需要按**指针类型**分流（触摸 / 鼠标），而不是两套 `pointerInput` 硬抢。
- 鼠标**拖拽 = 文本拖选**（桌面最自然）；**不允许拖动翻页**。
- 鼠标**点击左右页边距**翻页（「页边空白区」= **左右页边距**；上下页边距不算）。
- 桌面翻页**主要依靠键盘**（左右箭头，现有能力）。
- 鼠标**点正文区 = 无操作**（既不翻页也不清选区）。
- 触摸端的滑动翻页与三区点按**保留**（只改桌面鼠标）。
- 后果：桌面鼠标的**跟手滑动动画随之取消**（键盘与点击翻页仍走动画）。
- 分流按**指针类型**，不按平台——Android 平板接鼠标同样走鼠标语义。
- 实现注意：现有三区点按按屏宽 1/3 判定，桌面「点左右页边距翻页」要改成按**版心几何**
  （内容左/右缘之外的页边距区域）。
- 落地：鼠标按下后**移动超过点按阈值**才起选区（单击正文不闪选区）；点左右页边距走翻页动画，
  正文单击无操作（不翻页、不清选区、不触发链接）；触摸端的长按/滑动/三区点按不变。

### D-10 放大镜：移动端要，桌面不要

- 纯**用户层**（shared-ui）实现：复用页栅格位图放大绘制，不涉及排版层与渲染核心。
- **当前落地**：直径 96dp、1.5 倍、圆心优先在手指上方 56dp，贴顶翻到下方、贴边内移；
  长按起手和拖手柄时出现，松手即消失；桌面鼠标不出现（按指针类型判定）。
  实现上不另取位图，而是把同一个 `PageContent` + `ReaderPageRenderer` 再画进圆形裁剪层，
  由渲染器现有的页位图缓存直接命中，所以与静止页像素同源。

### D-11 移动端：三区点按保留，长按进入选区

- 点按三区（左 1/3 后退 / 右 1/3 前进 / 中间切栏）**必须保留**——这是移动端的主要翻页方式。
- **长按**是进入选区的唯一入口；进入选区后，点按改为「清除选区」（不翻页）。
- 桌面无「长按」语义，改由鼠标拖选进入（见 D-9）。

### D-12 动画与选区互斥（时间维）

- 翻页动画 / 滑动会话进行中 → **不响应**长按与选区手势（现有 `ctl.isBusy()` 守卫扩用）。
- 选区手势进行中（长按起手 → 抬手，或按住手柄拖动）→ **不播任何翻页动画**；
  跨页翻页一律**直接跳（瞬切）**，不做淡入。
- 选区**已存在但未在操作** → 翻页不受限（点按 / 滑动 / 键盘），翻页后选区保留，各页只画交集。
  - 触摸端例外（D-11）：有选区时**点按 = 清除选区**、不翻页 ⇒ 此时翻页走滑动或键盘。

### D-13 颜色体系：用户可自定义调色板

- 高亮与划线**各自一组色槽**（4–5 个）；每个槽的**颜色与透明度**（ARGB）由用户自定义。
- 两类各有一个**默认色槽**（新建标注时用它）；浮动菜单里点哪一格，哪一格就**成为默认**
  （即「记住上次用的颜色」，下次打开金边就在那一格）。
- 浮动菜单还记住**上次用的类别**（高亮 / 划线），下次打开直接摊开该类别的色槽行，
  不必先点一次类别按钮。
- 归属：**全局**（`ReaderSettings`），跨书统一——与字体 / 主题同类。
- 记录里存的是**创建当时的颜色**（解析后的 ARGB 快照）⇒ 改调色板**不影响已有标注**（墨迹已干）。
- 颜色仍**不进 CSS 级联**（延续 D-2）：它是标注自身颜色，不是覆盖书样式的声明。
- **当前落地**：高亮 / 划线各 5 格，存 `ReaderSettings` 的 `highlightColorSlots` /
  `underlineColorSlots`（ARGB `Int`），另存 `highlightDefaultSlot` / `underlineDefaultSlot`。
  设置面板「笔记」页两行标签各带五格色槽，点格后在下方调 RGB 与不透明度（100% = 完全盖住文字），
  拖动中即时生效、松手落盘；最下方的「恢复默认设置」把两类十格一起恢复出厂值；
  默认色槽不在这页体现（新建标注用哪一格由浮动菜单决定）。
  浮动菜单点高亮/划线后展开五格，点哪格就用哪格颜色创建标注。老存档缺键自动取默认，
  无需 bump 结构版本。
- **两个类别完全独立**：菜单里「高亮」「划线」的样张、色槽行、线型行各取**本类别**的色槽与默认槽；
  编辑另一类别的记录不会让本类别串色。从高亮转成划线（点线型）时颜色改用**划线的默认色槽**，
  不把高亮那半透明的底色带进墨线。
- **划线的线型**：实线 / 波浪 / 虚线 / 删除线（高亮没有线型，该行不出现）。线型行只画线、
  不写字，线色 = 当前划线色；选中那条垫一层与类别按钮同款的高亮底。
  选区场景**点线型即落笔**（用当前划线色，不必再点颜色）；编辑已有标注时点线型即改这一条
  （高亮顺手转成划线）。线型存 `Annotation.lineStyle`，浮动菜单另记「上次线型」
  `annotationLastLineStyle`（纯全局，同标注一族）。

### D-14 已有标注可编辑 / 删除（v1 必做）

- 入口：**长按已有标注 → 同一个标注浮动菜单**（改色 / 删除）；长按空白 → 新建选区。
  语义统一为「长按 = 针对此处」。
- 跨页标注是一条记录，菜单作用于整条。
- **当前落地**：长按只在当前章内存列表里按字符区间命中（不查库、不反查几何），页边距不参与；
  命中后清掉选区，弹出**与选区共用的同一个浮动菜单**（见 3.2）：该标注所属类别的五格色槽
  预展开（当前色描强调边，点哪格即改色、并同步换成该类别），删除一步直删（无二次确认），
  复制复制这条标注覆盖的原文。改色与删除先改内存立即出图，再异步落库，失败回滚并提示。
  长按空白仍进入选区；菜单外点按只关菜单。
  桌面鼠标按住正文等价于长按（拖过阈值仍是拖选）；翻页、换章、旋转/改排版都会收起菜单。

### D-15 视图模式按书持久化

- `CLEAN` / `REVIEW` 的状态**按书**存（每本书各自记），因为它描述的是「这本书的展示方式」。
- v1 恒为 `CLEAN` 且**不暴露界面**，只为 v3 的内容修改预置位置。

### D-16 颜色设置界面 = 共享 Compose，不开平台分支

- **不做**安卓 / 桌面 / iOS 各自的平台对话框；做**一套共享 Compose 界面**，挂在现有面板体系里
  （`ReaderSettingsPanel` / `FontLibraryPanel` / `ReaderTocPanel` 同制，复用 `paletteFor(scheme)`）。
- 理由：① `AGENTS.md` 的 KMP + CMP 约束要求基本组件跨平台共享；
  ② **Android 没有系统颜色选择器**，本来就得自绘；③ 透明度支持三端系统选择器参差不齐，自绘最省事。
- 形态建议：**色槽网格 + 透明度滑条**（必要时补 HEX 输入）。细节见待决。
- **当前落地**：设置面板内新增「笔记」页（与现有设置页同制，复用 `paletteFor(scheme)`）：
  高亮 / 划线两行标签各带五格色槽、红/绿/蓝/不透明度四条滑条、最下方的恢复默认设置按钮；
  四条滑条拖动中即时生效（只应用不落盘，松手才写设置）。
  不新增第三方依赖，也不开平台颜色对话框；未做 HEX 输入，也不再有快捷色。

### D-17 删书清理走共享的「一次删三张表」（事务）

- 现状**没有外键级联**，且两个平台各自删、**非事务**：
  - Android `BookRepository.removeBook` = `db.removeBook(id)` + `db.clearReadingState(id)`；
  - 桌面 `ShelfStore.delete` = `requireDb().removeBook(id)` + 删文件（**不碰** `reading_states`）。
- 定案：在 `LibraryDb` 加**一个共享方法**（`removeBookAndData(id)`），用 `db.transaction { … }`
  一次删 `books` + `reading_states` + `annotations`；两个平台都改调它。
- 顺带收益：修掉现状「删书与清进度分两步、非原子」的问题（中断即留孤儿）。
- 注意：改了桌面既有行为 ⇒ 实现后必须实测「删书 → 三张表都干净」。

### D-18 章节文本 = 引擎投影，同步、与排版同源

- **问题**：全仓没有「取整章原文」的现成入口。`DrawLine.text` 只是**行片段**
  （按页窗口切开、带断行与行尾连字符），直接拼会漏字 / 重字，复制出来与原文对不上，
  选词与断句也会跟着错。宿主侧同样没有章节文本查询。
- **定案**：在**排版层（下）**新增章节文本投影，复用
  `NormalFlowLayout.leafText`（与塑形同一份归一化字符串）+
  `ChapterPrepareResult.globalCharStarts`（与 `DrawLine.charBase` 同一套章内偏移），
  按叶序拼出整章文本。这样「排版用的字」「标注锚点」「复制/选词用的字」是**同一份**。
- 另给「按区间取原文」：块与块之间在**复制结果**里补换行，但**换行不计入偏移**
  （偏移只认排版字符流）。
- **必须同步**：长按是手指按下即要出结果的手势，不能走异步往返。宿主在开章排版时
  顺手缓存，`textOf(chapter, start, end)` 与 `pageLines` 同级（廉价、立即返回）。
- 归属：投影与切片都在共享层（排版层（下）），平台宿主只是转发；**不允许**两个平台各拼一遍。

### D-19 标注列表由 shared-ui 自持，数据库只在开章与保存时参与

- 阅读页要同时做三件事：画当前章的标注、长按命中已有标注、增删改后立刻可见。
  每帧查库会卡，异步往返又会让长按有延迟。
- 定案：shared-ui 进章时读一次，**持有当前章的标注列表（Compose 状态）**；
  新增 / 改色 / 删除先改内存并递增「装饰修订号」（界面立刻更新），再异步落库；
  落库失败回滚并提示。
- `ReaderHost` 只加四个后台口：读本章、增、改、删（平台实现转发给共享的 `LibraryDb`）。
- **不做**「监听数据库变化」的通用流：v1 只有这一个写入口；等 v2/v3 出现第二个写入口再补。

### D-20 视图模式延后到 v3：开关在阅读页底部工具栏，与书架无关

- 用户 2026-10-20 明确：审阅视图属于后面「内容修改」阶段的功能，
  开关预计放在**阅读页底部工具栏**，不是书架 / 书目属性。
- 因此 **v1 不建视图模式列、不建表、不存任何状态**；原 §5.10 的
  「`books` 加一列」建议**作废**（且与现有整行覆盖写入冲突，见 §5.10）。
- D-15 的「按书持久化」保留为 **v3 待定**：真做到内容修改时再定落点与默认值。

### D-21 颜色面板 = 共享自绘，不调平台颜色对话框

- 核实（Compose Multiplatform 1.11）：**没有官方颜色选择器组件**；通用 `Dialog` / `Popup`
  只是容器，取色控件仍要自己写。
- 平台系统对话框不可行：Android 本身没有系统取色器；桌面只有旧式 Swing 组件，
  风格与阅读器面板不一致，两端行为也不齐。
- 定案：沿用 D-16，**自绘共享 Compose 面板**（色槽网格 + 透明度滑条 + 可选十六进制输入），
  不新增第三方依赖，不开平台分支。色槽值存 `ReaderSettings`（§5.9）。

### D-22 自定义样式 = 读者规则层，压在 UI 之上

- 用户 2026-10-20 明确：选中一段内容后，应用反查候选选择器
  （元素本身、父元素 > 子元素、类名、ID、父类名 > 子元素等），**按具体程度从高到低**列出；
  读者挑一条选择器，再挑样式、填属性值，最后生成一条规则。
- 这不是「给一个元素塞内联样式」，而是**读者自己写的 CSS 规则**（选择器 + 声明）。
  因此它属于读者侧，整体压过书本；读者内部，它高于 UI 的全局偏好。
- 层叠顺序：`自定义样式（45/49） > UI（44/48） > 主题（42/46） > 书本 > UA`。
  层内仍按选择器特异度与源码序决胜；候选排序只帮读者选作用范围。
- **规则必须以样式表注入**，不能写成元素上的内联 `style`：内联样式在引擎里属于书本侧
  （tier 30），会被任何读者层压掉。
- 宽选择器（如 `p`）也会压过 UI 的全局设置，界面需显示命中范围 / 预览并提示。
- v1 不做（高亮 / 划线走装饰通道，不经过样式层叠）；v3 内容修改如需样式，走这一层。

### D-23 标注 / 批注清单 = 目录抽屉的第二个 tab（标题「笔记」）

- 用户 2026-10-22 提出：*这些高亮、画线、批注笔记需要在笔记面板中实现清单（跳转+删除），
  面板的入口早就有了，可以考虑把它和目录使用同一个面板的不同 tab。*
- 现状核实：底部工具栏**入口已有**（`✎ 笔记`，与 `☰ 目录` 并列），但 `onNote` 为 null，
  点按只弹一句「笔记（规划中）」；本方案原 §1 只在 v2 写了一行「标注列表面板」，没有设计。
- 定案：
  1. **同一个左停靠抽屉，两页**（目录 / 笔记）。抽屉壳（遮罩 + 滑入动画 + 顶部条 + ✕）
     抽成共享壳，标题文字位置换成「目录 | 笔记」分段控件，✕ 原位不动。
     `☰` 打开落在目录页、`✎` 落在笔记页；页内切换**不关面板**；当前页在会话内记忆。
  2. **设置面板不并入**：设置是分区滚动 + 滑块的另一种形态，并进 tab 只会让两边都变差，
     保持独立抽屉（现状）。
  3. **行内容**：原文摘录（最多两行，超出省略）**按该条标注本来的颜色与线型直接画在摘录文字上**
     —— 高亮垫同色底，划线画同色实线 / 虚线 / 波浪线 / 删除线，与正文那一处完全同一套口径；
     不在左侧另立类别图标（颜色和线型本身就是类别）。另有所在章标题（分组头）、
     批注行下一行显示批注正文、行尾删除按钮。
  4. **分组与排序**：按书内章序分组，章标题取目录项标题、缺项回退「第 N 章」；
     章内按区间起点升序（与 `annotationsForChapter` 同序）。打开时滚到当前阅读章所在组。
  5. **跳转**：点行落到**包含该区间起点的页**（不是章首），走壳里既有的锚页漏斗，
     与目录跳转同口径：`finalizeOnLeave` → 落位 → 保存进度 → 关面板。不新增手势、不新增状态机。
  6. **删除**：行尾按钮**直接删**（与长按菜单的删除同口径，无二次确认），删完立刻从面板列表
     与当前章内存态移除；落库失败则恢复并提示。删当前章的标注后，屏幕上那条装饰必须同时消失。
  7. **空态**：一句「还没有高亮、划线或批注」。
  8. **不做**：搜索、按类型/颜色筛选（v2 批注落地时再加）、导出、跨书汇总、分页
     （`LazyColumn` 足够；超大书若真卡再考虑按章折叠）。
  9. **键盘（桌面）**：清单内沿用现有 `PanelNav`（上下键 + 回车）；tab 切换先只做点按，
     不进 `Tab` 焦点链——真有人要键盘切页再加。
  10. 抽壳时**不改外观常量**：顶条高度、抽屉宽度、滑入时长（`TocAnimMs`）、遮罩透明度一律照旧，
     只把标题文字换成两页控件；否则等于顺手改了一遍目录的手感。
- 归属：**v1.5**。它只依赖已有标注数据，先做清单；v2 批注落地时同一列表直接多显示批注正文，
  不换壳、不返工。

### D-24 清单要摘录原文 ⇒ 标注表存「创建时原文快照」

- 冲突点：清单每行要显示「这段标注划的是哪句话」，但章节文本（`textOf`）**只对已排版缓存过的章
  可用**（远章已驱逐，返回 null）。为了一个清单去把全书各章的版排出来，直接违背分页调度总则
  （用户一开面板就排全书）。
- 定案：标注表加 `quote TEXT`（原文摘录），**创建时**从 `textOf` 取并截断到约 200 字，
  迁移 8→9（`8.sqm`）。与颜色同理是**创建当时的快照**：改排版参数不回溯（文字本身不变，
  基本不会漂）；v3 内容修改后引用原文可能变化，届时按「以原书为准 / 刷新快照」重新定，
  不在 v1.5 预支。
- 老记录（v1 已有标注）`quote` 为空：开该章时顺手回填一次（章节文本已在缓存里，一条 UPDATE/条）；
  仍未回填的面板显示「（无摘录）」兜底，不阻塞跳转与删除。
- 不另建表、不存富文本：一列足够；批注正文继续用 `note` 列，v2 不需要新表。

### D-25 批注 = 独立类型 + 虚线标记（v2 初版，**已被 D-26 取代**）

> 2026-10-22 用户否决：「批注的样式不好定，干脆让它作为高亮和划线的附件」。
> 本节留作失败路径的记录，实现已按 D-26 改成附件模型；旧的 `kind = 'note'` 记录
> 由迁移 9→10 统一改写为高亮，文字与颜色原样保留。

- 原定案：`kind = note` + 正文固定虚线下划线 + 独立色系（`noteColorSlots`）+ 自绘居中输入框；
  Android 阅读页 `adjustNothing`（键盘弹出不许改窗口尺寸）——这一条被 D-26 继承。
- 否决理由（留给后来人）：
  1. **同一段文字只能有一种墨迹**：读者先高亮、隔天想补一句话，独立类型会逼他再叠一条记录；
     两条记录各画各的，删除 / 改色 / 跳转 / 清单都要额外处理「两条落在同一段」。
  2. **样式没有判断依据**：虚线与「划线 + 虚线线型」在正文里看不出区别，只能靠颜色体系区分；
     颜色一独立成组，设置页就要多一个类别、菜单就多一套规则（编辑批注时不许点高亮色槽）。
  3. **居中弹窗挡住了那条墨迹**：批注是「顺手补一句」，读者要一边看着高亮一边写。

### D-26 批注 = 高亮 / 划线记录上的附件 + 底部输入条 + 正文旁就近显示（v3，现行）

> **2026-10-22 再次定形（见 D-28）**：贴着选区浮动的那个菜单取消，操作项并入键盘上方的输入条
> 组成一整条「操作栏 + 输入行」；被遮住时整页上顶；旁注增加指向原文的箭头。
> 本节其余内容（附件模型、`note` 列、旁注布点、清单筛选）继续有效。

- 一句话：**批注不是第三种标注，而是高亮 / 划线记录上附带的一句话**（`note` 非空即「带批注的标注」）。
  没有输入就是普通标注，有输入就是「标注 + 一句话」——墨迹仍是那一条，不会多出第二条记录。
- 定案：
  1. **记录形态**：只有 `highlight` / `underline` 两类；`note` 是可选文字，`color` 仍是创建当时的快照。
     旧数据：v2 试验期的 `kind='note'` 由迁移 9→10（`9.sqm`）统一改写成 `highlight`（颜色与文字不动）；
     解析侧未知类型**回落高亮**，不再抛错（外部导入不该让书架打不开）。
  2. **删掉批注专用色系**：`noteColorSlots` / `noteDefaultSlot` / `DEFAULT_NOTE_COLOR_SLOTS` /
     `DEFAULT_NOTE_ARGB` 全部移除，设置页的标注颜色回到「高亮 / 划线」两类。
  3. **输入条**（`NoteComposeBar`）：贴着**键盘上沿**的一行输入框（桌面没有键盘，就贴窗口下边框），
     用 `imePadding()` 把整条抬到键盘之上；Android 壳保持 `adjustNothing`——键盘弹出**不改窗口尺寸**，
     否则视口一变就是一次整书重排（本功能最大的坑，见 D-25 第 5 条）。
     - **落笔即弹**：点色槽 / 线型落成一条标注后，输入条自动弹出并聚焦。
     - 长按已有记录 → 菜单「批注 / 改批注」重新打开**同一条**（带出已有文字）。
     - **退出即保存**（口径已被 D-28 取代）：当时是完成 / 返回键 / Esc / 点条外全走提交。
       现在落笔只在 `完成` 与点卡片外的正文，返回键 / Esc 是取消（见 D-28 第 1 部分）。
     - 透明遮罩只吞点按、不压暗：打字时正文与刚画上去的墨迹一直看得见。
  4. **正文旁显示**（`NoteBubbles`）：批注文字就近显示在那条墨迹旁边，**纯覆盖层**——
     只读行几何（`DrawLine.yTop/yBottom/xLeft/lineWidthPx` + 页面位移）找空白，
     **不进分页、不进栅格、不触发重排**。候选取用顺序（都不会压到正文行）：
     ① 锚点末行右侧（最像「旁批」）→ ② 锚点下方到下一行之间的空隙（多半是段间距）→
     ③ 页脚空白 → ④ 左右页边距兜底（窄到只能显示一个字加省略号也认）。
     （**此候选顺序与兜底口径已被 D-28 §3 取代**：2026-10-23 起按整页空白统一评分，
     页边距是一等候选，且绝不显示只有省略号的框。）
     压到正文行或已放好的旁注即作废，四个都不成立就**不显示**（宁可看不见，也不糊住正文）。
     点旁注文字块 = 打开该条的输入条。
  5. **清单**：类型筛选改为独立枚举 `AnnotationFilter`（全部 / 高亮 / 划线 / 批注），
     「批注」按**有无 `note`** 判定；带批注的高亮 / 划线也显示正文（最多三行）。
  6. **浮动菜单**：「批注 / 改批注」只在**长按已有记录**时出现；新建场景用不着，
     输入条落笔后自己会弹。
- 不做（v3）：批注富文本 / 导出 / 跨书汇总 / 清单内直接编辑正文。
  旁注的字体 / 字号 / 颜色**已排期**（用户 2026-10-22 点名），见 **D-29**：只动 `NoteBubbles`
  与箭头绘制，不碰排版。

### D-27 批注输入条细则（D-26 第 3 条的落地细化，2026-10-22）

> 代码注释里的「D-27」指的就是这一节。它没有推翻 D-26，只是把输入条的行为写实。

- 输入条 = 贴着**键盘上沿**的一行输入框（桌面/无键盘时贴窗口下边框），透明遮罩只吞点按、不压暗正文。
- 打开即聚焦（顺带把键盘顶起来）。（**退出语义已由 D-28 取代**：落笔 = `完成` / 点卡片外；
  返回键 / Esc = 取消。）
- 它与浮动菜单**同开同关**：选中文字就一起弹（新选区），长按已有记录也一起弹（带出原文字）。
- 空输入 = 不写批注：新选区提交后只剩墨迹（连墨迹都没有就什么都不留），已有记录提交后只清掉那句话。
- 状态：输入条本身**保留**；D-28 把操作菜单并进它上面，合成同一张卡片。

### D-28 选区操作栏 = 菜单 + 输入条，遮挡时整页上顶，旁注用箭头指向原文（v2.1，2026-10-22 用户定形）

> 用户原话（2026-10-22）：「现有的弹出菜单删掉，合并到键盘上方的批注输入框上方，整体为一行……
> 菜单区+下方输入区+下方键盘区作为一个整体，计算它的总高度 H……把页面整体向上顶出上边界……
> 批注文字按就近优先，其次完整显示优先的原则，布放在同一页空白区，通过箭头指向书中对应的原文。」
> 以及：「对原有笔记，单击直接弹出键盘+功能区；其余划屏、点击翻页操作，首次触屏点必须避开所有
> 笔记标注区和链接区，手指滑动过程中可以触及笔记区和链接区，这时不弹出键盘+功能区。」
>
> **布点口径已于 2026-10-27 再次修订（现行）**：环数是绝对第一优先，近环截断也先于远环整句；
> 同一环里先整句、再比折行数，折行相同后先比就近（额外引线长度），同距再比方向
> （右上/右下 → 左上/左下 → 正右 → 正左 → 正上 → 正下）；
> 段界已删除，范围只由空白是否连成一片决定，满行左右页边距可用但排在四个角之后；
> 同一行多条先最右那条占正右、其余从左到右**各自独立取位**（不排成一列），环 0 整句放不下时才请挡路批注上下 / 左右
> 让位；全部落位后长外短内综合安排；所有环都不行才退成 0.5em 的小椭圆。
> 标注占空白；留白两档：空间够时正侧与正上 / 正下都留 1em，不够只收远离正文一侧到 0.1em；
> 近侧一律不压——正上 / 正下推不出 1em 就宁可不用这个方向，四个斜向近侧固定 2px，
> 靠横向错开的一个字画 L 形引线；
> 框宽按字体 / 字号 / 行距 / margin 综合计算；取位「贴住锚点行 / 角」；
> 引线只画横线、竖线与折线；指向**离框更近的那一头**（跨行选区比框到选区首尾，单行看框落在
> 这一行的左半还是右半）；四个斜向必须从框的侧边横着出去、再竖着接住文字，折成 L 形；两端必须接住。
> 完整方案见 `docs/旁注布点与引线-实施方案.md`，以下文现行规则为准。

#### 1. 一条操作栏取代浮动菜单

- **删掉**现在贴着选区/长按点浮动的那个 `AnnotationMenu`（锚点、上方/下方翻边、左右收边那套定位全部作废）。
  菜单项并入键盘上方的卡片，卡片自上而下两段：**操作栏**（可 1–2 行）+ **输入行**。
- **操作栏单行时的从左到右**：
  1. `高亮` `划线`（类别切换，按钮本身仍是样张）；
  2. `编辑`（**占位**：v3 的内容修改，未实现，虚掉且点了没反应）；
  3. 当前类别的一排 **5 个色槽**（点一格只选中，色槽仍记住上次的类别与格子）；
  4. **4 个线型开关**（实线 / 波浪 / 虚线 / 删除线，只在「划线」类别出现；高亮类别不占位）；
  5. 贴右侧的 **3 个按钮**：`复制` `删除` `完成`。
- **输入行**：只留输入框（占位提示「写点批注（可不填）」），**原来的「完成」按钮删掉**——
  落笔由操作栏最右的 `完成` 或点卡片外的正文承担；返回键 / Esc 是取消。
- **窄屏（手机、桌面小窗口）自动两行**：第一行 = `高亮` `划线` `编辑` … `复制` `删除` `完成`；
  第二行 = 5 个色槽 + 4 个线型。判定用**实测单行宽度**（一次测量装不下就换两行），不用屏幕 dp 阈值。
- **色槽（2026-10-23 改口径）**：点色槽**只选中**、不落笔（点错还有机会改，卡片也不会忽然关掉）；
  落笔交给 `完成` 或**点卡片外的正文**。选中后卡片不关、当前格描边，写下的字与颜色在落笔时一起写入。
  色槽仍记住上次的类别与格子（写盘、无重排提交）。
- 语义沿用已定案的部分：删除只在有可删记录时点亮
  （编辑时是这条记录，新建时是选区内相交的那一条）；成功不弹提示，失败才提示；点条外 = 提交并关闭。
- **点按已有标注 / 旁注 = 打开卡片（2026-10-23 落地）**：单击（不必长按）页上的高亮、划线或旁注框，
  直接弹出键盘与操作栏，带出这条的记录与批注；点按命中标注**不翻页**，长按与单击同一套字符区间命中。
- **线型（已确认）**：只**选中**、不落笔；落笔交给下面两个提交口，这样能先选线型再写字。
  新建时选中线型后落笔 → 按当前类别 + 当前线型 + 当前颜色（没选过就是该格默认色）落一条；
  编辑时选中线型 → 落笔后这条改成「划线」（高亮 → 划线）。
- **落笔只有 `完成` 一处（2026-10-23 定形）**：有批注文字就一起写入；新建选区即使没写字，
  也按当前类别 / 线型 / 颜色落一条（这是「先选样式再落笔」的落笔口）；编辑模式把选好的
  颜色 / 线型 / 文字一次性写回（清空文字即去掉批注）。
- **其余一切退出都是取消（2026-10-23 定形）**：点卡片外的屏幕、返回键、Esc —— **什么都不改**——
  写了一半的批注、刚选的颜色与线型全部丢掉；编辑态原记录保持原样；新选区连同选区一起清掉。
  它们都**不是**「保存后退出」。（复制只进剪贴板：不动记录，也不关卡片。）
- 菜单不再依赖选区锚点 ⇒ 选区在页面任何位置（含贴底、贴边、跨页）都不存在「菜单跑出屏幕」，
  也不需要 `noteBarHeightPx` 这类估算——卡片自己贴键盘上沿，量到多高就是多高。

#### 2. 被遮住时整页上顶（不是重排版）

- 操作栏 + 输入行 + 键盘（桌面为 0）合成一个整体，占有屏幕底部的高度 H；卡片上沿即「被占用区」的边界。
- **不遮选区就不动**：选区的墨迹（新建 = 选区矩形，编辑 = 该条标注的墨迹）整块都在卡片上沿之上时，
  卡片直接覆盖在页面上，页面一动不动。
- **会遮就整页上顶，且一次推满 H（2026-10-23 定形）**：只要卡片会压住选区，就把页面**上推 H**
  （H = 操作栏 + 输入行 + 键盘的总高度），推到「页面底边正好与卡片上沿相接」为止；
  顶部超出的部分直接截断。不再是「刚好让选区露出来」的少量推法——推满之后整页都在视口里，
  读者还能继续往下看刚才被盖住的部分。
- **只改绘制与命中，不改版式**：平移量是一个数（单一来源），
  - 页面画布（含翻页滑动层里的静止页）、选区覆盖层、手柄、放大镜、旁注覆盖层都按它平移；
  - 点按/长按/手柄命中在**屏幕坐标 → 页坐标**换算时加回同一个数；
  - **不分页、不重排、不重建栅格**（页位图只是整体位移，缓存照旧命中），也不动 `contentRevision`。
- 键盘收起 / 卡片关闭 ⇒ `shiftY` 归零（是否加一小段动画只是观感参数）。
- **视口内可上下滑（2026-10-23 新增）**：卡片开着时，视口 = 卡片上沿之上那一条（高 `屏幕高 − H`）。
  整页可以在这个视口里上下滑动：
  - 在页面区（卡片外）上下滑手指 → 页面跟着手指走，范围 `0 … H`（`0` = 页顶贴屏幕顶，`H` = 页底贴卡片上沿）；
  - 上下拖动手柄到视口边界 → 页面按步长自动滚，边滚边按手指位置延伸选区（能一路选到被盖住的部分）；
  - 读者自己滑过之后以他滑的位置为准；卡片关闭 / 换一条记录时复位，再按「遮不遮住」重新决定推不推。
- 卡片自身不参与平移：它永远贴键盘上沿；键盘动画过程中 `sheetTop` 逐帧变，页面跟着上顶，
  看起来是「页面给键盘让位」，而不是「页面被键盘盖住」。

#### 3. 退出输入后：旁注布点 + 箭头指向原文

**「空白」只排除四类东西（用户定形）**：判断能不能放旁注/箭头时，非空白**只认**——

1. **文字**：逐字墨迹矩形（不是「行的盒子」）；
2. **图形**：插图、图版等图形对象；
3. **表格**：表格整体（框线与全部单元格范围）算障碍，不在表格内部找空白；
4. **线条**：分隔线、框线、装饰线等画出来的线。

**其余全部算空白、可以压**：`blockquote` / `div` / `pre` 这类块的**非文字区**（底色、内边距）、
元素的 `margin` / `padding`、版心四周的四个页边距、行与行之间的空隙、行右侧没排满的地方、
首行缩进的留白。已经放好的旁注框本身当然要互相避开。

- 判据是**字的墨迹**而不是行的盒子：旧实现把整行当障碍，于是「行右侧还剩半截」也被判成压字，
  旁注索性不显示（缺陷 3 的一半原因）。
- **布点排序**（2026-10-23 四稿**定稿**，见 `docs/旁注布点与引线-实施方案.md` §0.1 / §1）：
  1. **环 → 整句 → 折行 → 就近 → 方向**（2026-10-27 用户定口）：环数是绝对第一优先，
     本行 → 隔 1 行……到空白连通范围边界（不再按段落截断）；同一环里先保整句、再比折行数，
     折行相同后先比额外引线长度，同距才比方向
     （右上/右下 → 左上/左下 → 正右 → 正左 → 正上 → 正下）；本行最右那条先占正右；右上/右下
     完整挡住右侧批注的上下出线时先走左上/左下；缩进行只让最左那条优先走左侧；
     满行左右页边距可用但排在四个角之后；
  2. **同环先整句、再截断**：近环截断先于远环整句（不再全页跑完整句档才开截断档，
     至少 4 字）；所有环都不行才退成小椭圆；
  3. **同一行多条**：先给最右那条占正右，再从左到右依次计算，但各自独立取位
     （不排成一列、不对齐）；
     占不到的走自己的下一格；别的空位都放不下、挡路的又占着同一块空白时，才请它上下让一让；
     落到这一行上方 / 下方的框（右下 / 右上 / 正下 / 正上）左缘不得越过**左侧那条批注第二个字的
     左缘**，也就是左侧那条第一个字的下方（或上方）始终空着，它的引线才接得进去；
  4. **标注本身占空白**：已放好的旁注框进障碍表，后面的标注不重叠、不紧贴；
  5. **标注不能紧贴文字**：留白只剩两档——空间够时正侧与正上 / 正下都留 **1em**，不够只收
     远离正文一侧到 **0.1em**，再不够就换位置；近侧一律不压：正右 / 正左 / 正上 / 正下守住 1em
     （引线从这里出去），**正上 / 正下推不出这 1em 就宁可不用这个方向**；四个斜向反过来，
     近侧固定 2px、横向特意错开一个字——那一个字是 L 形引线的走廊，不是摆放留白；
  6. **空白里怎么取位**：贴住锚点行 / 角——正右垂直居中于该行、右下 / 右上以末行第一个字
     右移一个汉字为基准、左下 / 左上以末行末字符左移一个汉字为基准，四个角上下贴该行行盒边
     留 2px；正上 / 正下横向与锚点对齐、离字墨迹 1em；贴不下才在空白内挪；
  7. **最少可读量 4 个字**：截断档也至少 4 字；不到 4 字或整页确实没空白时，退成原文右下角的
     0.5em 小椭圆（不画箭头，不参与其他标注的避让）；
  8. **框宽按字体 / 字号 / 行距 / margin 综合计算**：先算整句所需宽度，再看空白扣掉 margin
     后够不够；够就单行、按文字宽收窄，不够才按可用宽折行并得到行数与高度。
- **每条旁注配一条箭头**指向它的原文（§6）：
  - **只画横线、竖线与折线**（不画斜线、不画弧线），两端严格垂直于框边：
    - 先定终点：指向**离框更近的那一头**——比一比框到选区开头（首字左上角）与选区末尾
      （末字右下角）的距离，近开头就指首行起点、近末尾就指末行终点；单行选区看框中心落在
      这一行的左半还是右半，左半指行首、右半指行尾；正下 / 正上指向最近的字的对应边；
    - 再沿框边找能对齐的出口：上下左右摆法能画直线就画直线，不通才一折 → 两折 → 三折 → 四折绕开；
      **四个斜向必须画成 L 形两段折线**——从框的侧边横着出去，沿横向错开的那一个字走到选区角
      外侧，再竖着进字下 / 字上；不许变成贴着框的一条单线，也不许为了凑空档把批注推远；
  - **两端必须接触**：起点落在标注框边界上、终点落在锚点字墨迹边界上，**中间不许留缝**；
  - **起笔端朝正文那一头**：标注在右侧时从左侧（头部）起笔，在左侧时才用右缘；
  - 避让用的是**逐字墨迹**，不是整行行盒：线段不得进入字的墨迹，但**可以从两个字之间、
    标点前后的空白穿过**；图形、表格框线、线条、其他标注框同样要避；
  - **箭头必须画**：唯一例外是小图标形态。直线 / 一折 / 两折 / 三折 / 四折全撞时，
    取「穿得最少、最短」的一条照样画，**不返回空**；
  - **只避那四类障碍与标注框**：从块底色、`padding`、`margin`、页边距上穿过是允许的（那里本来就是空白）；
  - 箭头颜色 = 该条标注的墨色（将来可被「批注样式」覆盖，见 D-29），线细、箭头小；
    箭头画在旁注框之下（同一覆盖层里先画线后画框）。
- 旁注与箭头都是**纯覆盖层**：只读行几何、图版/表格/线条几何与页面位移，不进分页、不进栅格、
  不触发重排；翻页动画期间整层让位（与选区覆盖层同口径）。
- 点旁注框或小省略号图标 = 打开这一条（键盘 + 操作栏，带出原文字）；点箭头不额外响应（箭头不可点）。

#### 4. 点按与滑动：点按避开标注/链接，滑动照常翻页

- **单击已有标注（高亮 / 划线墨迹）或旁注框 = 直接打开键盘 + 操作栏**（带出这条记录的颜色与批注），
  不再需要长按；长按同一条记录保留同等效果（不删）。**单击链接 = 跳转**。
- **点按要避开标注 / 链接区**：三区点按（左翻 / 中间切栏 / 右翻）只在按下点**不落在**标注墨迹、
  旁注框或链接上时才成立；落在它们上面的一记「点按」归它们（打开操作栏 / 跳链接），不翻页。
- **滑动不受此限**：点击与滑动本来就能分开（现有判据就够——越过 tap slop 即滑动，
  未越过且时长在阈值内才算点按）。所以**从标注 / 链接区起手也可以滑动翻页**：
  一旦判定成滑动，标注与链接一概不触发，照常翻页 / 切栏 / 调亮度。
- 判定口径：
  - 归属只在**按下点**判一次，抬手点与途经点都不参与；
  - 按下点在标注 / 链接上 ⇒ 先记成候选：抬手时**没动过**（点按）就打开 / 跳转；
    **动过**（滑动）就什么都不打开，按滑动处理；
  - 滑动途经标注或链接区 ⇒ 一律不触发（与按下点在哪无关）。
- 现有实现要改两处：链接命中从「抬手点」改成「按下点」；标注命中从「只有长按」扩到「点按 + 长按」。
- 有选区时点按正文 = 清选区（沿用 D-11）；点标注则先清选区再打开那一条。
- 这条规则也是「操作栏必须贴在键盘上方」的理由：打开操作栏的那一下点击就发生在标注本身，
  卡片不能反过来盖住它（第 2 部分的整页上顶来保证这一点）。

#### 5. 与既有决策的关系

- D-26 的附件模型、`note` 列、清单筛选**不变**；D-27 的输入条**保留**，只是挪到操作栏下面。
- 浮动菜单里「取消」早已去掉，这次连「弹窗」本身也去掉：操作栏是阅读页的一部分，不再有锚点。
- 仍然**不改排版**：整页上顶与旁注/箭头都是覆盖层与绘制位移，`Paginator` / 分页表 / 磁盘表一概不参与。

## 3. v1 交互规格（提案，实现前定稿）

> 下面这些是配套的量化细节，方向已认可，具体数值可在实现时微调。

### 3.1 长按与手柄

- 长按时长用系统的 `longPressTimeoutMillis`（Android ≈500ms），不自造。
- 长按后**手指不抬起、直接移动 = 扩选**；**抬手 → 出菜单 + 显示两端手柄**。
- 手柄：视觉圆点 ~12dp，**命中范围 ~44dp**；贴在选区首 / 末行下缘；贴屏幕边自动内移。
- 长按选中的单位按 D-7（英文词 / 中文句）。
- **跨页时手柄只画落在当前页的端点**：另一端在别的页就暂不显示（翻回去即出现），
  **不画贴边的假手柄**；正在拖动的那个手柄永远在手指所在页。
- 手柄拖动按**字符**微调（长按起手才按 D-7 的整词 / 整句）；跨页后仍按字符继续。
- **当前落地**：长按立即出选区与两端手柄；抬手后出浮动菜单；手柄拖到左右页边会自动翻页并接力，
  到章首/章末停住并提示；长按与拖手柄期间会显示移动端放大镜。

### 3.2 浮动菜单

- v1 项：**高亮 / 划线（切类别）/ 复制 / 删除**（批注 v2 再加）。
- **一步到位**：打开即摊开**上次用过的类别**的色槽行，点一格颜色就落笔；
  顶部的高亮 / 划线只用来换类别（不再是「先展开色槽」的第一步），因此按钮上不需要类别色小圆点。
- **只有一套菜单**：新建（选区抬手）与编辑（长按已有标注）共用同一个弹窗，
  差别只在初始类别（编辑时用该条自己的类别）与删除是否可用。
- **不设「取消」项**：点菜单外面即关（长按场景有透明遮罩，选区场景由正文点按清除选区）。
- 删除：有可删记录（长按命中的那条，或选区与之相交的第一条）时才亮，否则虚掉且点了没反应。
- 位置：选区上方；贴顶则放下方；跟随选区变化。
- 阅读层目前零 `Popup` 使用 ⇒ 需确定用 Compose `Popup` 还是自绘覆盖层（与栅格层同制）。
- **当前落地**：自绘覆盖层（不用 `Popup`）；色槽行常显（默认格描金边 = 上次用的那格，
  编辑时当前色描强调边），点一格就用该格当时的 ARGB 快照创建（编辑时则改该条）并立即落库，
  同时把「类别 + 该格」记进设置（下次打开停在这里）。
  复制走整章原文并在块边界补换行（编辑时复制该条覆盖的原文）。

### 3.3 跨页自动翻页

- 触发：手柄进入距左 / 右页边 ≤ 24dp 并**持续 ≥ 300ms** → 翻一页；手指不放则每 400ms 再翻。
- 翻页**瞬切**（D-12），且**等目标页就绪再继续**（栅格 ~0.2s，不等会白一帧）。
- 翻页**必须走现有导航漏斗**（与链接跳转 / 目录跳转同一条提交路径）：
  位置提交后照常保存进度、按总则启用本章临时表 / 切换磁盘表。
  **不要**直接调宿主翻页查询口——那条口是只读的，推进指针会多翻一页（已有真机事故记录）。
- 到章末 → 停住（D-8 不跨章），并给提示（见 3.5）。
- **当前落地**：手柄进入左右页边 24dp 后等 300ms 瞬切一页，按住不放每 400ms 再翻；
  翻页后手柄按手指 y 接到新页最近行的靠边字；到本章首/末页停住，选区封顶到边界并提示。
  真机已验证向前连翻两页、接力与章首停住；章末向前停住走同一套边界判定。

### 3.4 放大镜（移动端）

- 圆形，直径 ~96dp；倍数 ~1.5x；中心悬在手指**上方 ~56dp**；贴屏幕边自动内移。
- 内容复用页栅格位图放大绘制（`PageRasterStore.obtain`），**纯用户层**。
- 出现时机：长按开始 + 拖手柄时（跟随当前拖动的手柄）。
- **当前落地**：`SelectionMagnifier.kt` 把同一页内容再画进圆形裁剪层并做 1.5 倍图层缩放；
  渲染器实例与 `PageContent` 都和当前页共用，命中现有页位图缓存，不重烤、不重排版。
  位置由纯函数 `magnifierCenter` 计算，贴顶翻到下方、左右上下内移；桌面鼠标不显示。

### 3.5 其它

- 章末停住提示：移动端轻触感；桌面一句 snackbar。
- 复制：内容 = 选区章内区间的**原文**（跨样式不带格式）；走 **D-18 的章节文本**，
  **不要**拼 `DrawLine.text`（行片段会漏字 / 重字）。块与块之间在复制结果里补换行，
  但换行不参与标注偏移。另需**剪贴板 expect/actual**（全仓目前零剪贴板代码）。
  复制后保留选区并提示「已复制」。
- 桌面键盘扩选（Shift+箭头）v1 不做。
- 高亮默认以 **~45% 不透明度**铺背景（荧光笔感）；划线粗细 / 位置刻意与书内下划线错开
  （更粗 ≥0.08em、更靠下），避免与书自带的线糊在一起。

## 5. 落地接线要点（实现前先定）

> 前面写的是「做什么」，这一节是「接在哪」。这几条不定清楚，写下去必返工。

### 5.1 装饰 run 怎么进到页里（分层关键）

- 数据流：DB → 宿主 → `shared-ui`（共享）→ **引擎的纯投影函数** → `DrawLine` 上的装饰 run。
- **投影必须在 `engine-skia`**（`LineAligner` 是 internal，`visibleSpan` 是唯一「区间 → 几何」入口）；
  但**取数据与调用点必须在 `shared-ui`**（commonMain，三端共享）——
  **不能**让宿主（平台侧）去投影，否则 Android / 桌面各写一遍，违反 KMP 共享约束。
- 落点：`rememberPageContent`（`PageContent.kt:87`）里，`host.pageLines(pos)` **保持原样记忆**，
  在其后**另加一步投影** `remember(rawLines, 本章标注列表, 装饰修订号)`（标注列表与修订号由
  `shared-ui` 自己持有，见 D-19 / §5.4）；`rememberPageContent` 因此要新增这两个入参。
  后面所有消费 `lines` 的地方（栅格 spec、`pageFrameLead` 等）改用投影后的行。
- 栅格失效**自动**：`PageRasterSpec.fingerprint()` 按值比较 `lines`（`DrawLine` 是 `data class`），
  装饰 run 一变即未命中重烤 ⇒ **不需要动 `contentRevision`，也不需要平台壳配合**。
- 预栅格同章邻页也走同一投影；**跨章目标暂不投影**（`shared-ui` 只持当前章列表，宁缺勿串），
  真页绘制时会按目标章重算。等后续需要时再把目标章标注一并加载，不动这条数据流。
- `DrawLine` 要新增一个装饰 run 字段（默认空）——这会改变它的值相等，正好是上面重烤的判据；
  旧构造点不传即行为不变。

### 5.2 引擎需新开的公开 API（渲染层）

- `projectDecor(lines, chapter, ranges) -> lines'`：把章内区间合进每行的装饰 run（烘焙用）。
- `decorRects(lines, chapter, range) -> List<Rect>`：只算几何、不画（拖拽覆盖层与手柄定位用）。
- 已落地：`DecorProjection.kt` 定义 `DecorKind` / `DecorRange` 与 `projectDecor`；
  `LineWindowDrawer.decorRects` 是几何入口（`Rect.x` 相对内容区左缘，`y` 为章节绝对 Y）。
  `DrawLine.decorRuns` 存**章内全局区间**，绘制侧按 `charBase` 换回行文本坐标；高亮底色在
  文字之下、书内行内盒之上，划线在文字与书内装饰之后（默认 `0.08em` 粗、基线下 `0.20em`）。
- 两者都复用 `LineWindowDrawer` 既有的 `aligner.visibleSpan(placement, n, ps, pe)` 路径
  （`LineWindowDrawer.kt:427/513/654`），保证**命中 / 绘制 / 装饰三者同一份几何**。
- **「点 → 章内字符」不另开引擎口**：复用现成的三步
  `ReaderMath.tapLineAt`（屏坐标 → 行）→ `LineHitTest.hit`（行内字形）→ `DrawLine.charBase`（章内偏移），
  在 `shared-ui` 收成一个 `charOffsetAt(...)`。**不要**另写一套反查几何。
- **页坐标换算抽公共函数**：`shift = pageAnchorY(行/图/背景/页首缺口) - 内容顶`。
  画布、链接点按、选区覆盖层、手柄、放大镜共用同一个 `pageShift(...)`；
  现状画布与链接点按各算一遍，第三次再抄必然漂移（链接点按有过整页偏移的事故记录）。

### 5.3 放大镜要拿到当前页位图（需要提权）

- 页位图现在**私有在 `ReaderPageCanvas` 内的 `PageRasterStore`**（由 `rememberReaderPageRenderer()`
  持有），`ReaderScreen` 拿不到。
- 放大镜**必须复用当前页已烤好的位图**（每帧重烤一页 ~0.2s，不可行）。
- **最终实现（不改接口）**：`SelectionMagnifier` 把同一页的 `PageContent` 和**同一个**
  `ReaderPageRenderer` 交给一个全屏 `ReaderPageCanvas`，外层只做圆形裁剪 + 1.5 倍
  `graphicsLayer` 缩放。`ReaderPageCanvas` 的 `renderer.drawLines` 会命中渲染器现有的
  `PageRasterStore`，因此像素与静止页同源，也不需要在 Android 侧每帧把 skia 图转成
  `ImageBitmap`（那会多一次整页拷贝）。代价是放大镜组合里多一层全屏画布，但绘制仍是一张
  缓存位图，不是重烤。

### 5.4 标注数据怎么到 shared-ui（D-19 落点）

- `shared-ui` 是 commonMain，可以依赖 common 的 `LibraryDb`；但 db 实例在宿主手里。
- 沿用现有模式（如 `onSaveProgress`）：**扩展 `ReaderHost` 的四个后台口**——
  「读本章标注 / 增 / 改 / 删」，宿主转手给 `LibraryDb`（实现集中在 common，平台侧只是转发）。
- **当前章列表由 shared-ui 持有**（D-19）：进章时读一次，放进 Compose 状态；
  增删改先改这份内存列表并递增装饰修订号，再异步落库（失败回滚 + 提示）。
  投影、长按命中、画覆盖层都读这份列表，**不查库**。
- 新增**同步**章节文本口（D-18）：`textOf(chapter, start, end)`（复制 / 选词 / 断句共用），
  与 `pageLines` 同级、开章时已缓存；**不要**做成异步。
- 长按查已有标注：直接在这份内存列表里按「章号 + 字符区间」找
  （`charStart <= off && off < charEnd`），**无需几何反查、无需查库**。

### 5.5 剪贴板平台缝

- 实际落地：使用 Compose Multiplatform 的 `LocalClipboardManager`，共享层直接取用，
  Android / 桌面各自平台实现由 CMP 提供；**不需要**再新开一套 `expect`/`actual`。
- 复制内容仍走 D-18 的整章原文，块间补换行只进剪贴板，不参与标注偏移。

### 5.6 手势状态机的改造原则（风险最高）

- 现有手势块是**长期调优过的**（`ReaderScreen.kt:828` 起，注释里记着多起「点了没反应」
  「快速闪一下」的历史缺陷），且已有单测（`ReaderLogicTest`）。
- 原则：**新增分支，不重写**。长按只加一条「未移动 + 超时」的旁路；
  手柄做成**覆盖层独立手势区**，避免主状态机去懂多指。
- 互斥守卫（D-12）**复用**现有的会话繁忙判定（`ctl.isBusy()`），不另立状态。

### 5.9 颜色槽的存储（D-13 落点）

- 存 `ReaderSettings`（**全局**，`settingsDir/reader.json`），与书无关。
- 读取是**手写 `opt*` + 默认值**（`ReaderSettings.fromJson`；`SettingsJson` 为
  `ignoreUnknownKeys` + `encodeDefaults`）⇒ **老存档缺键即取默认**，
  故新增色槽字段**不必强制 bump** `CURRENT_SCHEMA_VERSION`（现为 1）；
  只有当需要**改造旧值**时才 bump（先例：`migrateCjkLatinSpacing`）。
- 色槽形态建议：每类 4–5 槽，各存 ARGB `Int`（含 alpha）；另有「默认槽索引」。
- **当前字段**：`highlightColorSlots` / `underlineColorSlots`（各 5 个 ARGB `Int`）与
  `highlightDefaultSlot` / `underlineDefaultSlot`，另加浮动菜单的「上次类别」
  `annotationLastKind`（`highlight` / `underline`）与「上次线型」`annotationLastLineStyle`
  （`straight` / `wavy` / `dashed` / `strike`）；六者都登记进 `withoutNonLayout`
  （只改像素、不触发重排），设置面板的改色行走无重排提交。
  读取用 `SettingsJson.optIntList`：缺键/非数组取默认，短列表补齐、长列表截断到 5 格；
  默认槽索引越界自动钳到 `0..4`；上次类别未知值一律按高亮。因此老存档不需要迁移。
- **必须显式登记为「纯全局」**：落盘走的是双层设置——排版字段进按书增量，另有一份
  「与书无关的全局偏好」白名单才直写全局。标注这一族若两边都不登记，`changedFrom`
  看不见它 ⇒ 既不进按书层也不进全局，**改完等于没存**（重启回默认；设置面板的
  「笔记」页同样中招）。因此色槽四件与上次类别一律进全局直写，不进按书层。
