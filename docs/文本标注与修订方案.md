> [`引擎欠账-对齐浏览器语义.md`](引擎欠账-对齐浏览器语义.md)（0.4.7 计划）。

## 1. 目标与分期

用户原话（2026-10-17）：*这些功能作为**原书 html 的外挂附件**，进入阅读页面时提前处理、注入 html 文档、
并渲染呈现。目前先做**选区、画线、高亮**这些基本功能，稳定以后再添加**批注**，再以后才是真正会改变
html 内容的：**删除、修改、添加文字**。引入修改功能后，要参考 word 的审阅页面，添加**第二种视图模式**，
让用户能看到自己对 epub 的修改内容。这些后面再做，但**目前在架构上要先具备这个框架基础**。*

| 期 | 内容 |

| **v2** | 批注（文本框 / 标注列表面板 / 编辑与删除） |

## 2. 决策记录（逐条追加）

### D-1 锚点 = 章号 + 章内字符区间（与 `ReadingLocator`/`PageSlice` 同源）

- 表达为 `[charStart, charEnd)`，即用户所说的「原 CFI」；**不新造坐标**。
  （`ReadingLocatorCodec` 存 `chapter:char`；`PageSlice.charStart/charEnd`；页表 `PageRecord` 同源。）
- **所有标注都相对「原书」解算**：书不动，偏移就不动；标注之间**永不互相漂移**；
  排版参数改变（字号 / 边距 / 主题 / 旋转）不影响锚点。
- **装饰类不触发重排**；将来**内容修改**改变文字 ⇒ 该章必须重排一次 —— 这是唯一代价，接受。
- 引擎升级导致归一化口径变化的风险：**暂不处理**（还没有用户），与书签/阅读进度同一风险等级。

### D-2 渲染 = 专用「区间装饰通道」，不注入 CSS 标记，也不用 `border`

- 依据：`text-decoration` 在 CSS 里是「每元素一套、绘制时重合」，**无法与书内已有的下划线共存**
  （只能有一条线，且当前连颜色都改不了）；`border` 是「不得已」手段，**不采用**。
- 规范对应物：**CSS Custom Highlight API（`::highlight()`）** —— 样式挂在**区间**上而不是节点上，
  因此不去抢书作者元素那个「每元素一套」的槽位，可带自己的颜色 / 粗细 / 位置叠加在文字装饰之上。
- 本引擎里对应 **run（区间 + 样式）** 机制。
- 这条通道**同一个东西**同时服务：**临时选区**、**持久标注**、将来**审阅视图的标记**。
- 颜色随记录直达绘制，**不进 CSS 级联** —— 它是「用户侧叠加标记」，不是覆盖书样式的声明
  （故不涉及《样式层叠优先级》的 tier 之争）。

### D-3 标注层 = 两种应用模式，共用锚点与存储

| 模式 | 载体 | 用途 | 动树 / 重排 |
|---|---|---|---|
| **装饰模式（区间）** | 区间装饰通道（D-2） | 高亮、划线、选区、审阅视图标记 | 否，零重排 |
| **内容模式（节点）** | 注入 / 改写 `MarkupElement` | 将来删 / 改 / 加文字（v3） | 是，该章重排 |

- v1 只跑**装饰模式**；**内容模式的位置预留好** —— 这就是用户要的「框架基础」。
- 内容模式下注入会碰「import 时算结构 / open 时 relink」的持久化快路径
  （`PersistedChapterFile`；`MarkupElement.children` 是 `val`，注入 = 重建节点）。
  两条路待 v3 时定：**(a)** relink 之后受控就地插入（保叶身份与字符偏移，快路径不退化）；
  **(b)** 该章 open 时重算结构（丢持久化收益）。

### D-4 绘制归属与缓存

- **「字符区间 → 纸面矩形」只能在 `engine-skia` 做**（`LineAligner` 是 `internal`，只在渲染层可见）。
  用户层（`shared-ui`）只提供「章号 + 字符区间 + 样式」，消费结果。
- **持久标注烘焙进页面位图**：机制是「行数据变 ⇒ 指纹变 ⇒ 自动重烤」——
  `PageRasterSpec.fingerprint()` 按**值**比较 `lines`（`DrawLine` 与 `PageRasterFingerprint` 都是
  `data class`），行里的装饰 run 一变即未命中重画。位图池是**内存**的（`PageRasterStore`，非落盘）
  ⇒ 无旧像素残留。翻页动画 / 预栅格 / 两级分辨率天然一致。
- **不要复用 `contentRevision`**：它是**版式**修订号，由平台壳在**重排之后**推入
  （`ReaderActivity.applyReflowResult` / 桌面 `ReaderView` 的推送），`shared-ui` 无权 bump，
  语义也是「版式变了」而非「标注变了」。
- 正确做法：`host.pageLines(pos)` 的记忆**保持不变**，在其后**另加一步投影**
  `remember(rawLines, 装饰修订号)`；该修订号由 `shared-ui` 自己持有
  ⇒ 标注增删改**既不触发重排，也不必惊动平台壳**。
- **拖拽中的选区**不能每帧重烤（一页栅格 ~0.2s）⇒ 走**轻量覆盖层**路径，几何与烘焙同源，
  只是「即时画」而非「烘焙」。

### D-5 通道契约草案（渲染层定义，用户层消费）

```kotlin
// engine-skia（渲染层）：输入是章内字符区间 + 样式；输出是 DrawLine 上的行内 run
enum class DecorKind { BACKGROUND, UNDERLINE }   // 将来 OVERLINE / LINE_THROUGH

data class DecorRange(
    val start: Int,            // 章内字符偏移（与 ReadingLocator / PageSlice 同源）
    val endExclusive: Int,
    val kind: DecorKind,
    val argb: Int,
    val thicknessPx: Float? = null,
    val offsetPx: Float? = null,
    val priority: Int = 0,     // 叠加次序（例如选区压过标注）
)
```

- 归集的现成 seam：`styledSegments` 的每个 `StyledSegment` 都带 `node`（`StyledText.kt:55-60`），
  照 `collectUnderlineRuns` 的写法扩展即可。
- 绘制次序按规范：块背景 → 行内装饰背景 → 文字 → 下划线 / 着重号。

### D-6 存储 = SQLDelight 表（数据库），不用每书一个附件文件

- 新增一张标注表（终态表 + 一条迁移），与 `reading_states` 同源、同库、同事务。
- 形态（草案）：

  ```sql
  CREATE TABLE annotations(
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    bookId INTEGER NOT NULL,
    chapter INTEGER NOT NULL,
    charStart INTEGER NOT NULL,      -- 含
    charEnd INTEGER NOT NULL,        -- 不含（与 PageSlice 同口径）
    kind TEXT NOT NULL,              -- highlight / underline / note / ...
    color INTEGER,                   -- ARGB
    note TEXT,                       -- 批注文本（v2）
    createdAt INTEGER NOT NULL,
    updatedAt INTEGER NOT NULL
  );
  CREATE INDEX annotations_by_book_chapter ON annotations(bookId, chapter);
  ```

- 删书时与 `books` 同事务一并删除（不留孤儿）。
- **代价（已接受）**：标注不再是一个「用户可见、可随手拷走」的附件文件；
  将来导出「改过的 EPUB」要**另写一个导出器**（从库里取记录 → 生成补丁/新书），
  而不是像附件文件那样「天然就是补丁」。这是选 A 换取事务安全与查询便利的明账。
- **加一层接口**：读写走一个共享层的存储接口，DB 只是它的一个实现；
  将来若要做「可导出的附件」，在接口下再加一个实现，不必动上层。

### D-7 选区单位 = 英文按词、中文按句

- 英文「词」：文档空白 + 常规标点，撇号 / 连字符连缀。
- 中文「句」：以全角句末标点（`。！？…；` 等）断句，闭引号 / 闭括号归前句。
- **关键收益**：两者都**不需要分词器**，**不开平台 `BreakIterator` 缝**，纯共享层可做。
- 待细化：句末标点集合、换行是否算句边界。

### D-8 跨页 v1 必做；不跨章

- 交互模型：**拖手柄到页边缘 → 自动翻页并继续扩选**（移动端标准做法）。
- **手柄接力规则**：手指位置不动，翻页后手柄跳到**新页最靠近手指那一侧的行**，继续跟随手指。
- **不跨章**：拖到章末页边缘即停住（选区封顶到章末），保持「一条标注 = 一个章内区间」的模型。
- 存储不受影响：跨页只是**同一章内的区间变长**。
- 渲染：选区跨页时，每页只画该页与选区的**交集**；翻页动画期间选区覆盖层如何呈现，待细化。
- **架构约束**：自动翻页**不能**复用滑动翻页的手势会话（同一根手指正在拖手柄），
  需由选区逻辑驱动一条**独立的翻页路径**。

### D-9 桌面鼠标：只能拖选，不能拖动翻页

- 需要按**指针类型**分流（触摸 / 鼠标），而不是两套 `pointerInput` 硬抢。
- 鼠标**拖拽 = 文本拖选**（桌面最自然）；**不允许拖动翻页**。
- 鼠标**点击左右页边距**翻页（「页边空白区」= **左右页边距**；上下页边距不算）。
- 桌面翻页**主要依靠键盘**（左右箭头，现有能力）。
- 鼠标**点正文区 = 无操作**（既不翻页也不清选区）。
- 触摸端的滑动翻页与三区点按**保留**（只改桌面鼠标）。
- 后果：桌面鼠标的**跟手滑动动画随之取消**（键盘与点击翻页仍走动画）。
- 分流按**指针类型**，不按平台——Android 平板接鼠标同样走鼠标语义。
- 实现注意：现有三区点按按屏宽 1/3 判定，桌面「点左右页边距翻页」要改成按**版心几何**
  （内容左/右缘之外的页边距区域）。
- 落地：鼠标按下后**移动超过点按阈值**才起选区（单击正文不闪选区）；点左右页边距走翻页动画，
  正文单击无操作（不翻页、不清选区、不触发链接）；触摸端的长按/滑动/三区点按不变。

### D-10 放大镜：移动端要，桌面不要

- 纯**用户层**（shared-ui）实现：复用页栅格位图放大绘制，不涉及排版层与渲染核心。
- **当前落地**：直径 96dp、1.5 倍、圆心优先在手指上方 56dp，贴顶翻到下方、贴边内移；
  长按起手和拖手柄时出现，松手即消失；桌面鼠标不出现（按指针类型判定）。
  实现上不另取位图，而是把同一个 `PageContent` + `ReaderPageRenderer` 再画进圆形裁剪层，
  由渲染器现有的页位图缓存直接命中，所以与静止页像素同源。

### D-11 移动端：三区点按保留，长按进入选区

- 点按三区（左 1/3 后退 / 右 1/3 前进 / 中间切栏）**必须保留**——这是移动端的主要翻页方式。
- **长按**是进入选区的唯一入口；进入选区后，点按改为「清除选区」（不翻页）。
- 桌面无「长按」语义，改由鼠标拖选进入（见 D-9）。

### D-12 动画与选区互斥（时间维）

- 翻页动画 / 滑动会话进行中 → **不响应**长按与选区手势（现有 `ctl.isBusy()` 守卫扩用）。
- 选区手势进行中（长按起手 → 抬手，或按住手柄拖动）→ **不播任何翻页动画**；
  跨页翻页一律**直接跳（瞬切）**，不做淡入。
- 选区**已存在但未在操作** → 翻页不受限（点按 / 滑动 / 键盘），翻页后选区保留，各页只画交集。
  - 触摸端例外（D-11）：有选区时**点按 = 清除选区**、不翻页 ⇒ 此时翻页走滑动或键盘。

### D-13 颜色体系：用户可自定义调色板

- 高亮与划线**各自一组色槽**（4–5 个）；每个槽的**颜色与透明度**（ARGB）由用户自定义。
- 两类各有一个**默认色槽**（新建标注时用它）。
- 归属：**全局**（`ReaderSettings`），跨书统一——与字体 / 主题同类。
- 记录里存的是**创建当时的颜色**（解析后的 ARGB 快照）⇒ 改调色板**不影响已有标注**（墨迹已干）。
- 颜色仍**不进 CSS 级联**（延续 D-2）：它是标注自身颜色，不是覆盖书样式的声明。
- **当前落地**：高亮 / 划线各 5 格，存 `ReaderSettings` 的 `highlightColorSlots` /
  `underlineColorSlots`（ARGB `Int`），另存 `highlightDefaultSlot` / `underlineDefaultSlot`。
  设置面板「标注颜色」页可逐格改 RGB 与透明度、点「设为默认色槽」；浮动菜单点高亮/划线后
  展开五格，点哪格就用哪格颜色创建标注。老存档缺键自动取默认，无需 bump 结构版本。

### D-14 已有标注可编辑 / 删除（v1 必做）

- 入口：**长按已有标注 → 该标注的编辑菜单**（改色 / 删除）；长按空白 → 新建选区。
  语义统一为「长按 = 针对此处」。
- 跨页标注是一条记录，菜单作用于整条。

### D-15 视图模式按书持久化

- `CLEAN` / `REVIEW` 的状态**按书**存（每本书各自记），因为它描述的是「这本书的展示方式」。
- v1 恒为 `CLEAN` 且**不暴露界面**，只为 v3 的内容修改预置位置。

### D-16 颜色设置界面 = 共享 Compose，不开平台分支

- **不做**安卓 / 桌面 / iOS 各自的平台对话框；做**一套共享 Compose 界面**，挂在现有面板体系里
  （`ReaderSettingsPanel` / `FontLibraryPanel` / `ReaderTocPanel` 同制，复用 `paletteFor(scheme)`）。
- 理由：① `AGENTS.md` 的 KMP + CMP 约束要求基本组件跨平台共享；
  ② **Android 没有系统颜色选择器**，本来就得自绘；③ 透明度支持三端系统选择器参差不齐，自绘最省事。
- 形态建议：**色槽网格 + 透明度滑条**（必要时补 HEX 输入）。细节见待决。
- **当前落地**：设置面板内新增「标注颜色」页（与现有设置页同制，复用 `paletteFor(scheme)`）：
  高亮/划线切换、五格色槽、十格快捷色、红/绿/蓝/透明度四条滑条、默认色槽按钮。
  不新增第三方依赖，也不开平台颜色对话框；未做 HEX 输入。

### D-17 删书清理走共享的「一次删三张表」（事务）

- 现状**没有外键级联**，且两个平台各自删、**非事务**：
  - Android `BookRepository.removeBook` = `db.removeBook(id)` + `db.clearReadingState(id)`；
  - 桌面 `ShelfStore.delete` = `requireDb().removeBook(id)` + 删文件（**不碰** `reading_states`）。
- 定案：在 `LibraryDb` 加**一个共享方法**（`removeBookAndData(id)`），用 `db.transaction { … }`
  一次删 `books` + `reading_states` + `annotations`；两个平台都改调它。
- 顺带收益：修掉现状「删书与清进度分两步、非原子」的问题（中断即留孤儿）。
- 注意：改了桌面既有行为 ⇒ 实现后必须实测「删书 → 三张表都干净」。

### D-18 章节文本 = 引擎投影，同步、与排版同源

- **问题**：全仓没有「取整章原文」的现成入口。`DrawLine.text` 只是**行片段**
  （按页窗口切开、带断行与行尾连字符），直接拼会漏字 / 重字，复制出来与原文对不上，
  选词与断句也会跟着错。宿主侧同样没有章节文本查询。
- **定案**：在**排版层（下）**新增章节文本投影，复用
  `NormalFlowLayout.leafText`（与塑形同一份归一化字符串）+
  `ChapterPrepareResult.globalCharStarts`（与 `DrawLine.charBase` 同一套章内偏移），
  按叶序拼出整章文本。这样「排版用的字」「标注锚点」「复制/选词用的字」是**同一份**。
- 另给「按区间取原文」：块与块之间在**复制结果**里补换行，但**换行不计入偏移**
  （偏移只认排版字符流）。
- **必须同步**：长按是手指按下即要出结果的手势，不能走异步往返。宿主在开章排版时
  顺手缓存，`textOf(chapter, start, end)` 与 `pageLines` 同级（廉价、立即返回）。
- 归属：投影与切片都在共享层（排版层（下）），平台宿主只是转发；**不允许**两个平台各拼一遍。

### D-19 标注列表由 shared-ui 自持，数据库只在开章与保存时参与

- 阅读页要同时做三件事：画当前章的标注、长按命中已有标注、增删改后立刻可见。
  每帧查库会卡，异步往返又会让长按有延迟。
- 定案：shared-ui 进章时读一次，**持有当前章的标注列表（Compose 状态）**；
  新增 / 改色 / 删除先改内存并递增「装饰修订号」（界面立刻更新），再异步落库；
  落库失败回滚并提示。
- `ReaderHost` 只加四个后台口：读本章、增、改、删（平台实现转发给共享的 `LibraryDb`）。
- **不做**「监听数据库变化」的通用流：v1 只有这一个写入口；等 v2/v3 出现第二个写入口再补。

### D-20 视图模式延后到 v3：开关在阅读页底部工具栏，与书架无关

- 用户 2026-10-20 明确：审阅视图属于后面「内容修改」阶段的功能，
  开关预计放在**阅读页底部工具栏**，不是书架 / 书目属性。
- 因此 **v1 不建视图模式列、不建表、不存任何状态**；原 §5.10 的
  「`books` 加一列」建议**作废**（且与现有整行覆盖写入冲突，见 §5.10）。
- D-15 的「按书持久化」保留为 **v3 待定**：真做到内容修改时再定落点与默认值。

### D-21 颜色面板 = 共享自绘，不调平台颜色对话框

- 核实（Compose Multiplatform 1.11）：**没有官方颜色选择器组件**；通用 `Dialog` / `Popup`
  只是容器，取色控件仍要自己写。
- 平台系统对话框不可行：Android 本身没有系统取色器；桌面只有旧式 Swing 组件，
  风格与阅读器面板不一致，两端行为也不齐。
- 定案：沿用 D-16，**自绘共享 Compose 面板**（色槽网格 + 透明度滑条 + 可选十六进制输入），
  不新增第三方依赖，不开平台分支。色槽值存 `ReaderSettings`（§5.9）。

### D-22 自定义样式 = 读者规则层，压在 UI 之上

- 用户 2026-10-20 明确：选中一段内容后，应用反查候选选择器
  （元素本身、父元素 > 子元素、类名、ID、父类名 > 子元素等），**按具体程度从高到低**列出；
  读者挑一条选择器，再挑样式、填属性值，最后生成一条规则。
- 这不是「给一个元素塞内联样式」，而是**读者自己写的 CSS 规则**（选择器 + 声明）。
  因此它属于读者侧，整体压过书本；读者内部，它高于 UI 的全局偏好。
- 层叠顺序：`自定义样式（45/49） > UI（44/48） > 主题（42/46） > 书本 > UA`。
  层内仍按选择器特异度与源码序决胜；候选排序只帮读者选作用范围。
- **规则必须以样式表注入**，不能写成元素上的内联 `style`：内联样式在引擎里属于书本侧
  （tier 30），会被任何读者层压掉。
- 宽选择器（如 `p`）也会压过 UI 的全局设置，界面需显示命中范围 / 预览并提示。
- v1 不做（高亮 / 划线走装饰通道，不经过样式层叠）；v3 内容修改如需样式，走这一层。

## 3. v1 交互规格（提案，实现前定稿）

> 下面这些是配套的量化细节，方向已认可，具体数值可在实现时微调。

### 3.1 长按与手柄

- 长按时长用系统的 `longPressTimeoutMillis`（Android ≈500ms），不自造。
- 长按后**手指不抬起、直接移动 = 扩选**；**抬手 → 出菜单 + 显示两端手柄**。
- 手柄：视觉圆点 ~12dp，**命中范围 ~44dp**；贴在选区首 / 末行下缘；贴屏幕边自动内移。
- 长按选中的单位按 D-7（英文词 / 中文句）。
- **跨页时手柄只画落在当前页的端点**：另一端在别的页就暂不显示（翻回去即出现），
  **不画贴边的假手柄**；正在拖动的那个手柄永远在手指所在页。
- 手柄拖动按**字符**微调（长按起手才按 D-7 的整词 / 整句）；跨页后仍按字符继续。
- **当前落地**：长按立即出选区与两端手柄；抬手后出浮动菜单；手柄拖到左右页边会自动翻页并接力，
  到章首/章末停住并提示；长按与拖手柄期间会显示移动端放大镜。

### 3.2 浮动菜单

- v1 项：**高亮（展开色槽）/ 划线（展开色槽）/ 复制 / 取消**（批注 v2 再加）。
- 位置：选区上方；贴顶则放下方；跟随选区变化。
- 阅读层目前零 `Popup` 使用 ⇒ 需确定用 Compose `Popup` 还是自绘覆盖层（与栅格层同制）。
- **当前落地**：自绘覆盖层（不用 `Popup`），四项均可点；点高亮/划线先展开五格色槽，
  点某一格就用该格当时的 ARGB 快照创建并立即落库；默认格带金色描边。
  复制走整章原文并在块边界补换行。

### 3.3 跨页自动翻页

- 触发：手柄进入距左 / 右页边 ≤ 24dp 并**持续 ≥ 300ms** → 翻一页；手指不放则每 400ms 再翻。
- 翻页**瞬切**（D-12），且**等目标页就绪再继续**（栅格 ~0.2s，不等会白一帧）。
- 翻页**必须走现有导航漏斗**（与链接跳转 / 目录跳转同一条提交路径）：
  位置提交后照常保存进度、按总则启用本章临时表 / 切换磁盘表。
  **不要**直接调宿主翻页查询口——那条口是只读的，推进指针会多翻一页（已有真机事故记录）。
- 到章末 → 停住（D-8 不跨章），并给提示（见 3.5）。
- **当前落地**：手柄进入左右页边 24dp 后等 300ms 瞬切一页，按住不放每 400ms 再翻；
  翻页后手柄按手指 y 接到新页最近行的靠边字；到本章首/末页停住，选区封顶到边界并提示。
  真机已验证向前连翻两页、接力与章首停住；章末向前停住走同一套边界判定。

### 3.4 放大镜（移动端）

- 圆形，直径 ~96dp；倍数 ~1.5x；中心悬在手指**上方 ~56dp**；贴屏幕边自动内移。
- 内容复用页栅格位图放大绘制（`PageRasterStore.obtain`），**纯用户层**。
- 出现时机：长按开始 + 拖手柄时（跟随当前拖动的手柄）。
- **当前落地**：`SelectionMagnifier.kt` 把同一页内容再画进圆形裁剪层并做 1.5 倍图层缩放；
  渲染器实例与 `PageContent` 都和当前页共用，命中现有页位图缓存，不重烤、不重排版。
  位置由纯函数 `magnifierCenter` 计算，贴顶翻到下方、左右上下内移；桌面鼠标不显示。

### 3.5 其它

- 章末停住提示：移动端轻触感；桌面一句 snackbar。
- 复制：内容 = 选区章内区间的**原文**（跨样式不带格式）；走 **D-18 的章节文本**，
  **不要**拼 `DrawLine.text`（行片段会漏字 / 重字）。块与块之间在复制结果里补换行，
  但换行不参与标注偏移。另需**剪贴板 expect/actual**（全仓目前零剪贴板代码）。
  复制后保留选区并提示「已复制」。
- 桌面键盘扩选（Shift+箭头）v1 不做。
- 高亮默认以 **~45% 不透明度**铺背景（荧光笔感）；划线粗细 / 位置刻意与书内下划线错开
  （更粗 ≥0.08em、更靠下），避免与书自带的线糊在一起。

## 5. 落地接线要点（实现前先定）

> 前面写的是「做什么」，这一节是「接在哪」。这几条不定清楚，写下去必返工。

### 5.1 装饰 run 怎么进到页里（分层关键）

- 数据流：DB → 宿主 → `shared-ui`（共享）→ **引擎的纯投影函数** → `DrawLine` 上的装饰 run。
- **投影必须在 `engine-skia`**（`LineAligner` 是 internal，`visibleSpan` 是唯一「区间 → 几何」入口）；
  但**取数据与调用点必须在 `shared-ui`**（commonMain，三端共享）——
  **不能**让宿主（平台侧）去投影，否则 Android / 桌面各写一遍，违反 KMP 共享约束。
- 落点：`rememberPageContent`（`PageContent.kt:87`）里，`host.pageLines(pos)` **保持原样记忆**，
  在其后**另加一步投影** `remember(rawLines, 本章标注列表, 装饰修订号)`（标注列表与修订号由
  `shared-ui` 自己持有，见 D-19 / §5.4）；`rememberPageContent` 因此要新增这两个入参。
  后面所有消费 `lines` 的地方（栅格 spec、`pageFrameLead` 等）改用投影后的行。
- 栅格失效**自动**：`PageRasterSpec.fingerprint()` 按值比较 `lines`（`DrawLine` 是 `data class`），
  装饰 run 一变即未命中重烤 ⇒ **不需要动 `contentRevision`，也不需要平台壳配合**。
- 预栅格同章邻页也走同一投影；**跨章目标暂不投影**（`shared-ui` 只持当前章列表，宁缺勿串），
  真页绘制时会按目标章重算。等后续需要时再把目标章标注一并加载，不动这条数据流。
- `DrawLine` 要新增一个装饰 run 字段（默认空）——这会改变它的值相等，正好是上面重烤的判据；
  旧构造点不传即行为不变。

### 5.2 引擎需新开的公开 API（渲染层）

- `projectDecor(lines, chapter, ranges) -> lines'`：把章内区间合进每行的装饰 run（烘焙用）。
- `decorRects(lines, chapter, range) -> List<Rect>`：只算几何、不画（拖拽覆盖层与手柄定位用）。
- 已落地：`DecorProjection.kt` 定义 `DecorKind` / `DecorRange` 与 `projectDecor`；
  `LineWindowDrawer.decorRects` 是几何入口（`Rect.x` 相对内容区左缘，`y` 为章节绝对 Y）。
  `DrawLine.decorRuns` 存**章内全局区间**，绘制侧按 `charBase` 换回行文本坐标；高亮底色在
  文字之下、书内行内盒之上，划线在文字与书内装饰之后（默认 `0.08em` 粗、基线下 `0.20em`）。
- 两者都复用 `LineWindowDrawer` 既有的 `aligner.visibleSpan(placement, n, ps, pe)` 路径
  （`LineWindowDrawer.kt:427/513/654`），保证**命中 / 绘制 / 装饰三者同一份几何**。
- **「点 → 章内字符」不另开引擎口**：复用现成的三步
  `ReaderMath.tapLineAt`（屏坐标 → 行）→ `LineHitTest.hit`（行内字形）→ `DrawLine.charBase`（章内偏移），
  在 `shared-ui` 收成一个 `charOffsetAt(...)`。**不要**另写一套反查几何。
- **页坐标换算抽公共函数**：`shift = pageAnchorY(行/图/背景/页首缺口) - 内容顶`。
  画布、链接点按、选区覆盖层、手柄、放大镜共用同一个 `pageShift(...)`；
  现状画布与链接点按各算一遍，第三次再抄必然漂移（链接点按有过整页偏移的事故记录）。

### 5.3 放大镜要拿到当前页位图（需要提权）

- 页位图现在**私有在 `ReaderPageCanvas` 内的 `PageRasterStore`**（由 `rememberReaderPageRenderer()`
  持有），`ReaderScreen` 拿不到。
- 放大镜**必须复用当前页已烤好的位图**（每帧重烤一页 ~0.2s，不可行）。
- **最终实现（不改接口）**：`SelectionMagnifier` 把同一页的 `PageContent` 和**同一个**
  `ReaderPageRenderer` 交给一个全屏 `ReaderPageCanvas`，外层只做圆形裁剪 + 1.5 倍
  `graphicsLayer` 缩放。`ReaderPageCanvas` 的 `renderer.drawLines` 会命中渲染器现有的
  `PageRasterStore`，因此像素与静止页同源，也不需要在 Android 侧每帧把 skia 图转成
  `ImageBitmap`（那会多一次整页拷贝）。代价是放大镜组合里多一层全屏画布，但绘制仍是一张
  缓存位图，不是重烤。

### 5.4 标注数据怎么到 shared-ui（D-19 落点）

- `shared-ui` 是 commonMain，可以依赖 common 的 `LibraryDb`；但 db 实例在宿主手里。
- 沿用现有模式（如 `onSaveProgress`）：**扩展 `ReaderHost` 的四个后台口**——
  「读本章标注 / 增 / 改 / 删」，宿主转手给 `LibraryDb`（实现集中在 common，平台侧只是转发）。
- **当前章列表由 shared-ui 持有**（D-19）：进章时读一次，放进 Compose 状态；
  增删改先改这份内存列表并递增装饰修订号，再异步落库（失败回滚 + 提示）。
  投影、长按命中、画覆盖层都读这份列表，**不查库**。
- 新增**同步**章节文本口（D-18）：`textOf(chapter, start, end)`（复制 / 选词 / 断句共用），
  与 `pageLines` 同级、开章时已缓存；**不要**做成异步。
- 长按查已有标注：直接在这份内存列表里按「章号 + 字符区间」找
  （`charStart <= off && off < charEnd`），**无需几何反查、无需查库**。

### 5.5 剪贴板平台缝

- 实际落地：使用 Compose Multiplatform 的 `LocalClipboardManager`，共享层直接取用，
  Android / 桌面各自平台实现由 CMP 提供；**不需要**再新开一套 `expect`/`actual`。
- 复制内容仍走 D-18 的整章原文，块间补换行只进剪贴板，不参与标注偏移。

### 5.6 手势状态机的改造原则（风险最高）

- 现有手势块是**长期调优过的**（`ReaderScreen.kt:828` 起，注释里记着多起「点了没反应」
  「快速闪一下」的历史缺陷），且已有单测（`ReaderLogicTest`）。
- 原则：**新增分支，不重写**。长按只加一条「未移动 + 超时」的旁路；
  手柄做成**覆盖层独立手势区**，避免主状态机去懂多指。
- 互斥守卫（D-12）**复用**现有的会话繁忙判定（`ctl.isBusy()`），不另立状态。

### 5.7 建议实现顺序（里 → 外，风险最早暴露）

1. **数据层**：DB 表 + 迁移 + 迁移测试 + 存储接口（可纯单测，零 UI）。
2. **渲染层**：引擎投影 API（`projectDecor` / `decorRects`）+ 绘制次序；先用硬编码区间验像素。
3. **接线**：`ReaderHost` 扩展（含 D-18 的同步章节文本）+ 当前章标注内存态（D-19）
   + `rememberPageContent` 里加投影 + **装饰修订号**
   （`shared-ui` 自持，见 §5.1；**不是** `contentRevision`）。
4. **用户层·选区**：手势长按分支 + 覆盖层 + 手柄（移动端先闭环）。
5. **用户层·菜单**：浮动菜单 + 复制（含剪贴板缝）。
6. **跨页**：自动翻页（独立路径，瞬切）+ 手柄接力。
7. **桌面**：指针类型分流 + 鼠标拖选 + 左右页边距点击翻页。
8. **放大镜**、**颜色设置界面**（D-21）——**已落地**（颜色槽/颜色页 + 移动端放大镜）。
   视图模式不在 v1（D-20）。

### 5.8 存储、迁移与删书清理（具体落点，已核实）

- **迁移链**：`common/src/commonMain/sqldelight/orilumn/reader/db/` 现有 `1.sqm` ~ `5.sqm`，
  原 `OrilumnDb.Schema.version = 6`。**新增 `6.sqm`（6 → 7）**，标注表定义进
  `Annotations.sq`（终态；新库由 `Schema.create()` 一次建全）。落地后 `Schema.version = 7`。
- **连带修改（复核时新发现，照原方案会漏）**：
  - `Books.sq` 顶部「版本链」注释**当前只写到 v4**（实际已是 v6），不是补一行而是补
    v5 `hidden` / v6 `font_scan_state` / v7 `annotations` 三行。
  - `desktopApp` 的迁移测试里**写死了「当前版本」**（原先 6，现为 7）；以后每次升版都要同步，
    且「伪装 v5 库」时必须把新表（`font_scan_state` / `annotations`）一起删掉，否则迁移会撞
    「table already exists」。
  - `LibraryDb` 的构造参数现在**没存成属性**，D-17 要用的 `db.transaction {}` 用不了，
    实现前先把它留成字段。
- **驱动盖章差异**（历史踩坑）：
  - Android（`AndroidSqliteDriver`）自动维护 `user_version`；
  - **桌面（`JdbcSqliteDriver`）不会** ⇒ `desktopApp/.../ShelfStore.kt:88-129` 手动
    `PRAGMA user_version`（建库即盖章、迁移后再盖章）。**新迁移不用改这里**
    （它按 `Schema.version` 自适应），但改完**必须实测桌面老库升级**——该文件注释里记着
    两次真实故障（漏盖章 ⇒ 每次启动重跑迁移 ⇒ 撞 "table already exists" 直接炸启动）。
- **删书清理**：**没有外键级联**，且两平台各自删、**非事务**（现状细节与定案见 **D-17**）。
  标注必须并入那次清理；两个平台都改调共享方法，旧的「先删书、再清进度」两步写法一并删掉。
  实现后实测「删书 → 三张表都干净」。
- **迁移测试**：新增 6→7（手工搭 v6 库 → 真实迁移 → 标注可读写）；
  Android / 桌面各做一次**老库升级实测**（DoD 有硬要求）。

### 5.9 颜色槽的存储（D-13 落点）

- 存 `ReaderSettings`（**全局**，`settingsDir/reader.json`），与书无关。
- 读取是**手写 `opt*` + 默认值**（`ReaderSettings.fromJson`；`SettingsJson` 为
  `ignoreUnknownKeys` + `encodeDefaults`）⇒ **老存档缺键即取默认**，
  故新增色槽字段**不必强制 bump** `CURRENT_SCHEMA_VERSION`（现为 1）；
  只有当需要**改造旧值**时才 bump（先例：`migrateCjkLatinSpacing`）。
- 色槽形态建议：每类 4–5 槽，各存 ARGB `Int`（含 alpha）；另有「默认槽索引」。
- **当前字段**：`highlightColorSlots` / `underlineColorSlots`（各 5 个 ARGB `Int`）与
  `highlightDefaultSlot` / `underlineDefaultSlot`；四者都登记进 `withoutNonLayout`
  （只改像素、不触发重排），设置面板的改色行走无重排提交。
  读取用 `SettingsJson.optIntList`：缺键/非数组取默认，短列表补齐、长列表截断到 5 格；
  默认槽索引越界自动钳到 `0..4`。因此老存档不需要迁移。
