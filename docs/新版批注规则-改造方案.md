# 新版批注规则：改造方案与性能计划（2026-10-24）

> 依据：`docs/新版批注与引线规则.md`（用户本轮定稿的规则）+ `docs/旁注布点与引线-实施方案.md`（现行实现）。
> 本文是**改造计划**，不是最终方案；落地后并入《旁注布点与引线-实施方案》，本文删除。
>
> 层级：本方案只动**用户层覆盖层**（`NoteBubbles.kt`，旁注文字与引线），沿用渲染层与排版层的
> 只读几何入口；不改分页、不进栅格、不发任何 CSS 声明（不涉及样式层叠三问）。

---

## 0. 结论摘要

1. **4 秒不是被规则复杂度吃掉的，是被「用文字测量当几何判据」吃掉的。**
   10 条批注一页，现状会调用文字测量 **3886 次**（每条 380 次左右）：每个候选位置、每个留白档、
   每块空白都重新量一遍同一句话。Compose 的 `TextMeasurer` 默认只缓存 8 条，等于每次都真排版。
   在平板上一页 3～4k 次 `MultiParagraph` 布局 + 几十 MB 垃圾，正好是 4 秒。
2. **新规则要求的位置比现在多**（让位、相邻行、跨行、折叠、图标、硬交叉），
   如果照现状的「全量枚举 + 逐个测文字」写法加规则，只会更慢。
   所以先做**架构改造**（测量与几何分离、按跨行数惰性生成、空间索引），再改规则。
3. 目标：**10 条批注/页 ≤ 30ms（JVM）/ ≤ 50ms（平板），文字测量 ≤ 40 次/页**，
   并且页面完全相同、可复现。
4. 新规则与现行实现有 **7 处口径差异**，已按用户 2026-10-24 的答复定稿（§9），无遗留待定项。

## 1. 现状与测量

### 1.1 调用链（现状）

`ReaderScreen.kt:2036` 在**组合期**的 `remember` 里同步执行：

```
pageInkRects / pageMarkerRects / pageTextLines / pageGlyphRects   （逐条批注都各调一遍）
  → noteObstacles
  → noteBubblePlacements                                        （纯函数，见下）
      ├─ tightLineInk / tightTextInk        每行 × 全部逐字墨迹
      ├─ maximalFreeRects                   MaxRects + O(n²) prune
      ├─ 每条批注 noteCandidates            ← 热点
      │    跨行数 0..n × 3 个 family × 3 个留白档 × ≤5 块空白 × 9 个方向
      │    每个组合都调 noteBoxFit → naturalWidth + fit（真排版）
      ├─ orderedNoteCandidates              全量 sort（每条一次，chainFor 又排一次）
      ├─ assignNoteCandidates               让位时再调 noteBoxFit
      └─ routeNoteArrow                     每条：4 目标 × ~3 入口 × ~8 出口 × 1~4 折
```

### 1.2 探针数据（JVM，10 条批注 / 30 行 / 723 个逐字墨迹）

`shared-ui/src/jvmTest/.../NoteBubblesPerfProbe.kt`（设 `ORILUMN_PERF=1` 才跑）：

| 量 | 数值 |
|---|---|
| 候选生成阶段的文字测量次数 | **3810 次**（10 条） |
| 整条布点流程的文字测量次数 | **3886 次**（natural 1302 + fit 2584） |
| 几何与排序（测量成本记 0） | 72ms |
| 每次测量按 100µs 计（JVM 粗估） | **466ms** |
| 每次测量按 300µs 计 | **1.2s** |

平板上的 `TextMeasurer.measure` 还带 `MultiParagraph` 分配与 GC，单次常到 0.5～1ms，
3886 次正好落进 2～4 秒，与用户实测吻合。

其余两项**不是**主因（同样量过）：

- **逐字墨迹几何**（`drawer.inkRects`）：热身之后整页一次 6ms，10 条批注各扫一遍 13ms
  （冷启动首次 975ms 是字体/字形缓存，真机上渲染早就付过了）。可以优化到 4ms，但不是 4 秒的来源。
- **引线路由**：7 条引线冷跑 138ms（JVM），量级是百毫秒，协议上排第二，
  优化后应 ≤ 20ms。

## 2. 新规则 vs 现状：逐条差异

| 新规则 | 现状 | 需要改的地方 |
|---|---|---|
| N1 按从上到下计算 | 已有（基准行排序） | 无 |
| **N2 同一行内从左到右**（例外：本行最右那条若能用右侧，右侧先留给它） | **从右到左**（`noteRightOnRow` 降序） | 排序键改名改向；新增「本行最右批注先占右侧」的两阶段；所有「先占先得」的示例与测试随之翻向 |
| N3 行右侧 > 1em → 先用右侧 | 已有（`emitRightFamily` 门槛） | 门槛里再区分「页边距列」 |
| **N4 行左侧有缩进 → 先用左侧** | **左侧永远最后** | 新增「缩进行」判定与左侧提前 |
| **N5 方向顺序：右上→右下→左上→左下→上→下→右→左** | 右→右下→右上→左下→左上→下→上→左 | 改 `noteSideRank`；**右/左降到倒数** |
| **N5 右上/右下的横向基准 = 选区左缘 + 一个字**（用户 2026-10-24 更正） | 末行第一个字 + 一个字 | 改 `cornerRightX`：取**基准行**选区首字左缘右移一个字；左上/左下仍是末字左缘左移一个字 |
| **N5 上一行/下一行的左右算本行相邻（不算隔行）** | 相邻行算跨行 1 | 重定义「本行相邻空间」：本行 + 上一行 + 下一行的左右 |
| **N6 只有页边距的左右空白最多折 2 行** | 不限制 | 在 `emitLeft/emitRight` 里按空白性质封顶 |
| N7 上下左右摆法离正文 1em 给引线 | 已有（preferredMargin） | 无 |
| **N8 右侧被占：先纵向让位，再考虑既有批注右侧** | 只支持「同列正右/正左」整句让位 | 让位扩方向；新增「往既有框右侧找空」 |
| **N9 跨行时只用 4 斜向 + 上下；段内不折叠优先** | 跨行档内 6 向；折叠是全页第二档 | 方向集合分「本行相邻空间 / 跨行」两套；折叠按段落判定 |
| N10 跨过其他标注视同跨行 | 无 | 跨行数按「跨过的批注框」加罚 |
| **N11 折叠下限 = 1 个字 + …** | 至少 4 个字 | 改 `MIN_SHOWN_CHARS` 与「可读」判据 |
| N12 折叠也不行 → 小椭圆贴在选区右下 | 已有（`noteIconRect`） | y 基准改「下划线右侧」 |
| **N13 左右 margin 1em；上下 margin = 行盒之间的纯空白**（不是行高） | 上下也是 0.1em 起、1em 首选 | `marginY` 默认改成「相邻行盒之间的纯空白 = 行盒节距 − 行盒高」，压缩下限 2px |
| L1 上下左右：直线优先 | 已有 | 收紧 |
| **L2 斜向：L 形两段优先** | 最短优先（可能 1~4 折） | 斜向先只试 L 形，再放开 |
| L3 线段少优先 | 已有（折数第一） | 无 |
| **L4 画到行盒边框为止，不进入行盒** | 端点落在**字墨迹**上 | 入口改成行盒边（`NoteTextLine.rect`），并保证不穿行盒内部 |
| **L5 两端垂直于行盒边框或另一条引线** | 两端垂直框边 / 字边 | 入口按行盒边垂直 |
| **L6 避开四角，端点距边界 ≥0.5em 的带内任意取点** | 固定 0.5/0.25/0.75 三个点 | 按内缩带取点（含四角排除） |
| **L7 不要反复转折；宁可穿字也要少穿** | 以贴字（hug）先于长度 | 判据改成 折数 → 穿字量 → 贴字 → 长度 |
| **L8 两行之间横穿走中线** | 已有 `gapYs` | 保证所有折数级别都用，且优先级提到前面 |
| **L9 两条引线不得交叉（优先因素，无解才交叉）** | 只做软惩罚（`crosses`） | 交叉数提到折数之前：存在不交叉的候选就绝不取交叉的；全部候选都交叉时取交叉最少者并记 DEBUG 日志 |

## 3. 目标架构

一句话：**几何用整数矩形算，文字尺寸问缓存，候选按跨行数懒生成，引线用网格找障碍。**

```
noteBubblePlacements(noteInk, obstacles, 页面几何, style, sizer)
  │
  ├─ ① 页面准备（每页一次，所有批注共享）
  │     PageIndex
  │       ├─ lines / blockId / 每行 inkTop·inkBottom / 行盒高（= 正文行距）
  │       ├─ rowOfGlyph：逐字墨迹 → 行号（一次 O(g·log n)，替代每处的 O(g·n)）
  │       ├─ FreeIndex：按 y 带 / 按 x 列分桶 + 面积降序数组
  │       └─ RectGrid：逐字墨迹 / 图形 / 线条 / 已放框，格 ≈ 2 行高
  │
  ├─ ② 每条批注
  │     NoteMeasure（每条一次）
  │       ├─ naturalWidth：整句一行宽（**只量一次**）
  │       └─ fit(widthInt, maxLines)：按整数宽 + 行数缓存（宽度只来自空白边界，去重后很少）
  │     lazyChain(note)：按 跨行数 0 → 1 → …（段界内）生成候选，**每档不生成全量，取到即停**
  │
  ├─ ③ 分配（行自上而下；行内左→右，但本行最右那条先试正右）
  │     本行相邻空间先 take、再 makeRoom；同一跨行数内全部候选比较后再决定（保折行数优先）
  │     整句档 → 折叠档（≥1 字）→ 小椭圆
  │
  └─ ④ 引线（仅对已放好的框）
        直线 → L 形（斜向）→ 2/3/4 折；障碍查询走 RectGrid；已画引线优先避开
```

## 4. 性能设计（核心）

### 4.1 文字测量：从 3886 次降到 ≤ 40 次

| 手段 | 说明 | 预期 |
|---|---|---|
| `naturalWidth` **每条一次** | 现在每个候选都量整句宽；它只跟文字/字号有关 | 1302 → 10 |
| `fit` **按（整数宽, 行数）缓存** | 同一句话在同一宽度下折几行是常量；宽度只来自空白左右缘，天然去重 | 2584 → ≤ 30 |
| 单调剪枝 | 已知某宽度 `W` 在 `L` 行内能放完整句 ⇒ 任何 `W' ≥ W` 同样成立，不再量 | 进一步少一半 |
| 早停 | 跨行数 0 命中就再也不算后面的档（详见 4.2） | 省掉 ~90% 的候选 |

实现：新增 `CachingNoteTextSizer(delegate)`（common，纯装饰），键用
`IntArray(widthInt, maxLines)` + 每页 512 条上限的 HashMap；`ComposeNoteTextSizer` 本身不动。
顺带把 `rememberTextMeasurer(cacheSize = 32)`（默认只有 8）——它服务绘制侧，缓存大一点避免每帧重排。

### 4.2 候选生成：按跨行数惰性 + 正确早停

现在的写法是「先把整页所有候选生成出来（每条上限 300），再排序」。改成：

```
fun candidateChain(note, page): Sequence<NoteCandidate> = sequence {
    for (k in 0..)                    // 跨行数 0（本行 + 相邻行左右）、1、2…（到段界）
        yieldAll(zoneCandidates(note, k))   // 档内 8 方向 × 3 留白档
}
```

**早停的正确定性**（必须有证明，否则会选错位置）：

- 排序键是 `(段, 折行数, 跨行数, 方向, 留白档, 距离)`，**折行数在跨行数之前**。
- 留白档是「同一方向内的大→小留白」，最大档是 1em / 行盒间隙，最小档 2px；
  压缩留白不另起一轮，就在这个键里排（第 8 条：实用性优先，但方向顺序仍先于留白档）。
- 跨行数按升序生成，**同一档内全部算完再比较**（不能取档内第一个）。
- 若当前档里「放得下的最佳候选」的折行数 = `minLines`（无 `\n` 时为 1，否则段落数），
  则后面的档不可能更优（折行数相同、跨行数更大）⇒ 立即停。
- 否则继续下一档；到段界仍没有完整候选 → 才进折叠档 / 相邻段。
- 段是更外层的键：本段没有完整候选才允许看相邻段（新规则 N9 的「本段优先不折叠」正是这条）。

**代价**：顺利时每条批注只算跨行数 0（≤ 8 方向 × 3 档 × ≤3 块空白 ≈ 70 次几何判据、
其中最多 3～5 次缓存未命中），而不是 380 次真排版。

### 4.3 空白查询：索引替代 `filter + sort`

现状 `bandRects` / `columnRects` 每次都对**全部空闲矩形** `filter`，还现场 `sortedByDescending{面积}`
和两个 `minWithOrNull`；每行 × 3 档 × 3 family 就是几十次全表扫 + 排序。

改成 `FreeIndex`：

- 按 `top` 排序的数组 + 二分找「包含 y 的带」；
- 按 `left` 排序的数组 + 二分找「包含 x 的列」；
- **面积降序数组**：取「面积前 3」直接顺序扫到 3 个命中即停（不再排序）；
- 结果按几何去重（Long 键），不再拼字符串。

### 4.4 行身份与锚点：一次编好

`nearestLineIndex` 现在被 `noteRowsBottomUp`、`rowLefts`、`noteBaseRow`、`noteRightOnRow`
反复调用，每次 O(行数)。页内一次 `rowOfGlyph`（逐字墨迹中心 → 行号）后：

- `noteBaseRow` = 锚点各行的最大行号（O(锚点数)）；
- `noteRowsBottomUp` = 去重排序；
- `otherRowLefts` = 扫一遍锚点即可；
- `lastInBlock` / 块起止 = 预计算数组。

### 4.5 引线：网格 + 分级

| 现状 | 改成 |
|---|---|
| `arrowGapMidYs` 对窗口内**每对**字形做一次（O(k²)，k 可达数百） | 按行分桶，只配相邻两行（O(k)） |
| 每条候选路径都扫 `target.obstacles` 全部（~10²） | `RectGrid` 只取线段包围盒覆盖的格子（通常 <10） |
| 每条批注试 4 个目标 × 3 入口 × ~8 出口 × 1~4 折（最多数百条路径） | ① 先用「入口/出口各 3 个点」试直线；② 斜向先试 L 形两向；③ 再 2 折；④ 3/4 折只在「有障碍且前几级全不通」时开，坐标只在障碍附近取 |
| 引线交叉是软惩罚 | 已画线段整段进硬障碍（L9），实在无解才按「交叉最少」兜底 |
| 每条批注都重建 `ArrowObstacle` 列表（含全部字形） | 页内建一次，按窗口切片复用 |

### 4.6 线程与缓存

1. 先把单页总耗时压到 ≤ 16ms（一帧），留在组合期也感觉不到；
2. 若真机上仍超，就把计算挪到 `produceState` + `Dispatchers.Default`（旁注是覆盖层，
   晚一两帧出现完全可以接受；翻页期间本来就隐藏）。注意 `TextMeasurer` 内部有可变缓存，
   后台用**独立实例**（`TextMeasurer(..., cacheSize = 8)`）或加锁，不能和绘制侧共用；
3. 结果按 `(页, 版面几何, 标注修订号, 样式)` 缓存，前后各留一页：翻回去不再重算；
4. 逐字墨迹几何每页只算一次，按批注区间切片（现状每条批注调两遍全页扫描）。

### 4.7 验收预算（10 条批注 / 30 行 / 700 字墨迹）

| 指标 | 现状 | 目标 |
|---|---|---|
| 文字测量次数 | 3886 | **≤ 40** |
| 单页布点（JVM，测量成本记 0） | 72ms | **≤ 10ms** |
| 单页布点（平板，真实测量） | ~4000ms | **≤ 50ms** |
| 引线（10 条） | ~100～300ms | **≤ 20ms** |
| 同输入两次结果 | 相等 | 相等（键仍是整数/稳定坐标） |
| 现有 100+ 单测 | 绿 | 全绿（除口径变更导致的预期调整） |

超出这个预算就不算完成，不能靠「反正是覆盖层」糊过去。

## 5. 布点规则落地（新规则 → 代码）

### 5.1 位置与参照

| 摆法 | 框位置（页坐标） | 参照 |
|---|---|---|
| 右 | 左缘 = 该行**行盒**右缘 + `sideGap`（1em）；垂直居中于该行 | 行盒 |
| 左 | 右缘 = 该行**行盒**左缘 − `sideGap` | 行盒 |
| 右上 | 左缘 ≥ **基准行选区首字左缘** + 一个汉字；底边 = 该行行盒顶 − 行间空白 | 选区首字 / 行盒 |
| 右下 | 同上；顶边 = 该行行盒底 + 行间空白 | 选区首字 / 行盒 |
| 左上 | 右缘 ≤ **选区末字左缘** − 一个汉字；底边 = 行盒顶 − 行间空白 | 选区末字 / 行盒 |
| 左下 | 同上；顶边 = 行盒底 + 行间空白 | 选区末字 / 行盒 |
| 上 | 底边 = 锚点行盒顶 − 行间空白；横向与选区有重叠 | 行盒 / 选区 |
| 下 | 顶边 = 锚点行盒底 + 行间空白；横向与选区有重叠 | 行盒 / 选区 |

两个距离分清楚，别再混用：

- **左右 margin**（N13）= 1em，`sideGap`，给引线留位置（N7 的左右情形就是它）。
- **上下 margin**（N13）= **相邻行盒之间的纯空白**，即 `行盒节距 − 行盒高`（不是行高，也不是 1em）。
  框的上/下沿正好落在相邻行盒的边上，视觉上与普通正文对齐；没有额外空白（行距紧）时为 0。
- **两个 margin 都是「美观默认值」，不是硬门槛**（用户 2026-10-24 定稿）：
  空间不足时按同一方向内的留白档逐级压缩，一直压到 2px；压到 2px 仍放不下，才判定这个方向不可用，
  再按方向顺序换下一个方向 / 跨行 / 折叠 / 小图标。**压缩留白优先于换位置，实用性压过美观**。
- 同一方向内先试大留白、再试小留白；**方向顺序先于留白档**（右上只放得下 2px 也胜过右下 1em），
  但**折行数与跨行数都先于方向**（少折一行 > 方向靠前）。
- 「只有页边距」的左右空白：`capacity = min(容量, 2)`（N6）。

### 5.2 跨行数与段

「环」改称**跨行数 k**（避免 0/1 起点歧义）：

```
k = 0   本行相邻空间 = 基准行（8 向）+ 上一行左右 + 下一行左右（N5：相邻行不算隔行）
k = 1   距基准行 2 行的位置（跨过 1 行）；k = 2 跨过 2 行 …… 直到段界
k 加罚  跨过一条已放批注框，视同多跨一行（N10）
段界    基准段全部行；相邻段的左右两侧也计入本段可用范围（N9）
方向集  k = 0：右上→右下→左上→左下→上→下→右→左
         k ≥ 1：右上→右下→左上→左下→上→下（不含左右，N9）
```

### 5.3 取位流程（新顺序）

```
for row in 页内自上而下:
    if 本行有「最右的批注」且行右侧至页边距 > 1em:
        先给它试正右（命中就占位，右侧空白随即从本行扣除）
    for note in 本行其余批注，按选区左缘从左到右:
        chain = lazyChain(note)
        if k = 0 的候选被已放框挡住:
            makeRoom(note)                 # N8：先让位
        if k = 0 仍未命中:
            按 k 递增继续（命中 minLines 即停）
        if 段内没有完整候选:
            折叠档（≥1 字，省略号）
        if 连 1 字都放不下:
            小椭圆
```

- 第一段的例外只影响「本行最右那条」：它先占右侧，其余批注再从左到右，仍守 N2。
- 右侧留给它的条件是「能写在右侧」（正右候选整句放得下）。放不下就正常按 k=0 起算，
  右侧空白仍归本行其他批注使用，不留空。

### 5.4 让位（N8 扩展）

1. **纵向让位**：同一列/同一块空白里的挡路框整体上移或下移，取位移小的；让位后新框重新折行夹取，
   必须整句放下（现有逻辑保留）。
2. **往既有批注右侧找空**（新）：纵向让完仍不够时，试把挡路框**左移 / 收窄**，
   在它右侧留出新框位置；收窄不得低于「1 字 + …」（N11）；复核规则与纵向让位相同。
3. **只允许整句档让位**；折叠档不搬人（沿用现状，避免为一条要折叠的批注挪动已读顺的框）。
4. 让位后仍要复核：各自在自己空白内、互不冲突、不压字、新框整句放得下；任一不满足就整体作废。

### 5.5 折叠与小图标

- 折叠下限从 4 字 → **1 字 + …**（N11）；`NoteBoxSize.readable` 改为 `shownChars ≥ 1`。
- 折叠仍是「整句档全部失败之后」的第二档，但**判定范围按段落**：本段可用范围内先找完整位置，
  找不到才折叠（N9/N11）。
- 小图标：`noteIconRect` 的 y 基准改成「下划线右侧、与高亮同一位置」（N12），
  视觉尺寸与热区保持现状（0.5em × 0.32em，热区 1.2em）。

## 6. 引线规则落地

### 6.1 线型选择

```
正方向（上/下/左/右）: 直线 → 2 折 → 3/4 折
斜向（右上/右下/左上/左下）: L 形（两种折法各试）→ 2 折 → 3/4 折
```

- 「L 形」= 从框边横着出去 → 折点 → 竖着进入行盒边（或反之），**正好 1 折**（L2）。
- 斜向不再先试「任意最短」，避免为了少几像素画成两折（L3 线段少优先）。

### 6.2 端点

- **落在行盒边框**（`NoteTextLine.rect`），不进入行盒内部（L4）；箭头尖朝文字一侧。
- 端点取在「距边界 0.5em 的带内」的若干点上，**排除四个角点**（L6）；
  框侧同样如此（框边内缩 0.5em）。
- 两端垂直：第一段 ⊥ 框边、最后一段 ⊥ 行盒边（L5）。

### 6.3 选路判据（新顺序）

```
第一关: 交叉数 = 0 的候选优先（L9，优先因素而非硬约束）
同交叉数内: 折数 → 穿字像素量 → 贴字量(hug) → 长度 → 候选序
全部候选都有交叉: 交叉数 → 穿字量 → 长度（取最少交叉者，记 DEBUG 日志）
```

- 「不交叉」高于形态级别：低级形态（直线 / L 形）全部交叉、而高级形态存在不交叉时，取高级形态。
- 横穿两行之间时优先取两行墨迹的中线（L8，现有 `gapYs` 提前到各折数首选）。
- 已画引线整段进障碍查询；它只抬高「交叉数」，不再直接否决路径（L9 的兜底）。

### 6.4 性能约束

- 斜向 L 形只需要 1 个折点，候选数比现在少一个量级；
- 2 折只有两个方向族（先横后竖 / 先竖后横），坐标取障碍边界 ±1px 与中点；
- 3/4 折只在 2 折全不通时开，并且只在「命中障碍的包围盒 ±2 行高」内取坐标；
- 障碍查询走 `RectGrid`，单段检查 ≤ 10 个矩形。

## 8. 风险与退路

| 风险 | 说明 | 退路 |
|---|---|---|
| 折行数优先与早停不等价 | 取同跨行数内第一个会破坏「少折行优先」 | 同跨行数内全部比较 + 只有命中 `minLines` 才停（§4.2） |
| 上下 margin 取「行盒间隙」可能为 0 | 行距紧时上下两向贴着行盒，视觉像压字 | 按第 8 条直接压到 2px 硬塞（实用性优先），仍放不下才换方向 |
| 行盒端点导致引线穿过行距 | 行盒内部含行距，穿行距不算穿字但视觉上像贴字 | 入口沿行盒边，路径仍避逐字墨迹；穿行距用 hug 惩罚 |
| 不交叉优先可能逼出 3/4 折 | 密集页面上低级形态全交叉 | 先真机看效果；仍难看就改成「交叉数与折数加权」，但需重新征得同意 |
| 后台线程与 `TextMeasurer` | `TextMeasurer` 缓存不是线程安全的 | 独立实例或加锁；先优化到 ≤16ms 就不挪线程 |
| 口径理解偏差 | 改错方向会推翻本轮定口 | §9 已逐条记录答复原文；实现时遇到歧义先问，不自行发挥 |

## 9. 口径定稿（用户 2026-10-24 答复）

| # | 问题 | 定稿 |
|---|---|---|
| 1 | 同行顺序 | **左 → 右**。例外：本行最右侧的文字若属于另一条批注、且那条批注能用右侧，则本行右侧空间先让给它（实现见 §5.3 两阶段）。 |
| 2 | 方向顺序 | **右上→右下→左上→左下→上→下→右→左**。理由：左右只剩页边距时太窄；左右有空间的情形已由 N3/N4 提前处理。 |
| 3 | 右上/右下基准 | **基准行选区首字左缘 + 一个字**（不是选区右缘）。左上/左下仍是「选区末字左缘 − 一个字」。 |
| 4 | 折叠下限 | **1 个字 + …** |
| 5 | 上下 margin | **相邻行盒之间的纯空白**（`行盒节距 − 行盒高`），不是行高；目的是让标注上/下沿与普通正文对齐。左右仍是 1em；空间不足逐级压缩，下限 2px。 |
| 6 | 引线交叉 | **优先因素**：有不交叉的候选就不取交叉的；实在无法避免才交叉，取交叉最少者。 |
| 7 | 跨行定义 | 上一行/下一行的左右两侧算**本行相邻空间**（k=0），不算跨行；跨 1 行 = 距基准行 2 行（k=1），依此类推，直到段界。 |
| 8 | margin 的性质 | 左右 1em、上下行盒间隙都是**美观默认值**；空间不足时按留白档逐级压缩到 2px，压到 2px 仍放不下才换方向 / 跨行 / 折叠。**必要时实用性压倒美观。** |

### 9.1 由定稿推出的两处实现约定（如理解有偏差请指出）

1. **「右侧让给最右批注」按两阶段做**：本行最右那条先试正右，命中就占位并把它占掉的空白从本行扣除；
   其余批注再从选区左缘左→右处理。若它放不进右侧，则右侧空白照常归其他批注，不留空。
   这样做不引入回溯，也不会让先放好的框为后放的让路。
2. **上下 margin 与 N7 的 1em 不冲突**：N13 的「行盒间隙」决定框与行盒的距离（对齐正文）；
   间隙为 0 或框贴到选区墨迹时，先按 N7 外推到 1em；1em 放不下就压回 2px 硬塞，
   而不是把这条批注推去别的方向或折叠（用户第 8 条：实用性优先）。
