## 0. 结论摘要

1. 现在的分配是**顺序贪心**（行序 → 行内最右 → id），每条只看自己的候选链，
   「占了这个位置会把后面几条挤到哪儿」完全不计入。长批注的整句框最宽，
   又恰好最先挑大块空白，于是**先来的一条把一块大空白从中间切开**，后来者只能叠缝或飞走。
2. 让位只问「挡住的那几条一起挪、挪刚好够的距离」，**不连锁、不比较谁挪更划算、也不回退**；
   被挪的那条自己也变差了，但此后不会再被优化。
3. 收尾的「长外短内」只是同一块空白内的深度平移（2026-10-27 起不再限定同侧、也不再要求
   文字位置相邻），改不了「谁占了哪块空白」这个前提。
4. **单纯换排序解决不了**：短批注优先会把大空白切碎、长批注再也放不下；长批注优先就是现状。
   两种排序都只是换一种牺牲方式。
5. 建议：**候选链原样保留**（所有既有规则都在候选顺序里），把「分配」换成
   **贪心初版 + 有界局部搜索**；公平判据用**逐条名次的最小最大化（leximin）**，
   即「先保证最委屈的那条别太委屈，再管第二条」。这是地图注记排布里的成熟做法，
   规模也匹配（一页 ≤ 20 条、每条 ≤ 40 个候选，分配现在只占 3–5ms）。
6. **作用范围是局部的**：搜索只在「互相抢得到同一个候选位置」的那几条之间做
   （冲突图连通块，见 4.4）。单条批注的页、批注互不相干的页，输出与现在逐像素一致。
7. **允许长框让位**（2026-10-27 定）：名次可以变差，只要最委屈的那条变好；
   「挪远了引线不好画」由逐条的引线**绝对上限**兜住（自然留白 + 3em、且不许压在别人的框上）。
   这条是能不能修好真机那页的关键——长框正占着自己的第一志愿。

## 1. 问题与现场证据

### 1.1 现象

同一块大空白里有 2–5 条批注时，长的那条（整句、宽框）经常落在空白中间，
把短的挤到缝里、页边距或隔行位置；短批注的引线因此被拉长、折数变多，甚至出现
「1px 折」这种肉眼可见的抖动。

### 1.2 真机页（代码块那页，`notes=9`）

| 批注 | 宽度 | 落点 | 备注 |
|---|---|---|---|
| `再加一个批注，看看放在哪里。` | 162px | 同一块空白偏下 | 引线出现 `(788,1840)→(787,1840)→(787,1717)→…` 的 1px 小折 |
| `这里也有批注，会放哪里呢？` | 788px | 同一块空白 | 整句一行，占掉整条横带 |
| `这是什么意思?` | 212px | 右侧 | 与上一行批注挤在同一列 |
| `就是所有函数和类的外面` | 352px | 下一行下方 | 被上一条压到隔行 |

同一页 `NOTE-PLACE notes=9 free=2 cand=25 assign=5 route=76 total=108`：
分配只花 5ms，**大头在引线路由**。也就是说「分配」这一层还有充足的预算做优化，
不必为了性能继续维持最省事的贪心。

### 1.3 现有代码事实

- 顺序：`assignNoteCandidates` 里 `order = 基准行 → 是否罩住右侧 → 行内最右 → id`，
  逐行逐条 `placeNote()`，**先到先得**。
- 每条：按自己的候选链扫，第一个「放得下」的就占；撞上别人时
  先 `slideFree`（自己沿远离锚点方向挪），再 `makeRoom`（请挡路框让位，只在环 0 问）。
- 让位：把**所有**挡路框当成一个整体、用同一个位移推开「刚好够 + 2 倍 margin」；
  只要有一个挡路框属于更早的行就直接放弃；让完不做任何后续评估。
- 收尾：`arrangeSharedBlankNotes` 在同一块空白内把长的挪到外侧、短的挪到内侧，
  只平移、不换空白、不换方向。

## 2. 现状算法（按代码口径）

候选排序键（`noteCandidateOrder`，从高到低）：

```
整句/截断  →  越过别人的行数  →  是否挡住右侧出线通道  →  正右被占时的方向调整
  →  环（本行那一圈先）  →  折行数  →  就近档（一个行高一档）  →  额外引线长度
  →  首选侧  →  方向名次  →  基准行  →  留白档  →  角落横向偏移  →  框顶  →  框左
```

- 先保整句，截断是最后手段（2026-10-29 用户定口，取代此前「环数绝对第一」）。
- 整句之后**环先分家，同环内先折行、再就近**（2026-10-31 用户定口，取代 2026-10-29
  「就近第一、宽度第二」）：同一环里一行放得下的空位先于要折两行的，折行相同才比就近档
  （差一个行高以内算同样近）、再比精确的额外引线长度；方向名次最后。
- 候选按环分批发（`nextBatch`），池子只增不减，排序增量合并。

分配：`placeBest` 顺序扫链 → `take`（放得下就占）→ 失败且 `ring==0` 才 `makeRoom`。
`makeRoom` 成功后把被让的框写回 `occupied`，**不会**再回头看它们是否还有更好的位置。

## 3. 结构性缺口（为什么长的一定会挡住短的）

| # | 缺口 | 后果 |
|---|---|---|
| G1 | 决策是**局部**的：候选只看「自己放不放得下」，不看它挤走了谁 | 长框先占走大空白 |
| G2 | 候选链第一档是**整句**，整句又最宽 | 一旦落下就把空白切成两半，短框只能进缝 |
| G3 | 让位是**整体平移 + 单向**：所有挡路框同一个位移，遇到更早的行就放弃 | 让不动就整条掉到下一档；让动了也可能把别人推到更差处 |
| G4 | 没有**回退 / 重排**：位置一旦定下就只增不减，收尾只做平移 | 先到先得的结构性问题无法被纠正 |
| G5 | 「同块空白」在实现里没有显式身份（只有 `freeRect` 几何） | 无法做「一块空白内部怎么分」的局部决策 |

## 4. 目标、不变量、非目标

### 4.1 目标

- 同一块大空白里，**任何一条都不该为了别的条目被牺牲到隔行 / 页边距**，
  除非确实没有别的可行布局。
- 长框拿走「外侧 / 空白中间」时，必须给短框留下一条能贴住正文的走廊。
- **引线不能因为让位而变差**：挪动任何一条，它自己的引线长度 / 折数 / 是否被别的框挡住
  都不许比原来更差（硬门槛，见 6.8）；「总引线代价」只在公平程度相同时用来择优。
- 结果可复现：同一输入（页面几何 + 批注集合）每次画得一样。

### 4.2 硬不变量（不许破）

1. 批注框不重叠（含 0.1em 间距），不压文字 / 图形 / 表格 / 线条。
2. 候选只能来自该批注的候选链（不许凭空造位置），整句 / 就近 / 折行的规则口径不变。
3. 「让位不搬更早行的批注」这条（2026-10-24 用户定口）继续有效。
4. 一条都放不下时仍退成小省略号，不许整条消失。
5. 分配 + 路由的总耗时不明显上升（目标：`assign` ≤ 2× 当前，整页 ≤ +10ms）。

### 4.3 非目标

- 不改候选生成（空白切分、环、方向名次、角落基准都不动）。
- 不改引线路由与箭头规则。
- 不做跨页重排：批注只在本页落位。

### 4.4 影响范围：只在「会互相争位的那几条」之间动

这是本方案最需要说清的一条——**管道是整页的，效果是局部的**：

| 改动 | 作用范围 | 单条批注的页 / 互不相干的页 |
|---|---|---|
| P1 毁伤打分 | 任何候选在**其余每一级都打平**时才用到；不会越过整句 / 就近 / 折行 / 环 / 方向 | 只有同分候选才会选到别的，位置**不会**因此变远 |
| P2 让位链 | 只在这条批注的环 0 候选撞上已放批注时触发（与现状同一处） | 不撞就没有这一步 |
| P3 局部搜索 | **只在一个「争位连通块」内部**（见 6.1 定义），块与块之间互不影响 | 块大小 = 1 直接跳过，等价于现状 |
| P4 收尾平移 + 兜底补救 | 同一块空白 ≥ 2 条、或真的走了引线兜底 | 不满足就原样 |

「争位连通块」（下文简称**块**）的判定：

```
把每条批注的候选集合看成顶点集；
两条批注之间连边 ⇔ 它们各有一个候选会互相冲突（矩形 + 间距）。
块 = 这个冲突图的连通分量。
```

- 同一块大空白里互相抢位置的几条，必然在同一个块里——这正是要处理的对象。
- 同一页上隔得很远的两组批注，候选根本不相交，就分成两个块，**各管各的**；
  不会出现「为了把 A 组的引线缩短，去挪 B 组」这种跨空白的交换。
- 块大小 = 1 时（这条批注的候选谁也不碰）**直接返回初版，一个坐标都不动**。

公平判据（6.2）也按块内比较：每块独立取 leximin，块与块之间没有取舍。
（块之间互不影响，各自的 leximin 合起来就是全页的 leximin，不会因此变差。）

> 一句话：**只有「这条批注的某个候选，正好是另一条也能用的位置」时，两条才会被放在一起重新安排。**
> 单条批注的页、批注之间互不相干的页，行为与现在逐像素一致。

#### 为什么不用「同一个 `freeRect`」当判定

这个选项听起来更保守，实际上**既会漏、也会滥**，因为 `freeRect` 不是「空白」的身份：

- `maximalFreeRects` 用的是 MaxRects：每遇到一个障碍就切出「左 / 右两道整高 + 上 / 下两道整宽」
  四条**互相重叠**的矩形，`pruneFreeRects` 只剪掉被别的矩形**严格包含**的那些。
  所以**肉眼上的一片空白 = 好几个重叠的 `freeRect`**；`freeRect` 只是「这个候选从哪块几何区域量出来」的标签。
- **会漏**（危险的那一头）：两条批注明明在同一片空白里抢位置——一条的候选来自整高侧带、
  另一条来自两行之间的整宽带（这两块在几何上重叠）——`freeRect` 不同，就被判成互不相干，
  各排各的，问题原样留着。
- **会滥**：一条通页高的侧带只有一块 `freeRect`，页首那条和页尾那条都从它取候选，
  但两者相隔大半页、候选根本碰不到，却被判成同块，白白互相搬迁。
- 结论：决定「会不会争位」的唯一事实是**候选框本身会不会撞**（含 0.1em 间距），
  而不是它从哪块 `freeRect` 量出来。

> **已定（2026-10-27 用户定口）：块按「候选相交」认。**

## 5. 方案选型

| 方案 | 思路 | 优点 | 缺点 / 结论 |
|---|---|---|---|
| A. 保持先到先得 | 现状 | 零风险 | 就是问题本身 |
| B. 尺寸优先贪心（大框先放 / 小框先放） | 经典装箱 | 便宜 | 小框先放会把大空白切碎；大框先放就是现状。**只能换一种牺牲** |
| C. 全局整数规划 | 每条 × 每个候选 0/1 + 重叠冲突约束 | 最优、可解释 | 需要求解器 / 依赖；页面热路径上不可控；**不采用** |
| D. 模拟退火 | 随机扰动 + 温度下降 | 实现简单、质量好 | 需要固定种子、迭代次数不定、难解释、可能抖动；**不采用** |
| E. 拍卖 / 竞价 | 空白「涨价」，出价高的批注得到 | 分布式、公平 | 机制复杂、参数多；**不采用** |
| F. 贪心初版 + 有界局部搜索 | 在初版上做「搬迁 / 交换 / 连锁」，只接受整体更公平的 | 复用现有候选链；确定性；代价可控；能回退 | 需要定义「更公平」；**推荐** |

选 F。关键是把「更公平」定义成一个**与现有规则同源**的量，而不是新造一套权重。

## 6. 推荐算法：一志愿分配 + 冲突图上的局部搜索

### 6.1 形式化

- 批注集合 `N`，每条 `i` 有一个候选链 `C_i = [c_i0, c_i1, …]`（已按 `noteCandidateOrder` 排好）。
- **名次** `rank_i(c)`：`c` 在 `C_i` 里的下标（0 = 第一志愿）。这就是这条批注的**委屈值**。
  它天然满足「整句 < 就近 < 折行 < 环 < 方向」的全部既有口径，不需要新权重。
- 两条批注的候选冲突：`c_a.conflicts(c_b)`（矩形 + 间距）。
- 一个布局 = 给每条批注选一个候选，且两两不冲突（可行解）。
- **块**（4.4）：`i ~ j` ⇔ `∃a∈C_i, b∈C_j` 使 `a.conflicts(b)`；问题按连通分量切成互不相干的小问题。

这样问题就是：**带冲突约束的一志愿分配**（偏好只在批注一侧，位置没有偏好）。
它是一个「加权重独立集 / 列表着色」式的组合问题——精确解是 NP-hard；
不过我们只解**每个块**：块内条数通常 2–4，最大也就十来条，每链 ≤ 40，局部搜索足够。
（整页都是孤立点时，一个块都不用解。）

### 6.2 公平判据：leximin（先救最委屈的）

把**一个块内**所有批注的名次降序排成向量 `R = (r_(1) ≥ r_(2) ≥ …)`，两个布局按下式比较：

```
A 优于 B  ⇔  R_A 与 R_B 按字典序比较更小（先比最大值，再比第二大的…）
```

- 这条判据直接对应用户的抱怨：**不能让最委屈的那条被牺牲**。
- 反例说明为什么不用「总名次和最小」：1 条从 0 掉到 3（和 +3）与 3 条各从 1 掉到 2（和 +3）
  在和判据下等价，但后者三条都被牺牲、前者只牺牲一条——按 leximin，前者更优。
- **名次是序数的，不能单独当引线成本用**：名次 1 在这条链上可能是「往外侧挪 3 个字」，
  在另一条链上可能是「隔一行」。所以判据分三层：
  1. `leximin(rank)`——先把最委屈的那条救回来（规则口径）；
  2. `Σ leaderCost`——同样公平的布局之间，选**引线总代价小**的那个（定义见 6.8）；
  3. `Σ excessDistance` → 稳定 id 序。保证可复现。
- 注意 `leaderCost` 不是等全部落位后再真路由一次：它是随布局现算的**几何估计**（见 6.8），
  进搜索一起比较，否则「挪远一点更好看」这种判断要等到路由完才知道。

### 6.3 动作

以「当前最委屈的那条」为驱动：

1. **搬迁**：把它换到它自己名次更靠前的候选；目标位置空着就直接换。
2. **连锁（1 跳）**：目标位置被 1 条占着，就先试着把占位者挪到它自己的下一个候选
   （名次可以变差，只要整块的 leximin 变好、且引线不过上限）；成功则两条一起换。
3. **连锁（2 跳）**：被占位者的空候选又被别人占着，再展开一层；只试到 2 跳、每层最多 2 个分支。
4. **交换**：两条的位置互换（长框 ↔ 短框），按同样的两层验收判。
5. **拒绝即回滚**：任何一步都在副本上算，只有整体 leximin 变好、且每条引线都在上限内才提交。

验收分两层：

```
名次：     leximin(trial) < leximin(current)                       # 只要求「最委屈的那条」变好
引线：     leaderCost_new ≤ naturalGap + 3em 且 hits_new == 0      # 逐条硬上限（6.8 / 6.3 末表）
```

名次这一层**允许某条变差**（长框退一档、短框进两三档），否则占着第一志愿的那条永远不会让位；
引线这一层是**逐条硬上限**，「挪远了引线不好画」由它兜住。两层都过才提交。
只看名次的话，两条候选可能名次只差 1，引线却从 12px 变成 300px（真机 120 那条就是
「名次只差一档、引线 621px」），所以引线必须是硬约束、不能只当排序的软指标。

**这条「不变差」的边界要单独定**（待批第 6 条）：

如果**任何**被挪动的条目都不许变差，那么「正占着自己第一志愿的那条」就永远不会让位——
真机上 788px 的长框恰好占着它自己的第一志愿，短框才被顶到隔行。于是有两种口径：

| 口径 | 接受条件 | 能修什么 / 修不了什么 |
|---|---|---|
| **保守版**（不采用） | 每条的 `rank` 都 `≤` 原来的 | 只让短框自己找更好的空位；修不了「长框把近处全占了」（真机那页正是这种） |
| **进取版**（**已定，2026-10-27 用户定口**） | `leximin(trial) < leximin(current)` | 允许「长框退一档、短框进两三档」这类交易；用 6.8 的**引线绝对上限**兜住「挪远了不好画」 |

进取版必须配一条**绝对**的引线护栏（不是「不许比原来差」，而是「不许超过某个可见上限」）：

```
leaderCost_new ≤ naturalGap + NOTE_LEADER_BUDGET_EM × em     # 初值 3em
hits_new == 0                                                # 不许从别人的框上压过去
```

- 「变差」只对**名次**放开：允许为了救最委屈的那条把某条排到更后的候选去；
- 引线是**绝对上限**，不是相对门槛：退一档可以，退到大半页之外、或者要从别人的框上跨过去，不行；
- 谁都不许退过上限 ⇒ 上限本身就是兜底。上限触发时这一步直接不成立，回退。

公平判据随之确定：**进取版就是 leximin**（`leximin(trial) < leximin(current)` 作接受条件），
不用「总名次和最小」——后者会默许「牺牲一条、成全三条」，跟「允许长框变差」的初衷相反。
块划分、确定性、预算两种口径都一样。

### 6.4 伪代码

```text
assignGlobal(notes, chains):
    layout = greedyAssign(notes, chains)          # 现有 placeBest / makeRoom 的产物
    for block in conflictComponents(notes, chains):   # 4.4：冲突图连通分量
        if block.size <= 1: continue                  # 谁也不碰 → 一个坐标都不动
        layout = optimiseBlock(layout, block, chains) # 只动块内的这几条
    return layout

optimiseBlock(layout, block, chains):
    for pass in 1..NOTE_ALLOC_PASSES:                     # 2
        best = layout
        worst = block 里名次最大的那条（并列取 id 小）
        for cand in chains[worst].takeWhile(rank < currentRank):
            if cand 空闲:
                trial = layout.with(worst -> cand)
            else:
                blockers = 与 cand 冲突的、块内已放条目（≤2 条，取名次最大的两条）
                trial = tryChain(layout, worst, cand, blockers, hops = 2)
            if trial != null and leximin(trial) < leximin(best):
                best = trial
                break                                     # 只接受本轮的第一次改进（确定性）
        if best == layout: break                          # 本轮无改进
        layout = best
    return layout
```

### 6.5 复杂度与预算

- 按块算：单块 `b` 条（通常 2–4，极端十来条）× 每条最多 `m` 个更优候选 × 冲突检查 `O(b)`；
  连锁展开最多 4 个组合。b=4、m=25 时约几百次矩形比较，**远小于 1ms**（Kotlin/JVM）；
  整页 n=9 全部挤在一块时约 2–4 千次，仍 < 1ms。
- 预算上限：`NOTE_ALLOC_PASSES = 2`、连锁 2 跳、每层 2 分支、单轮候选上限 16 个。
- 超出预算直接返回当前布局（与现状等价，不会更差）。

### 6.6 确定性

- 迭代顺序固定：**块按最小 id 升序** → 块内名次降序 → id 升序 → 候选链顺序。
- 不用随机数、不用时间、不做浮点近似比较（沿用 `NOTE_GEOM_EPS`）。
- 同一输入必然得到同一布局；`NOTE-ALLOC` 日志记录各块的大小与最终名次向量，便于回归比对。

### 6.7 与现有代码的接口

| 现有 | 处理 |
|---|---|
| `notes` / `candidatesByNote` / `nextBatch` | **不动**，只要求能取到「该条的前若干个候选」；必要时把 `nextBatch` 的圈补到 1–2 圈再搜 |
| `placeBest` / `take` / `slideFree` | 保留，作为**初版**生成器（`greedyAssign`） |
| `makeRoom` | 第 2 步（P2 / 7.2）先升级；P3 之后再作为初版的让位手段，坏结果由搜索纠正 |
| `arrangeSharedBlankNotes` | 保留为**最后的装饰性平移**（长外短内）；全局分配在前，不改变它的语义 |
| `chainFor` | 不动，局部搜索直接用它的结果 |

### 6.8 引线成本：搜索里必须带上「挪远了引线还画不画得出」

**为什么单靠名次不够**：

- 名次是**序数**。`excessDistance` 虽然排在链里，但它是「超出自然留白的那一段」，
  不含折数、也不含「中间隔着别的批注框」——两条名次相邻的候选，一条可以是一条 12px 直线，
  另一条是绕 621px 的 L（真机 120 那条正是后者）。
- 引线的**最终**形状要等 `routeNoteArrow` 才知道（一页 ~76ms），搜索里不可能每条候选都真路由一遍。
- 更糟的是：引线是被**别的批注框**挡住的，而「别的框在哪儿」正是这一步要决定的东西。
  所以这个代价必须能在「本轮假设的布局」上快速算出来。

**做法：一个便宜的引线估计（不是真路由）**

对「批注 `i` 的候选 `c` + 当前假设布局里已放的框」：

```
入口：选区近那一端的边、内缩 0.5em（与 6.1 / 引线规则第 7 条同一口径）
出口：c 朝正文那条边的中点

直线可达（两端在 0.5em 容差内对齐，且走廊不碰任何已放框） → bends 0, hits 0
否则 L 形（先横后竖 / 先竖后横）任一方向不碰框           → bends 1, hits 0
都不通（走廊必然穿过别人的框）                          → bends 2, hits = 穿过的框数

leaderCost = |Δx| + |Δy| + bends × 1em + hits × 3em
```

- 全程只做矩形相交，O(已放框数)，单条候选几十次比较——**比真路由便宜两个数量级**。
- 依赖「已放框」，所以不进 `NoteCandidate`（那是纯几何缓存），在分配器里现算；
  同一次 trial 内对没动的批注结果可复用。
- 真路由仍然只跑一次（落位定稿后），估计只用于**搜索时的取舍**。

**两级用法**：

1. **硬门槛（逐条，绝对上限）**：任何一条被挪动后
   `leaderCost_new > naturalGap + 3em` 或 `hits_new > 0` → **不接受这一步**。
   名次可以变差（进取版已定），引线不行——「挪远了引线不好画」由这条兜住。
2. **软择优**（6.2 的第 2 层）：公平程度相同时取 `Σ leaderCost` 更小的布局。

**收尾闭环（P4）**：真路由跑完后，若某条走了兜底（`NOTE-ARROW fallback`，即 4 折仍不通
或压字），只对**这条 + 它的邻居**做一次「换到第二志愿 / 与占位者互换」的补救，
再局部重路由（2–4 条），不整页重排。这样搜索用估计、收尾用实测，两头都不贵。

**同一份成本也要补进现有收尾**：`arrangeSharedBlankNotes` 的「长外短内」平移目前只检查
空白边界与框间距，**不检查平移后引线会不会跨过别人的框**——这就是「挪远了引线不好画」
在现有代码里的实例。P4 要求它每平移一步都重算上面的 `leaderCost`，变差就保持原样。

## 7. P1 / P2：两个低风险前置改造（先做，各自可单独验收）

### 7.1 候选「毁伤」打分（P1：fragmentation cost）

- 位置：`noteCandidateOrder` 的**最后一级**（`rect.left` 之后），只做同分决胜，
  **绝不越过整句 / 就近 / 折行 / 环 / 方向**任何一级。
- 定义：候选 `c` 在 `freeRect = F` 里落下后，把 `F \ c` 分成四条残带；
  记 `widest(F, c) = 四条残带里最大的宽度`，`need = 本页还没落位的批注里最宽的那条整句宽`。
- 打分：`split = if (widest < need && F.width >= need) 1 else 0`（把能放长框的空白切没了）。
- 作用：短框不再插在大空白正中间，给长框留出整条横带。
- 风险：只影响同分候选，不会把任一条从更近的位置挪走。**待第 11 节第 2 条批准后作为 P1 实施**。

### 7.2 让位链（P2：让「最有退路」的那条挪）

现状是「所有挡路框当成一个整体、同一个位移推开，遇到更早的行就放弃」。改为：

1. 逐个挡路框单独找退路：在它自己的候选链里找空候选（从当前名次往后看，最多 8 个）；
2. 有退路的那条，按「名次变差最少」排序，取最划算的一条挪过去；
3. 一条都找不到退路，才回退到现有的整体平移；
4. 全程在副本上试，校验（空白边界 / 不撞别人 / 不搬更早的行 / **引线在上限内**）通过才提交。

**为什么排在 P3（块内搜索）之前**：这一步让「贪心初版」自己先变好——
长的挤过来时，短的那条会换到「第二志愿」（仍是本行、仍在自然留白内），而不是被一刀切到隔行。
初版越好，后面搜索要纠正的就越少，P3 的上限（2 轮 / 2 跳）也更容易够用。
另外这一步本身就能单独验收、单独回退，不依赖 P3。

**风险与约束**：`makeRoom` 是手工规则最密的地方（不搬更早的行、不盖住右侧文字、整句档才让），
所以只在「有更好退路」时改变行为，找不到退路完全走原路；单测覆盖原有全部让位场景。


### 7.3 收尾平移的引线护栏（P4 一起做）

`arrangeSharedBlankNotes` 现在只判「空白边界 + 框间距」，平移后引线可能跨过别人的框。
补一条：每试一步平移，就用 6.8 的 `leaderCost` 重算被平移那条的引线估计，
**变差（含 hits 由 0 变正）就保持原样**。这是最便宜的一处「挪远了引线不好画」修复。

## 8. 实施计划

**严格按 P1 → P2 → P3 → P4 → P5 顺序做，不跳步。** 每一步都独立提交、独立验收、可单独回退；
上一步真机验收不通过就不进下一步。

| 步骤 | 内容 | 改动点 | 验收 | 风险 |
|---|---|---|---|---|
| **P0**（本文档） | 方案与口径 | 仅文档 | 用户批准第 11 节 | 无 |
| **P1** | 毁伤打分（7.1） | `noteCandidateOrder` 末级 + 单测 | 现有 387 条 jvmTest 全绿；新增「短框不再切开长框要用的整条空白」 | 低 |
| **P2** | 让位链（7.2） | `makeRoom` + 单测 | 原有让位场景一条不退化；新增「长框挤过来时，短框换到自己的第二志愿而不是被推到隔行」 | 中（改动面大，靠原有用例兜底） |
| **P3** | 块内局部搜索（第 6 节，含 6.8 的引线估计与绝对上限） | `assignNoteCandidates` 末尾 + 块划分 + `NOTE_ALLOC` 日志 + 开关 | 真机同页 `ranks` 向量变好、任一条引线不超上限；**单条批注页与现有输出逐像素一致**；`assign` ≤ 2× | 中 |
| **P4** | 收尾整合 | 全局结果替代 / 收窄 `arrangeSharedBlankNotes`（7.3）+ 兜底补救 | 「长外短内」仍成立，且不再出现 1px 折 / 621px 长引线 | 低 |
| **P5** | 真机验收与文档收口 | 平板 10 页样本 + 截图对照 | 见 9.2 | 低 |

顺序的理由：

1. **难度递增**：排序末级（一行）→ 让位内部（一个函数）→ 分配整层（新算法）→ 收尾（平移）→ 验收。
2. **每步都给下一步铺路**：P1 让同分候选不再乱切空白；P2 让「初版」自己就少犯错，
   P3 要纠正的就越少（2 轮 / 2 跳才够用）；P4 才有意义（前面定的位置再来谈「长外短内」）。
3. **每步都能单独回退**：P1/P2 改动小、P3 有开关、P4 只动收尾，坏哪一步退哪一步，不用整体回滚。

## 9. 测试与验收

### 9.1 单元测试（`shared-ui/src/jvmTest/.../NoteBubblesTest.kt`）

1. **同块空白两条**：长框 6 行 + 短框 1 行，短框必须仍落在本行环 0，且引线 ≤ 自然留白。
2. **三条争一块**：两短一长，长的在中间插入时，短的两条不得同时掉到隔行。
3. **长框整句不被切**：短框先放会切开大空白的场景，毁伤打分应让短框换到边缘。
4. **最委屈最小化**：构造「牺牲 1 条 0→1」对「牺牲 3 条 1→2」的两个可行布局，断言选前者。
5. **确定性**：同一输入跑 100 次，布局与名次向量完全一致。
6. **预算**：20 条 × 40 候选的构造页，`assign` 增量 < 3ms（宽松门槛，防回归）。
7. **引线硬门槛**：构造「挪过去能救最委屈的那条、但引线要跨过别人的框 / 超出 3em 上限」的布局，
   断言不采纳。
8. **挪远不变差**：「长外短内」平移会让某条引线变长 / 多折时，断言保持原样（7.3）。
9. **长框让位（进取版）**：长框占着近处、短框被顶到隔行的布局，断言结果是「长框退一档、
   短框进到近处」，且长框的引线仍在 3em 上限内。
9. **估计与实测同向**：对同一批候选，`leaderCost` 的排序与真路由后的长度 / 折数排序
   方向一致（允许个别不等，只查「估计最好的那条实测不比最差的那条差」）。
10. **作用范围（4.4）**：单条批注的页、以及两条批注候选互不相交的页，
    新旧实现产出的 `rect` 与引线**逐像素相等**；`NOTE-ALLOC` 里 `blocks=0` 或每块 `size=1`。
11. **块拆分**：一页两组互不相干的批注，改 A 组的状态不影响 B 组的坐标。

### 9.2 真机验收（平板 vivo PA2353）

- **先验「没变」**：抽 10 页只有单条批注 / 批注互不相干的页，改动前后截图逐像素一致
  （`shasum` 不同的包，同页 PNG 的 diff 必须为空）。这一条是「只动争位场景」的实证。
- **再验「变了」**：同一页（代码块 + 变量段）截屏对照：批注不再互相挤到隔行 / 页边距；
  长框与短框的相对位置符合「长外短内」；不再出现 1px 折。
- 日志口径（`Orilumn.NOTE`，追加）：`NOTE-ALLOC blocks=… sizes=… ranks=… worst=… moves=… ms=…`，
  与 `NOTE-PLACE` 并列；验收时对比 `assign` 与 `total`。
- 翻回同一页两次，布局与引线逐像素一致。

## 10. 风险与回退

| 风险 | 缓解 |
|---|---|
| 局部搜索把布局改得「不如以前顺眼」 | 只接受 leximin 变好的整体布局；坏结果不可能被提交 |
| 分配变慢 | 硬上限（2 轮 / 2 跳 / 16 候选）+ `assign` 计时日志；超预算直接返回初版 |
| 与让位的手工规则冲突 | 让位仍先跑（初版），搜索只在名次层面做**不违反硬不变量**的搬迁 |
| 结果不稳定 | 全序确定性；不用随机数；测试跑 100 次比对 |
| **误伤不相干的批注** | 只解冲突图连通块、块大小 1 直接跳过（4.4）；P3 验收里有一条「单条 / 互不相干页逐像素不变」 |
| 估计便宜但不如真路由准 | 估计只用于取舍，硬门槛宁严勿松；真路由后仍有 P4 的局部补救；日志同时记估计与实测 |
| 为了引线不变差而锁死布局（长框永不让位） | 已定进取版：允许名次变差，改用引线**绝对**上限（`naturalGap + 3em`、`hits == 0`）兜底 |
| 需要临时关闭 | 开关 `NOTE_ALLOC_GLOBAL`（默认关 → 灰度），关掉即回到现状 |
