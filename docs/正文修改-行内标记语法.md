# 正文修改：行内标记语法（规格）

> 读者改正文时，**选区里的行内结构要在修改卡里看得见**：`<code class="test">hello</code>` 显示成
> `` `hello` ``，`<span class="pic">红</span>` 显示成 `<span>红</span>`——读者才知道自己是在元素
> 里面还是外面改字；确定时再按原来的样式、属性补回去，属性一个都不显示。
> 本文只定义**标记语法、显示规则、校验规则、提交后的落地方式**，是这块功能的唯一依据。
>
> 关联系：`文本标注与修订方案.md` §8（v3 正文修改）、D-31 ~ D-36（修订的坐标 / 缓存 / 输入卡）。
> 本文不改那套坐标契约，只加「样式区间」这一层显式覆盖。

## 0. 一句话

**标记只活在修改卡的输入框里**；提交时转成「纯文本 + 样式区间」，正文与落库文本仍是纯文本，
标记一个字符都不进正文、不进坐标、不进复制与摘录。**语法糖只负责显示和输入，属性由软件补回。**

## 1. 原则（四条铁律）

1. **两层分离**：输入框里是标记文本（纯文本控件，不是富文本）；提交后落库的是纯文本 `text`
   + 一份「样式区间」。分页、`delta`、标注映射、阅读进度全部只看纯文本，**一处都不用改**。
2. **显式优先**：读者写了标记，就按标记落元素；没写的地方沿用现状（新字挂左邻，见 D-33），
   **不做任何意图猜测**。标记就是读者的显式覆盖。
3. **幂等**：`显示 → 解析 → 落地` 必须逐字逐元素等价。打开卡不动、直接确定 = 不落库、不重排。
4. **行内标记不表达段落结构**：本文这套标记只表达**行内**元素，标题 / 列表 / 引用 / 代码块
   另有一套**块级**行首标记（`## ` / `> ` / `- ` / 围栏），见 `正文修改-块级标记.md`。
   两套互不混写：行内标记只在块内容里生效，块标记只在行首生效；`<p>` / `<div>` 这类块标签
   写进正文仍拒绝（见 §5.1）。

## 2. 支持的标记

### 2.1 markdown 语法糖

| 写法 | 含义 | 落地元素 |
|---|---|---|
| `*文字*` | 斜体 | `<em>` |
| `**文字**` | 粗体 | `<strong>` |
| `***文字***` | 粗斜体 | `<strong><em>文字</em></strong>` |
| `` `文字` `` | 等宽 / 代码 | `<code>` |
| `^文字^` | 上标 | `<sup>` |
| `~文字~` | 下标 | `<sub>` |
| `~~文字~~` | 删除线 | `<s>` |
| `[文字](url)` | 链接 | `<a href="url">` |

- 不支持 `_斜体_`（下划线在正文里太常见，避免误伤）；
- 标题、列表、引用、代码块**不在本文范围**：它们走行首的块级标记（`## ` / `- ` / `> ` /
  围栏），见 `正文修改-块级标记.md`；表格行与整块图片也有单独规则（同上 §1.1），
  但**标记语法本身不提供**表格 / 图片的写法，水平线两套都不做。

### 2.1.1 插图

行内 `<img>` 在正文里只占一个 `U+FFFC` 占位，卡片里就照原样显示它——字体把它画成一个
带虚框的物件图标，**是一个整体字符**：选中、退格、删除都按一格算，不存在「删掉一半」，
删掉这一格就是连图一起删。

- 相邻多张图靠位置区分，占位本身不带编号；占位留着，图就留在原处（图片本身不重写）；
- 语法里**没有插图的写法**：写不出新占位，也就不会凭空多出一个没有图的占位；
- **只用来包一张图的标签不摊成标记**（`<span class="pic"><img></span>`、`<a><img></a>`、
  `<span class="guiicon"> <span><img></span> </span>` 这类）：这层元素对读者没有可改的内容，卡片里
  只有那个占位字。**包几层就藏几层**，图旁边那些只当间距的空格也一起算在图里。
  元素跟着占位一起看——占位留着就原样保留，占位删掉、图没了，元素自己变空也会被剪掉（§5.3、§4.3）。

### 2.2 HTML 行内标签

没有语法糖的行内元素，直接写标签；**显示只有标签名，不带任何属性**：

```html
<span>红字</span>
<u>下划线</u>
<q>引文</q>
```

- `class`、`id`、`style`、`title`、`lang`、`dir`、`datetime` 这些属性**一律不进卡片**：
  它们是书自己的样式，读者看着是噪音，改了还会被下次补回覆盖（写回时由软件从原结构补回，§4.3）。
- 读者手写的属性**一律忽略**：`<span class="b">字</span>` 里的 `class` 不生效、也不报错，
  落地时按「同标签补回原属性 / 同段模板」走，与直接写 `<span>` 等同。
- 链接的地址是内容不是属性，仍用语法糖 `[文字](地址)` 写出来、看得见（§2.1）。

白名单之外的标签（如 `<p>`、`<img>`）会被拒绝，见 §5.1。

**白名单**（只允许行内元素）：

`em` `i` `strong` `b` `code` `kbd` `samp` `var` `span` `a` `sup` `sub` `u` `s` `strike`
`del` `ins` `small` `big` `mark` `q` `cite` `abbr` `dfn` `ruby` `rt` `rp` `bdi` `bdo` `br` `wbr`

- 白名单是**代码里的一个常量**，新增必须同步本文（便于审计）；
- `<br>`、`<br/>`、`<br />` 三者等价于段内换行：显示时统一写成 `\n`，提交时落成 `<br>`；
- **`</br>` / `</wbr>` 不合法**（规范里 `br`、`wbr` 是**空元素**，根本没有结束标签），
  按 §5.1 拒绝并提示「断行直接写 `<br>`」。不能悄悄当换行、也不能悄悄吃掉那几个字；
- 大小写不敏感，落地时统一小写。

### 2.3 配对规则

沿用 CommonMark 的核心约束，保证「正文里的星号 / 波浪号不会被误吃」：

- **开标记后面不能紧跟空白，闭标记前面不能紧贴空白**：`3 * 4 * 5` 里两个 `*` 都是字面；
- **同段内就近配对**（不跨 `\n`）：`*a *b* c*` → `<em>a <em>b</em> c</em>`；
- **长度优先**：`**` 先于 `*` 配对，`~~` 先于 `~` 配对；
- `~` 连写 3 个以上按字面处理（1 个 = 下标、2 个 = 删除线）。

### 2.4 未闭合：标签延伸到选区边界，markdown 标记按字面

**两类标记的「未闭合」含义不同，别混为一谈。**

**HTML 标签可以不配对**（选区本来就可能落在元素中间，元素在选区外还继续着）：正文
`正文未选中<code>abc` + 选区 `def` + `</code>`，卡里显示 `` `def` ``。

- 行尾未闭合的开标签（`<em>abc`）⇒ 样式覆盖到**这段文字的末尾**；
- 行首孤立的闭标签（`abc</em>`）⇒ 样式从**这段文字的开头**起；
- **显示时我们一律把两头写全**（`*abc*` / `<code>abc</code>`），读者删掉任一端照上面两条认；
- 选区外侧的元素**一个字都不动**；选区内侧新建的是同签名元素，两者相邻、视觉无差别；
- 只有**白名单与属性违规**才拒绝（§5），标签配对不是提交条件。

**markdown 语法糖必须成对**（§2.3）：写了一半的 `*abc`、`` `abc `` 里的那个符号是**普通文字**，
不会让 `abc` 变成斜体 / 代码。卡片里按字面显示，并且用另一种颜色标出来（§3.6），
读者一眼就知道「这个标记没生效」。要表达「这段字在 code 里」，请把两端写全（`` `abc` ``）。

### 2.5 转义

**书是 EPUB，不是 markdown**：原文里的 `*` `~` `^` `` ` `` `[` `<` `&` 都是**普通文字**，
只是碰巧长得像标记。输入区是 markdown 编辑区，所以显示时**必须按普通文字转义**，
不转义就会被解析成粗体 / 斜体 / 标签 / 实体，读者一点确定原文就被改掉了。**没有行内结构时也一样**（§3.1）。

序列化只在**不转义就会被解析成标记**时才加 `\`，避免正文里满屏反斜杠：

- `\` 永远写成 `\\`；
- `*` / `` ` `` / `~` / `^` 只有在能构成配对（满足 §2.3 的空白规则）时才转义，
  例如 `1~2` 原样写，`x~y~z` 里的第一个 `~` 写成 `\~`；
- `[` 只有在能构成 `[文字](url)` 时才转义，`见[注1]` 原样写；
- `(` `)` 自己**不构成语法**（链接必须由裸 `[` 起头），不转义，`函数()` 不会写成 `函数\(\)`；
  `]` 仍要转义——它会把链接名的括号配对截断；
- `<` 与 `&` **永远**转义成 `\<` 与 `&amp;`（标签与实体的识别不能靠上下文猜）；
- 输入时 `\x` 表示字面 `x`，`x` ∈ `\ * ` [ ] ( ) ^ ~ < > &`。

实体只认五个：`&amp;` `&lt;` `&gt;` `&quot;` `&#39;`（序列化也只产生这五个）。
`&nbsp;` 不认——要空格就敲空格。

## 3. 显示（选区 → 标记文本）

1. **原文一律转义，没有行内结构也照走**：书里的字进输入区前**永远**过一遍序列化（§2.5），
   原文自带 `**加粗**`、`10~20`、`[注1]`、`<b>`、`AT&T` 这类普通文字时，输入区显示成
   `\*\*加粗\*\*`、`10\~20`、`\[注1]`、`\<b>`、`AT&amp;T`。确认时 `parse` 把反斜杠去掉，
   落进书里的仍是原来那几个字、结构不变（原样确认 = no-op）。**不能**因为「选区上没有行内元素」
   就直接塞纯文本——那样一确认，字面标记就被当成语法吃掉或改写成样式（EPUB 不是 markdown）。
2. **取结构**：从排版叶的字符归属算出选区每个字的元素链（与排版、字符投影同源，不另建一套）。
   相邻两个叶在同一处结束（中间那个叶没有字）时只算一块，卡片的偏移换算按同一份块界走，
   不会把后面几行的行内结构整体挪一格。
3. **语法糖优先，不看有没有额外属性**：`em` / `strong` / `code` / `sup` / `sub` / `s` / `a` 一律用
   语法糖——`<code class="test">hello</code>` 就是 `` `hello` ``，`class` / `style` / `id` 这些
   属性在确定时**由软件补回**（§4.3），读者不必看见。
   - 链接的地址写进 `( )`；其余属性不显示；
   - 没有语法糖的元素（`span` `u` `mark` `q` `cite` `ruby` …）用标签形式，**也只写标签名**
     （`<span>`），属性同样不显示（§2.2）。
4. **截一半照实显示**：选区落在 `<em>慢慢</em>地走` 的第二个「慢」到后面正文时，显示成
   `*慢*地` —— 元素在选区边界处闭合，读者一眼看出后半已在元素外；元素在选区外面继续时，
   把这一端也写全（`*慢*` 而不是 `*慢`），删掉任一端解析结果一样（§2.4）。
5. **空元素**：选区没有字覆盖的空元素不显示、也不改动（重放不碰它）。
6. **标记淡化，两档颜色分得开**：输入框用 `AnnotatedString` 给标记字符换墨色（仅显示），
   文字本身颜色不变。**成对的标记淡化（浅灰）**，因为它们真的会生效；
   **没配上对的标记（§2.3 判为字面）用强调色（金）**——它们会被当普通文字落进正文。
   两档必须一眼分得开，不要让读者「以为生效了其实没生效」。
7. 输入框里的「复制」仍复制**选区原文（纯文本）**，不复制标记（D-36）。
8. **整段覆盖：书本来就有的隐形，读者新写的照实摊开**。元素正好盖住整张卡时（起止都落在
   文选区边界上），读者看不出边界在哪，早先一律不显示标记、确定时按整段套回。这条只对**书本来
   就有的**元素成立：读者这次新写、又正好盖住整段的标记（选中一段字整段加粗）必须写出来——
   那张卡就是这次改动的全部内容，藏起来读者只会看到一段没改过的普通文字，与审阅视图里
   那对绿色标记对不上（用户复报）。
   判据与审阅痕迹**同一份**（`FormatTraces`：新写的 = 修订的结构减掉这一段原来的结构），
   两处不许各说各话。这个回比只在**文字逐字没变**（替换文本与原区间等长）的修订上做：
   改了字的修订两头坐标不同，仍按「整段覆盖即隐形」处理。
9. **「这一行本身就是那个元素」照实写出整行标签**：书里用 `display:block` 把 `span` / `a` 这类
   行内元素做成独立一行时（`<h2><span class="sec_num">第四十八章</span> 夜话</h2>`），排版把它
   切成单独一叶，而这一叶**自己**就是那个元素。卡片写成整行包一层：
   `<span>第四十八章</span>`。正文段落里的同类叶
   （`<p>段落前<span class="blk">块中间</span>段落后</p>`）**同一套口径**——它不是标题的特殊分支，
   只要这一叶的元素在白名单里（§2.2）就写出来。
   - 这层包装与块标记同待遇：**只活在卡片里**。提交时先摘掉（叶元素本来就留着，进修订的只能是
     叶里的字与结构），不进原结构、不参与 no-op 比较、不写库，也不会在叶里再套一层同名元素。
   - 它**永远显示**，不适用上一条「整段覆盖就隐形」：它天生就盖住整行，藏起来读者会以为书里的
     `<span>` 凭空没了。
   - 读者删掉 / 换成别的标签 ⇒ 拒绝并提示（§5.3）。

## 4. 提交（标记文本 → 修订）

### 4.1 产物

```
纯文本 N（去掉所有标记、解开转义）
样式区间 [(start, endExclusive, sig), ...]   // 相对 N，可嵌套，按 start 排序
```

`sig` = 元素的**签名**：`tag` + `attrs`（只留 §5.2 允许的属性）。

### 4.2 纯文本仍走老路

`N` 交给现有 `TextEditPlanner`：公共前后缀裁剪、叶归属、跨段、吸收旧修订——**这一段逻辑不动**。
样式区间按同样的叶切分规则映射到叶内偏移，随修订一起落库。

### 4.3 元素从哪来：补回原属性

- **结构没变的那一段**：按「同标签 + 同嵌套顺序」从外到内把解析出的区间对回原选区的区间
  （第 k 个 `<em>` 对第 k 个 `<em>`，嵌套层数也一致才算对上）。对上的，
  **补回原元素的全部属性**——`class`、`style`、`id`、`title`、`lang`、`dir`、`datetime`……
  一个都不丢。这就是 `` `hello` `` 确定后仍是 `<code class="test">hello</code>` 的原因。
  对不上的（读者多写的、或原结构里被删掉的）按「新写」与「删除」分别处理。
- **读者在语法里写出的属性优先**：`[文字](新地址)` 的 `href` 取新地址，其余属性照旧补回。
  标签形式里写的属性一律忽略（§2.2）：卡片里根本写不出属性，写了也不算数。
- **`id` 的两条例外**：
  - 原位保留的那一份**保留原 `id`**（脚注锚点之类不能断）；
  - 因拆分 / 复制而**新增**的那一份丢弃 `id`（会撞号，与拆段同口径 D-34）。
  - 读者手写的属性一律不进（卡片里不显示、解析时直接丢掉）：`id` 不是靠读者抄一遍来传递的，
    原位保留的那份由补回逻辑从原文带回来。这样「宿主给不出原结构」的路径（比如非盒式排版、
    审阅视图降级）也不会把读者抄来的重复 `id` 写进正文。
- **读者新写的标记**：取模板元素——**同段**（选区所在的段，可以比选区更宽）已有的同标签元素；
  同段里没有同标签元素就用裸标签（如 `<em>`，书里给 `em` 的 CSS 照样生效）。
  模板属性一并采用，**`id` 一律丢弃**。链接地址是唯一由读者写的「属性性」内容：
  `[字](新地址)` 的地址按读者写的走，其余一律由模板 / 原结构补。
- **读者删掉了标记但留了字**：那段字变回正文，元素**整个消失**（不留空元素）。
  空元素只在"书里本来就有"且没被碰过时保留。

### 4.4 没写标记的新字

标记不是必须的，是**显式覆盖**；落在哪里取决于这条修订有没有样式信息：

- **有样式信息**（卡里开着标记、提交时带了区间）：这一段按区间**整段重建**——
  区间盖住的字落进对应元素，没盖住的字落回叶级文字。于是「元素后面的字被吞进元素」不再发生：
  在 `*斜体*` 后面继续打字，那几个字就是普通正文；把标记删掉，那些字就跟着退出元素。
  行内图片（`U+FFFC` 占位）在这条路径上也按占位去留决定：占位还在就留图、排在前后两截字的
  中间；占位不在就删图。
- **没有样式信息**（`styles` 为空的老修订，或审阅视图 / 带段界的降级路径）：沿用现状
  （挂前一个保留字所在节点，D-33），一个字节都不变。

**元素在这一点切开，字序不变**：新字落在某元素**中部**、又不属于这个元素时（如
`<code>getPriceInEuros()</code>` 里只把 `Price` 加粗、或审阅视图把绿 `**` 排进代码段里），
在那一处把元素切成两段，新字排在中间（`<code>get</code>` + 粗体 `Price` + `<code>InEuros()</code>`），
后面那段字仍留在原处。**任何情况下都不许把新字整体挪到元素之后**——那会把正文的字序改掉
（早先正是这样：`getPriceInEuros()` 变成 `getInEuros()Price`，审阅视图里的绿标记跑到段尾）。

### 4.5 跨段

- 标记不跨 `\n`：每行各自解析，在行边界上开口的标记按 §2.4 **夹到本行边界**
  （下一行是另一段，行内元素不跨块）；
- 段数不变（每叶一条修订）、段数变了（合并 / 拆分）都支持，**不再拒绝**带标记的提交。

## 5. 校验（提交前拦截）

**提示就地显示在卡片里**：解析错误、提交被拒（把整块图片改成文字、表格行列对不上、
非白名单标签…）一律写成输入框上方的一行提示，**卡片不关、正文不动**；有多少条错就列多少条
（用「；」分隔），不再只弹底部第一条。底部提示离输入框太远，读者不知道该改哪儿，
后面的错误也会全丢。

### 5.1 标签

| 情况 | 处理 |
|---|---|
| 未闭合 / 多余闭合（`<em>abc`、`abc</em>`） | **接受**，按 §2.4 延伸到选区边界 |
| 不在白名单（`<p>` `<div>` `<img>` `<table>` `<script>` `<iframe>` `<svg>` `<math>` …） | 拒绝，提示「只支持行内标记；段落用回车」 |
| 标签里的属性（`class` `id` `style` `onclick` …） | **一律忽略**：不显示、不生效、不报错，落地时由原结构 / 同段模板补回（§2.2 / §4.3） |
| 自闭合写法 `<br/>` `<br />` `<br>` | 接受，等价 `\n` |
| 空元素的结束标签（`</br>` `</wbr>`） | **拒绝**，提示「`br` 是空元素、没有结束标签，断行直接写 `<br>`」 |

### 5.2 属性策略

**属性只在写回时存在，卡片里一个字都不显示**（§2.2）：读者看不到、也写不出 `class` / `style` /
`id` 这些，所以这里说的是「从原结构补回时」的口径。

- 允许：`class`、`style`、`id`、`title`、`lang`、`dir`、`href` 与 `target`（仅 `a`）、
  `datetime`（`del`/`ins`）。`id` 只用于原位保留（§4.3），新增或复制出来的元素一律丢弃；
- 丢弃：`src`、`on*`（任何事件）、`contenteditable`、`hidden`、`data-*`、其余一切未列出的；
- `href`：只允许 `http://` `https://` `mailto:` `tel:` 与相对路径（读者写的地址走语法糖，照常校验）；
  `javascript:` `data:` `vbscript:` 一律拒绝并提示；
- `style`：只保留**不影响正文坐标与分页**的视觉装饰声明。注意保留名单里也有会改变字形宽高、
  进而影响排版的声明（`font-*` 的 `font-size`、`padding*`、`border*`、`margin-left/right`），
  这是**有意保留**的：行内元素的字号、内边距、边框本来就参与断行宽度，剔掉它们等于把书里
  看得见的排版悄悄改掉。真正剔除的是会**跳出正常流**、脱离文档流或整块隐藏的声明。
  - 保留：`color` `background-color` `font-*` `text-decoration*` `text-transform` `letter-spacing`
    `word-spacing` `vertical-align` `border*` `outline*` `padding*` `margin-left` `margin-right`
    `text-shadow` `opacity`
  - 剔除：`position` `float` `display` `visibility` `transform` `animation` `transition`
    `filter` `width` `height` `overflow` `z-index` `content` `white-space`

### 5.3 其它拒绝项

- **整块图片**：只许整张删除（删掉 `U+FFFC`）或原样保留；换成文字拒绝并提示
  「图片只能整张删除，不能改成文字」；
- **表格**：正好选中一整张表时按「网格自洽」校验——格子里的字、行数、每行列数、
  `rowspan` / `colspan` 都可以改，只要整张表还能铺成矩形网格（0 行 = 删表）；
  半张表 / 表格前后还带着段落时只许改格子里的字，改结构拒绝并提示
  「请只选中这张表」；
- **块级行内元素**（书里 `display:block` 的 `span` 之类，见 §3.9）：卡片里那层整行标签必须留着。
  删掉或换成别的标签拒绝并提示「删掉或换掉标签会把它并回上一行，这一版还改不了」——
  摘掉块级元素等于把这一行并回上一行，那是结构改写，卡片这一版不做；
- 生成内容（`::before`/`::after`、`q` 引号）不参与编辑。

**行内图片不拒绝**（`img` 在文字块内部，正文里是一个 `U+FFFC` 占位）：卡片里就是那一个占位字
（见 §2.1.1），读者删掉它就把图一起删掉；占位留着图就留在原处。只包着图的行内元素
（`<span class="pic">` 之类，包几层都一样）不摊成标记，跟着占位一起看。标记语法本身
**不提供插图的写法**（`<img>` 仍不在白名单里，写进来照样拒绝）。

## 6. 幂等与 no-op

- `显示(x) → 解析` 必须等于 `x`（同 tag、同 attrs、同嵌套、同文字）；不等就是 bug，
  表现为「什么都没改，点确定却重排了」。
- **多块同样适用**：输入区里有好几块时，回验拿的是拼起来的全文，所以块内区间要按全文坐标处理；
  任一版不相等就整篇退化成标签形式，读者会看到一屏 `<code>`（真出现过的回归）。
  每一块都必须各自用语法糖形式写出来。
- **块形态的回验口径**：普通段落的块标记就是空串，写出来什么都没有，解析回来只能记成「没有块标记」。
  回验时「普通段落」与「没有块标记」必须**等价**，不能逐字比；否则**任何普通段落**里的行内结构
  都会被判成结构变了，整段退化成标签形式（真出现过的回归：链接里套代码的那一行，卡片里显示成
  `<a href="…"><code>…</code></a>`）。
- **原文自带的字面标记也在这条里**：`**加粗**` 显示成 `\*\*加粗\*\*`，解析回来仍是 `**加粗**`
  （不是 `<strong>`），结构仍是空表 ⇒ 原样确认 = no-op，一个字都不动。
- **插图同理**：`U+FFFC` 占位在卡片里原样显示（一格），解析回来仍是那一个占位 ⇒
  原样确认 = no-op，图片也不动。
- 提交前先比较：纯文本与样式区间都和开卡时一模一样 ⇒ **直接当 no-op**（不落库、不重排）。
- 回归素材：真实书里抽含 `em` / `strong` / `code` / `a` / `sup` / `span[class]` 的段落，逐段断言往返；
  另抽含字面 `*` `~` `[` `<` `&` 的段落，断言「显示 → 解析」后文字与结构都不变。

## 7. 存储与版本

> 块级形态另存两个键（`b` / `eb`），同样复用 `styles` 这一列，见 `正文修改-块级标记.md` §6。


- `text_revisions` 加一列 `styles TEXT NOT NULL DEFAULT ''`（JSON：区间 + 签名表），迁移 `13.sqm`
  （schema 13 → 14）；老修订该列为空 = 没有显式样式，行为与今天完全一致。
- 这一列里可以有两份区间：`s` 相对最小修订文字（重放用），`e` 相对输入区全文（打开旧修改时
  回显结构用）。公共前后缀裁掉的两端只有 `e` 还带着结构，所以 `e` 必须有，否则「再打开改一次」
  会把选区边上的行内元素丢掉。`e` 是可选字段，不升编解码版本：老版本只读 `s`，忽略 `e`。
- `text` 仍是纯文本；`delta`、`originalText`、`editedText` 不变。
- 序列化 / 解析 / 落地规则的版本进 `contentRev`（`ChapterRevisionMap.ALGORITHM_VERSION`），
  规则一改旧分页表按章自动作废；不动 `LAYOUT_VERSION`（排版算法没变）。

## 8. 明确不做

- 富文本输入框、样式按钮条（读者自己写标记 / 标签）；
- 块级结构（标题、列表、引用、代码块）与表格整表结构（删行 / 加行 / 删表 / 增删列）都另有
  `正文修改-块级标记.md`；图片只能整张删除，水平线不做；
- **只去掉元素原有属性**（卡片里根本不写属性，写了也不生效：属性是书的样式，由原结构补回）；
- 自动纠正读者写错的标记（只校验并提示，不猜）；
- 生成内容可编辑（`::before`/`::after`、`q` 引号不参与）；行内图片只会跟着 `U+FFFC` 占位被删，
  不能换图 / 调大小；表格格子里的字可改，但结构只按整表网格自洽放行。
