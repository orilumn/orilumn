## 0. 唯一的组织原则：一切由紧急程度决定

判断任何一条后台任务该不该做、排多高、允不允许动用重手段，只问一句：

> **用户多快会需要它？**

需要得越快 → 越靠前、越不限手段（必要时允许动全量表）。越晚 → 越懒、越廉价
（只塑形不组装、不落盘）。本项目所有排版机制都是这同一枚硬币的不同侧面，**不是三套机制**：

| 机制 | 它在「紧急程度」上的作用 |
|---|---|
| 锚点增量（临时表） | 让目标页不必等全量，消掉"用户干等"这个最大的紧急度风险 |
| 中央调度（优先级池） | 保证投机性预排按紧急度出队，后台不抢前台 |
| 后台预排（本章/跨章全量） | 在用户不等的间隙把将来的目标页变成"命中" |

推论：优先级与"排哪张表"**没有绑定关系**。一个全量任务可以排在比另一个增量任务更高的档位
——只要它更可能被马上用到（§3 末两条即此例）。

## 1. 两张表：为什么必须分开

大章全量要十几秒。凡交互路径（开书/跳转/调参/翻页）都不能等全量；且这些操作**多发生在章中间**
（跳进大章第 8000 字、翻到第 18 页时改字号），锚点在中间，章头全量的边界与此处要的边界根本不是
一回事。必须另开一张**章内临时表**（增量表），锚在目标页向外分页，把已显示页面的内容钉住不乱跑。

| | 增量表（章内临时表） | 全量表（磁盘表） |
|---|---|---|
| 锚点 | 目标页 / 当前页 | 章头 |
| 边界口径 | 行锚页 | 整块页 |
| 服务 | 开书/跳转/调参/翻页的即时呈现 | 后台完备、到章首页承接 |
| 代价 | 有界滑窗，会被丢弃 | 十几秒 / 大章 |

两表**不合并**（边界口径不同，合了指针全乱），也不互相替代。

- **章内翻页恒走增量**（不分页参数影响版面，锚点不变，无需退回全量）。
- 小章（≤120 块）永恒全量，不进增量路径——小章全量足够快，没有必要引入临时表。

## 2. 任务模型

- 粒度两种：
  - **PAGE**：单页增量排版（锚点向外，或已知边界下的单页组装）。
  - **CHAPTER-FULL**：整章全量（`fullLayout` 整块，不可再分——P13 并行 chunk 已删，见 §6）。
- 任务携带：`kind` + `chapter`/`page` + `paramHash` + 代际（见 §5）。低优任务可被无限推迟。
- **目标页不进队列**：调用方线程直排，miss 即同步阻塞塑形并呈现。延迟不可控的活不许上关键路径。
- 调度器只管目标页之后的全部后台活。

## 3. 优先级阶梯（高→低）

| 档 | 内容 | 排序依据 | 排哪张表 | 在调度系统内 |
|---|---|---|---|---|
| **1** | **目标页** | 无条件最高 | 增量表（锚点） | **否**，同步阻塞 |
| **2** | **下一页** | 方向记录 | 增量表 | 是 |
| **3** | **上一页**；目标页已是章首页 → 全量预排上一章 | 方向记录 | 增量表 | 是 |
| **4** | **本章其余页**（临时表侧执行体为块水位前推预算 `TEMP_PREFILL_BUDGET`，非独立池任务） | 方向记录 + 距目标页 \|距离\| | 增量表 | 是（磁盘侧；临时表侧由水位深度表达，D3b 未做） |
| **6** | **本章全量**（**动态档位**：目标页在第 2 页时升到第 2/3 档，见 §3.4） | — | 全量表 | 是 |
| **7** | **其他章全量** | 方向记录 + 章号偏离 \|距离\| | 全量表 | 是 |
| — | 解析预热（邻章/开书：markup + 轻结构，无塑形） | 最低 | — | 是 |

### 3.1 第 2/3/4 档是同一个算法

三者不是三档并列，是**一段有序序列**。从目标页出发，按距离 d = 1, 2, 3, … 逐层展开，
每层先方向侧、后另一侧：

```
+1·dir,  −1·dir,  +2·dir,  −2·dir,  +3·dir,  −3·dir, …
```

「下一页」「上一页」是这段序列的**头两项**，「本章其余页」是**剩下的尾巴**。
头两项比尾巴更可能马上被用到，故各自独占一档；尾巴合为第三档。**算法一个，紧急度分档。**

### 3.2 翻页方向记录

单个内存值，三态：

- `+1` 上次向前翻页；`−1` 上次向后翻页；`0` **无记录**。
- 开书时为 `0`；每次翻页写入当次方向；**调参后清 `0`、跳转后清 `0`**。
- `0` 语义上等同向前：两条排序消费者（章距排序、邻页派发）都以「非负即前向」判定，
  故 `0` 无需特判分支。
- 清零的理由：开书/跳转/调参这三个动作**本身不携带方向含义**，不该继承上一个动作的猜测。

被三处消费：第 2/3 档的页选择、第 4 档的本章排序、第 7 档的跨章排序。

### 3.3 章外边界只在 d=1 处理

| 情形 | 处置 |
|---|---|
| d=1 方向侧，但目标页是本章**末页** | 章内无下一页 → **全量预排下一章**，留在第 2 档 |
| d=1 另一侧，但目标页是本章**首页** | 章内无上一页 → **全量预排上一章**，留在第 3 档 |
| d ≥ 2 越出本章 | 该页不存在，**跳过，不升级为整章** |

d ≥ 2 不做跨章升级：越界意味着本章至少还剩两页，隔两页仍不翻就不值得为它排整章。

### 3.4 距章首 d=1 时，本章全量升到第 2/3 档

**章首页是增量 → 全量的交接点。** 读者抵达章首页时按 S5 承接全量表——那一刻全量表必须已在，
否则会看到一次可见的临时表 → 全量切换。因此**逼近章首页的距离，直接决定本章全量的紧急度**：

| 目标页 | 本章全量的档位 |
|---|---|
| 第 2 页 | **第 2/3 档**（与 d=1 邻页同级） |
| 第 1 页 | 已在交接点，全量表同步承接，不走后台档 |
| 第 3 页及以后 | 第 6 档 |

理由：目标页在第 2 页时，读者实质站在章首，再翻一次就是交接点；而增量侧此刻还要逐页往后推
（每页边界依赖前页尾部），全量一趟就能给出整章全部边界。此处全量的"每次翻页收益"最高，
故按 §0 提到与 d=1 邻页同级——它**包含**那些邻页。

与 §3.3 互为镜像：向外越出本章 → 加急邻章整章（邻章是下一步要读的内容）；
向内逼近章首 → 加急本章整章（章首是交接点）。**两条规则都只在 d=1 触发，d≥2 一律不升级**——
隔两页仍不翻，就不值得为它动整章。

**推论：第 6 档不是固定档位。** 本章全量的档位由"目标页距章首"决定，落位那一刻算出，不是常量。

### 3.5 跨章全量有两种紧急度

按 §0，跨章整章不是一件事，是两件：

- **d=1 边界兜底**（§3.3）：用户在末页/首页，多半下一步就翻过去 → 紧急度**高于本章全量**（第 2/3 档）。
- **第 7 档章扫描**：纯章距投机 → 紧急度最低。

两者是同一份工作（整章全量），**触发信号完全不同**。若不区分，d=1 兜底会被埋在第 7 档的
章距序列里出不来——这正是"跨章跳过"旧规则想避开的困境（那时的解法是不排，现在给它紧急度）。
故 d=1 兜底须有**区别于第 7 档章扫描**的优先级身份：同一批章、同一份工作，插到 d=1 那一档
立即排，不等章距轮到。

### 3.5 饥饿与抢占

- 低优任务可被无限推迟，**不加 aging**：翻页有第 1 档兜底，正确性永不依赖后台。
- 第 1 档是同步的，后台随时可被抢占；任务幂等，靠状态表与代际门重启。
- **第 2 档及以上不进"等待静默"门**：抢占代替等待。等静默只会给已注定要取消的活加延迟。

## 4. 状态表（两张，随表走，不设第二份）

| | 增量表 | 全量表 |
|---|---|---|
| 范围 | 当章 | 全书 |
| 状态 | `UNLAID / SHAPING / DONE` + `paramHash` | `UNLAID / SHAPING / FULL` + `paramHash` |
| 表体 | 临时会话的前/后向页列 + 指针 | `paginationTable` + 磁盘文件 |
| DONE 判定 | 已成形页可被指针取用 | 磁盘表即 done 登记（B2 的 skip-fresh 查此表） |

- 状态表**不集中另存**。表体就在表自己身上，调度池只管队列与在途键，不存第二份，故无同步 bug。
  派发守卫各自就地判据（表前提 / skip-fresh / fast-path），**不得**再写一份计算式状态视图——
  那是第四份拷贝，且会把它要避免的 `paramHash` 重算塞进翻页热路径。
- **代际（脏标记）只置位不干活**：事件（改参/视口/字体/跨章）→ 代际 `++`；
  worker 开工快照代际，完工只清"代际未变"的，变了就地重排（ABA 必备，非可选）。
  代际未变的判据用 `paramHash` 等价实现（更严：hash 相同即同参数周期）。

## 5. 调度循环

- 槽数 = `max(1, min(2, cpuCount() - 2))`（给 UI / 目标页 / 系统各留一份；
  `cpuCount()` expect/actual）。**上限 2 是 P0 真机实测的结论**（平板：轻页在 0/1/2 并发下
  耗时持平、无 Skia 锁式崩塌；重页由内容主导 544–965ms，与槽数无关）——既然加槽买不到速度，
  就只给 2。翻页永不占槽（调用方线程同步跑），槽数只管后台活。
  *（D5 补记：代码曾写成 `cpuCount() - 1`，比本文少留一份核且无记录，已改回 -2。本机 12 核时
  两种算法都被上限夹住、测不出差别，只有 3 核一类小核设备才暴露。）*
- work-conserving：有空槽即取最高优就绪任务。
- 抢占：高优到达取消低优。**目标页入口调 `notifyFlip()` 统杀其下全部后台活**（唯一钩子）。
- 槽位是**唯一的并行度来源**；不得再有任务内并行（§6）。

## 6. P13 并行 chunk 删除决定（不变）

大章全量并行意义不大：全量活没人等（后台 best-effort），并行省的总时长换来抢核/发热/GC，
全打在前台体感上；handoff 时机账也算不过（稳定的中等 temp 翻 > 抖动的翻页 + 早几秒免费）。
删 `fullLayoutChunked` 整条路径，全量一律串行；等价单测同步删除。附带：嵌套并行审计问题
随之消失——调度槽是唯一的并行度来源。

## 7. 解析预热

邻章/开书的 markup + 轻结构（无塑形、无落盘），**最低档**，按 `paramHash` 幂等、同章去重。
它排在一切排版活之后，因为用户不需要它出字，只需要它别挡路。

## 9. 修订记录

**2026-09-26 全篇重写。** 相对 2026-09-25 初版，实质变更：

1. **§2 阶梯重裁定**。初版为「下页 / 上页恒覆盖 / 其余页 / 本章全量 / 其后整章」五档，
   其中"上页恒覆盖"特指跨章整章，且混入了同章上一页。现改为：第 2/3/4 档合并为**一段序列**
   （§3.1），**全量任务也纳入紧急度判断**（§3.4 本章全量动态升档、§3.5 跨章全量两种紧急度），
   章外边界只在 d=1 兜底（§3.3）。
2. **新增 §0**（紧急程度为唯一组织原则）与 §3.2（三态方向记录）。
3. **§8 推翻"temp 独立、不进池"**。理由：第 2/3/4 档按定义跑在增量/临时表上（§1），
   而章内翻页恒走增量（§1），temp 预排若不进池，这三档没有执行体——优先级排序对最延迟敏感的
   后台活失效，优先级本身是空的。
4. **§4 状态表不再要求中央表**。改为"表体随表走 + 派发守卫就地判据"，并明确禁止再写
   计算式状态视图。初版 §3 的"调度器第一次收成中央表"与 §4 的槽数公式保留为待决项。
5. **废止 `分页预排原则.md` §1 第 2/3 条的「仅全量路径执行」**。该限定把"读者当前在哪条路径"
   误当成"这一档排什么活"，是错的：第 2/3/4 档是锚点增量，与读者当前路径无关。
6. §5 P13 删除决定、§0 收编动机为历史记录，不变。
