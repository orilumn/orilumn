# 线程调度方案（分步）

依据：`docs/线程调度原则.md`。层级：排版层（上）为主；跨层点仅 `cpuCount()` expect/actual
与宿主现有的脏标记入口（改参/视口/字体沿用现有调用，不新增）。

## P0 verdict（2026-09-25 真机实测，CONDITIONAL GO）

- contention：slots=4 下轻页翻页耗时与空闲持平（~240ms both），无 Skia 锁式崩塌；
  重页耗时由内容主导（544–965ms），与槽数无关。并行在该 SoC 安全。
- cancel：设备上零触发（任务都在取消到达前自然结束）；语义由单测锁定。
  发现并修复真 race 一个：取消点摘 map 表项致槽位计数与实际 divergent（b1/b2:10 重叠 1.1s 实锤），
  已改为只杀 job、不摘表项（死亡时 finally 摘）。
- 正确性：40+ 分钟 grind+翻页，接缝全连续，顺序保持（FIFO），去重有效，无崩溃。
- 条件（进 P1 前补）：恢复完成信号（producer 重写时丢了 done 日志，B2 收尾不可观测）；
  auto-phase 定时换挡拆除（spike 专用），换挡逻辑保留给调试口；arm 原子化（两次 dispatch
  曾并发出双循环）；默认槽数取 2（保守，轻页已证平，重页与槽数无关）。
- 遗留观测：B2 整轮完成时间不可见（done 日志缺失期间无法确认）；force 重排的提交风暴
  （~37 FULL-PRELIM/分钟量级，skip-fresh 兜底但值得 P1 加计数对账）。

## P0 可行性 spike（已执行，见上 verdict）

目的：三个未知数在开发机/单测里验不出来——本机 SoC 并行塑形 scale 曲线（定槽数不能猜）、
抢占取消延迟（跟不跟得上翻页）、负载下发布/取消的正确性。

做法：最小调度器（优先级队列 + N worker 槽 + 取消），复用现有任务体（邻页塑形单页、
B2 整章），**不开新功能**，只加 `spike-` 日志。真机驱动：开书 → B2 全速 → 连翻，
对照组切 N=1/2/4（槽数可配）。

测量（落盘日志既有口径 + 新增）：
- 翻页 `ensurePageRangeShaped t=` 在后台 0/1/2 个塑形并发下的分布（ contention 曲线）；
- 取消延迟：翻页起点到 worker 停手的时间（`spike-cancel` 日志，目标 <200ms）；
- 吞吐：单位时间完成块数随槽数的 scale（定 `max(1, cores-2)` 是否靠谱）；
- 正确性冒烟：命中 `pagecache-hit` 照常、接缝连续（FLIP 接缝核对法）。

go/no-go：
- GO：2 槽后台 + 翻页线程无 contention 膨胀（t= 在噪声内）、取消 <200ms、吞吐随槽数涨。
  → 按 P1 落地，槽数取实测拐点。
- NO-GO（任一）：Skia 锁把并行全串行化（1→2 零涨幅）→ 槽数恒 1 + 纯时间片（翻页独占塑形，
  后台只在真静默跑）；取消延迟超标 → 加密检查点（P7 粒度细化）后再议。
- 时间盒：spike 不合则停，不写第二行正式代码。

## P1 调度骨架（spike GO 后）

- 任务类型/队列/代际计数器/两张状态表（§3）/worker 池（槽数取 P0 拐点）/`notifyFlip()` 钩子/
  `cpuCount()` expect/actual（android/jvm/desktop，JVM 系 `Runtime.availableProcessors`）。
- P13 删除（`fullLayoutChunked` + 等价单测）与骨架同批：此后并行度唯一来源。
- 验收：编译 + 全量 probe + 单测覆盖队列语义（优先级出队序、代际过期、抢占取消）。

## P2 存量迁移（按 §6 映射表逐项搬，每项独立提交）

1. windowPrefill → 第一/第二 PAGE 任务（含并行 warm 保留为任务内并行，结构化并发）。
2. canonicalJobs → 第四 CHAPTER-FULL（单章去重语义保留）。
3. wholeBookJob → 第五及之后（order 复用 R7 交错；epoch/quiet/park 删除，代之代际+抢占）。
4. openPreflight → P 解析任务。
5. tempPrefill 不动（temp 独立）；R18 散装取消收成 `notifyFlip()`。
6. 散装变量删除（epoch/dedup key/yielded flag/quiet 常量）——删一处跑一遍单测。

## P3 验证（设备为准）

- 翻页 t= 分布 vs 基线（R17/R18 版）：中位数/尾延迟双降，无回退；
- B2 整书完成时间 vs 基线（只应快不慢；skip-fresh 保留）；
- `pagecache-hit` 率 vs 基线（只升不降）；
- 接缝连续抽查 + 旋转/改参/跨章回归（S1–S7 不动）。
- 任一回退：二分到 P2 子项回滚，不动骨架。

## 风险与 open 项

- temp 收敛（与增量表合并）明确不在本轮，维持独立。
- `cpuCount` 在折叠屏/大小核上的解释（性能核 vs 能效核）：v1 取总数减二，不做核亲和；
  若实测小核拖慢 worker，再议亲和。
- R16（连打 stale-pos 跳页）与本轮正交，另行立项。
