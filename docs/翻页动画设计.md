# 翻页动画设计（截图管线 + 双页滑动 + 卷曲 / 折页）

> 状态：**地基已落地（P0a/P0b/P1/P4 已随 0.5.6 发布）**。翻页画法有两档，
> 现行定稿是 §17 的 **3D 卷曲**（三角形网格走公共 `drawVertices`，明暗 / 压淡 / 落影走渐变画笔，
> 不依赖系统着色器、无安卓版本门槛）；§16 的**折页**保留为降级档（本端画不出网格时）。
> §15 的「逐像素逆向映射」路线**已废弃**，保留作历史记录。
> 目标读者：排版层（分页调度）、渲染层（栅格化缝）、用户层（阅读面 UI）。
> 一句话结论：**截图路线可用但不必用**——页槽本来就把「页栅格 + 覆盖层」画在屏幕上，
> 直接交出来当纹理即可；折页用**多边形裁切**画三块分区，纯 Compose 画布、全平台同一份代码。

## 2. 质量阶梯（要支持什么、怎么退化）

统一入口一个枚举，逐级退化，**任何一级都不得让用户多等**（AGENTS.md 总则第一句）。

| 级 | 名称 | 实现 | 门槛 | 观感 |
| --- | --- | --- | --- | --- |
| **L0** | 无动画 | 直接落位（今天的全部行为） | 全平台 | 瞬切 |
| **L1** | 双页滑动 | 页位图 `translate`（spread 合成一张整图横移） | 全平台，纯 Compose | 纸张平移，最稳 |
| **L2** | 立体滑动 | 页位图 + `graphicsLayer{rotationY, cameraDistance}` 或 `withTransform` 做透视抬起 | 全平台（Compose 公共 API） | 有厚度/透视的「翻卡片」 |
| **L3** | 3D 卷曲 | 逆向映射 + 明暗/高光/折痕阴影（SkSL/AGSL） | 桌面全平台；Android **API 33+** | 真曲面，背面镜像+透光 |
| **L4** | 3D 卷曲降级 | 片带仿射（24–40 条 `clipRect+drawBitmap`）或旧 2D 折 | Android 24–32 | 近似曲面 / 假折痕 |

**推荐交付顺序：L1 → L2 → L3，L4 只在真机验证出 API 33 覆盖不足时再做**（目标平板 vivo PA2353 已是 Android 13+，L4 的收益不抵维护 4 套后端的成本）。

## 3. 截图管线（第一块地基，必须先做）

### 3.1 统一栅格：把「页 → 位图」收成一个 commonMain 能力

现状缺口有两个，缺一则动画不成立：

1. **插图不在位图里** ⇒ 截图丢图（且静止/动画两套像素不一致）。
2. **桌面没有位图** ⇒ 同一个动画层在桌面无米下锅。

方案：新增 **页栅格化器**（新代码全部在 `shared-ui`，见 §9 层级自检），输入一份与平台无关的绘制描述，输出一张页位图：

```
PageRasterSpec(
  pageBg, inkColor,
  lines: List<DrawLine>,            // 已是页坐标系（ReaderPageCanvas 同款 shift）
  backgrounds: List<PageBackground>,
  bgImages: Map<String, DecodedImage>,
  images: List<Pair<PageImage, ImageBitmap>>,  // ← 新增：插图下沉
  contentLeft, contentRect(L,T,R,B), w, h,
)
→ PageRaster(skia Image)
```

- 绘制顺序**严格照抄今天屏幕上的顺序**：`clear(pageBg)` → `drawPageBackground`（含背景图）→ `LineWindowDrawer.drawLines`（墨色盖章）→ 插图按 `used` 尺寸 `drawImage`（缺图仍画灰占位，与 `drawPageImage` 的 `:136` 同语义）。
- 复用现成能力，不新增基础设施：`LineWindowDrawer` / `drawPageBackground` / `DecodedImage` 全在 `engine-skia` commonMain，skia 依赖经其 `api(libs.skiko)` 传递（`engine-skia/build.gradle.kts`）。
- 静止显示也改吃这张位图 ⇒ **屏幕像素 = 动画像素**，只有一个真相源；插图从 Compose 层下沉后，`ReaderPageCanvas` 的 `:106-108` 删掉。
- 桌面 actual 从「直画」改成「离屏栅格 + 一次 `drawImage`」：多一次整页拷贝，换来与 Android 同构的缓存与动画能力（值得）。

### 3.2 平台包装缝

```
expect fun rasterPage(spec): ImageBitmap?     // androidMain / jvmMain 各自实现
```

- **jvmMain**：`org.jetbrains.skia.Image` 直接转 Compose `ImageBitmap`（Skia 侧零拷贝，桌面顺带拿到硬件路径）。
- **androidMain**：skia `Image` → `android.graphics.Bitmap`。**这是 P0 待验证点 S1**：
  - 现役是 JPEG 编解码单跳（`ReaderPageRenderer.android.kt:115-133`，实测 ~100ms/页）。
  - 候选零编码路线：`skia.Bitmap.readPixels(byte[], ImageInfo, …)`（skiko 0.144.6 有此 API，已用 `javap` 核实）→ `Bitmap.copyPixelsFromBuffer(ByteBuffer)`。
  - 注意：`ReaderPageRenderer.android.kt:115` 记的「`Bitmap.readPixels` 真机回 null」指的是 **`android.graphics.Bitmap.readPixels`**，与 skia 的 `readPixels(byte[])` 不是一回事，**不能据此判死这条路**，必须真机重测。
  - 验收：单页整页像素搬运 **< 25ms**（1200×1800 ARGB）。

### 3.3 页位图缓存与内存预算

已落地（P0b）：`PageRasterStore.kt` + `PageRasterCache.kt`（commonMain，按字节 LRU，LinkedHashMap
access-order + `maxBytes` 驱逐）。两端 actual 只剩「skia 图 → 平台位图」最后一跳。

- **键** = `PageRasterKey`：`chapter | charStart | charEnd | widthPx | heightPx | contentRevision | bgColor | inkColor`
  （`contentRevision` 必须在键里——字重这类「行数据完全相等」的变更只能靠它失效，见 `PageRasterRenderer` 的教训；
  `spreadSide` 待双页接线时再加）。行/背景/插图本身不进键，进 `PageRasterFingerprint` 做**二次校验**：
  同键但内容变了（插图补解码）必须重画，否则灰块留一辈子。
- **预算按字节，不按页数**：`PAGE_CACHE_BYTES` Android `56MB` / Desktop `64MB`。能装几页是
  `预算 ÷ (视口宽 × 视口高 × 4)` 除出来的，**随窗口/屏幕尺寸漂移**，实测：

  | 端 | 栅格尺寸 | 单页 | 稳态页数 |
  | --- | --- | --- | --- |
  | 平板 1840×2800 | ≈3.6M px | **14.3MB** | 56MB → **3 页**（实测 `pool=3/43MB`） |
  | 桌面窄窗 | 1194×1648 | 7.9MB | 64MB → 8 页 |
  | 桌面放大窗 | 1600×1718 | 10.5MB | 64MB → 6 页 |

  平板刚好只够 P1 要的「锚页 ±1 = 3 页」，**零余量**：任一页因插图补解码重写、或连翻两页，
  都会把邻页挤出去重栅格（真机 ~90ms/页）。P1 接动画前要么把预算提到 ~90MB（4 页），
  要么先做 1/2 代理位图那一级（见下）。低端机按 `ActivityManager.memoryClass` 下调（§7 开关）。
- **两级分辨率**（P0b 只做了第一级）：
  - **全分辨率**：静止显示（已落地，替代单槽 `cachedPage`，「回访页首帧即有图」扩到文字页）。
  - **1/2 代理位图**：动画专用，**待 P1**。理由：卷曲过程中纹理被压缩/拉伸，全分辨率无视觉收益，内存只要 1/4。
    注：`PageRasterStore` 限 UI/渲染线程，后台预栅格要另开一条路（§7 S2 线程安全验证之前不做）。

### 3.4 什么时候栅格化（对齐分页调度总则）

动画层的预热**不得抢占**排版调度：

| 对象 | 时机 | 线程 | 依据 |
| --- | --- | --- | --- |
| 当前页 | **提交前备齐**（`AnchorFunnel.beforeCommit` 追加栅格预热） | 后台（`Dispatchers.Default`），UI 帧命中零开销 | 总则第 1 条：锚页立即同步 |
| 锚页 ±1 页 | **±1 分页完成即栅**：临时表逐页成形 / 磁盘表 d=1 两侧装配 / 小章全章排完，各抛信号；**每次只补方向侧那一张**（反侧＝上一刻的当前页，池中命中；当前页由绘制同步栅），**不单独设优先级** | 后台（见 §14；页图重画进 `PageRasterStore.renderLock`，命中路径仍无锁） | 总则第 2 条：正负 1 是第二优先级；截图跟随±1 分页完成，不新设档位 |
| ±2 及远页 | **不预热** | — | 第三优先级是磁盘表，不抢 |
| 跨章目标页 | 落在目标章后按「当前页」处理 | — | 总则第 1 条已保证目标页已排 |

预热失败/超时（沿用 800ms 上限的量级，但动画路径用更短的 150ms 预算，§6）：**宁可不翻也不等**——直接 L0 落定。

> **P0c 修订（2026-10-09）**：上表「线程」列原为「UI/渲染线程」，前提是预栅格与绘制
> 共用一份离屏 surface、只能在同线程串行。P0c 把 surface 与缓存加锁后，预栅格的**重画**段
> 移到 `Dispatchers.Default`，UI 帧只走无锁命中路径——冻帧根因与修法见 §14。

## 4. 卷曲 3D 的数学（commonMain 纯函数，可单测）

### 4.1 建模：绕折线（crease）的圆柱卷曲

把「卷起来的那部分纸」看成绕 crease 线卷成的圆柱面。定义：

- `â`：crease 方向单位向量（沿屏幕上那条折线）。
- `n̂`：垂直 crease、指向卷起侧的单位法向。
- `R`：卷曲半径（可变 → 曲面）。
- 对任意片元 `q`，先求它在 crease 坐标系里的轴向坐标 `ξ = (q - p_crease)·â`，
  再取该轴向处的 crease 点 `p0 = p_crease + ξ·â`（轴向坐标卷曲不变，这是闭式解的关键）。

**正映射（页坐标 → 屏幕）**：材料点 `p0 + d·n̂`（d>0 为卷起侧）
```
θ = min(d / R, θmax)          // θmax ≤ π，自重叠后不再画
P = p0 + R·(1 - cos θ)·n̂     // 只沿法向移动，轴向不变
N = cos θ·n̂ + sin θ·â        // 表面法线：θ=0 → n̂（正面）；θ=π/2 → â（侧视）；θ=π → −n̂（背面）
```

**逆映射（屏幕片元 → 纹理 UV，片元着色器唯一需要的方向）**：
```
C = p0 + R·n̂                 // 圆柱中心
e = q − C
if (e·n̂ ≥ 0)        → 平坦「露出区」，采样**下一页**
else if (|e| ≤ R)   → 卷曲面上：cos θ = 1 − w/R，w = (q − p0)·n̂
                      d = R·θ = R·acos(1 − w/R)          // 弧长=材料坐标（不可拉伸）
                      uv = p0 + d·n̂                      // ← 采样**当前页**
                      背面（θ > π/2 ⟺ w > R）：镜像采样 + 纸背色 + 透光衰减
else                 → 平坦「未卷区」，采样**当前页**
```
三个分支的分类是**几何完备**的（半圆盘扫掠区 ∪ 右半平面 ∪ 左侧平地），天然无重叠、无缝、无 z-fighting。

**锥度（真 3D 曲面的落点）**：令 `R(ξ) = R0 · (1 − k·ξ/ξmax)`（k=0 即圆柱，k≲0.2 视觉稳定、迭代稳定）。
此时上式变成隐式（`w = R(ξ)·(1 − cos(d/R(ξ)))`），**对 θ 做 2–3 次牛顿迭代**（初值取 `acos(1 − w/R0)`），
收敛判据 `|Δw| < 0.01px`。k 与迭代次数必须作为**统一参数**同时喂给 GPU 后端与 CPU 片带后端，保证两级观感一致。

### 4.2 着色

- 朗伯：`max(0, N·L)`，`L = normalize(0.3, −0.4, 1)` 固定屏幕空间（光不跟着纸转，符合真实观感）。
- 卷起处高光：`pow(max(0, N·H), k_s)`，`H = normalize(L + ẑ)`。
- 背面：`uv` 镜像 + 乘纸背色（沿用 `CurlView.kt:48` 的「背面低透明度透出纸色」语义）
  + 背面比正面暗一档（`×0.82`），并允许**下一版透出反面文字**（ghost）。
- 折痕两侧投影带：沿折线法向的高斯带 `exp(−(dist/σ)²)`（σ = 0.05×页宽，继承 `CurlView.SHADOW_BAND=0.05f`），
  按进度淡出（继承 `CurlView.kt:506-511`）与折痕末端扶正（继承 `:310-320`）——**3 行 shader 取代现在那 100 多行的多边形切片拼带（`CurlView.kt:392-524`）**，且无接缝。
- 越界：`θ ≥ θmax` 的自重叠区输出透明；页宽有限 ⇒ 材料 `d > W` 即纸的**自由边**，到此为止。

### 4.3 手感：与手指的精确锚定（3D 版）

`CurlView.anchoredFoldX`（`:150-155`）解的是 2D 版的「折过去的纸边恰好过手指」。
3D 版条件：页自由边材料点 `d = W` 的正映射结果落在手指 `(fx, fy)` 附近：

```
solve for R:  P(ξ_f, W) = (fx, fy)   →  一维求根（二分 12 次足够，<0.1ms）
```

手指离开后**停止跟随**（继承 `CurlView.kt:329-331` 的结论：跟随会导致撤销时逐帧抖动）。

### 4.4 单测清单（`shared-ui/src/jvmTest`，纯函数无 GPU 依赖）

1. 平坦区恒等：`w ≤ 0` 分支 `uv == 输入`。
2. 连续性：相邻 1px 输入的 `uv` 跳变 `< 1e-3`（无裂缝）。
3. 单调性：`w ∈ [0, R]` 上 `x_screen = R(1−cos θ)` 单调增；`w > R` 后单调减（翻过去的正确形状）。
4. 无 NaN/Inf：`R→0`、`w=0`、`ξ` 超界、`progress ∈ [-0.9, 1.9]` 全域。
5. 锥度迭代：k∈{0, 0.1, 0.2} 收敛且与 GPU 后端同参数结果差 `< 0.5px`。
6. 分支完备：随机 10k 片元，三分类互斥且并集覆盖卷曲活动域（无既没画正面也没画背面的空洞）。

## 5. 渲染后端矩阵（唯一需要分平台的部分）

| 后端 | 平台/门槛 | 落点 | 关键 API（已核实存在于 skiko 0.144.6 / Android） |
| --- | --- | --- | --- |
| **Skia RuntimeEffect** | 桌面全平台 | `shared-ui/jvmMain` | `RuntimeEffect.makeForShader(sksl)` → `effect.makeShader(Data.makeFromBytes(...), children, Matrix33)` → `Image.makeShader(tileX, tileY, sampling, Matrix33)` → `canvas.nativeCanvas.drawRect(paint)` |
| **AGSL RuntimeShader** | Android **API 33+** | `shared-ui/androidMain` | `android.graphics.RuntimeShader(sksl)` + `setFloatUniform` + `setInputBuffer("page", BitmapShader)` → `Paint.shader` → `drawRect` |
| **片带仿射** | Android 24–32（可选 L4） | `shared-ui/androidMain` | `save/clipRect/rotate/scale/drawBitmap` × 24–40，硬件加速画布下走 GPU 合成 |
| **旧 2D 折** | 兜底 | 复用 `CurlView` 数学（提到 commonMain） | — |

> 已用 `javap` 在 skiko 0.144.6 的 `skiko-release-api.jar` 上核实存在：
> `RuntimeEffect.makeShader(Data, Shader[], Matrix33)`、`Image.makeShader(FilterTileMode×2, SamplingMode, Matrix33)`、
> `Data.makeFromBytes`、`Matrix33`、`Bitmap.readPixels(byte[], ImageInfo, …)`。
> 缺的只有 Android 侧的 `RuntimeShader`（平台 API，API 33 起）。

**SkSL 源码共享的坑（必须处理）**：两侧的「取子着色器像素」坐标约定不同——
SkSL 里 `child.eval(float2(px, py))` 用**像素坐标**，AGSL 里普通 shader 用像素坐标、
而 `#setInputBuffer(BitmapShader)` 给的是**归一化 0..1**。
因此源码里统一写一个宏占位 `SAMPLE(uv01)`，两平台各生成一份源码字符串（只差这一行与 uniform 声明），
`CurlGeometry` 产出的参数集（含 k、迭代次数）两平台共用。

**AGSL 注意事项（写入实现清单）**：
- AGSL 只有 fragment shader，无 vertex shader ⇒ 几何（卷曲区形状）必须由 CPU 算好并用 uniform 传入，片元只做逆映射采样。
- `RuntimeShader` 在硬件加速画布上可用（API 33+）；S3 需在真机确认是否真走 GPU、能否 60fps。
- 低版本（API < 33）**不实现 L4** 时，统一落 L2（`graphicsLayer` 透视），不出现「有动画但很假」的中间态。

## 6. 手势与状态机

### 6.1 现状缺口

手势只记方向、UP 才翻（`ReaderScreen.kt:559-586`），无进度、无速度、无取消。动画层需要**连续 progress + settle**。

### 6.2 新状态机 `FlipSession`（用户层，纯状态）

```
Idle
 └─(DOWN, 过 slop, 轴向=水平, 方向确定)→ Preparing(预取 landed pos + 代理位图, 不显示)
      ├─ 就绪 → Dragging(progress, 锚点)      ← 目标页露出来，可跟手
      └─ 超时/失败 → Idle（直接落位，L0）
Dragging
 ├─(MOVE)   progress = dx / pageW（域 [-0.9, 1.9]，`CurlView.kt:128-131`）
 ├─(UP, |dx|/w 或速度过阈)→ Settling(commit)
 └─(UP, 不足)→ Settling(rollback)
Settling
 ├─ commit  : progress → 1（下一页）/ → 1+0.9|tilt|（上一页，`:196-200`），**300ms**（CurlView 600ms 的两倍速），Decelerate；**起手斜率衔接手指速度**（`FlipSession.settleInitialSlope` + `VelocityHandoffEasing`），离手不刹停
 │           p ≥ 0.9 时**提前落位**（`:215-221`），动画尾与落位重叠 → 消除「看起来翻完了但点不动」
 └─ rollback: progress → 0 / −0.9|tilt|，**250ms**（CurlView 500ms 的一半，`:205-210`）
```

- 落位顺序：**先落位（数据）后出画（像素）**。落位走既有 `AnchorFunnel.navigate`，动画层只是它的观察者/装饰者，不新增第二个落位通道 ⇒ 不破坏「显示状态的唯一写入通道」这条不变式。
- 动画进行中再触发翻页：`AnchorFunnel` 现有 BUSY-DROP 语义直接沿用（丢弃），不新增排队。
- 封面页：沿用 `flip()` 封面特判（`ReaderScreen.kt:348-369`），动画层对封面走「淡入淡出」而非卷曲。

### 6.3 「动画不得增加等待」的具体口径

| 情形 | 处理 |
| --- | --- |
| 代理位图已就绪 | 全量卷曲（L3），零等待 |
| 代理位图未就绪、代理位图正在栅格 | 直接落位 + L1 平移（用当前页位图，最多 120ms），**不等** |
| 代理位图缺失（首次/被 LRU 淘汰） | 后台补栅格；本次 L0 |
| 目标页是别章 | 总则第 1 条已保证目标页已排好，位图可即时栅格 |

## 7. 双页（对开）

### 7.1 语义

- `spread = (left, right)`；`left` 偶数、`right` 奇数（订口朝内、书口朝外）。
- 章首页默认**独占右页**（左页留白）；是否允许「章首页独占左页」做成设置。
- 跨章自然成立：左页可以是上一章末页。

### 7.2 路线 A（推荐）：半宽视口 + 页对

- 分页按**半宽**进行：给引擎传 `setViewport(pxW/2 − gutterAdj, pxH)`，边距改为「外侧大 / 内侧小（订口）」。
- 排版层**零改动**：视口尺寸本来就是入参，单栏逻辑照旧。
- 显示层：`left = page[i]`，`right = page[i+1]`，翻页步进 2 页；spread 位图 = 两页并排合成（或保留两张、动画时分别变换）。

**影响面必须逐条交代**：

| 影响 | 结论 |
| --- | --- |
| 磁盘表作废 | `setViewport` 尺寸变化 → `cleanStaleDiskTables()`（`BookDocumentController.kt:686-690`）自动清；单双页切换 = 一次性全量重排，符合总则「版面改变即全部重来」 |
| 分页调度总则 | 调度单位仍是「页」，页对只是**显示层聚合** ⇒ 总则第 1/2/3 优先级表述**不用改**。只需补一句：spread 的左右两页都属第一优先级 |
| 锚页 | 仍是单页；落位存 `ReaderPos`（单页），恢复时向上取整到 spread 起点（跨章时回到上一章末页） |
| 页码口径 | 已落地（单页）：**全书累计页序号**，从第一张内容页起连续数，页脚右下角显示 `. n .`；全书总数暂不显示（值仍留备），**不估**。双页落地时沿用页序号（取左页），不另造 spread 序号——读者要的是「整本书读到哪儿」 |
| 进度条 | `host.pageProgress(pos)` 口径不变（单页 fraction），只影响滑块刻度显示 |
| 跨章页对 | 左页=上章末页 + 右页=本章首页 ⇒ 排版总则里「正负 1 页是另一章」的判定天然命中已有规则，无需新逻辑 |

### 7.3 路线 B（不推荐）：引擎双栏

分页器支持「一页两栏」⇒ `PageSlice` 跨栏 ⇒ 直接撞上分页调度总则的核心（页边界定义、临时表窗口、章首页交接点、`P10 enforceTempWindow` 驱逐策略）。改动面覆盖整个排版层上，收益仅是「行块不跨栏切断」这一点。**结论：不做**，除非路线 A 出现不可接受的问题。

### 7.4 双页下的卷曲语义

| 模式 | 描述 | 需要的位图 | 建议 |
| --- | --- | --- | --- |
| 整幅滑动 | spread 合成一张 2W×H 位图横移 | 1×spread | **先做**（L1） |
| 书页式对卷 | 右页卷起翻到左侧，露出的左页成为新右页 | front/back/next-left/next-right = 4 | L3 阶段做，观感最像纸书 |

### 11.1 P1 实施步骤（L1 整幅滑动）

P1 的难点不在画滑动，在**跟手期间要同时有两页内容**。现状 `ReaderScreen` 的
`pos → lines/pageImages/pageBackgrounds/rasterKey` 整段只对当前 `openPos` 算一次
（`ReaderScreen.kt:662-756`），而 `flip()` 是 UP 时才经 `AnchorFunnel.navigate` 换 `openPos`。
所以顺序必须是：**先把「一页内容」抽成对任意 pos 可复用的东西，再谈双页渲染**。

分五步，每步独立可验、可单独提交：

| 步 | 内容 | 落点 | 验收 |
| --- | --- | --- | --- |
| **1** | `FlipSession` 纯状态机（commonMain，用户层，无 Compose 依赖）：`Idle/Dragging/Settling`，`progress = dx/pageW` 夹在 `[-0.9, 1.9]`，UP 时按 `\|progress\|` 与速度阈值判 commit/rollback，动画时长与落位提前量按 §6.2 取 `CurlView` 的 600/500ms 与 `p≥0.9` | 新文件 `FlipSession.kt` | jvmTest 逐条锁状态迁移与阈值边界（含 commit/rollback 各一条、边界值、非法 progress） |
| **2** | 抽 `rememberPageContent(pos)`：把 `lines`/`pageImages`+`imageBitmaps`/`pageBackgrounds`+`bgImages`/`rasterKey` 的整段搬进去，对**任意** pos 求值。插图/背景图的 `LaunchedEffect` 解码逻辑随之搬家 | `ReaderScreen.kt` 重构，函数化 | 纯重构：`pageAnim=false` 下像素与本步前**逐像素一致**（复用 §13 的 A/B 手法） |

| **4** | 落位仍走 `AnchorFunnel.navigate`（动画层只做观察者，不新增第二个落位通道）。**落位被 BUSY-DROP 或返回 null 时必须回滚动画**，否则像素与数据脱节 | `ReaderScreen.kt` | 单测 + 手测：连点翻页时动画与落位不错位 |

**明确不在 P1 范围**：1/2 代理位图与后台预热（P0c，用户已决定留到动画全部完成之后）、
页位图预算上调（§12.6 待拍板）、双页（P2）、卷曲（P3）。

**已知要在 P1 处理的坑**：

1. **无 `Preparing` 态的简化**：§6.2 的 `Preparing`（预取 landed pos + 代理位图）在 P1

2. **封面页不走滑动**：沿用 `flip()` 的封面特判（`ReaderScreen.kt:346-370`），封面用淡入淡出。
3. **`openPos` 在会话中途被外部改写**（重排/外部落位/`seek`）：会话必须作废并回滚，

## 14. P0c：结算动画冻帧的根因与修法（2026-10-09）

**现象**：翻页动画在平板上「卡」——不是掉帧，是**整段冻住**（手指松手后画面不动几百毫秒，
再突然接管）。

**根因（帧插桩坐实，非推断）**：结算动画被 **UI 线程上的同步整页栅格**冻住。落盘日志给出
完整证据链（`Orilumn.Anim` 临时插桩 + `Orilumn.SkiaBridge`）：

```
[Orilumn.Anim] settle start ... frame p=0.637681
                                    ← 615ms 无任何帧
[Orilumn.SkiaBridge] raster ... 536ms hit=false key=5/22216-23289
[Orilumn.Anim] frame p=1.0
[Orilumn.Anim] settle end
```

同一会话另有开书首帧的 `raster n=34 imgs=0 877ms hit=false key=5/21158-22216`。
安静时单页栅格 ~90ms；翻页期间引擎 `win-prefill`/`spike-task` 抢 CPU，膨胀到 **0.5–0.9s**
（5–10×）。即：**栅格耗时被计入了 UI 帧预算**——`drawLines` 未命中时在 UI 线程同步重画，
一帧的预算（~16ms）被占了 30–60 倍。

**两个独立缺陷**：

- **P0c-a（预栅格窗口错位）**：预栅格窗口是「当前页 ±1」，而结算 commit 后 `openPos`
已达目标页 ⇒ 动画要画的目标页从未被预热，必然 miss。
- **P0c-b（绘制路径同步栅格）**：`drawLines` 未命中时在 UI 线程直接栅格，直接冻帧。

**修法**（两份改动，缺一不可）：

1. **重画段搬离 UI 线程**：`PageRasterStore` 的 surface/`width/height` 用 `SyncLock`
   （`renderLock`）串行、`PageRasterCache` 加锁；`prerasterPage` 的**重画**切
   `Dispatchers.Default`（取值/建 key 仍在前台）。命中路径完全绕开 `renderLock`，
   所以动画每帧命中不被后台预栅格挡住。Android actual 的 `onEvict` 改投主线程
   `Handler` 回收——淘汰可能发生在后台线程，`Bitmap.recycle()` 正在绘制的位图会崩。
2. **提交前备齐目标页像素**：`AnchorFunnel.beforeCommit`（原有「显示前备齐像素」钩子）
   追加**目标页栅格预热**——判断仍在漏斗内、`commit` 之前，把冻帧转成起手等待。
   之所以只能放这里：`commit` 与 `targetPos = landed` 之间不能插入挂起，
   否则 `ReaderScreen.kt` 的「外部改写」effect 会判 `openPos` 越位并 `rollbackSlide()`。

**验收（平板，无线 adb，脚本滑动手势）**：改装后同一脚本重跑——

- 动画期 `SkiaBridge] raster` **全部 `hit=true 0ms`**（改前同期为 `hit=false` + 0.5–0.9s）；
- `FLIPLAT target-ready` 回到 **40–100ms**（冷页偶发 190–230ms，即后台预栅格刚好在提交那一拍跑）；
- 落盘零 `Orilumn.Anim` 冻帧间隙；`preraster` 正常在后台跑（偶发 `[0-9]{3}ms hit=false`，
  不再计入任何 UI 帧）。

**遗留**：`prerasterBusy` 在快速连翻时会 `preraster window skip: busy`（信号被去重丢弃），
属预期；冷页首翻仍要等一次后台栅格（起手顿一下，非冻帧），根因是预栅格信号依赖预排完成，
而快速连翻时预排本身来不及。

### 15.3 选型：A 逐像素逆向映射（定稿）

| 方案 | 平台覆盖 | 观感 | 代码量/风险 | 结论 |
| --- | --- | --- | --- | --- |
| **A. Skia `RuntimeEffect`（桌面）+ AGSL `RuntimeShader`（Android 33+），同一份 SkSL** | 桌面全平台；Android 13+ | 真曲面：逐像素无接缝、折痕阴影/高光/纸背透光都在片元里 | 一份 shader 模板 + 两个 ~30 行平台壳 | **定稿** |
| B. 网格 `drawVertices` + 位图着色器 | 全平台、全 API | 曲面靠三角逼近；明暗只能顶点色插值（浅色纸上最易露面） | 中低，无 API 门槛 | 备选：只在「必须覆盖 API 24–32」时启用，不与 A 并行维护 |
| C. `graphicsLayer{rotationX/rotationY}` | 全平台 | 刚性翻卡片，不是卷曲 | 低 | 只作降级档 |
| D. `GLSurfaceView`/EGL | Android only | 最自由 | 高：自管 EGL/纹理/线程，且与选区/旁注/栏的 Compose 合成要另建一套 | **否决** |

选 A 的三条理由：
1. **地基已经为它铺好**：整页位图（P0a/P0b）就是纹理，翻页时两张页本来就在池里，内存零新增。
2. **跨平台成本最低**：AGSL 是 SkSL 子集，一份模板 + 一个 `SAMPLE(uv01)` 宏区分两端采样坐标，
   符合「逻辑共享、平台差异集中一处」的约束（§9）。
3. **观感上限最高**：旧 2D 版 100 多行多边形拼带（阴影/折痕）在 shader 里是三行，且天然无接缝。

已核实 API（本机 `javap` 于 skiko-awt 0.144.6）：`RuntimeEffect.makeForShader(String)`、
`makeShader(Data, Shader[], Matrix33)`、`Image.makeShader(FilterTileMode, FilterTileMode, SamplingMode, Matrix33)`。
桌面 `nativeCanvas` 在本项目就是 skia `Canvas`（`ReaderPageRenderer.jvm.kt` 已 import `skiaCanvas`）；
Android 侧 `RuntimeShader` 是平台 API（33 起），目标平板 PA2353 实测 **API 34**。

### 15.5 纹理供给侧：整页槽快照（含覆盖层）

**结论：纹理 = 整个页槽的快照（页栅格 + 页码 + 旁注气泡），不是裸栅格。**

- 高亮/下划线本来就在栅格里（`DecorRange` → `DrawLine` → 栅格），白拿；
  页码是 Compose `Text`，旁注是 7.6k 行 Compose 布局——把这两样重写成 skia 绘制是**双份实现**，
  以后改一处忘一处，不可取。快照天然包含全部，新增任何页内覆盖层都不用改纹理代码。
- 实现：页槽挂 `GraphicsLayer`，`record` 后 `toImageBitmap()` 取快照（CMP 1.11.1 已核实
  两者都在，桌面为 skia 后端；Android 侧 `toImageBitmap` 同样可用，本档只在 API 33+ 启用）。
  按「页身份 + 标注代数 + 版式参数」缓存，独立小池（不占页栅格预算）。
- 分辨率：快照可按 **0.75×** 抓取（静止显示仍由活槽全分辨率绘制），两页纹理 ≈ 2×11MB，
  卷曲期间够用；抓取缩放是常量，调它不影响其它任何东西。
- 抓取时机：页稳定后异步抓；目标页在起手/预取时抓。**未就绪 → 起手等待**（§15.7），不换档。
- 快照与实际显示同源（就是同一份组合的截图），不存在「动画像素与静止像素两套」的问题。
- 平台层只拿 `ImageBitmap` 外壳（两端零拷贝），后端按纹理身份缓存 shader 输入，
  不许每帧重建 shader / 重编码纹理。

### 15.6 覆盖层口径（2026-11-14 用户拍板）

- **页码、旁注、高亮、下划线与正文一起卷**。滑动档今天也是这么做的（它们和页在同一个槽里），
  卷曲档靠 §15.5 的快照拿到同样效果。
- **书签红带不进动画**：它是装订标记，不是纸面内容；卷曲会话期间隐藏，落位立刻恢复。
- **选区/手柄/放大镜**：交互态，卷曲会话期间隐藏（与今天滑动时一致），不画进纸里。
- **不做**：把旁注改写成栅格绘制——旁注是读者层交互元素，重写一份 skia 版本是双份实现。

### 15.7 降级矩阵（不出现「有动画但很假」的中间态）

| 条件 | 行为 |
| --- | --- |
| Android API < 33（AGSL 不可用） | L1 滑动（2026-11-14 拍板：老安卓不支持就算了） |
| 任一页快照未就绪 | **起手等待**：页面先不动，快照补齐即开始卷曲，**不换动画档**（2026-11-14 拍板） |
| 后端首帧创建/编译失败 | L1 + 一条日志，不反复重试 |
| 双页对开 | 本轮不接（§12.5） |

> 为什么不是「这次先滑动」：滑动和卷曲是两种完全不同的运动，同一本书里按图准备好没准备好随机换档，
> 读者看到的是「有时卷、有时滑」，像坏了。等一次栅格（通常 0 帧，冷页几百毫秒）比换档可接受；
> 且滑动本来也要等目标页像素，两者的等待是同一份，没有额外代价。

### 15.8 分期与验收

| 期 | 内容 | 验收 |
| --- | --- | --- |

### 15.9 拍板结果（2026-11-14）

1. **老安卓不支持就算了**：Android API < 33 落 L1 滑动，不补 L2/L4；**设置面板整行隐藏「翻页动画模式」**
   （只剩滑动一种，留着开关只会让读者选到一个不生效的档）。
2. **页码、旁注、高亮、下划线与正文一起卷**（靠 §15.5 的整页快照）；**书签红带不进动画**。
3. **「卷曲」这个开关就是给本动画准备的**：`pageAnimationMode == "curl"` 直接接 L3（今天它是死值，
   升级不存在「老用户习惯另一种手」的问题），不新增 `curl3d` 值。
4. **三张图**：被翻的纸正面、它的背面、露出的那一页——映射见 §15.10；双页对开本轮不做。

### 15.10 三张图与方向映射

| 翻页方向 | 被翻的纸（正面纹理） | 背面 | 露出的页（第二张纹理） |
| --- | --- | --- | --- |
| 向后（下一页） | 当前页 | 当前页的镜像 | 目标页（下一页） |
| 向前（上一页） | 上一页（即目标页） | 上一页的镜像 | 当前页 |

## 16. P3 二次定稿：折页（2026-11-15，分支 `feat/curl3d`）

> 照旧版 `orilum.bak` 的 `CurlView` 抄的 2D 折页。**自 §17 起这一节是降级档**
> （安卓 13 以下、或本端画不出网格时用）；默认路径是 §17 的 3D 卷曲。
> 16.1 说的「废掉 3D」废的是 §15 那条**逐像素逆向映射**路线，不是 3D 本身 —— 见 §17。

### 16.1 为什么废掉 3D

逐像素做「材质点逆向映射」时，屏幕像素要回答「我落在纸的哪一面」。可用信息只有
「到折痕的带符号距离」，而圆柱投影**不是单射**：纸卷的近侧与远侧投到同一条屏幕带，
纸背平铺段也压在同一带里。于是「这段像素该画卷筒还是画正面页」在着色器里没有依据，
真机表现为三件事：卷筒漏到正面页上、卷筒被纸深压扁、松手末段跳变。

折页没有这个歧义：三块区域是**屏幕空间的多边形**（正面页 / 纸背 / 露出页），
边界就是折痕与页边，画与不画由裁切决定，不存在「这个像素属于哪个面」的判断。
顺带两个好处：纯 Compose 画布 ⇒ 全平台同一份代码、不再依赖 AGSL（API 33）、
不需要平台能力判定与降级矩阵。

### 16.2 几何（`curl/CurlGeometry.kt`）

| 量 | 定义 | 出处 |
| --- | --- | --- |
| `foldX` | 向后翻 `w·(1-p)`，向前翻 `w·p` | 同 `CurlView.drawBody` |
| `lean` | `±tilt`（向前翻取反），末段乘扶正系数 | 同上 |
| `topX` | `clamp(foldX − lean·0.9w, 0, 2w)` | 折痕与页上边交点 |
| `bottomX` | `clamp(foldX + lean·0.9w, 0, 2w)` | 折痕与页下边交点 |

- **倾斜**来自手指位移的上下分量（`FlipController.curlTilt = dy/hypot(dx,dy)`），
  纯水平拖动 ⇒ 竖折痕。
- **末段扶正**（`tailFade`）：结算动画头尾 10% 里把倾斜与阴影一起淡到 0，折痕扶成竖直贴边。
  手指跟手阶段**不淡**——形状必须听手指的。
- **与旧版的差别**：旧版对「收在右缘」的那两端把进度冲过 1（`1 + 0.9|tilt|`）让整块滑出；
  本仓进度归一在 `[0,1]`（与滑动层共用），所以两端都用扶正收尾。末帧折痕竖直贴边、
  卷曲区面积为零 ⇒ 画面恰好等于目标页，撤层不跳。

### 16.3 三块分区与阴影（`curl/CurlPainter.kt`）

绘制顺序（缺一步就会看到重影或缺角）：

1. 整页正面（被翻的那一页）；
2. 露出区 = 折痕右侧多边形（`revealCorners`：折痕上端 → 页右上角 → 页右下角 → 折痕下端；
   某端滑出右缘时改用折痕与右缘的交点，面积退化为 0）；
3. 纸背 = 露出区**沿折痕镜像**（`Reflection`）出来的那一条：先铺纸色，再在镜像变换里画
   正面页的页栅格，透明度 0.39；
4. 纸背外缘的影：沿每条自由边向外一道渐变，长边用梯形（贴着右缘那头收成 0），
   拐角两侧各补一块三角；
5. 折痕旁的影：折痕朝露出页一侧的一道渐变，随 `shadowFade` 淡出。

**纸背不画覆盖层**：旁注/页码是读者层的浮层，不是印在纸上的东西，镜像过去只会得到一堆
倒着的批注卡。露出页照常画它自己的覆盖层。

### 16.4 纹理供给侧（沿用 §15.5，未变）

页槽自己画「页栅格（版心，1585×2400 量级）+ 覆盖层（整页大小、透明底）」时顺手发布，
`CurlPageImages` 收下这两张图。不做整页快照（`GraphicsLayer` 快照真机实测三十帧全空）。
两张图都在才画折页，缺图时页面保持不动——不切滑动、不冻帧。

### 16.5 覆盖层口径

覆盖层跟着纸一起弯/翻：正面页画、露出页画、纸背不画。批注热区不变（热区仍按未变换的
页坐标算，折页只是画法）。

### 16.6 未移植：跟手锚定

旧版在拖动时把折痕摆到「纸边正好穿过手指」的位置（`anchoredFoldX`，折痕半速）。本仓折痕由
归一进度驱动、与手指 1:1 移动，锚定如果接上会和滑动层共用的进度打架，故不接。

### 16.7 验收线

- `CurlGeometryTest`：折痕扫向、倾斜镜像、末段扶正只在结算里生效、镜射自逆、露出区退化；
- `CurlRenderTest`（离屏渲染读像素）：三块分区不接反、纸背是 1:1 刚性镜像、
  结算两端各自等于落回的那一页（进度 0 = 当前页，1 = 目标页）、整幅无透明像素、覆盖层只在正面页；
- `CurlPreviewTest`：落盘 PNG 到 `shared-ui/build/curl2d-*.png` 目视；
- 真机：滑/卷两档切换、两个方向各拖一次、末段不跳、撤层不闪。

## 17. P3 定稿（第四次）：照搬 moon+ 的卷筒几何（2026-11-16，分支 `feat/curl3d`）

> §15 废在「逆向映射」（逐像素问「我落在纸的哪一面」，而圆柱投影不是单射）；
> §17 前三次废在**自己编几何**：折痕一侧整个半平面掀起来、半径拿进度乘、折痕要回收一个半径、
> 透视除法、顶点色明暗 —— 这些在参考实现里一项都没有。读者报的四个症状
> （页面直角没了、同一段文字出现三处、上半截没纸、筒径几乎等于整页）全部出自编出来的那套。
> 定稿**逐行照搬** moon+ `NewCurl3D.java` 的 `Mesh3D.curl` 与 `updateCurlPos`。

### 17.1 折痕坐标系

原点 = 折痕与页面水平中线的交点；`t` 沿折痕向下，`n` 是折痕法向（指向 +x 一侧）。
页面四角只在原点做平移 + 旋转，所以**页面上的直角天然还是直角**（角点参与几何，
不存在「边界永远平行于折痕」那种斜切）。

扫线（`x'`，单位是**弧长**，0 = 折痕，负 = 沿纸面远离折痕）：

```
0,  −πR·i/(splits−1) (i = 1..splits−1),  外加页面四角的 x'
```

角点扫线让页面轮廓的折点精确落在网格上（缺它角就被削掉）。每条扫线与**页面矩形**求交
（参数化裁剪，取 `λ` 区间），端点按 `x'` 变换：

```
x' ≥ 0        :  原地（平铺，纸还贴在页面上）
−πR ≤ x' < 0  :  θ = x'/R，屏幕偏移 = R·sinθ，高度 z = R(1−cosθ)      （圆柱）
x' < −πR      :  屏幕偏移 = −(πR + x')，z = 2R                        （绕满半圈后平铺回来，落在另一侧）
```

**卷曲量与屏幕偏移之间还有一个负号**：参考实现先把页面旋转到「局部 +x = 拖动方向」的坐标系，
`R·sin(x'/R)` 算出来的是局部坐标，回到屏幕时 `局部 −x` 才是掀起侧。所以
`屏幕偏移 = −side × 卷曲量`：**纸卷朝掀起侧鼓出去、平铺段落回没掀起的那一侧**。

这条接反（纸卷鼓向没掀起的那半页、平铺段盖住露出页）是一次真实事故：翻到九成，平铺段把
新页盖回去，屏幕上仍是大半张旧页，同一段文字在一个画面里叠两三处 —— 读者报的「三段文字」
与「几乎没翻动」都是它。

三段可见面按 `x'` 分段：正面（z < R）/ 纸背（z ≥ R）/ 平铺段，画序即 z 序
（正面 → 纸背 → 平铺段，后者逐段盖住前者，纸背的 10% 压淡因此能「透」出下面的内容）。

### 17.2 半径不是进度

`R = 折痕到「还没掀起来那一侧页边」的距离`，封顶 **10% 页宽**
（式子形状取自 `updateCurlPos` 的 `dMax = clamp(pointer.x − pageLeft, 0, dWidth)`，
手指就是折痕）。

- **按进度算半径是错的**：进度 0.2 时半径 0.2 页、掀起的材料也正好 0.2 页，纸一离开折痕
  就绕满 1 弧度 —— 「翻了两成」看起来几乎没动。
- **参考值 ≈0.108 页宽本身不是问题**：纸卷一定压在**露出页靠折痕的那一条**上（弧从折痕抬起来
  朝掀起侧鼓出去），被盖住的宽度就等于 `R`；平板上 0.108 页宽 = 200px，比版心左边距
  （128px）还宽，会压掉每行开头一截。早先因此把它降到 3% / 5%，但那是**治错了病**：
  读者真正抱怨的是「纸背没画」，筒细下去纸背只会更看不见。
  这份实现里参考值的压力项是 0.7843（点按翻页那档），保留作对照常量。
- **定稿 10% 页宽**（筒径 ≈ 0.20 页宽）：早先取 3% / 5% 时读者报「筒太细、折页反面
  根本看不出来」—— 筒细到一定程度，掀起的纸被压进几十个像素，纸背就只剩一条白边。
  现在筒身看得见、纸背有地方落；代价是筒会盖住露出页靠折痕的那一条（宽度 = 半径），
  翻到一半时约 0.03 页宽压在行首上。这是「看得见卷筒」与「新页少被咬一口」之间的取舍，
  读者优先要前者。真机若再报「行首缺一截」，应先调这里的上限，而不是回头把纸背缩掉。
- 翻页途中粗细不变（筒跟着折痕往前滚，新页按手的节奏露出来）；只有最后剩下的纸比上限
  还窄（进度 0.97 以后）时半径才跟着收细，纸卷自然消失。
- **第三条上限：纸卷不能吃掉全部掀起材料。** 纸卷绕半圈要用掉 `πR` 那么长的纸，半径只要超过
  `掀起长度 / π`，翻起来的那部分纸就整段在筒上、一段平铺的纸背都没有：读者看到一页字被
  硬生生切断、切断处空无一物（原话「滚筒左侧的页面反面呢？为什么不画？」）。
  所以再加 `R ≤ 掀起长度 × 0.7 / π`（`CURL3D_BACK_SHARE = 0.7`）：**平铺的纸背至少占
  掀起材料的三成**，纸背从第一下拖动起就在。0.7 是「筒一眼看得见」与「纸背从起手就有」
  的交点：取更小（更多平铺）筒又细回去，取 1.0（全卷进筒）起手那段纸背的轮廓、落影、
  明暗全都不存在。起手时纸卷和纸背一起变宽，进度约四成半之后由 10% 页宽的上限接管。
  参考实现没有这条（它筒径恒等于半页，本来就不留平铺段），属于有意为之的偏差。
- 面积对了还不够：纸背跟旧页**同纸同色**，光靠落影读起来仍像「一条空白」。
  所以纸背自己还带两样东西（见 §17.4）：一层极浅的自身明暗、整圈外沿一道细实线。

### 17.3 网格只盖掀起的**材料**

没掀起的那半页由整页绘制负责。网格要是连平铺侧的材料一起铺，就是同一张纸画两遍
（文字重影、三段文字），明暗与纸背压淡还会顺着铺到没掀的纸上。
**露出区**才是折痕另一侧的那一块，按方向取页边（向后翻在右、向前翻在左）。

卷起来之后网格在**屏幕**上会压到露出页上（纸卷就鼓在那一侧）—— 那是纸自己盖住新页，
不是重复绘制。判「该不该画」只看材料坐标有没有越过折痕，不看屏幕坐标。

### 17.4 明暗与影

- 明暗取值照抄参考实现的顶点色公式 `√(sinθ + 1.5)·0.9 + 0.1`（θ ∈ [0, π]，中间最亮）。
  参考实现是**乘**（过曝到白）；Compose 渐变是 8 位色、表达不了大于 1 的乘数，
  改成等价的「往白里压」：近白的纸直接到白，墨色只被压一点，读起来就是纸面反光。
  归一化用的两个端点就是 sinθ = 0 与 sinθ = 1 的取值（1.202 / 1.523），跨度 0.321 是算出来的；
  跨度取错（当成 0.1…1.0）最亮处就只剩三成里的两成，卷面发灰。
- **明暗只画在看得见的那一面**：卷过 90° 后外层是纸背（z ≥ R，压在正面那半圈之上），
  没绕到 90° 时只有正面露在外面。画错面等于给被盖住的几何上高光，卷面明暗对不上光。
- 纸背压淡 = 纸色盖 10%（`BACKFACE_ALPHA = 0.9`），内容剩 90%，正面的字从下面透出来一点。
  平铺段因此是**一张带镜像印字的纸**，不是一条白带；压到 0.8 以上只剩一成透印时，读者眼里
  它就退化成空白条，仍然判「纸背没画」，所以照参考实现压一成。
- **筒内侧有一层缝影，只落在筒的内壁上、而且只落在它露出来的地方**。白纸叠白画不出圆柱，
  但只在纸从筒上绕回平铺段的切线上压一层暗（哪怕只有一成、哪怕铺成缓坡），筒的左侧就会留一道
  硬边 —— 一边是平铺的纸背、一边是同色的卷面，读者看到的就是「筒的左侧平白多出一条折痕」
  （原话「筒的左侧为什么要画折痕」「这条边以及阴影别画」）。所以这层影不做「整段压暗」、
  也不描边：它只画在**正面那四分之一圈（筒的内壁）的轮廓里**，沿折痕法向做一条渐变：**折痕那一侧
  为 0、越靠背离折痕的筒口越深**（折痕这一侧的纸面还朝着光，暗的是筒口；深淡接反会让读者看到
  「圆筒内部的阴影方向画反了，应该是右侧深、左侧浅」）。纸背与外圈（纸背那半圈）都后画、压在它上面，
  中段因此被盖掉，露出来的只有**卷筒探出折角（平铺的纸背三角形）以外的上下两头** ——
  那里看见的正是筒里的内壁，光进不去。早先按整条折痕铺一条矩形式渐变时，影越过卷筒落到纸背
  与外圈上，读者判「透到外侧」「没纸的地方也画」。
- **纸背不压暗、不描边**。早先给纸背铺过整片极浅明暗、又沿外轮廓描过一道细实线，两样都退役：
  整片压暗让读者觉得「反面比正面暗」，描边则让读者觉得「卷筒左侧凭空多出一条痕迹」。
  纸背的可辨识度只靠两样：自己的镜像内容 + 折角那**两条直角边**的接触影。
- 落影：从**网格沿法向最远处**（纸卷轮廓，不是折痕）起，往露出页一侧铺的渐变带，
  宽度 = 卷起高度的一半、浓度按 `卷起高度 / 2R` 走（纸刚离页时几乎没有影，卷得越高影越远越深）。
  影的形状**只能取纸卷自己的轮廓**：早先按「沿折痕的一条平行四边形」铺，折痕铺满整页、纸却不是
  —— 纸的切边在屏幕上是圆弧，折痕两头更早就是空白，影却顺着折痕拖到屏幕边，读者看到的就是
  「圆弧外面多画了一段直线」，判「卷筒到纸边也截止、不能在没纸的地方还卷」。现在取纸卷外沿
  那一段扫线沿法向挤出（`ROLL_SHADOW_OUTER_SHARE`），影的两头跟着纸的切边收成圆弧、到纸边即止。
- **纸背的影只落在折角那两条直角边上**（`CURL3D_BACK_SHADOW_WIDTH / _ALPHA`，0.7R / 0.62）：
  平铺的纸背是翻过去那半页的反面，跟底下的旧页同纸同色 —— 不落影时读者只看见旧页的字被
  切断、切断处什么也没有，读起来就是「纸背根本没画」。影按**每条边自己的法向**往外铺
  （背离纸心），因为纸边跟着折痕一起斜、法向互不相同。
  两条影带各自铺到纸角就停，转角那个 90° 缺口再用一把**以纸角为心的径向扇形影**
  （`drawCornerShadow`）补上：扇形的两条直边就是影带的终止线、边上浓度与影带相同，所以拼起来
  是一整片。早先两条带子各停一条垂线，角上正好空一个楔形缺口，读者看到的就是「直角处两条
  阴影带没有融合在一起」。扇形只在**自由边退化成一点**（两条直角边共用一个纸角）时才画：
  自由边还有长度时，每个角旁边是「纸压着纸」，不补。
  与折痕平行的那条**自由边不落影、也不描边**：它挨着纸卷，铺一道影过去就是读者说的
  「卷筒左侧那条平行痕迹 + 一道影」—— 那里是纸自己压着纸，没有影。
- **压淡与明暗都照着网格自己的轮廓画**（每段的外轮廓 = 两侧长边 + 首末行），
  不再另画「沿折痕的一条平行四边形」—— 那正是读者看到的「深浅不一的半透明长条」。
- **每段先铺纸色，纹理只画在版心材料范围内**。页栅格只有版心那么大（平板 1585×2400 放在
  1840×2800 里，右侧页边距 127px），页边距里没有像素；纹理一旦越界，`TileMode.Clamp` 就会拿
  版心的**最边一列/一行**去补，把那一列上的墨点拉成横贯页边距的短线 —— 读者看到的
  「反面页边距上有好几条短横线」就是这么来的（`Decal` 也不行：这个后端的
  `drawVertices` + `ImageShader` 在越界处画的是**不透明白色**，实测一条白带）。
  材料坐标沿一条扫线都是**线性**的（`u`、`v` 一起随扫线参数变），所以「裁到版心矩形」只需把
  这一行的参数区间裁掉两头，结果仍是一个四边形条带（`textureBandOutline`），纹理画在它里面，
  条带之外露出刚铺的纸色 —— 纸背的页边距因此还是纸，纸卷卷进页边距的那一截也只是纸，
  既没有条纹也不会透出底下那页的字。**两条边都要裁**：折痕一斜，同一条扫线上的材料 x 也在变
  （平板上一行能横跨大半个页宽），只按行首的 x 挑行就会把越界的另一半画进来 —— 竖着翻时看不
  出来、往页角斜着掀时才冒出来的那几条短横线就是它。

### 17.5 落点

- `commonMain` 一个函数：`drawCurl3DFrame(...)`。没有 expect/actual、没有着色器源码、
  没有安卓版本分叉。
- 纹理：Compose 公共 `Vertices` + `ImageShader` + `Canvas.drawVertices`
  （顶点色必须与顶点数等长，全给白色 + `SrcOver`；顶点级着色在真机上会变随机色，禁用）。
- 明暗 / 压淡 / 落影：`Path` + `Brush.linearGradient`（GPU 渐变画笔）。
- 页栅格（版心大小，画时减版心偏移）+ 覆盖层（整页大小）两张图各走一遍同一段网格，
  旁注 / 页码因此**跟着纸一起卷**；其中页栅格那张按材料坐标裁到版心矩形再画（见 §17.4）。
- 方向：一套式子 + `side` 因子（掀起的是 `+n` 侧还是 `−n` 侧）。向前翻是向后翻的左右镜像，
  **图像不换位**：`front` 永远是被翻走的那一页，`back` 永远是露出来的那一页。

### 17.6 验收线

- `CurlMeshGeometryTest`（16 条）：半径口径（封顶 10% 页宽、收尾随剩纸收细）、
  **纸背至少占掀起材料的三成**（两个方向、八档进度）、筒径是看得见的筒而不是整页、
  **纸卷至多压进行首 3% 页宽、露出宽度跟着进度走**、粗细恒定后才收细、纸卷鼓在掀起侧、
  网格只铺掀起的材料、每条扫线铺满页高、掀起侧页角在网格里、两个方向互为镜像、顶点不越页、
  三段索引首尾相接且画序正确、弧长跟着材料走、退化输入不出网格、斜折痕不断带。
- `Curl3DRenderTest`（11 条，走生产路径 `drawCurl3DFrame`）：起手帧等于当前页、翻完帧等于目标页
  （撤层不闪）、纸卷鼓在掀起侧且落影之外才露新页、九成时新页占屏幕大半、
  **自由边既不落影也不描边**、**折角那两条直角边有接触影**、纸背三条边的几何（自由边横穿纸面、
  两条直角边等于平铺段宽度）、纸背不比正面暗、筒底没有折痕线、
  **纸背的页边距不许把版心边列/边行抹成条纹**、**纸卷在版心之外仍是纸色**（不透出底下那页）。
- `CurlMeshPreviewTest`：平板真尺寸（1840×2800、版心 1585×2400 偏移 128/200）
  出 `dev-fwd-p*.png` / `dev-bwd-p*.png` / `dev-tilt-*.png`，逐张对形状；另有一次
  逐像素探针（纯色页 + 一行扫描）确认纹理、压淡、明暗、落影的落点与网格一一对应。
- 真机：两个方向各拖一次、松手收尾末帧等于目标页；斜拖时页面直角仍在、不断带。
