# 翻页动画设计（截图管线 + 双页滑动 + 3D 卷曲）

> 状态：**研究/设计阶段，本分支未动生产代码**（分支 `feat/page-flip-animation`）。
> 目标读者：排版层（分页调度）、渲染层（栅格化缝）、用户层（阅读面 UI）。
> 一句话结论：**截图路线可行且地基已铺了一半（Android 已有成品页位图、预热钩子已在位）**；
> 但必须先补两块地基——① 桌面没有页位图、② 插图不在位图里（截图会丢图）；
> 卷曲 3D 可 100% 跨平台共享数学与 SkSL 源码（skiko 在 `engine-skia` 的 `commonMain`，
> `RuntimeEffect`/`Shader`/`Matrix33` 均可用），只有「把片元画出来」这一步是平台 actual。

## 2. 质量阶梯（要支持什么、怎么退化）

统一入口一个枚举，逐级退化，**任何一级都不得让用户多等**（AGENTS.md 总则第一句）。

| 级 | 名称 | 实现 | 门槛 | 观感 |
| --- | --- | --- | --- | --- |
| **L0** | 无动画 | 直接落位（今天的全部行为） | 全平台 | 瞬切 |
| **L1** | 双页滑动 | 页位图 `translate`（spread 合成一张整图横移） | 全平台，纯 Compose | 纸张平移，最稳 |
| **L2** | 立体滑动 | 页位图 + `graphicsLayer{rotationY, cameraDistance}` 或 `withTransform` 做透视抬起 | 全平台（Compose 公共 API） | 有厚度/透视的「翻卡片」 |
| **L3** | 3D 卷曲 | 逆向映射 + 明暗/高光/折痕阴影（SkSL/AGSL） | 桌面全平台；Android **API 33+** | 真曲面，背面镜像+透光 |
| **L4** | 3D 卷曲降级 | 片带仿射（24–40 条 `clipRect+drawBitmap`）或旧 2D 折 | Android 24–32 | 近似曲面 / 假折痕 |

**推荐交付顺序：L1 → L2 → L3，L4 只在真机验证出 API 33 覆盖不足时再做**（目标平板 vivo PA2353 已是 Android 13+，L4 的收益不抵维护 4 套后端的成本）。

## 3. 截图管线（第一块地基，必须先做）

### 3.1 统一栅格：把「页 → 位图」收成一个 commonMain 能力

现状缺口有两个，缺一则动画不成立：

1. **插图不在位图里** ⇒ 截图丢图（且静止/动画两套像素不一致）。
2. **桌面没有位图** ⇒ 同一个动画层在桌面无米下锅。

方案：新增 **页栅格化器**（新代码全部在 `shared-ui`，见 §9 层级自检），输入一份与平台无关的绘制描述，输出一张页位图：

```
PageRasterSpec(
  pageBg, inkColor,
  lines: List<DrawLine>,            // 已是页坐标系（ReaderPageCanvas 同款 shift）
  backgrounds: List<PageBackground>,
  bgImages: Map<String, DecodedImage>,
  images: List<Pair<PageImage, ImageBitmap>>,  // ← 新增：插图下沉
  contentLeft, contentRect(L,T,R,B), w, h,
)
→ PageRaster(skia Image)
```

- 绘制顺序**严格照抄今天屏幕上的顺序**：`clear(pageBg)` → `drawPageBackground`（含背景图）→ `LineWindowDrawer.drawLines`（墨色盖章）→ 插图按 `used` 尺寸 `drawImage`（缺图仍画灰占位，与 `drawPageImage` 的 `:136` 同语义）。
- 复用现成能力，不新增基础设施：`LineWindowDrawer` / `drawPageBackground` / `DecodedImage` 全在 `engine-skia` commonMain，skia 依赖经其 `api(libs.skiko)` 传递（`engine-skia/build.gradle.kts`）。
- 静止显示也改吃这张位图 ⇒ **屏幕像素 = 动画像素**，只有一个真相源；插图从 Compose 层下沉后，`ReaderPageCanvas` 的 `:106-108` 删掉。
- 桌面 actual 从「直画」改成「离屏栅格 + 一次 `drawImage`」：多一次整页拷贝，换来与 Android 同构的缓存与动画能力（值得）。

### 3.2 平台包装缝

```
expect fun rasterPage(spec): ImageBitmap?     // androidMain / jvmMain 各自实现
```

- **jvmMain**：`org.jetbrains.skia.Image` 直接转 Compose `ImageBitmap`（Skia 侧零拷贝，桌面顺带拿到硬件路径）。
- **androidMain**：skia `Image` → `android.graphics.Bitmap`。**这是 P0 待验证点 S1**：
  - 现役是 JPEG 编解码单跳（`ReaderPageRenderer.android.kt:115-133`，实测 ~100ms/页）。
  - 候选零编码路线：`skia.Bitmap.readPixels(byte[], ImageInfo, …)`（skiko 0.144.6 有此 API，已用 `javap` 核实）→ `Bitmap.copyPixelsFromBuffer(ByteBuffer)`。
  - 注意：`ReaderPageRenderer.android.kt:115` 记的「`Bitmap.readPixels` 真机回 null」指的是 **`android.graphics.Bitmap.readPixels`**，与 skia 的 `readPixels(byte[])` 不是一回事，**不能据此判死这条路**，必须真机重测。
  - 验收：单页整页像素搬运 **< 25ms**（1200×1800 ARGB）。

### 3.3 页位图缓存与内存预算

已落地（P0b）：`PageRasterStore.kt` + `PageRasterCache.kt`（commonMain，按字节 LRU，LinkedHashMap
access-order + `maxBytes` 驱逐）。两端 actual 只剩「skia 图 → 平台位图」最后一跳。

- **键** = `PageRasterKey`：`chapter | charStart | charEnd | widthPx | heightPx | contentRevision | bgColor | inkColor`
  （`contentRevision` 必须在键里——字重这类「行数据完全相等」的变更只能靠它失效，见 `PageRasterRenderer` 的教训；
  `spreadSide` 待双页接线时再加）。行/背景/插图本身不进键，进 `PageRasterFingerprint` 做**二次校验**：
  同键但内容变了（插图补解码）必须重画，否则灰块留一辈子。
- **预算**：Android `56MB`（约 6 页）、Desktop `64MB`（约 8 页，窗口更大单页 8MB+），低端机按比例下调（§7 开关）。
- **两级分辨率**（P0b 只做了第一级）：
  - **全分辨率**：静止显示（已落地，替代单槽 `cachedPage`，「回访页首帧即有图」扩到文字页）。
  - **1/2 代理位图**：动画专用，**待 P1**。理由：卷曲过程中纹理被压缩/拉伸，全分辨率无视觉收益，内存只要 1/4。
    注：`PageRasterStore` 限 UI/渲染线程，后台预栅格要另开一条路（§7 S2 线程安全验证之前不做）。

### 3.4 什么时候栅格化（对齐分页调度总则）

动画层的预热**不得抢占**排版调度：

| 对象 | 时机 | 线程 | 依据 |
| --- | --- | --- | --- |
| 当前页 | 显示时同步栅格（保持现状） | UI/渲染线程 | 总则第 1 条：锚页立即同步 |
| 锚页 ±1 页 | 锚页落定后**后台**栅格代理位图 | 后台（§7 S2 待验证） | 总则第 2 条：正负 1 是第二优先级 |
| ±2 及远页 | **不预热** | — | 第三优先级是磁盘表，不抢 |
| 跨章目标页 | 落在目标章后按「当前页」处理 | — | 总则第 1 条已保证目标页已排 |

预热失败/超时（沿用 800ms 上限的量级，但动画路径用更短的 150ms 预算，§6）：**宁可不翻也不等**——直接 L0 落定。

## 4. 卷曲 3D 的数学（commonMain 纯函数，可单测）

### 4.1 建模：绕折线（crease）的圆柱卷曲

把「卷起来的那部分纸」看成绕 crease 线卷成的圆柱面。定义：

- `â`：crease 方向单位向量（沿屏幕上那条折线）。
- `n̂`：垂直 crease、指向卷起侧的单位法向。
- `R`：卷曲半径（可变 → 曲面）。
- 对任意片元 `q`，先求它在 crease 坐标系里的轴向坐标 `ξ = (q - p_crease)·â`，
  再取该轴向处的 crease 点 `p0 = p_crease + ξ·â`（轴向坐标卷曲不变，这是闭式解的关键）。

**正映射（页坐标 → 屏幕）**：材料点 `p0 + d·n̂`（d>0 为卷起侧）
```
θ = min(d / R, θmax)          // θmax ≤ π，自重叠后不再画
P = p0 + R·(1 - cos θ)·n̂     // 只沿法向移动，轴向不变
N = cos θ·n̂ + sin θ·â        // 表面法线：θ=0 → n̂（正面）；θ=π/2 → â（侧视）；θ=π → −n̂（背面）
```

**逆映射（屏幕片元 → 纹理 UV，片元着色器唯一需要的方向）**：
```
C = p0 + R·n̂                 // 圆柱中心
e = q − C
if (e·n̂ ≥ 0)        → 平坦「露出区」，采样**下一页**
else if (|e| ≤ R)   → 卷曲面上：cos θ = 1 − w/R，w = (q − p0)·n̂
                      d = R·θ = R·acos(1 − w/R)          // 弧长=材料坐标（不可拉伸）
                      uv = p0 + d·n̂                      // ← 采样**当前页**
                      背面（θ > π/2 ⟺ w > R）：镜像采样 + 纸背色 + 透光衰减
else                 → 平坦「未卷区」，采样**当前页**
```
三个分支的分类是**几何完备**的（半圆盘扫掠区 ∪ 右半平面 ∪ 左侧平地），天然无重叠、无缝、无 z-fighting。

**锥度（真 3D 曲面的落点）**：令 `R(ξ) = R0 · (1 − k·ξ/ξmax)`（k=0 即圆柱，k≲0.2 视觉稳定、迭代稳定）。
此时上式变成隐式（`w = R(ξ)·(1 − cos(d/R(ξ)))`），**对 θ 做 2–3 次牛顿迭代**（初值取 `acos(1 − w/R0)`），
收敛判据 `|Δw| < 0.01px`。k 与迭代次数必须作为**统一参数**同时喂给 GPU 后端与 CPU 片带后端，保证两级观感一致。

### 4.2 着色

- 朗伯：`max(0, N·L)`，`L = normalize(0.3, −0.4, 1)` 固定屏幕空间（光不跟着纸转，符合真实观感）。
- 卷起处高光：`pow(max(0, N·H), k_s)`，`H = normalize(L + ẑ)`。
- 背面：`uv` 镜像 + 乘纸背色（沿用 `CurlView.kt:48` 的「背面低透明度透出纸色」语义）
  + 背面比正面暗一档（`×0.82`），并允许**下一版透出反面文字**（ghost）。
- 折痕两侧投影带：沿折线法向的高斯带 `exp(−(dist/σ)²)`（σ = 0.05×页宽，继承 `CurlView.SHADOW_BAND=0.05f`），
  按进度淡出（继承 `CurlView.kt:506-511`）与折痕末端扶正（继承 `:310-320`）——**3 行 shader 取代现在那 100 多行的多边形切片拼带（`CurlView.kt:392-524`）**，且无接缝。
- 越界：`θ ≥ θmax` 的自重叠区输出透明；页宽有限 ⇒ 材料 `d > W` 即纸的**自由边**，到此为止。

### 4.3 手感：与手指的精确锚定（3D 版）

`CurlView.anchoredFoldX`（`:150-155`）解的是 2D 版的「折过去的纸边恰好过手指」。
3D 版条件：页自由边材料点 `d = W` 的正映射结果落在手指 `(fx, fy)` 附近：

```
solve for R:  P(ξ_f, W) = (fx, fy)   →  一维求根（二分 12 次足够，<0.1ms）
```

手指离开后**停止跟随**（继承 `CurlView.kt:329-331` 的结论：跟随会导致撤销时逐帧抖动）。

### 4.4 单测清单（`shared-ui/src/jvmTest`，纯函数无 GPU 依赖）

1. 平坦区恒等：`w ≤ 0` 分支 `uv == 输入`。
2. 连续性：相邻 1px 输入的 `uv` 跳变 `< 1e-3`（无裂缝）。
3. 单调性：`w ∈ [0, R]` 上 `x_screen = R(1−cos θ)` 单调增；`w > R` 后单调减（翻过去的正确形状）。
4. 无 NaN/Inf：`R→0`、`w=0`、`ξ` 超界、`progress ∈ [-0.9, 1.9]` 全域。
5. 锥度迭代：k∈{0, 0.1, 0.2} 收敛且与 GPU 后端同参数结果差 `< 0.5px`。
6. 分支完备：随机 10k 片元，三分类互斥且并集覆盖卷曲活动域（无既没画正面也没画背面的空洞）。

## 5. 渲染后端矩阵（唯一需要分平台的部分）

| 后端 | 平台/门槛 | 落点 | 关键 API（已核实存在于 skiko 0.144.6 / Android） |
| --- | --- | --- | --- |
| **Skia RuntimeEffect** | 桌面全平台 | `shared-ui/jvmMain` | `RuntimeEffect.makeForShader(sksl)` → `effect.makeShader(Data.makeFromBytes(...), children, Matrix33)` → `Image.makeShader(tileX, tileY, sampling, Matrix33)` → `canvas.nativeCanvas.drawRect(paint)` |
| **AGSL RuntimeShader** | Android **API 33+** | `shared-ui/androidMain` | `android.graphics.RuntimeShader(sksl)` + `setFloatUniform` + `setInputBuffer("page", BitmapShader)` → `Paint.shader` → `drawRect` |
| **片带仿射** | Android 24–32（可选 L4） | `shared-ui/androidMain` | `save/clipRect/rotate/scale/drawBitmap` × 24–40，硬件加速画布下走 GPU 合成 |
| **旧 2D 折** | 兜底 | 复用 `CurlView` 数学（提到 commonMain） | — |

> 已用 `javap` 在 skiko 0.144.6 的 `skiko-release-api.jar` 上核实存在：
> `RuntimeEffect.makeShader(Data, Shader[], Matrix33)`、`Image.makeShader(FilterTileMode×2, SamplingMode, Matrix33)`、
> `Data.makeFromBytes`、`Matrix33`、`Bitmap.readPixels(byte[], ImageInfo, …)`。
> 缺的只有 Android 侧的 `RuntimeShader`（平台 API，API 33 起）。

**SkSL 源码共享的坑（必须处理）**：两侧的「取子着色器像素」坐标约定不同——
SkSL 里 `child.eval(float2(px, py))` 用**像素坐标**，AGSL 里普通 shader 用像素坐标、
而 `#setInputBuffer(BitmapShader)` 给的是**归一化 0..1**。
因此源码里统一写一个宏占位 `SAMPLE(uv01)`，两平台各生成一份源码字符串（只差这一行与 uniform 声明），
`CurlGeometry` 产出的参数集（含 k、迭代次数）两平台共用。

**AGSL 注意事项（写入实现清单）**：
- AGSL 只有 fragment shader，无 vertex shader ⇒ 几何（卷曲区形状）必须由 CPU 算好并用 uniform 传入，片元只做逆映射采样。
- `RuntimeShader` 在硬件加速画布上可用（API 33+）；S3 需在真机确认是否真走 GPU、能否 60fps。
- 低版本（API < 33）**不实现 L4** 时，统一落 L2（`graphicsLayer` 透视），不出现「有动画但很假」的中间态。

## 6. 手势与状态机

### 6.1 现状缺口

手势只记方向、UP 才翻（`ReaderScreen.kt:559-586`），无进度、无速度、无取消。动画层需要**连续 progress + settle**。

### 6.2 新状态机 `FlipSession`（用户层，纯状态）

```
Idle
 └─(DOWN, 过 slop, 轴向=水平, 方向确定)→ Preparing(预取 landed pos + 代理位图, 不显示)
      ├─ 就绪 → Dragging(progress, 锚点)      ← 目标页露出来，可跟手
      └─ 超时/失败 → Idle（直接落位，L0）
Dragging
 ├─(MOVE)   progress = dx / pageW（域 [-0.9, 1.9]，`CurlView.kt:128-131`）
 ├─(UP, |dx|/w 或速度过阈)→ Settling(commit)
 └─(UP, 不足)→ Settling(rollback)
Settling
 ├─ commit  : progress → 1（下一页）/ → 1+0.9|tilt|（上一页，`:196-200`），600ms，EaseOut
 │           p ≥ 0.9 时**提前落位**（`:215-221`），动画尾与落位重叠 → 消除「看起来翻完了但点不动」
 └─ rollback: progress → 0 / −0.9|tilt|，500ms（`:205-210`）
```

- 落位顺序：**先落位（数据）后出画（像素）**。落位走既有 `AnchorFunnel.navigate`，动画层只是它的观察者/装饰者，不新增第二个落位通道 ⇒ 不破坏「显示状态的唯一写入通道」这条不变式。
- 动画进行中再触发翻页：`AnchorFunnel` 现有 BUSY-DROP 语义直接沿用（丢弃），不新增排队。
- 封面页：沿用 `flip()` 封面特判（`ReaderScreen.kt:348-369`），动画层对封面走「淡入淡出」而非卷曲。

### 6.3 「动画不得增加等待」的具体口径

| 情形 | 处理 |
| --- | --- |
| 代理位图已就绪 | 全量卷曲（L3），零等待 |
| 代理位图未就绪、代理位图正在栅格 | 直接落位 + L1 平移（用当前页位图，最多 120ms），**不等** |
| 代理位图缺失（首次/被 LRU 淘汰） | 后台补栅格；本次 L0 |
| 目标页是别章 | 总则第 1 条已保证目标页已排好，位图可即时栅格 |

## 7. 双页（对开）

### 7.1 语义

- `spread = (left, right)`；`left` 偶数、`right` 奇数（订口朝内、书口朝外）。
- 章首页默认**独占右页**（左页留白）；是否允许「章首页独占左页」做成设置。
- 跨章自然成立：左页可以是上一章末页。

### 7.2 路线 A（推荐）：半宽视口 + 页对

- 分页按**半宽**进行：给引擎传 `setViewport(pxW/2 − gutterAdj, pxH)`，边距改为「外侧大 / 内侧小（订口）」。
- 排版层**零改动**：视口尺寸本来就是入参，单栏逻辑照旧。
- 显示层：`left = page[i]`，`right = page[i+1]`，翻页步进 2 页；spread 位图 = 两页并排合成（或保留两张、动画时分别变换）。

**影响面必须逐条交代**：

| 影响 | 结论 |
| --- | --- |
| 磁盘表作废 | `setViewport` 尺寸变化 → `cleanStaleDiskTables()`（`BookDocumentController.kt:686-690`）自动清；单双页切换 = 一次性全量重排，符合总则「版面改变即全部重来」 |
| 分页调度总则 | 调度单位仍是「页」，页对只是**显示层聚合** ⇒ 总则第 1/2/3 优先级表述**不用改**。只需补一句：spread 的左右两页都属第一优先级 |
| 锚页 | 仍是单页；落位存 `ReaderPos`（单页），恢复时向上取整到 spread 起点（跨章时回到上一章末页） |
| 页码口径 | `settings.pageNum` 与目录页码要定：显示 **spread 序号**（读者心智，与纸书一致）还是页序号。二选一，文档化 |
| 进度条 | `host.pageProgress(pos)` 口径不变（单页 fraction），只影响滑块刻度显示 |
| 跨章页对 | 左页=上章末页 + 右页=本章首页 ⇒ 排版总则里「正负 1 页是另一章」的判定天然命中已有规则，无需新逻辑 |

### 7.3 路线 B（不推荐）：引擎双栏

分页器支持「一页两栏」⇒ `PageSlice` 跨栏 ⇒ 直接撞上分页调度总则的核心（页边界定义、临时表窗口、章首页交接点、`P10 enforceTempWindow` 驱逐策略）。改动面覆盖整个排版层上，收益仅是「行块不跨栏切断」这一点。**结论：不做**，除非路线 A 出现不可接受的问题。

### 7.4 双页下的卷曲语义

| 模式 | 描述 | 需要的位图 | 建议 |
| --- | --- | --- | --- |
| 整幅滑动 | spread 合成一张 2W×H 位图横移 | 1×spread | **先做**（L1） |
| 书页式对卷 | 右页卷起翻到左侧，露出的左页成为新右页 | front/back/next-left/next-right = 4 | L3 阶段做，观感最像纸书 |

f2571fa 已把「翻页动画/封面拉伸/启动续读/显示页码」四开关 + 翻页动画模式从 `onCommitTypography`

（`cleanStaleDiskTables` 空转）——是「白干一场」而非数据损坏，但大章/长书就是几百毫秒到数秒的无谓占用，

修法（已落地，两端同规则）：判定收敛到共享函数，两端问同一个问题，不在壳里各写一遍字段清单。

1. `ReaderSettings.withoutNonLayout()`（`common`，紧挨 `withoutLight()`，同构清中性值）：
   亮度族 + `pageAnim` / `pageAnimationMode` / `coverStretch` / `autoContinue` / `pageNum` /
   `showHiddenFonts`。桌面 `ReaderView.kt:244` 改用它；快照拆成 `layoutSnapshot`（判定基线，
   纯 UI 变更也跟随）与 `appliedLayout`（喂宿主构造）。
2. 面板 KDoc 写死维护条约：**新增字段必须同改两处**（面板路由 + `withoutNonLayout` 登记）。
3. `SettingsLayoutScopeTest`（`common/jvmTest`）锁三族行为 + **完备性**（从 `ReaderSettings.kt`
   源码抽字段名，新增字段未分类即红）——把「以后再漏一个」从口头纪律变成红灯。

顺带被这把锁抓出来的两件事：
- `fontSize` **确实进版式**（`TypographicProfile.kt:129` 用 `fontSize × fontScaleToRatio` 算 bodyPx），
  不能当惰性字段；
- `theme` / `scheme` / `bgOverride` / `fgOverride` / `schemaVersion` 属「只改像素不改版面」的惰性族，
  夜间切换在两端都仍会白跑一次本章重排——**本次刻意不摘**（要摘得先确认阅读面配色链路对
  无重排的假设成立），列为独立待办。

本设计的新字段归属：`pageAnimationMode="curl3d"` **必须**进 `withoutNonLayout()`；
`spreadMode` **故意不进**（切对开会改视口，本就该走 `setViewport` → 全量重排通道）。

## 9. 架构合规自检

### 9.1 层级（AGENTS.md 项目架构约束）

| 新增代码 | 所属层级 | 说明 |
| --- | --- | --- |

若日后有人想把 `CurlGeometry` 塞进 `engine-skia`，按「分层引擎基础设施」定位判为越界（除非它变成两个阅读器共用）。

### 9.2 KMP + CMP 跨平台共享

- 卷曲数学、状态机、键、预算策略：**commonMain**，jvmTest 可直测（skiko 在 `commonMain`，`RuntimeEffect`/`Shader`/`Matrix33` 已用 `javap` 核实存在）。
- 平台差异**只有两处**：① skia Image→平台位图；② 片元后端（RuntimeEffect / RuntimeShader / 降级）。
- 不引入 Android View（不复活 `CurlView` 的 View 路线），全部留在 Compose `Canvas` 内（`drawIntoCanvas{ nativeCanvas }`）。

### 9.3 样式层叠三问

**不适用**：本设计不发任何 CSS 声明，不新增 tier，不碰 `Cascade`。主题底色/墨色仍由既有层产出，
翻页层只做**像素搬运与几何变换**（读者层压过书的原则在这里表现为「读者选的翻页效果压过书的 CSS 动画」，方向一致）。
