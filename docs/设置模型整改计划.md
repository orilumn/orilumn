# 设置模型整改计划（全局 / 本书两级）

> 依据：2026-10-28 读者定口 —
> 1. 每本书打开时默认采用**原书设置**，所有非全局设置均从原书读取设置值；原书未设置的样式，
>    采用本项目预设默认值。
> 2. 面板中所有非全局设置**仅对本书有效**，不再保留它们的全局存储区。
> 3. 全局项只有：亮度全部、阅读主题全部、笔记全部、启动时继续阅读开关、显示页码开关（未实现），
>    外加**首行缩进**（`null` = 不声明、`0` = 明确不缩进、N = N em）。其他均为私有项。
> 4. 行距不给「跟随原书」伪档位，也不用 0 冒充「没配」：没配就是 `null`（不发行距声明），
>    0 就是 0；面板显示原书实际行高，原书没写就显示引擎初值 1.5（实际生效值）。
>    书有就书、书没有才落到 1.5。字重与字族一起按书，旧全局字重不搬运。
>
> 状态：**P0–P5 已落地**（2026-10-29 收口）：归属与存储（全局项只写全局、私有项只写本书、稀疏覆盖层）、
> 排版主题与缩进三态、行距「没配不声明」、开书探针退役、面板路由收口、文档与 CHANGELOG 同步；
> 两端开书合成统一走保存层同一入口，面板读数（缩进/行高）有专门用例锁住「不落盘」。
> 遗留小尾巴（页码无渲染、桌面逐帧落盘等）登记在 `docs/TODO-未尽事宜.md`；
> §7.2 手工验收（真机/桌面各开两本书）待在设备上走一遍。
> **2026-10-29 复核**（覆盖上面 2026-10-28 定口的第 3 条）：`showHiddenFonts` 定为全局
> （字体列表隐藏过滤，与书无关）；**首行缩进为私有项**（上面「外加首行缩进」一句作废）；
> 行距「默认 1.5」是**生效值**口径（见 §3.3），不是存储值口径。

## 0. 一句话

全局存储区只剩「跟某本书无关的阅读环境与读者印记」；其余全部按书保存。
每本书默认原书样式：读者没配的项**一律不发声明**，由书自己的 CSS 生效；
书没写的部分才落到本项目预设（UA 层）。

## 1. 目标模型

### 1.1 全局项（`settings/reader.json`，唯一的全局区）

| 组 | 字段 | 说明 |
|---|---|---|
| 亮度全部 | `brightness` `brightnessFollowSystem` `brightnessOffset` `eyeProtectionLevel` `brightnessGestureLeft/Right/Two` | 物理背光 / 遮罩 / 手势，与书无关 |
| 阅读主题全部 | `scheme` `bgOverride` `fgOverride` | 白天/夜间、背景/墨色、三色预设滑条；自定义主题预设仍存原处（不入 `ReaderSettings`） |
| 笔记全部 | `highlightColorSlots` `underlineColorSlots` `highlightDefaultSlot` `underlineDefaultSlot` `annotationLastKind` `annotationLastLineStyle` `noteFont` `noteFontWeight` `noteFontScale` | 标注色槽、默认格、浮动菜单上次类别/线型、批注字体、字重与字号 |
| 开关 | `autoContinue` | 启动时继续阅读 |
| 开关 | `pageNum` | 显示页码（**尚无渲染实现**，见 §2.2） |
| 字体表 | `showHiddenFonts` | 字体管理列表里「隐藏/显示」的过滤。**现状就在全局，本次不动**（与某本书无关，换书不复位；2026-10-29 复核确认） |
| 元数据 | `theme` `schemaVersion` | `theme` 仅旧档迁移输入；`schemaVersion` 持久化版本 |

### 1.2 私有项（`settings/books/{bookId}.json`，一本书一份）

`layoutTheme` `fontSize` `fontScale` `lineSpacing` `cjkLatinSpacing` `firstLineIndent` `paragraphSpacing`
`paragraphGap` `letterSpacing` `marginTop/Bottom/Left/Right` `fontBody` `fontTitle` `fontCode`
`fontWeightAnchors` `fontWeightAnchorsBySlot` `useUserScripts` `pageAnim` `pageAnimationMode`
`coverStretch`（`useOriginalStyle` 退役，见 §3.6）

**覆盖层是稀疏的**：只存「和本项目预设默认值不同」的项。文件不存在 = 这本书完全没配过 = 原书。
（这推翻 2026-10-28「全量快照」口径 —— 那条的理由是「把改动传染给全局、新书继承」，
本次决定把传染通道整个删掉了，前提消失，全量快照只剩坏处：把预设值焊死进书里，
以后改预设到不了它。）

**字体分三件，别混**：
- **隐藏/显示过滤**（字体管理列表）**本来就是全局**（今天就在 `reader.json` 里，本次不动）：
  它是「我装了一堆字体，列表里别全塞给我」的偏好，与书无关，换书复位才是怪事；
- **选哪个字族**（`fontBody/Title/Code`）与**选哪一档字重**（`fontWeightAnchors*`）都是私有
  （2026-10-28 定口）：同一本书挑宋体 + 粗一档，不许传染到别的书，也不许被别的书的挑选改掉；
- 将来若做「全局把某族整体换成 sans-serif/serif」的**通用族替换**，那是另一条全局通道，
  与上面三件无关，本次不做（§10-7）。

### 1.3 开书时生效值怎么合成

```
effective = ReaderSettings.DEFAULT          // 本项目预设
              .onlyGlobal()                 // 覆盖全局文件里的全局项
              .applyOverlay(本书覆盖层)      // 覆盖本书显式配过的私有项
```

- 新书（无覆盖层）= 预设 + 全局项 → 排版上就是「原书样式」。
- 有覆盖层 = 预设 + 全局项 + 读者在本书动过的那几项。
- **全局文件里不再有私有项**；旧档里的这些键读时忽略（§5）。

### 1.4 每个私有项「没配」时渲染成什么

| 私有项 | 没配时 | 效果 |
|---|---|---|
| `layoutTheme` | `"original"` | 主题层整张不加载 → 书 CSS 说了算 |
| `fontBody/Title/Code` | `""` | 不发 `font-family` → 书的字体 |
| `fontWeightAnchors*` | 空 | 不发 `font-weight` → 书的字重 |
| `lineSpacing` | `null`（**没配**） | 不发 `line-height` → 书的行高；书没写则由**引擎初值** 1.5 兜底（不加 UA 声明） |
| `letterSpacing` | `null`（**没配**） | 不发额外字距 → 本书正文段落的 `letter-spacing` 生效（书没写 = 0）；面板显示原书实测字距（§3.4c） |
| `cjkLatinSpacing` | `25` | CLREQ 预设间隙（本项目排版规则，不是书的） |
| `paragraphSpacing` | `null`（**没配**） | 引擎不覆盖 → 书的段距原样；面板显示原书实测值（书没写 = UA 的 1em） |
| `paragraphGap` | `100` | 乘 1.0 → 其它结构块边距原样 |
| `margin*` | 预设几何 | 阅读页面边距（书侧没有对应声明，属读者几何） |
| `fontScale`/`fontSize` | `51.39`/`18` | 本项目基准字号（书的相对 `em` 照常乘算） |
| `useUserScripts` | `false` | 不启用用户样式表（当前无消费者） |
| `pageAnim` `pageAnimationMode` `coverStretch` | `true` `"slide"` `true` | 预设 |

首行缩进是私有项（§1.2）：`null` = 不声明（书的缩进生效），`0` = 明确不缩进（发声明清零），N = N em。

## 3. 设计要点

### 3.1 单一归属源

新增 `common/.../data/settings/SettingsScope.kt`（纯数据，无平台代码）：

```kotlin
object SettingsScope {
    val GLOBAL: Set<String>        // §1.1 的字段名（不含 schemaVersion 的可写清单单列）
    val PRIVATE: Set<String>       // §1.2
    fun ReaderSettings.onlyGlobal(): ReaderSettings        // 私有项全部回预设
    fun ReaderSettings.withGlobalFrom(next: ReaderSettings): ReaderSettings
    fun BookSettings.normalized(): BookSettings            // 丢掉 == 预设默认值的项
}
```

`SettingsPersistenceScopeTest` 用源码扫描锁「`ReaderSettings` 全部字段 = GLOBAL ∪ PRIVATE，且不交」，
新增字段忘了归属即红。

### 3.2 存储与写入规则

`PerBookSettings` 收敛为两条独立写：

```kotlin
fun effectiveFor(bookId: Long?): ReaderSettings =
    globalStore.load().applyOverlay(if (bookId != null) bookStore.load(bookId) else BookSettings.EMPTY)

fun persist(bookId: Long?, next: ReaderSettings) {
    val g0 = globalStore.load()
    val g1 = g0.withGlobalFrom(next)
    if (g1 != g0) globalStore.save(g1)                     // 全局项只写全局

    if (bookId != null) {
        val o0 = bookStore.load(bookId)
        val o1 = BookSettings.fromReaderSettings(next).normalized()   // 只留有差异的私有项
        if (o1 != o0) bookStore.save(bookId, o1)           // 私有项只写本书；空文件即删除
    }
}
```

- 删掉 `bookOnly` 参数与三分支：**没有任何一项需要「只写本书」的特殊通道**。
- 删掉 `bookChanged` 判定、`BookSettings.fromReaderSettings` 的全量语义、`ReaderSettings.mergeFrom`
  与 `BookSettings.fromReaderSettingsJson`（均无生产调用方）。
- 并发写保护（`Mutex` + 提交序号）保留：拆写之后仍有「后落盘的旧快照顶掉新改动」风险。
- `ReaderSettingsStore.load()` 改为 `fromJson(text).onlyGlobal()`；`save()` 写 `onlyGlobal()` 的 JSON，
  全局文件里从此不会出现私有键。

### 3.3 行距：默认仍是 1.5，但「没配」= `null`（不声明），0 就是 0

- **「默认 1.5」是生效值口径，不是存储值口径**（2026-10-29 复核）：书没写行高时，实际生效值
  就是 1.5（引擎初值），面板也显示 1.5 —— 这一点不变。变的是**存储**：读者没配时存 `null`，
  不是把 1.5 焊进书里。否则「读者没配」与「读者就要 1.5」在存档里同形，书自己的行高永远读不到。
- `ReaderSettings.lineSpacing` 由 `Double = 1.5` 改为 **`Double? = null`**：`null` = 本书没配 ⇒
  不发行距声明，书的行高生效；**任何实数都照原样发**（0 就是 `line-height: 0`）。模型里**不存在**
  「0 代表没配」的约定 —— 那是从首行缩进的既有门控借过来的，行距不适用：行距旧默认是 1.5，
  滑条 0.5–2.5，0 从来不是这里的值，不该为了给「没配」找位置临时造一个哨兵。
- `TypographicProfile.lineSpacing` 跟着改成 `Float?`；`ReaderUiSheet.build`：`null` → 不发行距规则，
  非 null 才发。`LayoutParamKey` 用 NaN 的位模式编码 `null`，保证 `null ↔ 0` 也算键变化
  （不能让它和某个实数撞成同一个键）。
- **UA 层不加任何行高声明**（原计划想在 `ua.css` 给 `p, li, blockquote, td, th, dd` 以及 `div`
  加 `line-height: 1.5`，**已否**）：UA 一旦声明行高，就会压住「书在 `body`/容器类上声明、
  段落靠继承」的那批书 —— 实测 33 本声明行高的书里有 9 本正是这种写法，加了反而读不到原书行高，
  方向与目标相反。书没写时由**引擎初值** 1.5 兜底（`CssDefaults.DEFAULT_LINE_HEIGHT` 建在根样式上，
  级联结果本来就是 1.5），不需要任何 CSS 声明。
- 面板**不设「跟随原书」档位**：滑条显示的数字就是本书正文段落的实际行高 ——
  **原书是多少就显示多少；原书没写，显示引擎初值 1.5**（那本来就是实际生效值）。
  显示优先级：本书显式值 > 原书实测值 > 1.5。实测值按**当前章**的正文段落量
  （打开面板时一次**只读测量**），不落盘、不参与版式；读者一拖动，才写成本书的显式值。
  （不用 0 表示「没有」：0 是合法的 0 倍行高，拿它冒充「没配」就是把刚拆掉的哨兵换个地方装回去。）
- 测量要能区分「书把正文行高改过」与「书没写、停在引擎初值」：先用 UA + 作者样式算出正文段落的
  众数，再和「只有 UA」的结果比；两者相同 → 显示 1.5（书没写，或者写了也正好等于 1.5，无差别）；
  不同 → 显示书那个值。书把 `line-height` 写在 `body`/容器上、段落靠继承的，也在这一步被正确读到。
- 滑条范围仍是 0.5–2.5、0.1 一档（0 不是可选值）；拖到哪档就存哪档，没有归零档。
- 主题层不再需要写行距；`withLayoutTheme` 三支都不再碰行距。

这样「每本书首先读原书设置」不靠开书探针，而是靠**不声明**让级联自己读：
书有就书、书没写才 1.5。开书路径零额外工作（§3.7）。

### 3.4 首行缩进：私有，`null` / `0` / N 三态

- 字段 `Double? = null`（**本书私有**，2026-10-29 定）：
  - `null` = **不声明**，书的缩进原样（含悬挂缩进）；
  - `0` = **明确不缩进**，发 `p{text-indent:0em}`（tier 44 压过书，书的 2em 与悬挂缩进都让位）；
  - `N` = 缩进 N em。
- 现有门控 `firstLineIndentEm != 0f` 相应改成「`null` 才不发」；0 与 N 都走发声明那条。
  旧的门控是为了**保护悬挂缩进**（读者层一条裸 `p{text-indent:0}` 会把书的 `-2em` 清零），
  结果把「没配」和「不要缩进」挤进同一个 0 —— 读者选 0 也抹不掉书的 2em，正是这个 bug。
  现在保护交给 `null`（默认值，不动书），读者真要清零就选 0 —— 书的 2em 与悬挂缩进让位，
  是读者明确要求的。
- 旧档里的 0 是「没配」（旧默认 0），**升级时迁移一次**（见 §5-3：迁移后落版本标记，
  此后 0 就是「明确不缩进」的真值，不再被改写）。
- 保留在 `BookSettings`（私有）；`applyOverlay` 只取本书值，全局档里的旧键忽略；面板滑条写本书。
- 面板：未配时滑条显示**当前书的实测缩进**（只读读数，拖动即写本书显式值）。
  滑条范围 0–10 em，0 档现在真的是「不缩进」。
- **不设「回到未配」的复位入口**（2026-10-29 改口，推翻本节前面那版「加复位按钮」的设想）：
  行距与缩进和别的设置项一样，面板上没有特殊的清空按钮。要回到「按原书」，
  用「原书设置」把本书的排版覆盖整体清空（§3.5）；单项没有复位通道。
- `withLayoutTheme("traditional")` 不再写 `firstLineIndent = 2.0`——传统主题的 2em 由
  `traditional.css`（tier 42）提供，`modern.css` 的 `p{text-indent:0}` 同理；写了等于把
  读者层的显式值钉进本书，反而盖掉主题层自己的口径。

### 3.4b 段间距：绝对值 0–2em（2026-10-29 改回，推翻百分比乘算）

- 字段 `Double? = null`（**本书私有**）：`null` = 不覆盖（书 / 主题 / UA 的 `p`/`li` 边距原样生效）；
  `N` = `p`/`li` 的上下外边距**直接设为 N em**（0 = 段落紧贴）。左右外边距始终归书，不受影响。
- **为什么不再用百分比**：百分比乘的是书自己的 margin，书里 0.3em 时 50% = 0.15em、200% = 0.6em，
  而书里 1.5em 时同样两档是 0.75em / 3em —— 同一条滑条在不同书上代表完全不同的物理间距，
  读者无法凭手感记住档位。绝对值下 N em 就是 N em。
- 引擎落点 `StyleComputer.paragraphEm`（`p`/`li` 的纵边距）；`LayoutParamKey.paragraphSpacingEm`
  用 NaN 编码 `null`（与 0 区分）。UI 层仍然**零纵边距声明**（纵边距随版式算，不进层叠）。
- 疏密（`paragraphGap`）仍是百分比乘算，只作用于 `p`/`li` 之外的块；两者的滑块取值不再互相映射。
- 面板：未配时显示**原书实测段距**（`BookStyleProbe.paragraphSpacingEm`：`<p>` 的
  `max(margin-top, margin-bottom) / font-size` 众数，量化到 0.1 并夹在 0..2；读数**含 UA 基线**，
  书没写就是 1em）。这与行距「书没写显示 1.5」同口径——面板显示的是**实际生效值**。
- 旧档百分比一次性迁移：`100` → `null`（原书节奏），其余 `÷100` 后夹到 0..2
  （150% → 1.5em）；`> 2` 的值必是旧百分比，读时就地按旧口径折算。
- **字间距（2026-10-29 补齐，见 §3.4c）**：书的 `letter-spacing` 此前是死字段，现已由引擎消费，
  于是字间距也能「没配按书」。

### 3.4c 字间距：没配按书，配了全章覆盖（2026-10-29）

- 字段 `Double? = null`（**本书私有**，槽位 -100..100 = -0.2em..0.2em）：`null` = 读者没配 ⇒
  引擎**按书**（正文段落的 `letter-spacing`，书没写就是 0）；`0` = 明确不加字距（与没配不同，
  会压掉书的字距）。
- 引擎侧新增**章级唯一取值** `BoxChapterLayouter.chapterLetterSpacingEm(profile, markup, styleOf)`：
  读者配了就取 `profile.letterSpacingEm`，否则取 `BookStyleProbe.bodyLetterSpacingEm`（与面板
  读数同一边取样：树序第一个 `<p>`，没有 `p` 时退回根元素）。断行器、塑形、绘制、命中四处
  **共用这一个数**（`LightPrepare.letterSpacingEm` / `DrawLineBuilder` / `LineWindowDrawer`），
  避免量画分叉。
- 章内共用一个值而不是逐元素取值：断行器按实例携带字距，逐元素会导致盒流与绘制拿不同的数。
  这是已知的精度上限（书里若给某个段落单独写 `letter-spacing`，本章其它段落也会跟着用第一个
  `<p>` 的值），比「书自带的字距完全不生效」更接近浏览器。
- 面板：读者没配时滑条显示原书实测字距（`probeLetterSpacing`，槽位 = `em × 500` 夹在 -100..100）；
  拖动即写本书显式值。旧档里的 `0`（旧默认，等于「不加字距」）读档时按没配处理 ⇒ 升级后书的
  字距立刻生效。
- 分页键：`LayoutParamKey.letterSpacingEm` 用 NaN 编码 `null`，与 `0` 分开（两者版面不同）。

### 3.5 排版主题：只切开关，基线回主题层

`TypographicProfile.withLayoutTheme` 只写**私有**字段：

| 主题 | 写入 | 不写 |
|---|---|---|
| `original` | `layoutTheme`；把本书的排版覆盖恢复预设（字体槽清空、行距/字距/段距回预设、首行缩进清成 `null`） | 字号、页边距、任何全局项 |
| `modern` | `layoutTheme="modern"`、段距回 `null`、`fontBody="sans-serif"` | 首行缩进（`modern.css` 已有 0）、段距（主题层 `p,li{margin:1em 0}`） |
| `traditional` | `layoutTheme="traditional"`、`paragraphSpacing=0`（p/li 边距清零，靠缩进分段落）、`fontBody="serif"` | 首行缩进（`traditional.css` 已有 2em） |

「原书设置」按钮因此变成「把本书的排版覆盖清空」：`normalized()` 后覆盖层为空，
文件被删除，本书重新完全听书。面板不需要新增回调（`onCommitBookPrivate` 可以删掉）。
是否连字号/页边距一起重置见 §10-4。

### 3.6 退役 `useOriginalStyle`

- `build()` 的门控改为只看 `layoutTheme == "original"`。
- 读档：`BookSettings/ReaderSettings.fromJson` 里 `useOriginalStyle == true` → `layoutTheme = "original"`。
- 字段从两个数据类删掉；`TypographicProfile.useOriginalStyle` 保留（派生值，键里还用）。
- **同时**把 `layoutTheme` 补进 `LayoutParamKey` 与 `BoxChapterLayouter.structureKeyOf`：
  以前靠 `withLayoutTheme` 同步写字体槽/段距把键带变，现在不写了，裸切主题必须自己进键，
  否则会命中旧主题的磁盘表。

### 3.7 开书探针退役

`probeOriginalOnOpen`（引擎）、`probeOriginalTheme`（面板切原书时用）、`snapshotBookStyle`、
两个壳的探针调用（Android `applyOpenProbe`、桌面 `onApplyOpenProbe`）全部删除。

理由：探针存在的唯一理由是「行距默认 1.5 会无条件盖掉书的行高，只能量出来再填」。
§3.3 用「未配 = 不声明」直接消灭了这个前提；探针保留只会带来
「每次开书一次本章轻刷 + 800ms 整书重排 + 旧参数磁盘表被清」的固定代价，
以及「量出来的值要不要落盘」这个永远说不清的问题。

行距面板要显示「原书实际行高 1.7」，只留一个**打开面板时**按需测量的只读入口（§3.3）：
不参与版式、不落盘、不进开书路径。`BookStyleProbe` 的缩进与行高两项都留，都只做面板读数：
缩进不回填设置，只用来显示「当前书实际缩进多少」（§3.4）；行高同理（§3.3）。

### 3.8 面板路由

- Home 四个开关改走 light（§2.2-1）。
- `onCommitBookPrivate` 删除（不再有「只写本书」的特殊提交）。
- 笔记页 / 阅读主题页 / 缩进行本来就走 typography 或 light，只是持久化归属变化，
  面板代码不动；`lineSpacing` 那一行改成显示**原书实测行高**（原书没写就显示 1.5），
  不设「跟随原书」伪档位；拖动即写本书显式值。
- 面板不需要知道全局/私有的划分：它照旧提交整份 `ReaderSettings`，归属由 `PerBookSettings` 拆。

### 3.9 并发写

保留现有 `Mutex` + 提交序号（两端）。拆分后写的目标变多（全局文件、本书文件），
「先提交的先拿锁」仍不成立，序号判旧仍必要。

## 4. 层叠三问（AGENTS 必答）

| 声明 | 层 / tier | 谁赢 | 盖掉书的什么 | 没配时发不发 |
|---|---|---|---|---|
| `ua.css` 行高 | **不加任何声明** | — | 不盖书的任何行高（含 `div`） | 引擎初值 1.5 已在根样式上，书没写自然落到它 |
| UI 层 `line-height` | UI，tier 44 | 压过书 | 只在本书显式配过行距时发；今天是无条件发（本次改动把覆盖收窄） | **不发**（`null`） |
| UI 层 `text-indent`（缩进） | UI，tier 44 | 压过书 | `null` 不发（书的缩进/悬挂缩进原样）；`0` 发 `0em` 明确清零；N 发 N em | 不发（`null`） |
| 主题层（`modern.css` / `traditional.css`） | theme，tier 42 | 压过书（现状不变） | 字体族/缩进/段距/对齐；只在选了该主题时加载 | 原书设置整张不加载 |
| 字体槽 / 字重 | UI，tier 44 | 压过书 | 只在读者选过字族/字重时发 | 不发（空槽 / 无锚点） |

量过的结论：行高的**覆盖面今天最大**（`body,p,div,li,dd,dt,td,th,…,h1..h6` 全部无条件 1.5），
改后只剩「读者显式配过的书」。今天被 UI 1.5 盖着、书自己没声明行高的元素，删掉 UI 声明后
由引擎初值 1.5 接住，视觉不变；书声明了行高的（含只在 `body`/容器上声明、段落靠继承的那 9 本）
第一次真正按书排。UA 层保持零声明，避免反过来把继承链上的书声明压掉。

## 5. 迁移

1. **全局文件**：`load()` 时只取全局字段，旧档里的私有键（字号、字体、行距、边距、主题色、
   缩进…）一律忽略；**笔记族键保留**（它们在新模型里就是全局项，忽略会把读者的色槽与
   批注字体丢掉）。下一次任何提交把它重写成纯全局 JSON。除下面第 3/4 条（行距 / 缩进 / 段距 /
   字距）外不做值级迁移、不 bump schema。
2. **本书文件**：新 `BookSettings` 里已没有全局字段，旧键读时自然丢弃。
   旧版本探针写进去的 `lineSpacing`（量出来的书的行高，不是 1.5 的）仍然是显式覆盖，渲染不变；
   旧档 `firstLineIndent` 丢弃后改由全局 `null`（不声明）走「书自己的缩进」，视觉同样不变。
3. **行距旧值 / 缩进旧值**（都在**本书**覆盖层里）：旧档里这两项都必有值（行距旧默认 1.5，
   缩进旧默认 0），新模型里「没配」是 `null`，无法区分「读者调过」和「从来没调」。
   **一次性迁移**：第一次按新模型读本书档时，把 `lineSpacing == 1.5`、`firstLineIndent == 0`
   删掉（视为没配），重写文件并落版本标记（`settings/books.version`）；此后这两个值都是读者
   真设的值，**不再被改写**。
   不这么做的话，升级瞬间会把本书的行高压回 1.5、缩进抹平。
   **也不能每次读档都比值**（2026-10-29 修）：那样读者把行距设成 1.5、缩进设成 0，下次开书
   就会被当成「没配」打回原书的值（真机实测：行距设 1.5，关书重开回到书的 1.3）。
   行距另外一条：旧探针写进本书的实测值（不是 1.5 的）保留为显式覆盖，渲染不变。
   旧**全局**档里的缩进值直接丢弃（它已不是全局项）——一次性代价，各书回到自己的缩进。
4. **段间距 / 字间距旧值**（都在**本书**覆盖层里）：
   - 段间距旧档存百分比（0..1000，100 = 原书节奏），新语义是绝对值 em（0..2）。读档时
     `100` → `null`（不覆盖），其余 `÷100` 夹到 0..2（150% → 1.5em）；`> 2` 的值必是旧百分比，
     就地按旧口径折算，随 `books.version` 一次性重写。
   - 字间距旧档默认 `0`（旧语义「不加额外字距」）。新模型里 `0` 是「明确压掉书的字距」，
     两者不是一回事 ⇒ 读档时 `0` 一律按没配处理（`null`），于是升级后书自带的字距立刻生效。
     读者真想要「不加字距」时拖一次 0 档即可（此后就是显式值）。
5. **字重锚点改私有：不搬运**（2026-10-28 定口）：旧存档里锚点只有全局一份，改私有后读时
   直接丢弃，每本书回到预设字重；读者要的那一档，进本书字体页重选即可。
   搬运不值当 —— 锚点只在挑字体时顺带选，且「哪本书当时用的是哪一档」本来就没被记录过，
   从一份全局值还原不出每本一份，多写一个一次性函数也只是猜。
   **CHANGELOG 必须写明**：升级后每本书的字重回到预设，需要的话在本书字体页重新选。
6. **一次性代价（要写进 CHANGELOG）**：
   - 升级后所有书都以原书样式打开（旧全局「现代/传统」不再沿用）；
   - 全局字号 / 页边距 / 字体 / 行距不再跨书继承，新书与本项目预设对齐；
   - 书自己声明了行高的，从此按书的行高排（今天被 1.5 压掉）；
   - 旧档里行距正好是 1.5 的，升级后视为没配（本来也是旧默认）；
   - 旧档缩进正好是 0 的，升级后视为没配（各书恢复自己的缩进，不再统统抹平）；
   - 旧**全局**档里的缩进值丢弃（缩进改为私有项，不再跨书继承）；
   - 旧全局字重锚点丢弃，每本书回到预设字重（逐本重选）。
7. **回退的未提交改动**：当前工作区那批「全量快照 + 写全局 + 探针会话内生效」的改动属于被本次
   决定取代的实现，实施时回退（保留并发写保护）；`CHANGELOG` 对应条目重写。

6. 关掉再开同一本书：上述设置保持；删 `books/{id}.json` 后回到原书。
7. 开一本正文 `p{margin:0.3em 0}` 的书：面板段间距显示 0.3；拖到 1.5 → 段落之间就是 1.5 个字高，
   拖到 0 → 段落紧贴；再开一本没写 margin 的书，面板显示 1.0（UA 基线）。
8. 开一本正文写了 `letter-spacing`（如 `body{letter-spacing:0.05em}`）的书：面板字间距显示
   对应的槽位（0.05em = 6 档），**正文真的变松**；拖到 0 档 → 松开的字距消失（明确压掉书的字距）；
   再开一本没写字距的书，面板显示 0、正文与改动前逐像素一致。

## 9. 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 视觉效果变化 | 书声明了行高的书从此按书排（今天被 1.5 压） | 正是本次要的；CHANGELOG 说明 |

| 旧档行距 1.5 / 缩进 0 被当成没配 | 这两个值就是旧默认，分不清「调过」和「没调」 | 一次性，CHANGELOG 说明；要那个数拖一下即回 |

| 桌面首帧 | 异步加载 `settings` 的旧竞态（§2.2-9） | 本次不动，登记 |
| 覆盖率 | 面板每行都要落到正确归属 | `SettingsScopeTest` + 手工清单 |
