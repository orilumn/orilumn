# 平板调试日志与分页跟踪查看指南

记录如何在平板（无线 adb）上找到调试日志、看懂分页跟踪输出，避免重启会话后重新摸索。

## 1. 连接平板（无线调试）

平板：vivo PA2353，内网 `172.16.0.203`，**端口号会变**（每次开无线调试都不同，例如 `172.16.0.203:45099`）。

```bash
adb connect 172.16.0.203:<当前端口>   # 从平板上「无线调试」界面抄当前端口
adb devices
```

注意：连接后 `adb devices` 可能同时出现**两个条目**（一个是 IP:端口，一个是 mDNS 的 `adb-400D91019H00000-...`），指向同一台平板。后续命令务必带 `-s` 指定：

```bash
adb -s 172.16.0.203:<端口> shell <命令>
```

端口变化后：`adb disconnect` 旧地址 → 重新 `adb connect`。其他工具（installDebug 等）默认选第一个设备即可，但批量调试命令建议统一用 `-s`。

## 2. 安装与启动

```bash
./gradlew :app:installDebug
adb -s 172.16.0.203:<端口> shell am start -n orilumn.reader/.MainActivity
```

- 包名 / applicationId：`orilumn.reader`
- 必须先启动（或任意一次布局/翻页）后，日志文件才会创建/追加。

## 3. 查看调试日志的两种方式

### 3.1 落盘文件（推荐，最全）

引擎日志（含分页跟踪）同时写进 app 私有目录，按天轮转（实际不一定是按天，随时有可能更新的）：

```
files/logs/日志_YYYYMMDD.txt        （当天）
files/logs/日志_YYYYMMDD.1.txt      （轮转出的旧文件）
```

读取（debug 版可用 run-as，无需 root）：

```bash
# 当天全部
adb -s 172.16.0.203:<端口> shell run-as orilumn.reader cat files/logs/日志_20260919.txt

# 只看分页跟踪
adb -s 172.16.0.203:<端口> shell run-as orilumn.reader cat files/logs/日志_20260919.txt | grep DBGPAGE

# 或顺带翻页/落位/布局上下文
... | grep -E "DBGPAGE|Orilumn.FLIP|doFlip 落位"
```

日志行格式：`W 10:44:40.870 [Orilumn.DBGPAGE] 10:44:40.862 #[000785] <正文>`，`#[000NNN]` 是全局序号，方便跨 tag 按时间排序对照。

### 3.2 logcat（实时过滤）

```bash
adb -s 172.16.0.203:<端口> logcat -s Orilumn.DBGPAGE:W Orilumn.FLIP:W
```

## 4. 日志 Tag 一览

| Tag | 内容 | 级别 |
|---|---|---|
| `Orilumn.DBGPAGE` | **当前页分页跟踪**（见 §5，每显示一页打一条） | W |
| `Orilumn.FLIP` | 每次翻页前快照：inProgress/diskTable/layout/pageSlices 等 | W |
| `Orilumn.Reader` | 打开/布局/落位/章内翻页/跨章落位，如 `flip: 章内 dir=1 -> page=18/43` | W |
| `Orilumn.View` | 绘制层 onDraw，确认渲染用的 layout 与 line 数 | D |
| `Orilumn.Engine` | 重活：DISK-HIT shape / PGL / PGAP / canonical | W/D |

## 5. `Orilumn.DBGPAGE` 分页跟踪字段

每显示一页打一行（源码入口：`BodyPageView.setPage` → `BookDocumentController.debugCurrentPage`，见 `app/src/main/java/com/orilumn/engine/BookDocumentController.kt` 文件末尾）。

示例：

```
PAGE|ch=8 2 Kotlin mode=TEMP-INCR(锚点增量流)|slice char[9199,10158) line[1,31) blk[120,130)
|diskPages=46 diskPageIdx=12 rec=char[8575,9463)blk[113,123) !!MISMATCH-当前切片≠表页
 tempWin=fwd0/bwd2 cur=bwd[1] anchorBlk=165 shapedFwdTo=306 headReached=false headLanded=false
 pageNo=13/46 totalChars=37239
|content len=959 head=... ...tail=...|nextStart=...
```

| 字段 | 含义 |
|---|---|
| `mode=` | 当前页由哪个分页机制产出：<br>`TEMP-INCR(锚点增量流)` = 大章锚点临时 block-cut 分页（增量，盘表未用/未对齐）<br>`DISK-INCR(磁盘表+窗口增量成形)` = 命中磁盘表，只成形当前页所在窗口（增量）<br>`DISK-FULL(磁盘全量表)` = 磁盘 table 已绑定（全量）<br>`FULL-CHAPTER(全章布局)` = 整章布局（小章/遗留） |
| `slice char[a,b)` | 当前页可见字符区间（全章 char 流：`img`=1 槽，`br`=1） |
| `line[x,y)` / `blk[m,n)` | 页线区间 / 参与块区间 |
| `diskPages=N diskPageIdx=i rec=...` | 磁盘分页表规模、本页 char 在表中落在第 i 页、该页表记录区间 |
| `!!MISMATCH-当前切片≠表页` | 临时切片与磁盘表页区间**对不上**（增量与全量不一致的症状） |
| `tempWin=fwdA/bwdB cur=..` | 锚点流的窗口：前后页数、当前指针（`anchorBlk`=锚点块、`shapedFwdTo`=前向已成形块、`headReached/headLanded`=是否到章头） |
| `pageNo=13/46` | 相对章头的页码（章头=1）；盘表未落时分页号不可知 → `?(无盘表)` |
| `content len=N head=...tail=...` | 页内可见文本（显示首/尾 150 字，`[img]`=一张图、`\n`=换行）；`len` 是页真实长度 |
| `nextStart=...` | `charEnd` 之后 80 字的预览（= 下一页开头），用于核对接缝 |

## 6. 核对"当前页末尾 / 下一页开头"的流程

1. 翻页前后各抓一条 `Orilumn.DBGPAGE`（带序号 `#`）。
2. 看当前页 `tail=...` 与实际屏幕末尾是否一致。
3. 看当前页 `nextStart=...` 与下一页 `head=...` 是否吻合。
4. 若两页 `char 区间` 不连续（后页 `charStart` > 前页 `charEnd`），中间就是丢了内容——把两条 `#` 序号记下给开发。
5. 顺带看 `mode=` 与 `!!MISMATCH` 判断是增量路径还是全量路径出的问题。
